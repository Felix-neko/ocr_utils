# Отчёт: Работа скрипта select_best_raws.py

## Назначение

Скрипт `select_best_raws.py` предназначен для автоматического отбора самых резких RAF-файлов (RAW-формат камер Fujifilm) из групп дубликатов. Это полезно при съёмке с брекетингом фокуса или когда делается несколько кадров одной сцены для выбора лучшего.

## Основная идея

1. **Сканирование папки** с RAF-файлами
2. **Поиск дубликатов** одним из двух методов (CNN или локальные признаки)
3. **Группировка** дубликатов в связные компоненты
4. **Оценка резкости** каждого файла
5. **Выбор лучшего** (самого резкого) файла из каждой группы
6. **Копирование** отобранных файлов в выходную папку

## Архитектура

### Перечисления

#### `Method`
```python
class Method(str, Enum):
    CNN = "cnn"
    LOCAL = "local"
```

Определяет два метода детектирования дубликатов:
- **CNN** — быстрый метод на основе MobileNet-эмбеддингов (требует GPU)
- **LOCAL** — точный метод на основе AKAZE локальных признаков (работает на CPU)

### Основные функции

#### 1. `read_raf_image(path: Path) -> np.ndarray`

**Назначение:** Читает RAF-файл и возвращает RGB-массив изображения.

**Алгоритм:**
1. Открывает RAF-файл через `rawpy`
2. Пытается извлечь встроенный JPEG-превью (быстро, ~0.1 сек)
3. Если превью отсутствует — обрабатывает RAW через `rawpy.postprocess()` (медленно, ~2-3 сек)
4. Применяет EXIF-ориентацию для корректного поворота

**Оптимизация:** Использование встроенного JPEG-превью ускоряет обработку в ~20-30 раз.

**Возвращает:** RGB-массив numpy с shape `(height, width, 3)` и dtype `uint8`.

---

#### 2. `compute_sharpness(rgb: np.ndarray) -> float`

**Назначение:** Вычисляет метрику резкости изображения.

**Алгоритм:**
1. Извлекает центральный кроп размером 2/3 × 2/3 от исходного изображения
2. Конвертирует в градации серого
3. Применяет оператор Лапласа (выделяет границы)
4. Вычисляет дисперсию результата

**Почему центральный кроп?** Края изображения часто имеют виньетирование или меньшую резкость из-за оптики объектива.

**Интерпретация значений:**
- **500-2000+** — резкое изображение
- **200-500** — приемлемая резкость
- **<200** — размытое изображение

**Возвращает:** Значение резкости (float).

---

#### 3. `compute_local_features(rgb: np.ndarray, max_width: int = 1024) -> tuple[list, np.ndarray | None]`

**Назначение:** Вычисляет AKAZE-ключевые точки и дескрипторы для сопоставления изображений.

**Алгоритм:**
1. Извлекает центральный кроп 2/3 × 2/3
2. Ресайзит до `max_width=1024` пикселей по ширине (ускорение ~8×)
3. Конвертирует в градации серого
4. Детектирует AKAZE-ключевые точки и вычисляет дескрипторы

**Почему AKAZE?**
- Быстрее SIFT/SURF
- Устойчив к изменениям освещения
- Бинарные дескрипторы (61 байт) — быстрое сравнение через расстояние Хэмминга

**Возвращает:** Кортеж `(keypoints, descriptors)`, где:
- `keypoints` — список `cv2.KeyPoint`
- `descriptors` — массив shape `(n_keypoints, 61)` dtype `uint8` или `None`

---

#### 4. `match_local_features(...) -> int`

**Назначение:** Сопоставляет локальные признаки двух изображений и считает RANSAC-инлайеры.

**Параметры:**
- `kp1, desc1` — ключевые точки и дескрипторы первого изображения
- `kp2, desc2` — ключевые точки и дескрипторы второго изображения
- `ratio=0.75` — порог для Lowe's ratio test
- `max_scale=1.3` — максимально допустимое изменение масштаба гомографии

**Алгоритм:**
1. **Проверка наличия дескрипторов:** Если дескрипторы отсутствуют или их мало — возврат 0
2. **Сопоставление через BFMatcher:** Использует расстояние Хэмминга для бинарных дескрипторов
3. **Lowe's ratio test:** Отфильтровывает неоднозначные совпадения
4. **RANSAC-гомография:** Вычисляет гомографию через `cv2.findHomography()` с RANSAC
5. **Проверка масштаба:** Вычисляет `scale = sqrt(|det(H[:2, :2])|)`
   - Если `scale ∉ [1/1.3, 1.3]` — возврат 0 (разное кадрирование)
   - Иначе — возврат количества инлайеров

#### Детальный разбор ключевых строк кода

##### Шаг 3: Lowe's Ratio Test
```python
good = [
    m for m, n in cv2.BFMatcher(cv2.NORM_HAMMING).knnMatch(desc1, desc2, k=2) 
    if m.distance < ratio * n.distance
]
```

**Что происходит:**
1. **`cv2.BFMatcher(cv2.NORM_HAMMING)`** — создаёт Brute-Force Matcher с расстоянием Хэмминга
   - Для бинарных дескрипторов (AKAZE) расстояние Хэмминга = количество различающихся бит
   - Вычисляется через XOR + popcount (очень быстро)

2. **`.knnMatch(desc1, desc2, k=2)`** — для каждого дескриптора из `desc1` находит 2 ближайших в `desc2`
   - `m` — лучшее совпадение (минимальное расстояние)
   - `n` — второе лучшее совпадение

3. **`if m.distance < ratio * n.distance`** — Lowe's ratio test (D. Lowe, 2004)
   - Если лучшее совпадение **значительно лучше** второго → принимаем
   - `ratio=0.75` означает: `distance(m)` должно быть < 75% от `distance(n)`
   - **Зачем:** Отсекает неоднозначные совпадения (когда несколько точек похожи)

**Пример:**
- Дескриптор A из img1 имеет 2 кандидата в img2:
  - Кандидат B: distance = 30 бит
  - Кандидат C: distance = 45 бит
- Проверка: `30 < 0.75 × 45` → `30 < 33.75` → ✅ принимаем (B — однозначное совпадение)
- Если бы distance(C) = 32, то `30 < 0.75 × 32` → `30 < 24` → ❌ отклоняем (неоднозначно)

**Результат:** Список `good` содержит только надёжные совпадения.

---

##### Шаг 4: RANSAC-гомография
```python
H, mask = cv2.findHomography(pts1, pts2, cv2.RANSAC, 5.0)
if H is None:
    return 0
```

**Что происходит:**
1. **`pts1, pts2`** — координаты совпавших точек из двух изображений
   - `pts1` — координаты ключевых точек из img1
   - `pts2` — соответствующие координаты из img2

2. **`cv2.findHomography(...)`** — вычисляет матрицу гомографии 3×3
   - Гомография описывает проективное преобразование между двумя плоскостями
   - Формула: `pts2 = H @ pts1` (в однородных координатах)

3. **`cv2.RANSAC`** — метод устойчивой оценки (RANdom SAmple Consensus)
   - **Проблема:** Среди `good` совпадений всё равно есть выбросы (outliers)
   - **Решение RANSAC:**
     1. Случайно выбирает 4 точки (минимум для гомографии)
     2. Вычисляет гомографию по этим 4 точкам
     3. Проверяет, сколько остальных точек согласуются с этой гомографией
     4. Повторяет N раз, выбирает лучшую гомографию
   
4. **`5.0`** — порог репроекционной ошибки в пикселях
   - Точка считается инлайером, если `||H @ pts1[i] - pts2[i]|| < 5.0` пикселей
   - Меньше порог → строже критерий → меньше инлайеров

5. **`H`** — матрица гомографии 3×3 (или `None`, если не найдена)
   ```
   [h11 h12 h13]
   [h21 h22 h23]
   [h31 h32 h33]
   ```

6. **`mask`** — бинарный массив shape `(n_matches, 1)` dtype `uint8`
   - `mask[i] = 1` → i-е совпадение — **инлайер** (согласуется с гомографией)
   - `mask[i] = 0` → i-е совпадение — **аутлайер** (выброс, ошибочное совпадение)
   - **Пример:** Если `good` содержит 800 совпадений, а `mask.sum() = 650`, то:
     - 650 инлайеров — правильные совпадения
     - 150 аутлайеров — ошибочные совпадения (шум, повторяющиеся паттерны)

**Зачем RANSAC?**
Даже после Lowe's ratio test остаются ошибочные совпадения:
- Повторяющиеся текстуры (газетный текст, кирпичная кладка)
- Симметричные объекты
- Случайные совпадения бинарных дескрипторов

RANSAC отсекает эти выбросы, находя глобально согласованную геометрическую модель.

**Проверка `if H is None`:**
Гомография не найдена, если:
- Слишком мало совпадений (<4)
- Все совпадения — аутлайеры
- Точки лежат на одной прямой (вырожденная конфигурация)

---

##### Шаг 5: Вычисление масштаба гомографии
```python
scale = np.sqrt(abs(np.linalg.det(H[:2, :2])))
```

**Что происходит:**
1. **`H[:2, :2]`** — извлекает левый верхний блок 2×2 из гомографии
   ```
   [h11 h12]
   [h21 h22]
   ```
   Этот блок описывает аффинную часть преобразования (поворот + масштаб + сдвиг).

2. **`np.linalg.det(...)`** — вычисляет определитель матрицы 2×2
   - `det = h11×h22 - h12×h21`
   - **Геометрический смысл:** Определитель = изменение площади при преобразовании
   - Если `det = 2.0` → площадь увеличилась в 2 раза
   - Если `det = 0.5` → площадь уменьшилась в 2 раза

3. **`abs(...)`** — берём модуль (отрицательный det означает зеркальное отражение)

4. **`np.sqrt(...)`** — извлекаем корень
   - **Почему корень?** Определитель пропорционален площади (2D), а нам нужен линейный масштаб (1D)
   - `scale = sqrt(det)` — изменение линейных размеров

**Интерпретация:**
- `scale ≈ 1.0` — одинаковый масштаб (дубликаты одного кадра)
- `scale ≈ 1.05` — небольшое изменение (цифровой зум, кроп)
- `scale ≈ 0.7` — сильное изменение (полоса газеты vs. целый разворот)
- `scale ≈ 2.0` — один кадр в 2 раза крупнее другого

**Пример из практики съёмки газет:**
```
Кадр A: полоса газеты (2000×6000 пикселей)
Кадр B: разворот газеты (6000×4000 пикселей)
```
Полоса занимает ~1/3 ширины разворота → `scale ≈ 0.33`

Если `max_scale = 1.15`, то проверка `1/1.15 ≤ scale ≤ 1.15` → `0.87 ≤ 0.33 ≤ 1.15` → ❌ отклоняем.

Это предотвращает объединение в группу кадров с разным кадрированием, которые визуально похожи, но не являются дубликатами.

---

**Зачем проверка масштаба?**
При съёмке газет часто снимаются:
- Отдельные полосы (узкие вертикальные кадры)
- Целые развороты (широкие горизонтальные кадры)

Эти кадры имеют высокое сходство по содержанию, но разный масштаб (~0.7). Проверка масштаба отсекает такие ложные совпадения.

**Возвращает:** Количество RANSAC-инлайеров `int(mask.sum())`. Типичные значения для дубликатов: 500-2000+.

---

#### 5. `find_duplicates_local(...) -> dict[str, list[str]]`

**Назначение:** Находит дубликаты через попарное сравнение AKAZE-дескрипторов в скользящем окне.

**Параметры:**
- `all_names` — список имён файлов
- `all_kps, all_descs` — списки ключевых точек и дескрипторов
- `n_search` — размер скользящего окна (обычно 3-10)
- `min_matches` — минимальное количество инлайеров для признания дубликатами (обычно 300-700)
- `max_scale` — передаётся в `match_local_features()`

**Алгоритм:**
1. Инициализирует adjacency list: `{имя: [] для каждого файла}`
2. Для каждого файла `i`:
   - Сравнивает с `n_search` следующими файлами `j`
   - Если `match_local_features(i, j) >= min_matches`:
     - Добавляет `j` в список дубликатов `i`
     - Добавляет `i` в список дубликатов `j`

**Сложность:** O(n × n_search) вместо O(n²) при полном переборе.

**Возвращает:** Словарь adjacency list `{имя_файла: [список_дубликатов]}`.

---

#### 6. `filter_by_window(...) -> dict[str, list[str]]`

**Назначение:** Фильтрует дубликаты по позиции в отсортированном списке файлов.

**Параметры:**
- `duplicates` — adjacency list дубликатов до фильтрации
- `all_names` — отсортированный список всех имён файлов
- `n_search` — максимальное расстояние в позициях

**Алгоритм:**
1. Строит словарь `{имя: позиция}` для быстрого поиска
2. Для каждого файла оставляет только тех соседей, у которых `|pos[neighbor] - pos[file]| <= n_search`

**Зачем это нужно?**
Критично для CNN-метода. Разные полосы одного газетного номера имеют высокое CNN-сходство (≥0.96), но находятся далеко друг от друга в очереди съёмки (например, позиции 10 и 150). Скользящее окно отсекает такие ложные совпадения, сохраняя только соседние кадры одной и той же полосы.

**Возвращает:** Отфильтрованный adjacency list.

---

#### 7. `build_groups(...) -> list[list[str]]`

**Назначение:** Преобразует adjacency list дубликатов в список связных компонент.

**Параметры:**
- `all_names` — список всех имён файлов
- `duplicates` — adjacency list дубликатов

**Алгоритм (BFS):**
1. Инициализирует `visited = set()` и `groups = []`
2. Для каждого непосещённого узла:
   - Запускает BFS (поиск в ширину)
   - Собирает все достижимые узлы в группу
   - Добавляет группу в результат

**Возвращает:** Список групп `[[файл1, файл2, ...], [файл3], ...]`, где:
- Группы размером >1 — дубликаты
- Группы размером 1 — одиночные файлы

---

#### 8. `main(...) -> None`

**Назначение:** Основная функция скрипта.

**Параметры (CLI):**
- `input_dir` — папка с RAF-файлами
- `output_dir` — папка для лучших файлов
- `--n-search` (default=5) — размер скользящего окна
- `--method` (default='local') — метод детектирования ('cnn' или 'local')
- `--min-similarity` (default=0.97) — [CNN] минимальное косинусное сходство
- `--min-matches` (default=500) — [local] минимальное количество инлайеров
- `--max-scale-change` (default=1.15) — [local] максимальное изменение масштаба

**Алгоритм:**

##### Общие шаги:
1. Создаёт выходную папку (если не существует)
2. Сканирует `input_dir` для RAF-файлов (регистронезависимый поиск `*.[Rr][Aa][Ff]`)
3. Сортирует файлы по имени

##### Метод CNN:
1. **Создаёт временную папку** для JPEG-превью
2. **Читает RAF-файлы:**
   - Извлекает RGB через `read_raf_image()`
   - Вычисляет резкость через `compute_sharpness()`
   - Сохраняет центральный кроп 2/3 × 2/3 как JPEG (quality=90)
3. **Вычисляет CNN-эмбеддинги:**
   - Использует `imagededup.methods.CNN()` (MobileNet)
   - Батч-размер 32, автоматически использует CUDA если доступна
   - `num_enc_workers=0` — отключает IPC-оверхед для небольших датасетов
4. **Находит дубликаты:**
   - `cnn.find_duplicates(min_similarity_threshold=0.97)`
   - Применяет `filter_by_window()` для отсечения ложных совпадений
5. **Группирует через `build_groups()`**

##### Метод LOCAL:
1. **Читает RAF-файлы:**
   - Извлекает RGB через `read_raf_image()`
   - Вычисляет резкость через `compute_sharpness()`
   - Вычисляет AKAZE-признаки через `compute_local_features()`
2. **Находит дубликаты:**
   - `find_duplicates_local()` — попарное сравнение в скользящем окне
3. **Группирует через `build_groups()`**

##### Финальные шаги (для обоих методов):
1. **Выбор лучших файлов:**
   - Для каждой группы выбирает файл с максимальной резкостью
   - Выводит информацию о группе в консоль
2. **Копирование:**
   - Копирует лучший файл из каждой группы в `output_dir`
   - Сохраняет метаданные (timestamps) через `shutil.copy2()`

## Сравнение методов

| Характеристика | CNN | LOCAL |
|----------------|-----|-------|
| **Скорость** | Быстро (~0.5 сек/файл на GPU) | Медленно (~2-3 сек/файл на CPU) |
| **Требования** | GPU с CUDA, PyTorch, imagededup | Только OpenCV |
| **Точность** | Высокая для идентичных кадров | Очень высокая, устойчив к кадрированию |
| **Ложные срабатывания** | Высокие для похожих сцен (требует `filter_by_window`) | Низкие (проверка масштаба гомографии) |
| **Память** | ~2-4 GB VRAM | ~100-200 MB RAM |
| **Применение** | Большие датасеты (>1000 файлов) | Средние датасеты (<500 файлов) |

## Примеры использования

### Пример 1: Обработка газетных сканов (метод LOCAL)
```bash
python select_best_raws.py \
  "/mnt/dump3/yandex_disk_linux_baby_zergling/Общее/Фотки/неразобранное/2026-05-25 ЭГ 1965 I-III" \
  "/mnt/system/raw/1965_out" \
  --method local \
  --n-search 5 \
  --min-match-ratio 0.2 \
  --max-scale-change 1.15
```

**Параметры:**
- `n-search=5` — сравниваем каждый кадр с 5 следующими (газеты снимаются последовательно)
- `min-match-ratio=0.2` — требуется минимум 20% инлайеров от max(количество ключевых точек в паре)
- `max-scale-change=1.15` — отсекаем пары с разным кадрированием (полоса vs. разворот)

### Пример 2: Обработка фотосессии (метод CNN)
```bash
python select_best_raws.py \
  "/mnt/photos/wedding_2026" \
  "/mnt/photos/wedding_2026_best" \
  --method cnn \
  --n-search 10 \
  --min-similarity 0.98
```

**Параметры:**
- `n-search=10` — больше окно для серийной съёмки
- `min-similarity=0.98` — очень строгий порог (только почти идентичные кадры)

## Оптимизации

### 1. Использование JPEG-превью вместо RAW
- **Ускорение:** ~20-30× для чтения файлов
- **Компромисс:** Превью может быть менее резким, чем полный RAW
- **Решение:** Резкость всё равно коррелирует между превью и RAW

### 2. Ресайз перед детекцией признаков
- **Ускорение:** ~8× для AKAZE
- **Параметр:** `max_width=1024` пикселей
- **Компромисс:** Теряются мелкие детали
- **Решение:** Для газетного текста 1024px достаточно

### 3. Скользящее окно вместо полного перебора
- **Ускорение:** O(n × n_search) вместо O(n²)
- **Параметр:** `n-search=5` (типично)
- **Компромисс:** Пропускаем дубликаты, удалённые друг от друга
- **Решение:** При последовательной съёмке дубликаты всегда рядом

### 4. Центральный кроп для анализа
- **Ускорение:** ~2× (меньше пикселей для обработки)
- **Размер:** 2/3 × 2/3 от исходного
- **Компромисс:** Игнорируем края
- **Решение:** Края обычно менее резкие из-за оптики

## Типичные проблемы и решения

### Проблема 1: Ложные дубликаты между разными полосами газеты

**Симптомы:** CNN-метод объединяет в группу кадры с разных страниц.

**Причина:** Высокое визуальное сходство (одинаковый шрифт, вёрстка).

**Решение:**
- Используйте `--n-search=3-5` (малое окно)
- Или переключитесь на `--method local` с проверкой масштаба

### Проблема 2: Не находятся дубликаты с разной экспозицией

**Симптомы:** Брекетинг экспозиции не группируется.

**Причина:** CNN чувствителен к яркости, AKAZE — к контрасту.

**Решение:**
- Понизьте `--min-similarity` до 0.95 (CNN)
- Понизьте `--min-match-ratio` до 0.15 (LOCAL)

### Проблема 3: Медленная обработка на CPU

**Симптомы:** LOCAL-метод обрабатывает <10 файлов/мин.

**Причина:** AKAZE + сопоставление дескрипторов CPU-bound.

**Решение:**
- Используйте CNN-метод с GPU
- Уменьшите `--n-search` (меньше сравнений)
- Увеличьте `max_width` в `compute_local_features()` (меньше точность, больше скорость)

### Проблема 4: Слишком много/мало дубликатов находится

**Симптомы:** Скрипт объединяет не-дубликаты или пропускает дубликаты.

**Причина:** Неправильно подобран порог `min_match_ratio`.

**Решение:**
- Запустите `analyze_match_threshold.py` на своих данных
- Изучите распределение мер близости
- Подберите оптимальный порог на основе анализа
- Для строгого отбора: увеличьте `min_match_ratio` до 0.3-0.4
- Для мягкого отбора: уменьшите `min_match_ratio` до 0.1-0.15

## Технические детали

### Формат RAF
- **Производитель:** Fujifilm
- **Расширение:** `.RAF` (RAW AF)
- **Содержимое:** RAW-данные сенсора + встроенный JPEG-превью
- **Размер:** ~30-50 MB на файл

### Метрика резкости (Variance of Laplacian)
```python
gray = cv2.cvtColor(crop, cv2.COLOR_RGB2GRAY)
laplacian = cv2.Laplacian(gray, cv2.CV_64F)
sharpness = laplacian.var()
```

**Почему это работает?**
- Лапласиан выделяет границы (вторая производная)
- Резкое изображение → много резких границ → высокая дисперсия
- Размытое изображение → плавные переходы → низкая дисперсия

### AKAZE (Accelerated-KAZE)
- **Тип:** Локальный детектор признаков
- **Дескриптор:** Бинарный, 61 байт
- **Расстояние:** Хэмминг (быстрое XOR + popcount)
- **Инвариантность:** Масштаб, поворот, освещение
- **Скорость:** ~100-200 мс на изображение 1024px

### Гомография
Матрица 3×3, описывающая проективное преобразование между двумя плоскостями:
```
[x']   [h11 h12 h13] [x]
[y'] = [h21 h22 h23] [y]
[1 ]   [h31 h32 h33] [1]
```

**Масштаб гомографии:**
```python
scale = sqrt(|det(H[:2, :2])|)
```
- `scale ≈ 1.0` — одинаковый масштаб (дубликаты)
- `scale ≈ 0.7` — разный масштаб (полоса vs. разворот)

## Рекомендации

### Когда использовать CNN-метод:
- ✅ Большие датасеты (>500 файлов)
- ✅ Доступна GPU с CUDA
- ✅ Дубликаты — идентичные кадры (без кадрирования)
- ✅ Нужна максимальная скорость

### Когда использовать LOCAL-метод:
- ✅ Средние датасеты (<500 файлов)
- ✅ Нет GPU или ограничения по VRAM
- ✅ Дубликаты могут иметь разное кадрирование
- ✅ Нужна максимальная точность

### Настройка параметров:

#### `--n-search`
- **3-5** — последовательная съёмка (газеты, документы)
- **10-20** — серийная съёмка (спорт, репортаж)
- **50+** — хаотичная съёмка (разные сцены перемешаны)

#### `--min-similarity` (CNN)
- **0.99** — только почти идентичные кадры
- **0.97** — стандартное значение
- **0.95** — включает кадры с разной экспозицией

#### `--min-match-ratio` (LOCAL)
- **0.3-0.4** — очень строгий порог (только очевидные дубликаты)
- **0.2** — стандартное значение (сбалансированное)
- **0.1-0.15** — мягкий порог (захватывает больше дубликатов, возможны ложные срабатывания)

#### `--max-scale-change` (LOCAL)
- **1.1** — только идентичное кадрирование
- **1.15** — стандартное значение
- **1.3** — допускает небольшие различия в кадрировании

## Заключение

Скрипт `select_best_raws.py` — это эффективный инструмент для автоматического отбора лучших кадров из групп дубликатов. Он сочетает:

1. **Два метода детектирования** (CNN и локальные признаки) для разных сценариев

Скрипт особенно полезен для:
- Обработки архивных сканов газет и документов

- Очистки фотоархивов от дубликатов
- Автоматизации пост-обработки RAW-файлов
