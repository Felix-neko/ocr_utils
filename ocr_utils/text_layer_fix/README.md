# text_layer_fix — чистка и дополнение текстового слоя FineReader для повёрнутого текста

Зачем и что делаем — в докстринге `__init__.py`. Отчёт с замерами и порогами —
`reports/text_layer_fix.md`. Ядро (разбор слоя, зоны, чтение, вердикты, правка, кэш) зовёт сборщик
финальных PDF `ocr_utils.final_pdfs`; стенд исследования (обзор по паку, выборки, оверлеи, оценка
источников line art, сравнение с LLM) — команды `python -m ocr_utils.text_layer_fix <команда>`
(`survey`, `run`, `second-opinion`, `reclassify`, `fix`, `overlay`, `eval-lineart`, `llm-compare`,
`report`), их run-скрипты — `run_scripts/text_layer_fix`.

## Как вызывается из сборщика финальных PDF (`ocr_utils.final_pdfs`)

1. В воркере: `pipeline.process_page(doc, pikepdf_doc, index, Options(known=default_morph().known))`
   → `PageResult.to_json()` → `cache.save_page(cache.cache_path(cache_dir, pdf_name, index), payload)`.
   Тяжёлая часть — tesseract по ячейкам и зонам (медиана 1,8 с на страницу, p90 5,6 с).
2. В родителе (GPU): `second_opinion.revise([(pdf_path, json_path), …])` дочитывает surya зоны, где
   tesseract ненадёжен, и дописывает чтения в те же JSON.
3. При сборке: `fixer.plan_page_edits(source_page, pikepdf_doc, payload)` → скопировать страницу в
   выходной документ → `fixer.apply_page_edits(out_doc, out_index, edits, InsertFont())` → после
   сохранения `fixer.verify_saved(source_page, saved_page, edits, saved_main_xref)`.
   Правка требует **одного** потока содержимого на странице — делать её до добавления
   своих слоёв (JPEG-иллюстраций).

## Как устроено

| Модуль | Что в нём |
|---|---|
| `text_layer.py` | Разбор потока содержимого до слов (спан `/Span <</MCID n>>` = слово) и глифов; привязка к символам `rawdict` по началу глифа; метрики шрифтов через pikepdf; строки дерева структуры |
| `raster.py` | Рендер страницы в родном разрешении образа (600 dpi), рамки дополнительных картинок FineReader (`figures`), перевод pt ↔ px |
| `zones.py` | Зоны повёрнутого текста: таблицы детектора → сетка → ориентация ячеек (`rotated_text.tables`); боковой текст вне таблиц по соседям глифов; сторона по tesseract. Прямой текст без слоя вне таблиц (`upright_zones`) — только чтение и вставка |
| `docstrum.py` | Направление на ближайших соседей глифа: вертикальные цепочки → рамки боковых подписей; те же цепочки по транспонированному растру → прямые строки |
| `classify.py` | Вердикт по слову: KEEP / KEEP_ROTATED / DELETE / SANITIZE / SUSPECT по перекрытию рамки слова с зонами; словарная страховка в непрочитанных зонах |
| `ocr.py` | Чтение зон tesseract-ом; сравнение с прямым чтением снимает ложные «боковые» ячейки; приём чтения (`acceptable`: слово от 3 букв при уверенности ≥ 0.6; число без букв — ≥ 0.9, либо ≥ 0.8 без ведущих нулей) |
| `second_opinion.py` | Surya по ненадёжным зонам в родителе, фильтр выдумок из `rotated_text` |
| `rewrite.py` | Правка потока: вырезание `BT…ET` внутри спана, усечение слова, вставка невидимого повёрнутого текста своим шрифтом одним потоком (`wrap_lines` — перенос по словам с наибольшим кеглем, при котором строки помещаются и по длине, и по толщине зоны; перебор кегля шагом 0,25 pt от 10 до 2,5), подгонка слов под обрезанную страницу (`refit_target`, `refit_text_object`: та же матрица, ужатая в рамку не меньше 2 pt); сверка `verify_page` (со сдвигом координат обрезанной страницы, свои вставки не считаются «неудалённой» россыпью) |
| `fixer.py` | План правок по JSON (`plan_page_edits`, с `crop` — плюс `refits`), применение (`apply_page_edits`), сверка (`verify_saved`); `fix_pdf` — копия целого PDF |
| `pipeline.py` | Одна страница от растра до вердиктов и чтений; `PageResult.to_json()` |
| `cache.py` | JSON на страницу: `cache_path`, `load_page` (только текущей `VERSION`), `save_page` |

Шрифт вставок — `rewrite.DEFAULT_FONT_PATH` (Noto Sans, пакет `fonts-noto-core`); другой —
параметр `InsertFont(path)`.

## Что важно знать о слое FineReader

* Один поток содержимого на страницу; каждое слово — спан со своим `Tm` (растяжение под ширину
  слова), каждый глиф — `Tj` + `Td`. Страничный сдвиг `cm` лежит внутри первого спана — удалять
  спан целиком нельзя, только `BT … ET`; тогда и дерево структуры остаётся валидным.
* Повёрнутый текст FineReader чаще всего пишет горизонтальной россыпью из 1–3 знаков; но иногда
  (39 страниц пака, 220 слов) — правильно, с повёрнутой матрицей: такие слова не трогаются.
* Куски, которые FineReader счёл картинкой (чертежи, схемы, фото, иногда полоска вертикального
  текста), лежат отдельными JBIG2-образами (`/Im1 Do` в том же потоке); текстового слоя на них нет
  вовсе — там текст только добавляется.
* Текст обрезанной части образа FineReader кладёт за CropBox; `rawdict` их не видит.
* MediaBox страницы и её образ могут не совпадать — координаты считаются через
  `page.transformation_matrix`, а не переворотом по высоте.
