# docx_md — DOCX → Markdown и нарезка Markdown на куски для LLM

Подпакет для постобработки OCR-выгрузок журналов/книг: сначала превращаем `.docx`
(результат OCR) в удобный `.md`, затем режем этот `.md` на куски по статьям, чтобы
подавать их в LLM по стратегии **Long Context** (не весь номер целиком, а по
одной/несколько статей — так внимание модели не размывается).

Два независимых инструмента:

| Модуль | Что делает |
|---|---|
| `docx_to_md` | Экспорт `.docx` → `.md` со структурой и **колонтитулами** |
| `split_md_by_articles` | Нарезка `.md` на куски по статьям (статья не рвётся) |

---

## Установка / запуск

Зависимость: [`python-docx`](https://python-docx.readthedocs.io/) (уже в проекте).
Запуск — как модуль пакета `ocr_utils`:

```bash
uv run python -m ocr_utils.docx_md.docx_to_md          --help
uv run python -m ocr_utils.docx_md.split_md_by_articles --help
```

## 1. `docx_to_md` — DOCX → Markdown

### Быстрый старт

```bash
# один файл: рядом появится foo.md
uv run python -m ocr_utils.docx_md.docx_to_md "/путь/foo.docx"

# все .docx в каталоге (нерекурсивно), .md рядом с каждым
uv run python -m ocr_utils.docx_md.docx_to_md "/путь/к/каталогу"

# рекурсивно по подкаталогам, все .md — в отдельный каталог
uv run python -m ocr_utils.docx_md.docx_to_md "/путь" --recursive --out "/путь/md_out"

# без выгрузки колонтитулов
uv run python -m ocr_utils.docx_md.docx_to_md "/путь/foo.docx" --no-colontituls
```

### Что сохраняется

- **Заголовки** — стили `Заголовок №N` / `Heading N` → уровни `#…######`.
  Многострочный OCR-заголовок (разбитый на несколько абзацев одного стиля) склеивается
  в **один** `#`-заголовок.
- **Абзацы** — основной текст; оглавление → пункты списка `-`; подписи к
  рисункам/таблицам → *курсив*; сноски → цитата `>`.
- **Полужирный/курсив** — на уровне отдельных runs (`**…**`, `*…*`).
- **Таблицы** → markdown-таблицы (многострочные ячейки — через `<br>`).
- **Колонтитулы** — печатаются как HTML-комментарии на границе каждой секции (≈ страницы):

  ```markdown
  <!-- колонтитул сверху [секция 4]: # Б. МИРОШНИЧЕНКО -->
  ...текст страницы...
  <!-- колонтитул снизу [секция 4]: ... -->
  ```

> **Почему это не тривиально.** В OCR-DOCX бегущий колонтитул (автор на чётной
> странице, название статьи — на нечётной) хранится не обычным текстом, а в
> **текстовом блоке** (text box внутри `w:drawing`). Штатный `paragraph.text` из
> python-docx его **не видит**, поэтому текст колонтитула вынимается напрямую из XML.
> Подробности — в docstring'ах `docx_to_md.py`.

### Как программно

```python
from pathlib import Path
from ocr_utils.docx_md.docx_to_md import convert_docx_to_md

md = convert_docx_to_md(Path("foo.docx"), with_colontituls=True)
Path("foo.md").write_text(md, encoding="utf-8")
```

## 2. `split_md_by_articles` — нарезка MD на куски

### Быстрый старт

```bash
# паковка под бюджет ~150k символов (≈ 25%): 2–4 статьи в куске
uv run python -m ocr_utils.docx_md.split_md_by_articles "/путь/foo.md"

# одна статья/рубрика = один кусок
uv run python -m ocr_utils.docx_md.split_md_by_articles "/путь/foo.md" --per-article

# мельче куски
uv run python -m ocr_utils.docx_md.split_md_by_articles "/путь/foo.md" --max-chars 100000

# свой каталог для кусков
uv run python -m ocr_utils.docx_md.split_md_by_articles "/путь/foo.md" --out "/путь/chunks"
```

### Что на выходе

Папка `<имя>.chunks/` рядом с исходником:

```
foo.chunks/
  chunk_01.md      # каждый файл начинается с шапки-оглавления куска
  chunk_02.md
  ...
  manifest.json    # id, файл, диапазон строк, размер, доля, список статей
```

Шапка каждого куска:

```markdown
<!-- CHUNK 1/5 | строки 0–514 | 125182 симв -->
<!-- Статьи в этом куске:
     - Б. Мирошниченко — ПЛАНИРОВАНИЕ НАРОДНОГО ХОЗЯЙСТВА СССР…
     - Т. Хачатуров — ПУТИ УЛУЧШЕНИЯ КАПИТАЛЬНОГО СТРОИТЕЛЬСТВА…
     - К. Виноградов — ЗАДАЧИ ТЯЖЕЛОГО МАШИНОСТРОЕНИЯ… -->
...текст статей...
```

### Гарантии

- **Статья никогда не разрывается** между кусками (юнит — неделимая единица).
- Ни один кусок **не крупнее половины** файла (иначе — предупреждение в stderr).
- **Мелкие «мусорные» куски** (обложка, TOC, одинокий рубрика-заголовок) вливаются в
  соседа, ничего не теряется — сумма символов кусков равна исходному файлу.

### Как определяются границы статей

Начало статьи/рубрики помечено «сильным» заголовком Markdown из `docx_to_md`:

- статья — `######` (обычно с курсивным байлайном автора над ним);
- рубрика — `###` (напр. `КРИТИКА И БИБЛИОГРАФИЯ`);
- обложка — `#` / `##`.

Мусорные псевдозаголовки (`####`/`#####` и одиночные `#` внутри тела: `*`, `/ V 520`)
отсекаются фильтром «в заголовке должно быть ≥ 8 букв». Короткие материалы без своих
заголовков (рецензии в «Критике», заметки) остаются внутри своей рубрики — это
допустимое «несколько статей в одном куске».

### Параметры

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--max-chars N` | `150000` | Бюджет символов на кусок при упаковке |
| `--min-chars N` | `4000` | Порог: юнит короче вливается в соседа |
| `--per-article` | выкл. | Один юнит = один кусок (игнорирует `--max-chars`) |
| `--out DIR` | `<имя>.chunks/` | Каталог для кусков (для одного файла) |
| `--recursive` | выкл. | Искать `.md` в подкаталогах |

### Как программно

```python
from pathlib import Path
from ocr_utils.docx_md.split_md_by_articles import split_file

manifest = split_file(
    Path("foo.md"), out_dir=None, max_chars=150_000, min_chars=4_000, per_article=False
)
for c in manifest["chunks"]:
    print(c["file"], c["chars"], [u["title"] for u in c["units"]])
```

## Типовой сценарий (весь путь)

```bash
# 1) OCR отдал .docx → делаем .md
uv run python -m ocr_utils.docx_md.docx_to_md "/scans/1962/02.docx"

# 2) режем .md на куски по статьям
uv run python -m ocr_utils.docx_md.split_md_by_articles "/scans/1962/02.md"

# 3) подаём в LLM chunk_01.md, chunk_02.md, … по одному/несколько за запрос;
#    manifest.json — карта, что в каком куске.
```

## Пример на реальном номере журнала

«Вопросы экономики», 1962, №2 (~160 страниц, ~596k символов): экспорт даёт `.md` с
105 колонтитулами и 45 таблицами; нарезка по умолчанию — **5 кусков** по 15–24% файла,
каждая из 20 статей номера целиком внутри ровно одного куска.
