# defocus_detection — детектор расфокуса сканов газетных полос

Инструмент **скрининга/ранжирования**: среди сотен RAF/JPEG-сканов выпуска находит те,
где есть расфокус — в том числе **зональный** (размыта лишь часть полосы из-за наклона
плоскости фокуса, неплоского разворота, перекоса камеры). Это не точный классификатор:
он поднимает кандидатов наверх, финальное решение — за человеком.

> Исторический контекст и обоснование методов — в корне репозитория:
> `focus_detection_report.md` (FFT-метод HF/MID) и `defocus_moire_improvement_plan.md`
> (доработки муара A/B/C/E).

---

## Быстрый старт

```bash
# по одному выпуску (режим по умолчанию: муар+нормировка, зона C, кросс-проверка FFT)
uv run python -m ocr_utils.defocus_detection "/путь/к/выпуску"

# только подозрительные (без «чистых»)
uv run python -m ocr_utils.defocus_detection "/путь/к/выпуску" --quiet

# md-отчёт с таблицей и кликабельными ссылками на файлы
uv run python -m ocr_utils.defocus_detection "/путь" --md-report report.md

# тепловые карты тайлов для диагностики
uv run python -m ocr_utils.defocus_detection "/путь" --debug-dir heat/

# все опции
uv run python -m ocr_utils.defocus_detection --help
```

Принимает файлы и/или **одну директорию** (обходится **нерекурсивно**), расширения
`.RAF`, `.jpg`, `.jpeg`. Из RAF берётся встроенное JPEG-превью 4416×2944 — его хватает
с запасом и извлекается мгновенно.

> **Запускайте по одному выпуску.** Базовый уровень муара зависит от бумаги/растра и
> различается между выпусками; относительные пороги считаются внутри переданной выборки.

## Как читать вывод

```
 резкость    зона  глубина  отн.  FFT  файл / вердикт
------------------------------------------------------------------------------
     0.71       —        —     —   да  DSCF0004.RAF  <-- расфокус ✓ FFT (муар не увидел)
     0.59     9x3     0.22  0.31  нет  DSCF0031.RAF  <-- ? только муар (возм. цв.декор/край)
     0.91       —        —     —  нет  DSCF0200.RAF
...
ОБЛОЖКА/ПУСТО (нет растра, исключены из ранжирования): 1
   edge=0.0260  DSCF0001.RAF
```

- **резкость** — медиана нормированного муара по печатным тайлам (выше = резче).
- **зона** — размер найденной связной 2D-зоны расфокуса в тайлах (`строки×столбцы`) или `—`.
- **глубина** — средний нормированный муар внутри зоны (ниже = сильнее размыто).
- **отн.** — глубина зоны относительно «здоровья» полосы (`глубина / медиана полосы`);
  чем меньше, тем сильнее зона выпадает из своей же полосы.
- **FFT** — голос второго детектора (HF/MID): `да`/`нет`.
- **вердикт** (по нему же идёт сортировка, сверху — самые надёжные):

| вердикт | смысл | доверие |
|---|---|---|
| `РАСФОКУС ✓✓ (муар+FFT)` | оба детектора согласны | высокое |
| `расфокус ✓ FFT` | FFT видит, муар нет (FFT чувствительнее к тонкому) | среднее |
| `? только муар` | муар-зона есть, FFT не подтвердил → возможно цв.декор/край | низкое |
| (нет метки) | чисто | — |

**ОБЛОЖКА/ПУСТО** — файлы без типографского растра (картон, дерево, рукописные этикетки):
исключаются из ранжирования, перечисляются отдельно с плотностью краёв `edge`.

## Как это работает

Все метрики считаются **по сетке тайлов** (по умолчанию 16×11), а не по всему кадру —
это и позволяет ловить зональный расфокус.

### Основной метод — энергия растрового муара (`moire.py`)

Газетный полутоновый растр при нормальном фокусе порождает сильный **муар**, если
уменьшить кадр **без сглаживания** (так дефект ловят глазами в XNView). Меряем муар как
`std(NEAREST − AREA)`: уменьшение методом NEAREST даёт алиасинг/муар, AREA усредняет (муара
нет). Структура текста/фото есть в обоих и сокращается — остаётся чистая энергия растра.
Низкий муар на **печатном** тайле = расфокус.

Доработки поверх базового муара:

- **A. Нормировка (`--normalize`).** Сырой муар растёт вместе с количеством краски на
  полосе (corr с количеством контента ≈ +0.5), поэтому малотекстовые полосы ложно
  всплывали наверх. Делим муар тайла на меру «сколько в нём резких переходов»:
  - `structure` (**по умолчанию, A1**) — делить на `std` AREA-уменьшения; убирает
    зависимость от количества текста (corr падает до ≈ −0.1);
  - `global_contrast` (A1+, **экспериментальная**) — `structure` + дополнительная
    нормировка на центральный std изображения; пытается убрать зависимость от общего
    динамического диапазона/экспозиции, но может давать ложные срабатывания;
  - `gradient` (A2) — делить на RMS полноразмерного градиента; **тупиковый**: при
    расфокусе падают и числитель, и знаменатель, сигнал сокращается;
  - `none` — сырой муар (прежнее поведение).
- **B. Гейт обложек (`--min-edge-density`).** Обложка/картон/пустой лист почти гладкие —
  у них очень низкая плотность краёв (Canny). Такие файлы помечаются `ОБЛОЖКА/ПУСТО` и
  исключаются из ранжирования (их нельзя оценивать муаром — растра нет).
- **C. Решение по связной 2D-зоне (`--zone`, по умолчанию вкл.).** Подозрение выносится не
  по всей полосе, а по **связной компоненте** «мягких» тайлов. Тайл «мягкий», если
  одновременно: `ratio < k_abs` И `ratio < k_rel·медианы полосы` И `grad < g_rel·медианы
  градиента`. Последнее условие (низкий градиент) отсекает резкие **нерастровые** края
  (тёмная полоса/сгиб/граница страница-стол): у них низкий муар, но **высокий** градиент —
  это не расфокус. Зона засчитывается, только если она ≥ 2 строк И ≥ 3 столбцов — это
  отсекает одно-строчные артефакты (крупные заголовки, фото). Краевые тайлы (поля) заранее
  исключаются параметром `margin`.

### Второй метод для кросс-проверки — FFT HF/MID (`fft_hf.py`, этап E)

Независимый детектор: `HF_ratio = E(высокие частоты) / E(средние частоты)` по тайлам.
Расфокус обрушивает ВЧ (тонкие штрихи), оставляя СЧ (шаг строк/букв), поэтому величина
почти не зависит от контента. Он **чувствительнее** к тонкому зональному расфокусу, чем
муар (на старом эталоне 1960/0650 перепад был ~10× против ~2× у муара). Включён по
умолчанию (`--cross-check`): **совпадение обоих детекторов = высокая уверенность**,
расхождения выносятся на ручной просмотр.

> Ядро HF/MID повторяет валидированный standalone-скрипт `detect_zonal_defocus.py` в корне
> репозитория (там же — параллельный CLI на много процессов для очень больших папок).

### Альтернатива — variance of Laplacian (`laplacian.py`)

Классическая метрика резкости (`--method laplacian`). Проще и быстрее, но сильнее зависит
от контента; для тонкого зонального расфокуса хуже основного метода. Оставлена как опция.

## Режимы и ключевые параметры

| Опция | По умолчанию | Назначение |
|---|---|---|
| `--method` | `moire` | `moire` или `laplacian` |
| `--normalize` | `structure` | нормировка муара (A): `none` / `structure` / `gradient` / `global_contrast` (эксп.) |
| `--zone / --no-zone` | `--zone` | решение по 2D-зоне (C) vs прежнее ранжирование по «худшей зоне» |
| `--cross-check / --no-cross-check` | `--cross-check` | второй детектор FFT (E) |
| `--min-edge-density` | `0.045` | порог гейта обложек (B) |
| `--grid-x`, `--grid-y` | `16`, `11` | сетка тайлов для муара |
| `--zone-k-abs`, `--zone-k-rel` | `0.6`, `0.6` | пороги «мягкости» тайла (C) |
| `--zone-grad-rel` | `0.7` | гейт градиента в C (большое значение, напр. `99`, отключает) |
| `--zone-margin` | `1` | сколько крайних рядов тайлов (поля) исключить |
| `--zone-min-rows/-cols` | `2` / `3` | минимальный размер зоны |
| `--md-report PATH` | — | записать md-отчёт с таблицей и кликабельными ссылками на файлы |
| `--debug-dir` | — | сохранить тепловые карты тайлов |
| `--quiet` | — | печатать только подозрительные (в консоль; md-отчёт всегда полный) |

**Md-отчёт** (`--md-report report.md`) содержит полную ранжированную таблицу (самые
подозрительные сверху) с теми же колонками, что и консоль, где имя файла — кликабельная
ссылка на абсолютный путь (URL-кодированный, без `file://`), и отдельную таблицу
отсеянных обложек. Удобно открыть в просмотрщике markdown и проходить по ссылкам.

**Режим `--no-zone`** (а также `--normalize none` и `--method laplacian`): прежнее
ранжирование по «худшей зоне» (минимум по 10% самых мягких тайлов) с адаптивным порогом
`медиана − z·MAD` (`--relative`, `--z`).

## Калибровка и ограничения

- **Калибруйте `--zone-*` на размеченной пачке** конкретного года/камеры перед массовым
  прогоном: пороги муара переносятся между выпусками лучше сырого муара (метрика
  нормирована), но не идеально.
- **Остаточные ложняки муара:** цветной декор (крупный красный вертикальный заголовок на
  газетной бумаге даёт низкий *люминансный* контраст → низкий и муар, и градиент → проходит
  гейты) и приграничные столбцы. Именно для отсева таких случаев и нужна кросс-проверка
  FFT: доверяйте в первую очередь вердикту `✓✓`.
- **Муар менее чувствителен к тонкому зональному расфокусу, чем FFT.** Для чувствительного
  зонального поиска опирайтесь на колонку `FFT`/вердикт, а не только на наличие муар-зоны.
- **FFT — тоже не оракул:** его проверка размера зоны по bbox может объединять разнесённые
  1D-артефакты (заголовок + угол). Поэтому ценность — именно в *согласии* двух методов.

## Соседняя задача: выбор лучшего дубля одной страницы

`compare_focus_series.py` решает **другую** задачу: снято несколько дублей ОДНОГО разворота
(охота за фокусом на док-камере) — какой оставить?

```bash
uv run python -m ocr_utils.legacy.defocus_detection.compare_focus_series "/путь/к/дублям" \
    --md-report focus_series_report.md --figures-dir focus_series_figs/
```

Ключевой момент: дубли почти никогда не сняты с одного расстояния, масштаб страницы в
пикселях гуляет на десятки процентов, и пиксельные метрики резкости (lapvar, Tenengrad) при
уменьшении масштаба **растут** — наивное сравнение уверенно выбирает самый мягкий кадр.
Поэтому кадры сперва регистрируются друг к другу (SIFT+RANSAC), а размытие меряется как
разница квадратов σ по наклону `log(PSD_a/PSD_b)` от `f²` в *страничных* частотах — сперва
вовсе без ресемплинга, затем после приведения всех кадров к общему масштабу. Пример готового
отчёта — `focus_series_report.md` в корне репозитория.
