# У меня есть сканы вот такого вида.

Я хочу использовать модели семейства YOLO для следующих целей:

1) Находить области с руками и пальцами для их последующего вырезания.
2) Находить области с буквами, знаками, картинками и др.
3) Находить область страницы.

Могут ли модели семейства Yolo мне в этом помочь? Какие лучше брать? У меня RTX 5060Ti 16 Gb.

Да, модели семейства YOLO отлично подойдут для всех трёх задач. RTX 5060Ti с 16 GB VRAM — более чем достаточно для работы даже с самыми крупными вариантами. Разберём каждую задачу отдельно.

***

## Задача 1: Обнаружение рук и пальцев

Для вырезания рук лучше использовать **YOLOv8-seg** (сегментационный вариант) — он даёт не просто bounding box, а точную маску области руки, что позволит аккуратнее вырезать её через inpainting.[^1_1]

Готовые веса можно взять прямо с Hugging Face, не дообучая с нуля:

- **`hand_yolov8s.pt`** из репозитория [Bingsu/adetailer](https://huggingface.co/Bingsu/adetailer) — mAP50 ~0.794, обучен на 2D и реальных руках[^1_2]
- **`EtanHey/hand-detection-3class`** — YOLOv8s, точность >96%, различает hand / arm / not_hand[^1_3]

Для сегментации (маска пикселей, а не просто прямоугольник) нужен именно `yolov8s-seg.pt` или дообученный на руках сегментационный вариант.

***

## Задача 2: Разметка элементов страницы (текст, картинки, заголовки и т.д.)

Это задача **Document Layout Analysis (DLA)** — она идеально решается специализированными YOLO-моделями:

- **DocLayout-YOLO** ([github.com/opendatalab/DocLayout-YOLO](https://github.com/opendatalab/DocLayout-YOLO)) — построен на YOLOv10, обучен на 300K синтетических документов, real-time, открытый код и веса. Распознаёт: заголовки, параграфы, таблицы, рисунки, подписи, колонтитулы.[^1_4][^1_5]
- **yolo-doclaynet** ([github.com/ppaanngggg/yolo-doclaynet](https://github.com/ppaanngggg/yolo-doclaynet)) — YOLOv8/v11, обучен на датасете DocLayNet от IBM, mAP50-95 до 78.7 для YOLOv8x[^1_6][^1_7]
- **YOLOv9** для обнаружения графики в документах показал точность >98.6% mAP на датасете PubLayNet[^1_8]

Для советских газетно-книжных разворотов (двухколоночная вёрстка, мелкий текст) рекомендуется **YOLOv11l** или **DocLayout-YOLO** с input size 1280px — исследования показывают, что именно 1280 пикселей оптимально для документов с мелкими деталями.[^1_9]

***

## Задача 3: Обнаружение области страницы

Эта задача проще — страница как единый объект. Хорошо подойдут:

- **YOLOv11-OBB** (Oriented Bounding Boxes) — принципиально важен для документов, снятых под углом. Исследование по историческим документам показало, что OBB-вариант значительно превосходит обычный AABB, достигая mAP@50:95 = 0.721[^1_10]
- Альтернатива — классический детектор страниц из пайплайнов типа **DocTR** или **PaddleOCR**, которые уже имеют встроенный детектор страниц

***

## Рекомендуемый стек

| Задача | Модель | Режим |
| :-- | :-- | :-- |
| Руки/пальцы | YOLOv8s-seg (веса из adetailer) | Instance Segmentation |
| Layout (текст, рисунки) | DocLayout-YOLO или YOLOv11l на DocLayNet | Detection |
| Область страницы | YOLOv11n-OBB | OBB Detection |

На RTX 5060Ti 16 GB можно комфортно запускать даже `YOLOv11x` в batched-режиме. Для инференса на ваших сканах рекомендую input size **1280** и формат `.pt` через `ultralytics`. Если потребуется дообучение на советской полиграфии (специфичная вёрстка), DocLayNet или PubLayNet послужат хорошей отправной точкой для fine-tuning — структура разметки совместима с форматом YOLO.
