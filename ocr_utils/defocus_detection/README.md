# defocus_detection — поиск расфокусированных кадров в папке

Инструмент **скрининга**: сканирует папку со сканами газетных полос и выводит **два
отчёта**, отсортированных от худшего к лучшему. Задача — вытащить наверх те 3–5 % кадров,
которые стоит переснять.

1. **Общее качество фокуса** — насколько плох кадр целиком.
2. **Зональный расфокус** — насколько сильно резкость проваливается внутри кадра.
   Кадр может быть хорош в среднем и всё равно требовать пересъёмки, если поплыла его
   часть; в первый отчёт такой кадр по построению не попадёт.

Это не классификатор: он ранжирует кандидатов, финальное решение — за человеком.
Второй отчёт особенно: у него заметная доля ложных срабатываний (см. «Валидация»).

---

## Быстрый старт

```bash
# все файлы папки с метрикой, худшие сверху
uv run python -m ocr_utils.defocus_detection "/путь/к/выпуску"

# типовой режим «что переснять»: по 5 % худших в каждом отчёте
uv run python -m ocr_utils.defocus_detection "/путь/к/выпуску" --worst-percent 5 --zonal-percent 5

# ровно 15 худших по общему фокусу и 10 по зональному
uv run python -m ocr_utils.defocus_detection "/путь/к/выпуску" --worst-count 15 --zonal-count 10

# только первый отчёт
uv run python -m ocr_utils.defocus_detection "/путь/к/выпуску" -p 5 --no-zonal

# другой алгоритм + отчёты
uv run python -m ocr_utils.defocus_detection "/путь" -a combo \
    --md-report defocus.md --csv defocus.csv

# все опции и список алгоритмов
uv run python -m ocr_utils.defocus_detection --help
```

Принимает `.RAF`, `.tif`, `.tiff`, `.png`, `.jpg`, `.jpeg`. Из RAF берётся встроенное
JPEG-превью 4416×2944: полноразмерный RAW распаковывается ~8 с против ~0,2 с у превью,
а разрешения превью хватает (см. «Валидация»). Папка обходится нерекурсивно, `--recursive`
включает обход вложенных.

> **Запускайте по одному выпуску.** Пороги здесь не абсолютные: файлы ранжируются
> относительно друг друга внутри переданной выборки.

**Нагрузка на машину.** Прогон по выпуску идёт минутами, и всё это время компьютером надо
продолжать пользоваться, поэтому по умолчанию: процессов берётся на `--reserve-cores`
меньше, чем ядер (по умолчанию на два); каждому воркеру понижается приоритет (nice +10);
внутренняя многопоточность OpenCV и BLAS в воркерах отключается. Последнее важнее всего:
без него каждый из полутора десятков процессов вправе развернуть по потоку на ядро, и
машина оказывается занята целиком, считая при этом не быстрее. Замерено на 16 ядрах:
14 воркеров по одному потоку каждый, около 1000 % CPU из 1600 %.

## Как читать вывод

```
 #  балл (1/σ)  σ края, px  файл
--  ----------  ----------  -------------------------------
 1       1.544      0.6478  DSCF0180_defocus_ultralight.RAF
 2       1.563      0.6400  DSCF0311_defocus_light.RAF
 3       1.570      0.6370  DSCF0320_defocus_light.RAF
 4       1.590      0.6289  DSCF0120.RAF
...
Показано 16 из 317 файлов; сортировка — от худшего фокуса к лучшему.
```

- **балл** — качество фокуса, **больше = резче**; сортировка по возрастанию.
  В режиме `combo` это средний нормированный ранг в [0, 1] (0 — самый мягкий файл выборки).
- **вторая колонка** — тот же балл в естественных единицах метрики: для `edge_width` это
  ширина края σ в пикселях, меньше = резче. Читать её как «физическое размытие» нельзя,
  величина относительная (оценщик занижает σ на плотном тексте — см. отчёт о валидации).
  В режиме `combo` вместо неё показываются баллы отдельных метрик.

Второй отчёт выглядит так:

```
 #  перепад  σ резч.  σ мягч.                       где мягче  файл
--  -------  -------  -------  ------------------------------  -------------------------------
 1     +20%    0.456    0.545   низ (11 из 12, резче всего 6)  DSCF0196_defocus_light.RAF
 2     +14%    0.491    0.561  верх (4 из 12, резче всего 11)  DSCF0132.RAF
```

- **перепад** — на сколько процентов шире штрих в самой мягкой полосе кадра, чем в самой
  резкой. Это и есть мера «перекоса»; сортировка по её убыванию.
- **где мягче** — куда пришёлся провал, в номерах горизонтальных полос сверху вниз.
  Полезно для понимания механики: «низ» из раза в раз — значит завалена плоскость съёмки.

Отбор в каждый отчёт задаётся своими опциями: `--worst-percent` / `--worst-count` для
первого, `--zonal-percent` / `--zonal-count` для второго. Без них печатаются все файлы.

`--md-report` пишет обе таблицы в markdown с кликабельными ссылками на файлы — удобно
проходить список глазами. `--csv` пишет **все** файлы папки со всеми метриками и
зональными колонками: это рабочий материал для калибровки, а не для чтения.

## Алгоритмы (`--algorithm`)

| имя | что меряет | AUC¹ | зависит от кол-ва текста | от кегля | от ISO |
|---|---|--:|:--:|:--:|:--:|
| `edge_width` **(по умолчанию)** | субпиксельную ширину края штриха | **0.901** | **нет** | **нет** | **нет** |
| `combo` | средний ранг `edge_width` + `reblur` | 0.877 | нет | нет | нет |
| `laplacian` | дисперсию лапласиана (наивная база) | 0.871 | **да** | **да** | **да** |
| `moire` | муар типографского растра | 0.860 | нет (нормирован) | слабо | слабо |
| `reblur` | сколько кадр теряет от повторного размытия | 0.832 | нет | нет | нет |
| `hf_mid` | долю ВЧ-энергии спектра | 0.798 | нет | **да** | слабо |

¹ качество ранжирования на размеченной папке 1979 года (317 файлов, 15 размеченных);
подробности и оговорки — в `defocus_detection_validation_report.md`. Разница меньше
0.03 на такой выборке незначима.

### `edge_width` — ширина края (Marziliano / JNB / CPBD)

Опорный метод, и именно он прямо отвечает на вопрос «насколько расплылись штрихи».
Строки и столбцы кадра режутся на монотонные участки между локальными экстремумами
яркости; каждый такой участок — один край. Ширина края считается не в целых пикселях,
а как СКО профиля градиента внутри участка:

```
σ² = Σ (k − центр)² · |ΔI_k| / Σ |ΔI_k| − 1/12
```

Для ступеньки, размытой гауссианой σ, это в точности даёт σ — субпиксельно (вычитаемая
1/12 — дисперсия пиксельной апертуры). Это тот же принцип, что в slanted-edge измерении
MTF по ISO 12233, только вместо специальной миры используются случайные края текста.

Почему метод подходит под все три оговорки из постановки задачи:

- **Разное заполнение текстом.** Плотность текста меняет ЧИСЛО замеров, а не их среднее:
  полоса в одну колонку и полоса-простыня при одинаковой оптике дают одну и ту же
  среднюю ширину края.
- **Крупные заголовки.** У большой буквы переходов мало, но каждый переход такой же
  крутой — ширина края та же. Ломаются здесь именно энергетические метрики, которые
  считают суммарную энергию, а не геометрию.
- **Разные ISO и освещение.** Ширина края — геометрия профиля, а не его амплитуда.
  Порог отбора перепадов берётся относительно контраста самого кадра (доля от p95
  амплитуд), поэтому уезжает вместе с экспозицией.

Литература: Marziliano et al. (ICIP 2002), Ferzli & Karam JNB (IEEE TIP 2009),
Narvekar & Karam CPBD (IEEE TIP 2011).

### `reblur` — метрика Crete «The Blur Effect»

Кадр размывается ещё раз, и меряется, какую долю перепадов между соседними пикселями
он при этом потерял. Резкому терять есть что, уже размытому — нечего. Величина
нормирована на собственную энергию перепадов кадра, поэтому не зависит ни от контента,
ни от контраста, и не требует ни одного порога. Второй голос в `combo`.

Ограничение: меряет относительную мягкость, а не абсолютную ширину штриха, поэтому на
очень мелком тексте ближе к насыщению, чем `edge_width`.

### `moire` — муар типографского растра

Газетный растр — это готовая мира, отпечатанная прямо на странице. Уменьшение кадра
методом NEAREST даёт на резком растре сильный алиасинг, на размытом — нет; меряем
`std(NEAREST − AREA) / std(AREA)`. Знаменатель убирает зависимость от количества краски
(корреляция с количеством контента падает с +0.5 до −0.1 — замерено в
`defocus_moire_improvement_plan.md` в корне репозитория).

Ограничение: требует наличия растра. Обложки, картонные переплёты, рукописные этикетки
метрика ранжирует бессмысленно.

### `hf_mid` — доля ВЧ-энергии спектра

`E(высокие частоты) / E(средние частоты)` по тайлам. Расфокус обрушивает ВЧ (тонкие
штрихи), оставляя СЧ («рисунок» полосы — шаг строк и букв), который и служит
нормировкой. Метод валидирован в этом репозитории на зональных расфокусах
(`detect_zonal_defocus.py`).

Ограничение, подтверждённое тестом: **к кеглю он не устойчив**. Крупный шрифт сдвигает
вниз обе полосы спектра сразу, и отношение падает без всякого расфокуса. Поэтому в
`combo` по умолчанию он не входит.

### `laplacian` — наивная база

Дисперсия лапласиана из всех туториалов. Оставлена **не потому, что хороша**, а чтобы
было с чем сравнивать: она честно воспроизводит все три проблемы из постановки задачи.
Тест `test_known_metrics_are_fooled_by_font_size` фиксирует этот дефект намеренно.

## Как ищется зональный расфокус

Кадр режется на сетку вдвое мельче основной (по 18 тайлов в ширину), по каждому тайлу
считается ширина края σ, затем строится **профиль по горизонтальным полосам** (полоса =
ряд тайлов), и метрика — относительный перепад между самой резкой и самой мягкой полосой.
Три решения, без которых это не работает:

1. **В профиль идут только однородно набранные тайлы.** σ зависит не только от фокуса,
   но и от того, чем набран кусок полосы: узкая колонка мелким шрифтом, жирный курсивный
   лозунг и полутоновое фото дают большую σ и при идеальном фокусе. Поэтому тайл проходит,
   только если у него И число краёв, И средняя длина штриха лежат в коридорах перцентилей
   этого же кадра, И доля белой бумаги не ниже 0.18 (последнее отсекает фотографии —
   у них фона нет вовсе, а у самой плотной полосы его пятая часть).

2. **Полосы поперёк колонок, а не вдоль.** Горизонтальная полоса пересекает все колонки
   разворота и усредняет вёрстку; вертикальная целиком лежит внутри одной колонки и
   наследует её кегль. На реальной выборке столбцовый профиль оказался бесполезен: в топ
   стабильно лезли кадры из-за узкой колонки другим шрифтом у правого поля — одной и той
   же во всех выпусках. Ось переключается опцией `--zonal-axis cols`, но по умолчанию
   горизонтальная: она верна для газет и книг с вертикальными колонками.

3. **Сглаживание профиля и разнос полос.** Профиль сглаживается по три полосы, а самая
   резкая и самая мягкая обязаны отстоять друг от друга минимум на три полосы: оптический
   завал — это плавный градиент через полкадра, а не скачок между соседями. Без этого
   метрика срабатывает на шуме соседних полос.

## Как считается балл файла

1. Кадр режется на сетку в девять тайлов по ширине — на превью RAF это ~490 px, то есть
   примерно газетная колонка на треть высоты полосы. Сетка задаётся числом тайлов, а не
   пикселями, чтобы на кадрах другого разрешения тайл покрывал ту же ДОЛЮ полосы;
   явный размер можно задать через `--tile-size`.
2. Тайлы без краски отсекаются: из кадра вычитается сильно размытая копия (уходит
   неравномерность освещения), берётся RMS остатка, порог — доля от 75-го процентиля
   **этого же кадра**. Относительный порог не зависит ни от экспозиции, ни от того,
   насколько плотно набрана полоса. На боевой крупной сетке этот шаг обычно ничего не
   отсекает (тайл размером в колонку почти всегда чем-то занят) — он начинает работать
   при мелком `--tile-size` и на кадрах с большими пустыми полями.
3. Метрика считается по каждому печатному тайлу и сводится в балл файла — по умолчанию
   как резкость **самых мягких 20 % тайлов** (`--aggregate worst --quantile 0.8`).

Про пункт 3 подробнее — это главное решение здесь, и оно важнее выбора самого алгоритма
(AUC 0.90 против 0.81 у того же `edge_width` при другой агрегации). Проверено на
размеченной папке:

- **медиана по тайлам** — заложница вёрстки: тайлы с крупным заголовком, полутоновым фото
  или широким полем дают низкую резкость и при идеальном фокусе;
- **самый худший тайл** — это шум и артефакты вёрстки, AUC проваливается до 0.59–0.81;
- **самые резкие тайлы** («есть ли на полосе хоть один участок чёткого мелкого текста»)
  — правдоподобная гипотеза, которая на данных не подтвердилась: AUC 0.81 против 0.90.
  Реальные промахи фокуса при съёмке с рук почти всегда неравномерны по кадру, и видно их
  по мягкому краю распределения, а не по резкому. Режим оставлен как `--aggregate best`.

В режиме `combo` баллы отдельных метрик переводятся в нормированные ранги [0, 1] и
усредняются. Именно ранги, а не значения: шкалы метрик несопоставимы (пиксели, доли
энергии, [0,1]-мера), а порядок файлов сравним всегда.

## Валидация

Прогон по размеченной папке `…/ЭГ/в работе/1979/7-12 дофотать лёгкие расфокусы/` —
317 файлов RAF, из них 15 помечены вручную суффиксами `_defocus_light` (4 шт.) и
`_defocus_ultralight` (11 шт.). Разметка тяжёлая: явных промахов в выборке нет вообще,
только пограничные — весь сигнал укладывается в четверть пикселя ширины края
(σ от 0.357 до 0.648 px по всей папке).

```
AUC = 0.901
в худших 5 % (16 файлов):   6 из 15 размеченных
в худших 10 % (32 файла):   9 из 15
медианный ранг размеченного файла: 24 / 317 (у неразмеченных — 166)
```

Скорость: 317 файлов RAF за 2 мин 38 с на 16 процессах.

Полные цифры, таблицы подбора параметров и разбор пропусков — в
`defocus_detection_validation_report.md` в корне репозитория.

### Зональный отчёт

Проверить его так же строго не на чем: подтверждённый зональный случай в папке ровно
один — `DSCF0196_defocus_light`, разобранный отдельно (§ 8 отчёта о валидации). На нём
детектор даёт **1-е место из 299 с перепадом +20 % при медиане по папке около +5 %** —
второй в списке отстаёт вдвое. Ещё три размеченных файла попадают в верхние 15.

**Ложные срабатывания в этом отчёте реальны.** Ниже первой строки в топе встречаются
кадры, у которых крайняя полоса занята шапкой, фотографией или выделительным шрифтом,
и фильтры однородности их не отсеяли. Каждый случай в топе проверялся глазами по кропам
полноразмерного RAW, и часть оказалась именно такой. Поэтому второй отчёт — список на
просмотр, а не приговор; ориентируйтесь в первую очередь на величину перепада и на то,
повторяется ли «где мягче» из кадра в кадр (систематический завал плоскости съёмки).

Из-за фильтров однородности часть кадров остаётся без зональной оценки (в выборке 18 из
317: обложки, полосы-таблицы, кадры с малым количеством тела-текста) — они перечисляются
отдельной строкой.

Что эта папка **не** проверяет:

- **Разброс ISO и освещения** — 310 файлов из 317 сняты на ISO 2000, все на f/8.
  Устойчивость к экспозиции проверена только на синтетике
  (`tests/ocr_utils/defocus_detection/test_metrics.py`).
- **Обложки и переплёты.** Кадры без текста (картон, дерево) инструмент ставит в *самый
  резкий* конец списка: краёв мало, но все контрастные и крутые. На поиск худших это не
  влияет, но расфокус на самой обложке замечен не будет.

## Структура подпакета

```
defocus_detection/
├── cli.py            # CLI: опции, отбор худших, вызов отчёта
├── analysis.py       # прогон по файлам (multiprocessing), сводный ранг
├── image_io.py       # чтение RAF-превью / TIFF / PNG / JPG, сбор файлов
├── tiles.py          # сетка тайлов, маска печатных тайлов
├── scoring.py        # агрегация тайлов в балл, сведение метрик в ранг
├── zonal.py          # второй отчёт: перепад резкости внутри кадра
├── report.py         # консольная таблица, markdown, CSV
└── metrics/
    ├── base.py       # общий интерфейс Algorithm
    ├── edge_width.py # ширина края (опорный метод)
    ├── reblur.py     # re-blur Crete
    ├── hf_mid.py     # доля ВЧ-энергии
    ├── moire.py      # муар растра
    └── laplacian.py  # наивная база
```

Тесты: `tests/ocr_utils/defocus_detection/` — синтетические «полосы», на которых
проверяется монотонность по размытию и независимость от вёрстки, кегля и экспозиции.

Зависимости (уже в `pyproject.toml`): `rawpy`, `numpy`, `opencv-python-headless`,
`Pillow`, `click`, `tqdm`.
