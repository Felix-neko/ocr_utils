# external_ocr_services — выпуск журнала → размеченный markdown через VLM, по этапам

Боевой внешний OCR: папка полос выпуска уходит в DeepSeek V4.1 Flash через OpenRouter, на каждую
полосу получается markdown со структурой (статьи, рубрики, авторы, таблицы) и JSON с полями.
Зачем и где граница задачи — в докстринге `__init__.py`; выбор модели и промпта сделан в стенде
`research/external_ocr_models` (отчёт `reports/external_ocr_models.md`). Здесь — как пользоваться
и как всё устроено.

## Команды

```bash
uv run python -m ocr_utils.external_ocr_services run \
    --in-dir /mnt/SYSTEM/raw/mts/pack1_background_blurred_v2/sharpened \
    --out-dir /mnt/SYSTEM/raw/mts/pack1_external_ocr_services/out \
    --debug-dir /mnt/SYSTEM/raw/mts/pack1_external_ocr_services/debug \
    --cache-dir /mnt/SYSTEM/raw/mts/pack1_external_ocr_services/cache \
    --db ~/Projects/mts_markup/pack1_reviewed.sqlite --pack-name пак-1 \
    --only-year 1966 --only-issue 03 \
    --source "журнал «Материально-техническое снабжение», Москва, 1966–1976" \
    [--max-src-tile-size 4500] [--max-model-tile-size 2200] [--jobs 4] [--skip-done]
    [--on-missed-toc redo|ask|skip] [--redo-scope structured|all] [--pages список.txt]
    [--second-pass] [--second-pass-transcript] [--no-assemble]

uv run python -m ocr_utils.external_ocr_services assemble --out-dir …/out --in-dir …/sharpened --cache-dir …/cache \
    [--only-year 1966 --only-issue 03] [--no-check-boundaries]   # пересобрать выпуски в один md; к модели — только сомнительные стыки
uv run python -m ocr_utils.external_ocr_services models    # реестр с ценами
uv run python -m ocr_utils.external_ocr_services balance   # баланс ключа OpenRouter
```

Ключ OpenRouter — `$OPENROUTER_API_KEY` (или `--api-key`). Готовые прогоны —
`run_scripts/external_ocr_services/`: `run_issue_sharpened.sh [год/выпуск]` (один выпуск,
интерактивный), `run_pack_sharpened.sh` (весь пак, идемпотентно, в фон), `run_probe_tiles.sh`
(проверка сетки тайлов и слияния многополосного оглавления), `assemble_pack.sh [год/выпуск]`
(пересборка целиковых md из готовых полос).

Все опции `run`:

| опция | что делает |
|---|---|
| `--in-dir`, `--out-dir`, `--debug-dir` | вход `{год}/{выпуск}/{полоса}`; выход той же раскладки; отладка (сырые ответы, промпты, тайлы, оба прохода) |
| `--cache-dir` | кэш запросов: каждый запрос к модели — своя папка с промптами и ответом, тот же запрос второй раз берётся с диска (см. «Кэш запросов») |
| `--assemble/--no-assemble` | после каждого выпуска собирать его в один markdown `{год}/{выпуск}.md` с sidecar `.pages.json` (по умолчанию включено; см. «Сборка выпуска») |
| `--check-boundaries/--no-check-boundaries` | при сборке показывать сомнительные стыки полос модели — один запрос на выпуск (по умолчанию включено; см. «Проверка стыков моделью») |
| `--db`, `--pack-name` | база разметки (обычно `DB_REVIEWED`): флаги оглавления `is_toc` / `is_year_index` и вето `force_is_not_toc`; читается через ORM `ocr_utils.db` с `open_db(create=False)` — без создания таблиц и дописывания колонок, одним `select`, ничего не пишется |
| `--toc-lists` | запасной вход без базы: корень списков `<год>/<выпуск>/toc_pages.txt` от `scan_markup toc-pages` |
| `--model` | имя из реестра (`models.py`); умолчание `deepseek-v41-flash` |
| `--max-src-tile-size` | шаг сетки тайлов в пикселях исходника (пак-1: 4500 — обычная полоса 1×2, разворот 2×2) |
| `--max-model-tile-size`, `--quality` | длинная сторона тайла после уменьшения (2200) и качество JPEG (85) |
| `--source` | описание издания в системный промпт; `{year}` заменяется годом выпуска, но лучше без него — см. «Стоимость и кэш префикса» |
| `--second-pass/--no-second-pass` | второй проход по полосам с `is_damaged` (по умолчанию **выключен** — см. «Второй проход») |
| `--join-hyphens/--no-join-hyphens` | склейка разорванных переносов («кре-диты» → «кредиты») по словарю pymorphy3 после доводки структуры (по умолчанию включена; склейки — в meta `hyphens_joined` и колонке `summary.csv`) |
| `--second-pass-transcript` | во второй проход (если включён) слать и полный текст первого (выигрыша не дал) |
| `--reasoning`, `--max-tokens` | рассуждения модели (выключены), потолок ответа (16 000) |
| `--jobs`, `--attempts`, `--timeout` | параллельных запросов (4 — лимиты провайдера, не CPU), повторов при 429/5xx, таймаут |
| `--only-year`, `--only-issue`, `--pages`, `--limit` | что брать |
| `--skip-done` | не запрашивать готовые полосы (см. «Идемпотентность») |
| `--on-missed-toc` | что делать, если модель нашла оглавление вне базы: `redo` (умолчание — перераспознать выпуск с ним), `ask` (спросить; без терминала = `skip`), `skip` (только `missed_toc.txt`) |
| `--redo-scope` | какие обычные полосы запрашивать заново на круге повтора: `structured` (умолчание — только чувствительные к спискам, см. «Fallback»), `all` |

## Как идёт выпуск

Полосы группируются по папке выпуска, выпуски идут последовательно, полосы внутри этапа —
в пуле потоков `--jobs`.

1. **Этап `toc`.** Полосы, помеченные в базе как «Оглавление» / «Годовой указатель» (вето
   `force_is_not_toc` сильнее), распознаются по одной с промптом «детектор предварительно
   счёл эту полосу оглавлением/указателем — реши сам по картинке»: `#` только у главного
   заголовка списка, весь список в `<toc>…</toc>`, строки «Автор. Название — страница»,
   рубрики внутри списка в `<rubricintoc>` (полностью, как напечатано), плюс структура `toc`
   (секции по рубрикам со статьями). Полосы сливаются в `toc.json` / `toc.md` выпуска
   (`toc.py`): первая секция полосы-продолжения без рубрики приклеивается к последней секции
   предыдущей, статьи с одинаковым названием схлопываются. Блок `<toc>…</toc>` вокруг списка
   **ставит код**, а не модель (`toc.ensure_toc_block`): границы — первый и последний абзац,
   похожий на пункт «Автор. Название — где» или `<rubricintoc>`; хвост «где» принимается в любом
   виде указателя («5», «№ 3, 12», «№ 3, с. 12», «5, 49», «№№ 1, 2, 4»). Просить тег у модели
   пробовали (v10–v13): в 4 × 20 прогонах с. 93 1966/03 она писала его правильно лишь в 1–11 случаях
   из 20, иначе `< toc>` или кириллицей `<тoc>`; если тег всё же приходит, омоглифы и пробелы
   приводятся к `<toc>` при разборе (`schema.normalize_tags`).
   **Сверка тела с объектом `toc`** (`toc.reconcile_toc`): пункты блока `<toc>` разбираются
   («Автор. Название — страница») и сопоставляются со статьями объекта в обе стороны; статьи только
   из тела добавляются в секцию объекта с той же рубрикой, после чего блок `<toc>` строится заново по
   достроенному объекту — тело и объект совпадают ровно. Расхождения — warning в лог, `meta.toc_check`
   и поле `messages` полосы (в `.json`, в шапке `.md`, колонка в `summary.csv`; итог прогона
   считает полосы с замечаниями) — чтобы при прогоне всего пака видеть, где код что-то достраивал.
   **Понижение.** Детектор оглавлений ошибается (таблица, прайс, библиография), и такая полоса
   может доехать до этапа `toc` с тегом. Если модель ответила `toc_kind = none`, полоса
   считается «понижённой»: статьи, которые она всё же извлекла в `toc` (если извлекла),
   попадают в оглавление выпуска, а сама полоса дополнительно распознаётся этапом `page` как
   обычная. Ответ этапа `toc` сохраняется рядом как `имя.toc.json`, в meta полосы —
   `toc_demoted: true`; повтор с `--skip-done` берёт вклад в оглавление из этого файла без
   запроса. Понижённые полосы дописываются в `demoted_toc.txt` (проверить тег в CVAT: снять
   «Оглавление» или поставить вето). Проверка: обложка 1976/12, поданная как «Содержание»
   через `--toc-lists`, понижена, 8 настоящих полос оглавления и указателя — нет.
2. **Этап `page`.** Остальные полосы (и понижённые) — с рубриками и статьями «Содержания» в промпте. Ответ
   доводится кодом (`structure.py`, ниже). Модель заодно проверяет, не оглавление ли перед ней
   (`toc_kind`).
3. **Второй проход** по полосам с `is_damaged = true` — только с `--second-pass` (ниже; по умолчанию выключен).
4. **Fallback.** Полоса с `toc_kind != none`, которой нет среди оглавлений базы и без вето, —
   «оглавление вне базы». По умолчанию (`redo`) выпуск перераспознаётся: найденные полосы
   этапом `toc`, список пересобирается, обычные полосы заново; `ask` спрашивает в терминале,
   `skip` только дописывает `missed_toc.txt`. В базу пакет не пишет: теги ставит человек в CVAT, `from-cvat`
   их приносит.

   **Частичный повтор** (`--redo-scope structured`, умолчание). Списки выпуска влияют только на
   структуру ответа — `#` у названий из списка, `<rubric>`/`<marker>`, привязку `<author>`, правки
   `structure.apply`; транскрипция текста и теги повреждений от них не зависят. Поэтому на круге
   повтора заново идут только полосы с хотя бы одним признаком (`pipeline.redo_reason`):

   | причина | признак в результате первого круга |
   |---|---|
   | `demoted` | полоса понижена (в базе оглавление, модель — нет) |
   | `heading` | в теле есть строка `#`…`######` |
   | `structure_tag` | `<rubric>`, `<marker>` (так помечается рубрика-надпись, которой нет в списке), `<author>`, `<position>` |
   | `title_or_authors` | модель заполнила `title`, `rubric` или `authors` |
   | `structure_edits` | пост-обработка что-то правила (`meta.structure`: понижала `#`, снимала утёкшие `##`, переносила рубрики) |
   | `article_start` | `page_number` совпал с началом статьи по **новому** «Содержанию» — страховка, если заголовок первым проходом не выделен |
   | `no_first_pass` | результата первого круга на диске нет или он битый |

   Колонтитул не в счёт: `##`, `<rubric>`/`<marker>` или поле `rubric` с текстом `running_header` /
   `running_footer` — переписанный колонтитул (модель дублирует его почти на каждой полосе), списки
   его не меняют. На МТС 1991/02 (29 обычных полос) без этой оговорки оставалось 4 полосы, с ней — около половины.

   Остальные полосы берутся с диска: в их meta переписывается `toc_hash` и ставится `redo_kept:
   true` (`articles_in_prompt` остаётся старым — по нему видно, что список в промпте был прежний).
   `--redo-scope all` — прежнее поведение, все обычные полосы заново. Полосы и причины — в логе
   выпуска, число оставленных — в итоге прогона.

Без `--db` можно передать `--toc-lists`; без того и другого оглавление узнаётся только по
ответу модели (fallback).

## Конвенция разметки полосы

Под будущую сборку выпуска и нарезку по статьям и рубрикам. **Оглавление — источник истины**
для статей, рубрик и заголовков:

* `#` — только название статьи из оглавления выпуска; любой другой заголовок (раздел статьи,
  письмо или заметка без записи в оглавлении, заголовок вверху страницы-продолжения) — `##`.
  Мелкие письма без записи в оглавлении сливаются с соседней статьёй — так решено.
* `<rubric>` — только рубрика из оглавления и только непосредственно перед `#` своей статьи,
  где бы её маркер ни был напечатан (над названием, в нижнем углу страницы, на поле). Нарезка
  по рубрикам режет только по `<rubric>`, поэтому маркер, оставшийся посреди текста, разрезал
  бы статью — этого не бывает.
* `<marker>*…*</marker>` — текстовые элементы вне потока статьи: маркер раздела в углу, девиз,
  надпись у логотипа, рубрика, которой нет в оглавлении. Остаются там, где напечатаны, видны
  читателю курсивом, нарезкой игнорируются. Эпиграф — блок цитаты с источником курсивом внутри
  блока, цитируемый не становится `<author>`.
* `<author>` (+ `<position>`) статьи, начинающейся на полосе, — сразу после её `#`, где бы имя
  ни было напечатано (над заголовком, слева от него, под ним, в колонтитуле).
* Подпись статьи, заканчивающейся на полосе, — после её последнего абзаца, до следующей
  `<rubric>`/`#`.
* Имя из колонтитула на странице-продолжении — в `running_header` и в `authors`
  (`article: continues`, `printed: running_header`), в тело не пишется.
* В JSON у каждого автора `article` (`starts_here` / `ends_here` / `continues`) и `printed`.
  Поля «полоса продолжает статью» нет намеренно, а в промпте стоит прямой запрет писать
  заголовок, которого нет на странице: без него модель подписывала продолжение названием
  статьи из списка (1991/02, с. 95: 5 из 5 прогонов; после запрета 0 из 5). Продолжение —
  это просто полоса без `#`.
* На полосах оглавления: список — внутри `<toc>…</toc>` (заголовок `#` перед тегом; на
  полосе-продолжении `#` нет — код снимает переписанный колонтитул), рубрики
  внутри списка — `<rubricintoc>*…*</rubricintoc>` полным текстом. Отдельный тег нужен, чтобы
  нарезка выпуска по `<rubric>` не резала оглавление на части, а `<toc>` — чтобы не спутать
  оглавление с другими списками на той же полосе.
* Таблицы — всегда HTML `<table>` (строка на печатную строку, `rowspan`/`colspan`). Картинки
  (с v15) — fenced-блок ``` без XML-тега и без `>`; первая строка — вид в квадратных скобках,
  дальше по элементу на строку: `[блок-схема]` (блоки `А → Б`, подписи связей `А → Б: подпись`,
  прочее `надпись: …`), `[фотография]` (строка описания, затем `подпись: …`), `[графика]`
  (чертежи, графики, диаграммы, карты, логотипы: строка описания, затем все надписи — у графиков
  `ось X: …`, `ось Y: …`, `легенда: …`, у чертежей `надпись: …` по одной на строку). Блок цитаты
  `>` — только для эпиграфа. Старые обёртки `<schema>/<photo>/<line_art>` с block quote (v10–v14)
  разбор переводит в fenced-блоки (`schema.modernize_illustrations`), так что прежние `.json`
  читаются в новом виде. Сноски — `<footnote>[^1]: текст</footnote>`, ссылка `[^1]` в тексте;
  разрядка → курсив. Число блоков каждого вида — в `meta.blocks` (`toc`, `footnote`, `photo`,
  `schema`, `line-art`); незакрытый fenced-блок — в `meta.tag_warning`.
* Имена тегов — слитно, без подчёркиваний и дефисов (вьюер markdown в PyCharm не прячет ни
  `<rubric_in_toc>`, ни `<rubric-in-toc>`): `<rubricintoc>` (v18); старые написания разбор приводит
  к новому (`schema.LEGACY_TAG_NAMES`), так что `.json` v15–v17 читаются.
* Повреждения — теги TEI в тексте: `<supplied>` (буквы не видны, вписаны по контексту),
  `<unclear>` (видны, но прочитаны с сомнением), `<gap>` (утрачены). Установка промпта (v16):
  обрезанное или скрытое у края слово модель сначала читает как целое слово (или как фрагмент с
  переносом) по остаткам и контексту и только потом помечает невиденные буквы; смазанное слово,
  которое не читается уверенно, — лучшее прочтение в `<unclear>` или `<gap>`, но не правдоподобная
  подстановка без тега; перенос у повреждённого края — обычный перенос. Слова, которых нет в
  печати, не добавляются (правило 1), но обрезанные и повреждённые буквы восстанавливаются
  (правило 5) — до v16 правило 1 предлагало писать `[неразборчиво]`, и модель ставила его вместо
  одной буквы («сущест[неразборчиво]ует») и на продолжениях переносов (23 на с. 93 1991/02).
  В `<gap>` модель пишет
  только ЧИСЛО утраченных знаков — `предпри<gap>4</gap>`, целая строка `<gap>60</gap>`, — а
  разбор раскрывает его (`schema.expand_gaps`): меньше 16 → по «▒» на букву
  (`<gap>▒▒▒▒</gap>`), иначе `<gap>[60 symbols]</gap>`. Число вместо повтора символа — потому что
  повтор «▒» при `temperature 0` зацикливался до потолка токенов (IMG_0008_L, 15 тыс. символов),
  а число — 1–3 токена, повторять нечего; ряд «▒» из ответа по памяти старого формата
  раскрывается тем же правилом, ряд от 20 «▒» считается обрезанным ответом и уходит на повтор в
  следующем режиме JSON. Плюс `edge_words` по словам с достройкой или сомнением (`kind`:
  `hidden` / `unclear` / `gap`). Поля JSON — `is_damaged` (булев вердикт), `damage_description`
  (одно предложение по-русски), `supplied`, `unclear`, `gap`; прежние `damaged`/`damage`,
  `restored`/`fuzzy`/`unknown` и теги старых ответов разбор переводит в новые, так что `.json`
  до v16 читаются (`--skip-done`, круг повтора).
  Что доделывает код по `edge_words` (`schema.py`, счётчики в meta): дописывает `<supplied>`/`<unclear>`
  в слова, которые модель в теле не пометила (`tags_from_edge_words`), **не** переносит в тело
  `<gap>` — это почти всегда строка, оборванная переносом, а слово в теле целое (24 ложных пропуска
  вида «в первую<gap>▒▒▒</gap> очередь» на 3 полосах 1991/02); пропускает и считает пустые записи
  `seen == full` (`edge_words_empty`, четверть списка); снимает `<supplied>` с продолжений переносов,
  у которых `seen` кончается на «-» (`hyphen_supplied_stripped`: «кре<supplied>ди</supplied>ты» →
  «кредиты»); убирает дубли «трудностей <supplied>стей</supplied>» (`duplicate_supplied_dropped`).
* Формулы — LaTeX в долларах внутри тега `<latex>`: выключная
  `<latex>$$Q = \frac{N \cdot П \cdot К}{100} + Q_{п.з}$$</latex> (4)` (номер формулы снаружи
  текстом), переменная в строке `<latex>$V_{потр}$</latex>`. Тег — для машинной обработки,
  доллары — чтобы просмотрщики с MathJax/KaTeX (GitHub, Obsidian, VS Code) отрисовали формулу;
  буквы как напечатаны, кириллические индексы остаются кириллицей. Проверка на 1976/04
  (с. 30–33, 64–65): дроби, суммы, черта над буквой и индексы переданы верно, на полосах без
  формул тег не появляется (химическая `P_2O_5` и расчёт себестоимости — по делу). На одной
  полосе из 21 модель поставила доллары без тега — `structure.wrap_bare_math` оборачивает
  такие формулы кодом (`meta.structure.wrapped_math`).

Модель следует этому нестрого, поэтому после разбора `structure.py` доводит markdown кодом
(детерминированно и идемпотентно): превращает `## Рубрика` прямо перед `#` в `<rubric>`, понижает
`#` не из списка (совпадение по нормализованному названию, `difflib` ≥ 0.75), переносит блок
автора `starts_here` из-под `#` (через рубрику) сразу после `#`, первый абзац полосы с автором
перед `#` — тоже (подписью предыдущей статьи он быть не может), удаляет из тела имя из
колонтитула на продолжении. Рубрики: в промпт уходит рубрика каждой статьи из оглавления
(`[рубрика: X]` в списке), а код подтягивает `<rubric>` к `#` статьи с этой рубрикой, где бы
маркер ни стоял; тег `<rubric>` с текстом не из оглавления или на странице без `#` своей статьи
перетегирует в `<marker>` на месте. **Рубрика только в колонтитуле** (МТС: курсивная строка над
заголовком, 0190_1L 1976/12) — модель пишет её и в `running_header`, и тегом в тело; тег
`<rubric>`/`<marker>` с текстом колонтитула из тела убирается (`header_rubrics_dropped`), настоящая
шапка рубрики (крупная, с буквицей) в колонтитул не попадает и остаётся. **Рубрика не напечатана**
(на полосе ни тега, ни маркера с её текстом) — ничего не вставляется: до 19.09.2026 код подставлял рубрику из
оглавления перед каждым `#`, и `<rubric>` стоял над каждой статьёй (0120_1L 1976/12); рубрика
статьи и так известна из `toc.json`. Что изменено — в `meta.structure` (`moved_rubrics`,
`rubrics_replaced`, `markers_from_rubrics`, `markers`); `title_in_list` пересчитывается кодом.
Ещё страховка: `##` с названием статьи из списка в начале страницы без `#` — утечка списка из
промпта (МТС 1991/02, с. 95), убирается (`dropped_headings`).
После доводки структуры — **склейка разорванных переносов** (`hyphen_join.py`): на полосе с
обрезанным краем модель в части ответов оставляет переносы как напечатано («кре-дитного», 38 из

известна словарю pymorphy3, кроме составных с соединительной «о» (первая половина от 5 букв на

## Стоимость и кэш префикса

Счёт за полосу — примерно 0.1 ¢: 5.3–7 тыс. токенов входа (из них ≈ 3.2 тыс. — текст промптов,
остальное — тайлы) и около тысячи выхода. У DeepSeek кэш префикса автоматический, параметров
запроса нет: совпавшее байт в байт начало запроса (system → текст user → картинки, блоками по 64
токена) считается по $0.003/M вместо $0.15/M, OpenRouter отдаёт
`usage.prompt_tokens_details.cached_tokens` и учитывает скидку в `usage.cost`; тайлы не кэшируются
никогда. Промпты собраны «от общего к частному», чтобы префикс совпадал как можно дольше:

* системный промпт не зависит от выпуска — список статей ушёл в пользовательское сообщение, а
  `--source` задаётся без года (в run-скриптах «…, Москва, 1966–1976»); поэтому он один на весь
  пак и кэшируется между выпусками и годами;
* внутри системного промпта общие правила (текст, таблицы, картинки, формулы, колонтитулы,
  повреждения) идут первыми, стадийные (структура, объект `toc`, JSON) — последними, так что
  этапы `toc` и `page` делят префикс ≈ 2 тыс. токенов;
* в пользовательском сообщении сначала константы (фраза о повреждениях, задача этапа), потом
  список статей выпуска (меняется по выпускам), потом раскладка тайлов и блок второго прохода
  (меняются по полосам).

Замер (промпт v11 → v12, 1976/12 + первые полосы 1976/04 одним прогоном): на первых полосах
второго выпуска, пока кэш выпуска не построен, `cached_tokens` 256 → 3840; внутри выпуска, как и
раньше, кэшируется всё до картинок (≈ 5.2 тыс. со списком). Итоговая доля кэша от всех токенов
входа почти не меняется (71 → 70 %, картинки перевешивают), выигрыш — на первых `--jobs` полосах
каждого выпуска и на полосах оглавления: по паку-1 это ≈ 3 M токенов, ≈ $0.45 за прогон в
льготные часы (2–4 % стоимости). Качество на 1966/03 (97 полос) при перестановке не изменилось:
`#` 21 = 21, `title_in_list` 20 = 20, `<rubric>` 14 = 14, оглавление 20 статей / 8 рубрик в
обоих, сбоев 0, медиана CER тела 0.000. `cached_tokens` пишется в `.meta.json` и `summary.csv`,
итог прогона в логе показывает долю кэша от всех токенов входа.

**Часы скидки DeepSeek.** У родного провайдера (`deepseek`, он первый в `provider_order`) тариф
двойной: пиковые часы — 01:00–04:00 и 06:00–10:00 UTC по будням, всё остальное время — вход и
выход вдвое дешевле (страница pricing в документации DeepSeek). По Москве (UTC+3) в будни это
полный тариф 04:00–07:00 и 09:00–13:00, скидка — 07:00–09:00 и с 13:00 до 04:00 следующего дня;
в субботу и воскресенье скидка круглые сутки. OpenRouter отдаёт в `usage.cost` уже итоговую
цену, поэтому разница видна прямо в `cost_usd`: одни и те же 9 полос 1976/12 при тех же токенах
стоили $0.021 в 01:26 МСК и $0.042 в 12:20 МСК. Полный прогон пака (`run_pack_sharpened.sh`,
~12 тыс. полос) выгоднее запускать после 13:00 МСК или на выходных. На резервных провайдерах
(`allow_fallbacks`) тариф свой, скидки нет.

## Второй проход по повреждённым полосам

**По умолчанию выключен** (`--second-pass` включает). Первый проход отвечает булевым `is_damaged`
(плюс `damage_description`, `edge_words`, теги). С флагом полоса с `is_damaged = true` (или с
тегами / непустым `edge_words`) уходит во второй запрос с подсказкой из ответа первого: описание,
затронутые слова «как видно, вид» (без догадок `full` — с ними модель перечитывала названные строки
и портила чистые слова: «Солкомфлот» 8/12, без списка 0/12), счётчики, и указание самому решить,
скрыты ли буквы (`<supplied>`) или видны, но ненадёжны (`<unclear>`). Финал — второй проход, кроме
страховки: если в нём больше `<gap>` без прироста `<supplied>` или он сбойнул, остаётся первый. Оба
прохода лежат в debug (`имя.pass1.*`, `имя.pass2.*`), в meta финала — `second_pass` с тегами обоих и
выбором, `cost_usd` — сумма. `--second-pass-transcript` добавляет во второй запрос полный текст
первого (замер выигрыша не дал).

Почему выключен (`reports/external_ocr_hyphenation_second_pass.md`, МТС 1991/02, 44 пары проходов):
на чистом тексте проходы равны (медиана различия 0.002), на повреждённых полосах второй в равной
мере чинит (`[неразборчиво]` на с. 93, разорванные переносы на с. 47) и портит — снимает теги с
достроек, не меняя букв (с. 93: 8 `<supplied>` в абзаце → 0), подставляет слово без тега на смазе
(«немецкое»/«страховое» вместо `<supplied>акционерное</supplied>`, которое даёт только первый
проход), обвешивает чистые слова `<supplied>` (с. 4: 2 → 23, и страховка по счётчикам берёт его
вместе с ошибкой «перетерпеть»); арбитраж замен 28:13 за первый проход. Стоимость на повреждённых
полосах ×2.1. Замер 2026-09-17 на мини-наборе, ради которого проход вводился (111/75 → 216/234
`<restored>` за счёт «молчаливого восстановления»), после v16 закрывается иначе: первый проход сам
достраивает слова, `tags_from_edge_words` дописывает теги.

## Кэш запросов

`--cache-dir` (`cache.py`; в run-скриптах `EXTERNAL_OCR_SERVICES_CACHE`). Полоса за прогон может
уйти в модель несколько раз — этапом `toc`, после понижения этапом `page`, на круге повтора с новым
списком статей, внутри прохода в нескольких режимах JSON, — а `--debug-dir` хранит только последний
проход (`.prompt.txt`/`.raw.txt` перезаписываются). В кэше каждый запрос лежит отдельно:

```
cache/{год}/{выпуск}/{полоса}/{этап}[.pass2].{режим JSON}.{12 знаков ключа}/request.json
                                                                          /response.json
cache/{год}/{выпуск}/{полоса}/errors.jsonl
```

* **Ключ** — SHA-256 от payload запроса (`ocr.build_payload`), в котором каждая картинка заменена
  хэшем её JPEG-байтов. В ключ входит всё, что влияет на ответ: модель, системный и пользовательский
  промпты (версия промпта, список статей выпуска, раскладка тайлов, блок второго прохода),
  `response_format`, `reasoning`, `temperature`, `max_tokens`, сами тайлы. Поэтому разные этапы,
  понижение, круг повтора и режимы JSON получают разные папки сами собой, а имя файла полосы в
  ключ не входит.
* **`request.json`** — контекст (полоса, этап, ожидаемый вид оглавления, `toc_hash`, версия
  промпта, модель, сетка тайлов, хэши тайлов, полный ключ) и payload без байтов картинок — промпты
  видны целиком. **`response.json`** — ответ модели как есть (текст, провайдер, токены, цена,
  `request_id`) и `verdict`: `ok`, `format_echo` (эхо `response_format`), `gap_runaway` (цикл «▒»).
  Эхо и цикл тоже кэшируются: при повторе они остаются эхом и циклом, и цепочка откатов идёт к
  следующему режиму без запроса (при `temperature 0` ответ был бы тем же).
* **Сетевые ошибки** (429, 5xx после повторов клиента) не кэшируются — они временные, — но
  дописываются в `errors.jsonl` полосы.
* **Попадание.** Перед каждым `client.chat` ищется папка с таким ключом; есть — ответ берётся с
  диска, в meta `cache_hit: true` и `cache_entry` (папка), в логе полосы «(из кэша)». `cost_usd` в
  meta остаётся историческим (цена того ответа), в итог прогона и `stats.cost_usd` попадания не
  входят; отдельный счётчик — «из кэша запросов N» в итоговой строке, колонки `cache_hit` /
  `cache_entry` в `summary.csv`.
* **Связь с `--skip-done`.** `--skip-done` вообще не собирает запрос (не режет тайлы, не строит
  промпт) — это быстрее; кэш работает на уровне запроса и ловит то, что `--skip-done` пропустить не
  может: полосу, чей `.json` удалён или перезаписан, повтор без `--skip-done`, `--redo-scope all`
  для полос с тем же списком, стенд `replay_page.py` с теми же промптами. Прерванный прогон
  продолжается любым из двух способов.
* Тайлы в кэш не пишутся (только хэши): их и так можно пересобрать из входа, а по паку они весили бы
  ≈ 7 ГиБ (столько занимает `--debug-dir`). Записи без тайлов — около 30 КБ на запрос.

## Сборка выпуска

После каждого выпуска (`--assemble`, по умолчанию включено) или отдельно командой `assemble` из
готовых `.json` (`assemble.py`): `out/{год}/{выпуск}.md` — весь выпуск одним markdown, рядом
`{выпуск}.pages.json` — привязка к полосам. В тело идут полосы по порядку имён файлов (как в
`toc.json`): у полосы оглавления — ответ этапа `toc` с блоком `<toc>`, у понижённой — этапа `page`;
YAML-шапки полос отбрасываются, колонтитулы в тело не идут. **Маркеров границ полос в тексте
нет** — так решено 19.09.2026; полоса находится по sidecar: `pages[].offset` — смещение первого
символа полосы в файле (после склейки оно попадает внутрь сшитого абзаца), `line`, `page_number`,
`stage`. Единственное исключение — полоса без результата (нет `.json`, `error`/`parse_error` в meta):
на её месте `<!-- полоса … не распознана: причина -->`, и она в `missing`. Шапка файла — `year`,
`issue`, `pages`, `missing`; времени сборки в ней нет, чтобы файл воспроизводился байт в байт.

**Граница полос A → B.** Хвост — последний абзац A, голова — первый абзац B, не считая
«плавающих» блоков (текст обтекает их и продолжается на следующей полосе): сноски (`<footnote>` и
голые `[^1]:`), `<marker>`, иллюстрации (fenced-блок, старая цитата `> [картинка…]`), таблицы (HTML
и markdown), их подписи («Рис. 2.», «Таблица 3» и название таблицы следующей строкой) и примечания
к ним («*Примечание.* …»). Оба должны быть простым текстом: не `#`-заголовок,
не `<rubric>`/`<author>`/`<toc>`/`<latex>`, не список, не строка внутри `<toc>`/`<table>`. Тогда по
порядку:

| вид в sidecar | условие | что в тексте |
|---|---|---|
| `hyphen` | хвост кончается половиной слова с дефисом (закрывающие теги повреждений могут стоять до или после дефиса), голова — строчное продолжение, слитная форма известна словарю (правило E `hyphen_join`). Половина может быть частью дефисной цепочки: «технико-техно-» + «логического» (перед половиной составное — хватает правила A), «снаб-» + «женческо-сбытовых» (словарь знает всё слово «снабженческо-сбытовых») | дефис убран, теги на местах: `<supplied>снаб-</supplied>` + `жения` → `<supplied>снаб</supplied>жения` |
| `compound` | то же, но словарь слитной формы не знает («торгово-» + «экономических») | абзацы сшиты без пробела, дефис оставлен |
| `duplicate` | модель достроила перенесённое слово сама (см. «Проверка стыков моделью»): хвост — словарное слово `w`, голова — строчный фрагмент `h` вне словаря, и у `w` есть префикс `p`, для которого `p+h` словарное («направлена» + «ны» → «направлены»; «сокращением» + «нием» → «сокращением»); зеркально — хвост «направле-», голова «направлены»; или обе стороны достроены одинаково | остаётся одно слово, абзацы сшиты |
| `model` | стык переписан по вердикту модели (проверка полосками строк) | слова со стыка заменены словами модели |
| `paragraph` | хвост не кончается `.`, `!`, `?`, `…`, `*` (точка после сокращения «тыс.», «руб.», «г.» не в счёт), голова начинается со строчной буквы, цифры или знака продолжения (`—`, `,`, `(`, `;`) | сшиты через пробел |
| — | иначе | отдельные абзацы |

**Многополосное оглавление/указатель.** На полосе-продолжении (`toc.continues_previous`) модель
пишет `# Указатель статей` — это колонтитул (1976/12: 4 полосы из 5, на скане только колонтитул);
код убирает с таких полос все `#` (`meta.continuation_headings_dropped`). При сборке выпуска блок
`<toc>` полосы-продолжения сливается с блоком предыдущей полосы этапа `toc`: закрывающий `</toc>` и
открывающий `<toc>` на стыке убираются, список идёт одним блоком (`toc_merged` в sidecar; в md
полос блоки остаются постраничными).

**Повторы рубрик.** В тексте выпуска две одинаковые `<rubric>` подряд (хотя бы и через другой
контент) идти не могут: вторая и следующие с тем же текстом убираются (`repeated_rubrics` в sidecar,
с полосой); чередование A → B → A остаётся — для других журналов может пригодиться. Модель пишет
рубрику раздела из списка статей над каждой статьёй раздела (0280_1L 1976/12: напечатана шапка
«Резервы — на службу десятой пятилетке!» → `<marker>`, а `<rubric>` — рубрика из списка) — в md
полосы такой тег остаётся, в выпуске схлопывается. На 1976/12 после всех правил в выпуске ровно
шесть `<rubric>` — печатные шапки разделов.

Плавающие блоки, отодвинутые с хвоста и головы, остаются на своих местах: сноска A идёт сразу за
сшитым абзацем, таблица с начала B — после него. `--no-join-hyphens` / `--no-join-paragraphs` у
`assemble` выключают виды склеек. Проверка на 1966/03 (97 полос, 96 границ): 24 склейки по слову
(22 переноса, 1 составное «электро-энергии» — правило E не знает слитной формы, 1 дубль половины),
25 сшитых абзацев — все проверены глазами по тексту, ложных нет; 46 границ без склейки —
предложение кончилось на полосе, дальше заголовок статьи, рубрика, оглавление, реклама; одна
пропущена — пункт нумерованного списка, оборванный границей (списки не сшиваются). На 1976/12
(99 полос): 29 склеек по слову (1 дубль «направлены+ны», «Минстройдор-маша» — модель на проверке
стыка), 16 абзацев, все проверены глазами.

## Проверка стыков моделью

Модель достраивает перенесённое слово в последней строке полосы сама: на скане 0270_1L/0270_2R
1976/12 чисто «были направле-» | «ны на …» (дефис виден, корешок ни при чём), в транскрипции —
«направлены» | «ны на …»; то же «сокращением» | «нием» в 1966/03. Это правило 5 промпта («обрезанное
слово прочитай целиком»), распространённое на честный перенос; второй сценарий — дефис или половина
буквы под корешком тугой подшивки. На 195 границах двух выпусков — 2 случая (~1 %). Словарные
эвристики (`duplicate` выше) ловят их, когда истинное продолжение сохранилось хоть на одной стороне;
остальное — модели (`boundary.py`, `--check-boundaries`, по умолчанию включено):

* **Сомнительные стыки** (`DoubtReason`): `fragment_head` — голова начинается со строчного токена вне
  словаря, а склейки нет (сюда попадают и дыры словаря pymorphy3 вроде «затрачивается» — дёшево);
  `fragment_tail` — хвост кончается строчным несловарным токеном без знака конца перед строчной
  головой; `compound_unknown` — дефис на границе оставлен, но дефисной формы целиком словарь не знает
  («Минстройдор-маша»); `duplicate` — сработала эвристика дубля (текст изменён — модель подтверждает).
  На 1966/03 — 3 стыка, на 1976/12 — 2.
* **Один запрос на выпуск.** Сборка идёт в два прохода: первый решает стыки эвристиками и собирает
  сомнительные, они уходят модели одним запросом (до 10 стыков в запросе, дальше ещё один), второй
  проход кладёт вердикты поверх эвристик. Без сомнительных стыков запроса нет.
* **Что в запросе.** На стык — две полоски: последние 3 строки полосы A и первые 3 строки B по
  проекции чернил (Оцу → доля чернил по строкам → полосы; ширина по чернилам ± 2 %; JPEG 2200 px по
  длинной стороне, ≈ 150–200 px высоты). Если между хвостом и краем полосы плавающие блоки (подпись
  к чертежу, сноска, таблица), берётся 12 строк и модель предупреждается, что нужная строка выше
  (1966/03, IMG_0121_2R: с тремя строками она читала подпись «…подвеска кабеля» вместо текста).
  Текстом — хвост и голова транскрипции (по 200 знаков) с пометкой «слово могло быть достроено».
  Ответ — JSON по стыкам: `last_line`, `first_line` как напечатано, `tail_word`, `head_word`,
  `same_word`, `joined`. Промпты — `prompts/boundary_system.md.j2`, `boundary_user.md.j2`
  (перевод `boundary.ru.md`), своя версия `BOUNDARY_PROMPT_VERSION`; рассуждения выключены так же,
  как у полос (без этого DeepSeek думал в счёт потолка ответа: 800 токенов, JSON оборван).
  Кэш — тот же `--cache-dir`: `cache/{год}/{выпуск}/_boundaries/boundary.json_object.{key}/` с
  координатами полосок в `request.json`. Цена ≈ 0.02 ¢ на стык, ≈ 0.05 ¢ на выпуск.
* **Применение** (`apply_verdict`, `model.status` в sidecar): `rewritten` — слова на стыке заменены
  словами модели (`same_word` → одно слово `joined`; иначе подстановка прочитанных слов и сшивка через
  пробел); `confirmed` — совпало с эвристикой; `rejected` — слова модели не похожи на слова стыка
  (общее начало короче 4 букв: читала чужую строку) или это не слова — остаётся эвристика; `error` —
  сбой запроса или разбора. Стык, который не сшит, но проверен, тоже попадает в `joins` (вид `none`).
* Проверка (19.09.2026): 1976/12 — «направле-» | «ны» подтверждено, «Минстройдор-» | «маша» →
  «Минстройдормаша» (rewritten, верно); 1966/03 — «электро-» | «энергии» → «электроэнергии»
  (rewritten), «почтой» | «затрачивается» подтверждено раздельно, «сокращением» | «нием» — модель
  прочла строку выше («соот-») и была отклонена, эвристика права. Посеянная ошибка «направлена» | «ны»
  исправлена эвристикой и подтверждена моделью.

## Промпты

Jinja-шаблоны в `prompts/`: `system.md.j2` (правила, ветки по этапу и по наличию списка статей,
текстовая копия JSON-схемы) и `user.md.j2` (раскладка тайлов, подсказка про повреждения или блок
второго прохода, задача этапа). Оригиналы на английском: мелкие модели держат английские
инструкции надёжнее, а язык текста видят на картинке. **Переводы для чтения — рядом:
`prompts/system.ru.md` и `prompts/user.ru.md`**, ветки шаблона в них помечены `[если …]`;
при правке оригинала обновлять и перевод. Нейтральная фраза по умолчанию — `DEFAULT_DAMAGE_NOTE`
в `prompts/__init__.py` (переведена в `user.ru.md`). При любой правке шаблонов поднимать
`PROMPT_VERSION` в `__init__.py` (сейчас 19); версия пишется в каждый `.meta.json`, и полоса,
распознанная другой версией, для `--skip-done` устарела.

Правило о повреждениях в промпте одно (правило 5 системного) плюс короткая фраза по умолчанию в
пользовательском; третий повтор «Apply rule 5 strictly» в конце пользовательского сообщения убран
в v16 (на втором проходе его удаление ничего не меняло; на первом — см. регрессию v16).

A/B версий промпта — `scripts/replay_page.py`: N повторов полос боевым `recognize_page` (без
второго прохода и списков выпуска), `--prompts-dir` подменяет шаблоны (папка с `system.md.j2`,
`user.md.j2` и, если нужно, `damage_note.txt` — старую версию берут из git через `git show`), `summarize`
сводит по повторам флаг `is_damaged`, теги, `edge_words` (с пустыми и дослано кодом), «[неразборчиво]»,
дефисы внутри слов, длину, сходство повторов и сходство с другим прогоном (`--baseline-dir`).
Пометки модели плавают между одинаковыми запросами (IMG_0008_R: 16 против 64 `<supplied>`), поэтому
версии сравнивают по двум и более повторам, а не по одному прогону.

Ответ запрашивается как `response_format: json_schema` (strict) → `json_object` → без формата;
отвергнутый `reasoning` убирается. У DeepSeek сразу `json_object`, схема продублирована текстом в
промпте. DeepSeek на длинном промпте со списком статей в трети случаев отвечает эхом
`{"type": "json_object"}`: такой ответ распознаётся и запрос повторяется без `response_format`
(`meta.cost_usd_wasted`).

## Картинка

Сетка тайлов по `--max-src-tile-size` (шаг в пикселях исходника): `ceil(сторона / шаг)` столбцов
и строк, перекрытие 8 % стороны сверх шага, обход по столбцам (весь левый столбец, потом правый).
Для пака-1 при 4500: обычная полоса 1×2, повёрнутая на 90° 2×1, склеенный разворот
(`1967/10/IMG_0041`, 6444×5336) 2×2. Каждый тайл уменьшается до `--max-model-tile-size` по
длинной стороне (2200 px ≈ 216 dpi), серый JPEG q85. Зачем тайлы: DeepSeek ужимает любую
картинку до ~1300 px, целая полоса 6000 px теряет текст.

Какой край у корешка, модель определяет сама по картинке: опции «сторона на весь прогон» нет
(сторона плавает от части к части выпуска), а суффикс `_L`/`_R` имени файла бывает ложным.
Ручных подсказок про повреждения нет: модель ищет их сама по нейтральной фразе (`DEFAULT_DAMAGE_NOTE`); подсказка по полосе от своего детектора корешка — в планах (`gutter_loss_detection` пока не проверен).

## Клиент OpenRouter

`client.py` работает поверх штатного SDK `openrouter` (PyPI, `OpenRouterTeam/python-sdk`): запрос
уходит через `OpenRouter.chat.send`, баланс — через `credits.get_credits`. Интерфейс клиента прежний:
`OpenRouterClient(api_key, timeout, attempts).chat(payload)` принимает «сырой» payload в форме HTTP API
и переводит его в аргументы SDK. Три вещи SDK не умеет так, как нужно прогону, поэтому они остались
в клиенте:

* **Ретраи.** SDK повторяет только 5xx; нам нужны ещё 429/408, сетевые обрывы и «200 с ошибкой
  провайдера в теле». У SDK ретраи выключены, цикл с backoff свой (`RETRY_STATUSES`, `--attempts`).
* **Выключение thinking.** Модель запроса SDK знает у `reasoning` только `effort`; прежнее
  `{"enabled": false}` она молча выбросила бы, и DeepSeek думал бы за втрое большие деньги. Уходит
  `{"effort": "none"}` (по докам OpenRouter выключает рассуждения целиком; проверено — 0 reasoning-токенов).
  Потолок `reasoning.max_tokens` через SDK не передать, поэтому у Gemini остаётся только уровень.
* **Кто обслужил запрос.** В модели ответа SDK нет поля `provider`; клиент запрашивает
  `x_open_router_metadata=enabled` и берёт провайдера из `openrouter_metadata.endpoints` (`selected`).

Заголовки-визитка (`HTTP-Referer`, `X-Title`) задаются в конструкторе SDK. В тестах сеть подменяется
`httpx.MockTransport` через параметр `http_client`.

## Что лежит в выходе

В md (полосы и выпуска) одинарный перевод строки сразу перед `<author>`/`<position>` и сразу после
`</author>`/`</position>` удваивается (`render.space_author_tags`): иначе вьюер markdown склеивает
подряд идущих авторов и должности в одну строку; двойной перевод и любой другой символ рядом с тегом
не трогаются, `.json` остаётся как есть.
На полосу `имя.md` (YAML-шапка: `page_number`, колонтитулы, `toc_kind`, `rubric`, `title`;
тело — markdown), `имя.json` (все поля `schema.PageResult`, у полос оглавления —
`toc`) и `имя.meta.json` (этап, `toc_hash`, сетка тайлов, провайдер, токены, `cost_usd`,
`structure`, `is_damaged`, `damage_description`, `tags`, `tags_from_edge_words`, `edge_words_empty`,
`second_pass` (если включён), `blocks`, `toc_check`, ошибки). Поле `messages` в `.json`/`.md` — замечания
пост-обработки (сверка оглавления и т. п.). При сбое разбора рядом `имя.raw.txt`; у понижённой
полосы — `имя.toc.json` с ответом этапа `toc`. На выпуск `toc.json`
и `toc.md`, рядом с папкой выпуска — `{выпуск}.md` (весь выпуск одним файлом) и `{выпуск}.pages.json`
(см. «Сборка выпуска»). В корне `summary.csv`, `run.log`, `missed_toc.txt`, `demoted_toc.txt`. В `--debug-dir`: `имя.raw.txt`
(всегда), `имя.prompt.txt`, `имя.tile_{столбец}{строка}.jpg`, при втором проходе `имя.pass1.*`,
`имя.pass2.*`. В `summary.csv` есть колонка `is_damaged` — по ней видно долю полос, которые модель
сочла повреждёнными (в том числе ложно: палец, тень, просвет на чистой полосе).

## Идемпотентность

`--skip-done`: полоса готова, если есть `.json`, meta без ошибки, та же `prompt_version`, тот же
этап и тот же `toc_hash` — отпечаток списков рубрик и статей, с которыми её распознавали. Сменился
промпт — все полосы устарели (с v18). Сменился список
(например, после fallback по оглавлению) — полоса устарела и идёт заново (кроме оставленных
частичным повтором: у них `toc_hash` переписан на новый, `redo_kept: true`). Прерванный прогон
продолжается тем же вызовом. Второй уровень — кэш запросов (`--cache-dir`, выше): он ловит повтор
того же запроса и без `--skip-done`.

`Reasoning` в `models.py`; `SecondPassReason`, `PassChoice` в `ocr.py`; `OnMissedToc`, `RedoScope`,
`RedoReason` в `pipeline.py`; `CacheVerdict` в `cache.py`; `JoinKind`, `DoubtReason`, `VerdictStatus` в `boundary.py`.
В коде они сравниваются через `is`, а в JSON-схему, файлы выхода и `summary.csv` уходят строковыми
значениями, так что формат файлов от этого не меняется; строки из старых вызовов приводятся к
перечислениям в `__post_init__` (`PageJob`, `PipelineParams`). Ключи `.meta.json` остаются строками —
это внешний формат, по нему строится сводка.


| модуль | что делает |
|---|---|
| `cli.py` | команды `run`, `assemble`, `models`, `balance` |
| `pipeline.py` | обход выпусков: этап toc → слияние → этап page → fallback → сборка выпуска; сводка |
| `cache.py` | кэш запросов: ключ по payload с хэшами тайлов, папка на запрос, вердикт ответа |
| `assemble.py` | выпуск одним markdown: два прохода по стыкам, sidecar с привязкой полос |
| `boundary.py` | стык полос: словарные эвристики (переносы, дубли), признаки сомнения, полоски строк по проекции чернил, один запрос на выпуск, применение вердикта |
| `pages.py` | обход входа, флаги полос из базы (только чтение) или списков |
| `ocr.py` | сборка запроса, откаты по режиму JSON и эху формата, второй проход (опция), файлы выхода |
| `tiling.py` | сетка тайлов и подготовка JPEG |
| `schema.py` | `PageResult`, JSON-схема по этапу, терпимый разбор |
| `toc.py` | слияние полос оглавления, списки для промпта, `toc_hash` |
| `structure.py` | пост-обработка markdown: `#` из списка, авторы при статье, рубрики |
| `hyphen_join.py` | склейка переносов по словарю pymorphy3: внутри полосы и через границу полос |
| `prompts/` | шаблоны полос и проверки стыков, их переводы |
| `client.py` | клиент OpenRouter поверх SDK `openrouter`: адаптер payload, ретраи, provider из metadata (его же реэкспортирует стенд `research/external_ocr_models`) |
| `models.py` | реестр моделей |
