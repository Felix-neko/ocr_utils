# page_layout.text_blocks — детектор текстовых блоков

Подпакет отвечает на два вопроса про страницу, снятую с изогнутой бумаги:

1. **где границы текстового блока** — не bounding box, а плавная замкнутая кривая по телу блока;
2. **где идёт каждая строка** — осевая кривая через все символы строки примерно по её центру.

Дополнительно по каждому блоку определяется **выключка**: выровнен ли он по левому краю, по правому,
по обоим (по формату) или рваный — и это работает, даже если блок сильно наклонён или изогнут.

Детектор живёт внутри `page_layout` и умеет принимать его находки на вход (растр, таблицы, line art,
повёрнутый текст), но ни от одной из них не зависит: без подсказок он работает по одним пикселям.
В детектор порчи геометрии (`ocr_utils/geometry_regression`, `research/geometry_regression`) подпакет
пока НЕ подключён: он разрабатывается и отлаживается отдельно.

## Вход: как сформировать данные для детектора

### Минимум — одна серая картинка

```python
import cv2

from ocr_utils.page_layout.text_blocks.engines.ink import InkEngine
from ocr_utils.page_layout.text_blocks.page import analyse_gray

gray = cv2.imread("страница.png", cv2.IMREAD_GRAYSCALE)  # 8 бит, 300 dpi бумаги
analysis = analyse_gray(gray, InkEngine())
```

Требования к картинке, и все три обязательны:

* **серая 8-битная**, `numpy.uint8`, бумага светлая, краска тёмная. Цветную привести
  `cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY)`, бинарную не трогать — детектор бинаризует сам (Оцу), и
  заранее бинаризовать не нужно;
* **разрешение ровно `RENDER_DPI` = 300 dpi бумаги**. Это не придирка: все пороги детектора заданы
  в миллиметрах бумаги (`page_layout.mm_to_px`), а не в долях кадра, поэтому картинку другого
  разрешения надо пересчитать: `cv2.resize(gray, None, fx=300/свой_dpi, fy=300/свой_dpi,
  interpolation=cv2.INTER_AREA)`;
* **страница целиком, без полей-обрезков**. Межколонники ищутся по лентам высоты 40 мм, и вырезка
  в пару строк их не даёт.

### Страница PDF

```python
from pathlib import Path

from ocr_utils.page_layout.text_blocks.engines.ink import InkEngine
from ocr_utils.page_layout.text_blocks.page import analyse_pdf_page, render_page

```

Номер страницы — **с единицы**. `variant` — только подпись в результате (`geo`/`nogeo`, два прогона
FineReader), на разбор он не влияет.

### Необязательные подсказки: где текста быть не должно и где он лежит боком

Подсказки собираются в `hints.LayoutHints` и подаются ДВАЖДЫ — в движок и в разбор (движок гасит
краску до сегментации, разбор режет по рамкам и разбирает повёрнутые области):

```python
import numpy as np

from ocr_utils.page_layout.text_blocks.engines.ink import InkEngine
from ocr_utils.page_layout.text_blocks.hints import LayoutHints, OrientedZone
from ocr_utils.page_layout.text_blocks.page import analyse_gray

height, width = gray.shape[0] // 2, gray.shape[1] // 2  # координаты подсказок — в WORK_DPI = 150
allowed = np.ones((height, width), dtype=bool)
allowed[100:400, 50:500] = False  # фотография: текста здесь быть не может

hints = LayoutHints(
    text_allowed=allowed,              # маска «текст искать можно»; None — можно везде
    zones=(                            # области с ориентацией текста; пусто — вся полоса прямая
        OrientedZone((0, 0, width, height), 0),      # полоса целиком идёт ПЕРВОЙ
        OrientedZone((600, 200, 660, 900), 90),      # шапка графы набрана боком
    ),
    barriers=((160, 120, 1480, 840),),  # рамки таблиц и схем: через рёбра строка не тянется
)
analysis = analyse_gray(gray, InkEngine(hints=hints), hints=hints)
```

Что важно знать про подсказки:

* **все координаты — в пикселях рабочей копии** (`WORK_DPI` = 150), то есть вдвое мельче входной
  картинки. Маска `text_allowed` — того же размера, что рабочая копия;
* **порядок областей значим**: старшинство у ПОСЛЕДУЮЩИХ. Полоса целиком идёт первой, врезки за
  ней, и каждая область гасит у себя всё, что забрали последующие, — так один и тот же текст не
  разбирается дважды;
* `rotate_cw` — на сколько повернуть область ПО ЧАСОВОЙ, чтобы текст стал прямым: 0, 90, 180, 270.
  Для геометрии 90 и 270 неразличимы (оси и огибающие у них одни и те же), а вот 180 от 0
  отличается и выпрямляется;
* подсказки необязательны целиком и по частям: `LayoutHints()` даёт разбор бит в бит такой же, как
  без них.

### Подсказки из готовых детекторов

Две готовые фабрики вместо ручной сборки — обе тонкие, только перевод координат:

```python
import fitz

from ocr_utils.page_layout.image import Variant
from ocr_utils.page_layout.text_blocks.from_layout import hints_of as layout_hints
from ocr_utils.page_layout.text_blocks.from_text_layer import hints_of as cell_hints

with fitz.open("full_1967_07.pdf") as document:
    # Растр и печати → запрет текста; таблицы и line art → рамки-запреты; повёрнутый текст вне
    # таблиц → боковые области. forbid_figures=True запрещает текст и ВНУТРИ таблиц и схем —
    # годится для набора сплошного текста и категорически не годится для табличных полос.
    hints = layout_hints(document, page_index=72, surya=None, variant=Variant.FR_NOGEO)

# Ячейки таблиц и их поворот из кэша `text_layer_fix`: каждая ячейка с краской становится своей
# областью разбора, поэтому блок по построению не попадает сразу на несколько ячеек.
work = cv2.resize(gray, (gray.shape[1] // 2, gray.shape[0] // 2), interpolation=cv2.INTER_AREA)
hints = cell_hints("full_1967_07.pdf", page_index=72, cache_dir=cache, work=work, base=hints)
```

`surya=None` — разбор `page_layout` по одним пикселям, без модели; промах кэша surya тоже не
ошибка, детектор сам откатится на пиксели. Нет кэша `text_layer_fix` — `cell_hints` вернёт `base`
как есть.

## Выход: как разобрать результат

`analyse_gray` возвращает `page.PageAnalysis` — один неизменяемый объект на страницу. **Все
координаты в нём — пиксели рабочей копии** (`analysis.dpi`, по умолчанию 150); в миллиметры бумаги
переводит `page_layout.px_to_mm`.

| Поле | Что внутри |
|---|---|
| `axes` | `tuple[LineAxis]` — осевые кривые ВСЕХ строк страницы, включая те, что не попали в блоки |
| `blocks` | `tuple[TextBlock]` — текстовые блоки слева направо и сверху вниз |
| `alignments` | `tuple[Alignment]` — выключка, по одному элементу на блок, В ТОМ ЖЕ порядке |
| `gutters` | локальные межколонники-ломаные (`columns.Gutter`) |
| `zones` | зоны вёрстки (`columns.Zone`): полосы, внутри которых число колонок постоянно |
| `leaders` | отточия «. . . . .» (`leaders.Leader`) |
| `width`, `height`, `dpi` | размер и разрешение рабочей копии |
| `ink_share` | доля краски текста, накрытая полосами найденных строк, — грубая мера «всё ли нашли» |
| `seconds`, `name`, `page`, `variant`, `engine`, `key`, `note` | служебное |

### Блоки

```python
from ocr_utils.page_layout import px_to_mm

for block, alignment in zip(analysis.blocks, analysis.alignments):
    polygon = block.envelope.polygon          # замкнутый контур (N, 2), главная граница блока
    x0, y0 = polygon[:, 0].min(), polygon[:, 1].min()
    x1, y1 = polygon[:, 0].max(), polygon[:, 1].max()
    print(
        f"колонка {block.column}, блок {block.index}: строк {block.lines}, "
        f"шаг {block.pitch_mm:.1f} мм, выключка {alignment.kind.value}, "
        f"рамка {px_to_mm(x1 - x0, block.dpi):.0f}×{px_to_mm(y1 - y0, block.dpi):.0f} мм"
    )
    for row in block.rows:                    # ряды блока сверху вниз
        print(f"   ряд y={row.y:.0f}, x {row.x0:.0f}..{row.x1:.0f}, высота {row.height:.1f}")
```

* `block.envelope` — **главная граница: полоса вокруг оси**. Верх и низ — оси крайних рядов,
  отодвинутые на устойчивый отступ; она гладкая и обещает, что все ОСИ её рядов лежат внутри;
* `block.envelope_ink` — справочная граница ПО КРАСКЕ. Только она обещает, что внутри лежат все
  БУКВЫ рядов (включая выносные элементы «р», «д» и прописные), зато она заметно зубчатее;
* `block.envelope_coarse` — та же огибающая с окном в `coarse_factor` раз шире: по расхождению с
  основной видно, насколько блок «ведёт себя иначе» на мелком масштабе;
* у каждой огибающей есть `left`, `right`, `top`, `bottom` (кривые `(N, 2)`), `polygon` (обход этих
  четырёх), `polygon_dilated` (раздутый на полсимвола) и `core_left`/`core_right` — гладкий тренд по
  ТЕЛУ блока, от которого считаются меры выключки.

Проверить, лежит ли точка в блоке, и получить его маску:

```python
import cv2
import numpy as np

polygon = analysis.blocks[0].envelope.polygon
hull = polygon.astype(np.float32).reshape(-1, 1, 2)
inside = cv2.pointPolygonTest(hull, (520.0, 300.0), False) >= 0  # >= 0 — внутри или на контуре

mask = np.zeros((analysis.height, analysis.width), dtype=np.uint8)
cv2.fillPoly(mask, [np.round(polygon).astype(np.int32)], 255)
```

### Строки

```python
for axis in analysis.axes:
    points = axis.points                      # ломаная (N, 2) слева направо, пиксели рабочей копии
    print(
        f"строка x {axis.x0:.0f}..{axis.x1:.0f}, середина y={axis.cy:.0f}, "
        f"высота {axis.height:.1f}, наклон {axis.slope_deg:+.2f}°, "
        f"прогиб {axis.sagitta_mm:+.2f} мм, непрямизна {axis.bend_mm:.2f} мм"
    )
```

* `sagitta_mm` — прогиб относительно прямой по концам, со знаком (вниз — плюс);
* `bend_mm` — размах остатка от этой прямой, то есть «насколько строка непрямая»;
* `resid_parabola_mm` — то же от ПАРАБОЛЫ: где и параболы не хватает, бумага смята, а не изогнута;
* `mark_spans` — отрезки по x, занятые точками и запятыми: там ось провисает к базовой линии, и в
  меры формы строки эти участки не входят. При своих замерах их тоже стоит выбрасывать;
* `cross` — строка на самом деле кусок широкой строки (заголовка), разрезанной межколонником.

Строки блока лежат в `block.rows[i].axes` — их может быть несколько на ряд, если строка разорвана
(обрывки на одной высоте). Оси, не попавшие ни в один блок, остаются только в `analysis.axes`.

### Выключка

```python
alignment = analysis.alignments[0]
alignment.kind          # AlignKind: ragged / left / right / both
alignment.left.core_share       # доля рядов, легших на тренд с этой стороны
alignment.left.indent_rows      # сколько рядов с абзацным отступом
alignment.left.envelope_dev_mm  # расхождение основной огибающей с крупной
alignment.left.bend_mm          # изгиб самой огибающей
```

На оверлее вердикт пишется крупно посередине блока: `both` (зелёным), `left` / `right` (синим), `center`
(фиолетовым), `none` (красным; в JSON и CSV это `ragged`). Порядок решения: `both` → `left` → `right` →
`center` → `none`. **По центру** — середины рядов вдоль строк (в системе координат блока, с поворотом на
наклон строк) у 80 % рядов не дальше 1.5 мм от медианы, при этом длины рядов различаются больше чем на
3 мм (иначе это формат): подписи авторов, эпиграфы. **Однострочный блок** выключки не имеет — `none`
(раньше он получал `both`: оба края одной строки совпадают со своим трендом по определению). На оверлеях выравнивания стенда сторон (`sides`) — тоже, по доле рядов в
выровненных сериях каждого способа (порог тот же, 0.8).

## Валидационное множество

Оно разделено на две папки, каждой соответствует свой run-скрипт:

| Набор | Что в нём | Скрипт | Выход |
|---|---|---|---|
| текстовый контент и оглавления | 12 страниц × 2 варианта: сплошной набор в 1–4 колонки, заголовки, сноски, подписи авторов, одна таблица с отточиями. Считается дважды: без подсказок и с масками растра, таблиц и line art | `run_scripts/text_blocks/run_text_pages.sh` | `…/curved_layout_validation/text_and_toc` и `…_hinted` |
| табличный и нетекстовый контент | 21 страница × 2 варианта: 12 с line art (схемы, графики, чертежи), 3 таблицы с повёрнутым текстом в ячейках, 3 с набранной боком таблицей, 3 с повёрнутым текстом на line art | `run_scripts/text_blocks/run_tables_pages.sh` | `…/curved_layout_validation/tables_and_nontext` |
| подсказки на входе | 9 полос с боковым текстом, таблицами и схемами, три прохода: без подсказок, с находками `page_layout`, плюс ячейки таблиц | `run_scripts/text_blocks/run_layout_hints.sh` | `…/curved_layout_hints/{plain,hinted,cells}` |

Второй набор собран по разметке пака (`pack1_reviewed.sqlite`, виды областей `line_art_schema` и
`table`) и по сводке повёрнутых таблиц (`pack1_rotated_tables/summary.csv`). Детектор под него НЕ
дорабатывался: прогон нужен, чтобы видеть, что происходит на сложных страницах.

Выход: `pages/<pdf>_p<NNN>_<вариант>_<движок>.json` (все кривые), `blocks.csv` (строка на блок),
`overlays/*.jpg` (оверлеи для просмотра глазами), `report.md` (сводка).

## Как это устроено

| Модуль | Что делает |
|---|---|
| `columns.py` | **локальные межколонники**: вертикальные пустоты ищутся по лентам высоты 40 мм и сливаются в отрезки `(x0, x1, y0, y1)`; кандидат подтверждается текстом по обе стороны на его высоте. ## Граница блока и её дилатация

Кромка по краске идёт вплотную к самым дальним символам, поэтому она заметно «зубчатее» осей
строк: выносные элементы («р», «д») и прописные торчат наружу. Рядом с ней строится вторая
кривая — `envelope.polygon_dilated`: исходный контур растеризуется и раздувается ЭЛЛИПТИЧЕСКИМ
ядром на `--dilate-glyphs` (умолчание 0.5) от среднего размера символа блока, после чего контур
снимается заново. Впадины уже двух радиусов при этом заполняются, и граница становится ровнее, а
не только шире. Исходный `polygon` не меняется, меры выключки по-прежнему считаются от `core_*`.

Средний размер символа блока — медианы ширины и высоты компонент краски от 0.8 до 7 мм по рядам
(`blocks.glyph_metrics`); если глифов не набралось, он оценивается от высоты ряда.

Оверлей `--dilate-compare "0.5,1.0"` рисует поверх исходной границы ещё две — на полсимвола и на
символ — с легендой: так видно, что даёт дилатация.

## Настройки, которые стоит крутить

* `--smooth-block` — окно огибающей в **межстрочных интервалах** (умолчание 2.5; пользователь просил 2–3).
  В окно всегда берётся не меньше `MIN_TREND_ROWS = 5` рядов: по двум-трём кромку не провести.
* `--coarse-factor` — во сколько раз шире окно «крупной» огибающей, с которой сравнивается основная
  (мера `envelope_dev_mm` — насколько блок ведёт себя иначе на мелком масштабе).
* `--smooth-line` — окно сглаживания оси строки в долях высоты строки (умолчание 0.6).
* Пороги выключки — `alignment.ALIGN_TOL_MM` (0.8 мм), `CORE_SHARE` (0.8), `INDENT_MIN_MM` (2.5 мм).

## Что важно про кривую бумагу

Зона вёрстки — служебное понятие: горизонтальная полоса, внутри которой постоянно ЧИСЛО колонок.
Границей блока она не является. Все решения о принадлежности строки колонке принимаются по
межколоннику-ЛОМАНОЙ на высоте самой строки, а разрывы между блоками меряются вдоль наклона
(`blocks.row_gap`: ординаты осей берутся в общей точке по x). По той же причине оси сливаются в
ряд не по медианам ординат (`LineAxis.cy`), а в ТОЧКЕ ВСТРЕЧИ: каждая ось продолжается от своего
ближнего конца с собственным наклоном (`blocks._same_row`). Сравнение медиан на перекосе давало
«половинки»: левая и правая половины одной строки стоят на разной высоте (1973/11 с.79 — 11 px
при шаге 20), в один ряд не сливались, и колонку резало пополам правило «слабое перекрытие по x»
— это и были рваные границы блоков. Поэтому на трапеции блок не цепляет
номер полосы, уехавший под него, и не рвётся там, где строки просто наклонены.

## Верх и низ блока — от базовой линии, а не от оси

Ось строки — середина КРАСКИ, и над словом из прописных, цифрами или сокращением она поднимается:
у прописной верх выше, а низ тот же. На 1975/05 с.97 («В УМТС Башкирского») верх краски 1015.0 и
1018.5, низ 1026.5 и 1027.0, и верх блока, отмеренный от оси, опускался ступенькой на 1.8 px там, где
кончается «УМТС». Поэтому верх и низ блока (кромка-полоса) отмеряются от **линии середины строчной**
(`blocks.body_line`, `Row.body`): базовая линия букв ряда, поднятая на полвысоты строчной.

Как она строится:
* буквы — связные компоненты краски в окне вокруг оси;
* отбрасываются пыль, выносные элементы соседних строк (низ выше оси), точки и запятые, выносные вниз
  (низ ниже общего уровня больше чем на 0.2 икса — отсев односторонний, как у якорей букв в `pieces`);
* поправка к оси по буквам сглаживается медианой по трём буквам: одна ошибочная буква ступеньки не
  делает, а слово из прописных честно выравнивается.

Ступенька на 1975/05 с.97 уходит: верх 1013.2 → 1015.0 стал 1012.8 → 1013.0. Отступ полосы тоже
меряется от этой линии. Лента ряда, которая обещает держать внутри свои оси, по-прежнему идёт вокруг
оси, и оси из своих контуров не выходят. Замер по валидации: оси и их меры не меняются, пересечения
контуров на тексте +207 px² (5955 → 6162), на таблицах +2 %; «за контуром» +3 на таблицах — это чужие
оси, чья середина попала в соседний перекрывающийся блок (1968/01 с.75, до 4 px).

## Последняя строка блока

Последняя строка абзаца (и блока) даже при выключке по формату до правого края не доходит, и
правее её конца у нижней кромки блока нет опоры: раньше кромка продлевалась по наклону конца строки
не дальше 8 мм и дальше шла горизонталью, не повторяя изгиба бумаги, а правый нижний угол блока
заваливался внутрь (1976/09 с.92). Теперь короткая последняя строка достраивается **хвостом**
(`blocks._tail_of`):

1. опора — ось ПРЕДПОСЛЕДНЕЙ строки, пересобранная с шагом 1 мм и сильно сглаженная
   (`TAIL_SMOOTH_MM` = 8 мм: изгиб бумаги остаётся, форма букв уходит);
2. **линия отсечки** — перпендикуляр к сглаженной опоре в её правом конце (наклон — по последним
   `TAIL_SLOPE_MM` = 10 мм);
3. межстрочный интервал — медиана расхождения последней строки с опорой по её последним трём
   символам (крайняя ордината ненадёжна: ось на конце может нырять к засечке);
4. хвост — опора, сдвинутая на этот интервал, от конца оси до линии отсечки; на первом символе
   интервал плавно переходит от фактического к медианному. Ось доходит до края краски (замер на
   1976/09 с.92: медиана −1.5 px, p90 +0.5), поэтому отступ за отсечку на полсимвола не нужен.

Хвост не строится, если последняя строка почти доходит до отсечки (недобор меньше символа), если
ряды не соседние (интервал вне 0.5–2.5 шага строк) и если справа от строки не пустота: в полосе
±0.4 высоты строки вокруг хвоста краска стоит больше чем под 30 % узлов (`TAIL_MAX_INK_SHARE`;
замер по 84 хвостам валидации: 77 без краски вовсе, 0.07–0.17 — своё — отточие строки, «__ г.» вне
оси, 0.40–0.89 — чужой текст: соседняя графа, сноска 1969/11 с.69, разрезанная на два блока).

Опора — всегда предпоследняя строка, даже если она сама короткая: на перспективу можно искать
ближайшую полную строку выше, но какая из них полная, до построения границы блока не известно.

Хвост виртуальный: краски под ним нет, в `analysis.axes` и в метрики осей он не входит, меры
выключки считаются по краске (`row.x1`). Учитывает его только **кромка-полоса** (главная граница
и крупная огибающая): ряд широк до конца хвоста, низ блока идёт вдоль хвоста, а `_swallow_rows`
гарантирует, что полоса вокруг хвоста (толщиной как у самой строки) лежит внутри контура.
Справочная граница по краске его не видит. Лежит в `Row.tail` и `Row.cut`, в JSON — `rows[].tail`
и `rows[].cut`; на оверлее — розовым, вместе с отрезком линии отсечки.

Замер на валидации (было → стало): оси и их меры не меняются; хвостов 43 на тексте, 121 на
таблицах и схемах; «за контуром» не растёт; пересечения контуров +19 px² на тексте, +0.2 тыс. на
таблицах, +4 и +5 тыс. на полосах с подсказками — там хвосты раздвигают блоки, которые и до этого
перекрывались (1970/06 с.62: строка через несколько граф таблицы; 1971/11 с.59: крупный набор,
нарезанный на блоки по две строки).

## Стороны границы блока и выравнивание по ним (стенд)

`sides.py` размечает каждое звено главной границы блока стороной (`SideKind`: лево, низ, право, верх)
и флагом «угол» — тремя методами (`SidesMethod`), и считает выравнивание по вертикальным сторонам —
тоже тремя (`AlignMethod`). В конвейер разбора не подключён: методы сравниваются на оверлеях.

```bash
python -m ocr_utils.page_layout.text_blocks sides --geo-dir … --nogeo-dir … \
    --pages full_1976_09:92,full_1973_08:85 --out-dir …/curved_layout_sides
```

```python
from ocr_utils.page_layout.text_blocks.sides import AlignMethod, SideKind, SidesMethod
from ocr_utils.page_layout.text_blocks.sides import side_alignment, side_measures, sides_of

block = analysis.blocks[0]
sides = sides_of(block, SidesMethod.RAYS)       # polygon (N, 2), labels[N], corner[N] — по звеньям
for item in side_measures(sides, block.dpi):   # наклон и изгиб БЕЗ угловых звеньев
    print(item.side.value, item.tilt_deg, item.bend_mm, item.corner_share)
right = side_alignment(block, SideKind.RIGHT, AlignMethod.ROBUST)
right.aligned_share                           # доля рядов в выровненных сериях
[(end.row, end.status.value, end.resid_mm) for end in right.ends]
```

* `construct` — по построению огибающей (контур — обход её четырёх кривых); **метод по умолчанию**
  (`DEFAULT_SIDES_METHOD`, `sides_of(block)` без второго аргумента, CLI `--sides-method`);
* `rays` — лучи из концов крайних строк по нормали и по касательной, в каждом углу ОДИН разрез;
  короткая крайняя строка (абзацный отступ, конец абзаца, подпись автора) сначала продлевается по
  ближайшей ПОЛНОЙ строке, сдвинутой на межстрочный интервал (`edge_axis`, на оверлее — розовый пунктир);
* `frame` — нормаль звена против местного направления строк, контур делится ровно на четыре дуги ДП.

У верхней и нижней сторон концы длиной в букву крайнего ряда (первого у верха, последнего у низа)
помечаются **неуверенными** (`BlockSides.uncertain`): там кромка загибается в угол по краске крайних
букв. Как и углы, они рисуются пунктиром и в меры наклона и изгиба сторон (`side_measures`) не входят.

Выравнивание: `trend` — по x от тренда тела блока (как `alignment.py`), `tangent` — вдоль касательной
к строке, `robust` — устойчивая кривая по концам строк в системе координат блока (как векторы
табуляции Tesseract). Ряд — «на кривой» (≤ 0.8 мм), «отступ» (внутрь ≥ 2.5 мм) или «мимо». Серия —
подряд идущие ряды на кривой; одиночный ряд между ними (отступ, конец абзаца, повреждённая строка —
1973/07 с.88, «…монтажных р» без «а-») её не рвёт, если рядов на кривой в серии не меньше 75 %
(`RUN_MIN_ON_SHARE`: иначе рваный край склеился бы в выровненный). Серия от трёх рядов на кривой —
выровненный участок стороны. Доля выровненных считается среди рядов БЕЗ отступов, как у вердикта
`alignment.py`; сторона выровнена при доле от 0.8. На 36 блоках от 10 строк стенда вердикт совпадает
с основным у `trend` и `tangent` в 35 случаях, у `robust` — в 34. Сравнение и литература —
`reports/text_blocks_sides.md`.

## Как делятся блоки

Блок — колонка целиком, но внутри колонки он рвётся, если:

* вертикальный разрыв вдоль наклона больше `BLOCK_GAP_PITCHES` (2.5) межстрочных интервалов;
* медианный кегль по четырём рядам с одной стороны границы отличается от другой стороны больше
  чем в `HEIGHT_BREAK_RATIO` (1.6) раза — заголовок над корпусом, подпись автора под ним;
* между рядами идёт сплошная черта (`segment.rules_of`) — разделитель сноски;
* соседние ряды почти не перекрываются по x (`MIN_ROW_OVERLAP` 0.35) — логотип рубрики слева и
  заголовок заметки справа под ним не один блок, хотя и стоят подряд.

Обратные ходы: куски одной колонки из соседних зон склеиваются (`_merge_pieces`), а хвост широкой
вводки, уместившийся в одну колонку, возвращается в неё (`_absorb_continuation`, не больше двух
строк, с тем же шагом, кеглем и левым краем).

## Жирность набора и черта под заголовком

**Жирность** (`Row.weight`, `blocks.stroke_weight`) — средняя толщина штриха ряда: удвоенное расстояние
до фона на пикселях скелета краски, по рендеру 300 dpi. Прежняя мера `stroke` (медиана горизонтальных
пробегов на рабочей копии) идёт шагом 0.5 px и полужирный набор того же кегля почти не отличает. На
1975/05 с.97 подпись «Ф. ШАРИФЬЯНОВ, директор Салаватской металлобазы» из-за этого сидела в блоке
колонки, и колонка по формату получала `none`. Новая мера: текст 4.05–4.19 px рендера, регалии
4.95–5.37, фамилия 6.47.

Блок делится по жирности (`_heavy_break`, признак в `_style_break`), если медианы по окнам с двух сторон
границы отличаются больше чем в 1.18 раза. Окна — до четырёх рядов, не меньше двух. Режется только
граница с наибольшим отношением среди соседних: окна захватывают подпись постепенно, и порог проходят
несколько границ подряд. Одиночная крайняя строка большого блока (от 8 рядов), которая жирнее соседей
больше чем в 1.25 раза, отделяется окном в один ряд — это подпись одной строкой («Э. САВИНА»,
1973/07 с.88). Замер по 34 валидационным полосам в двух вариантах: внутри блоков медиана отношения
1.011, p99 1.069.

**Черта под заголовком** не сцепляется со словом (`zones._allowed`): куски одной строки не накрывают
друг друга по x больше чем на 30 % более короткого. На 1973/07 с.77 слово «кадров» сцеплялось с чертой
через всю полосу, кусок «черта + слово» выбрасывался как черта, и заголовок «Экономическое
образование кадров» терял последнее слово.

## Два масштаба сегментации

Строки ищутся дважды: корпусным набором и крупным (заголовки, логотипы, подписи). Корпусному
масштабу остаются только строки не выше `BODY_HEIGHT_RATIO` (1.6) медианы страницы — заголовок он
собирает хуже (узкий допуск на перепад высот соседних слов) и рвал его посреди строки. Крупный
масштаб добавляет то, чего корпус не нашёл, и забирает корпусные обрывки внутри своих строк.

Две защиты от склейки строк через рисунок (1973/11 с.79: вензель «Э» с ножками и чертой — одна
компонента 590 × 126 px, к которой смыкание RLSA пришивало буквы обеих строк заголовка, и ось шла
от «Э» к «образование»):

* в маске глифов (`component_mask`) выбрасывается **рамка** — компонента выше `FRAME_HEIGHT_RATIO`
  (2.2) медианы с заполнением бокса ниже `FRAME_MAX_FILL` (0.1): вензели, рамки таблиц, линии схем.
  Буква заголовка даёт 0.5–0.7, по 33 полосам валидации буквы ниже 0.1 нет;
* крупная строка, внутри которой корпус нашёл два ряда один над другим (`_multi_row`), считается
  склейкой рядов и отбрасывается: корпусные ряды она больше не поглощает. «Один над другим» —
  середины разошлись больше чем на полвысоты И строки перекрываются по x (`MULTI_ROW_OVERLAP`
  0.5): без второго условия разваливалась на слова «Нам пишут…» (1975/05 с.97), где курсивная
  прописная «Н» поднимает середину «Нам» на полвысоты над «пишут».

Замер по трём наборам валидации (было → стало): осей, уходящих от хорды, 39 → 37 на тексте, 34 → 24
на таблицах и схемах; блок-схема 1971/09 с.80 и шапка таблицы 1968/01 с.75 больше не собираются в
ложные «строки» по контуру рамок. Цена — на 1971/09 с.80 две оси (заголовок схемы и строка в
рамке) остались вне блоков.

## Чего он пока не умеет

* Таблицы с отточиями разбираются как обычный блок: правая кромка идёт по концам отточий (1971/10 с.93).
* Рисунки и растр не исключаются — это делает `page_layout`, и при подключении к детектору его рамки
  надо передавать снаружи (`--layout-cache`, `hints.LayoutHints`).
* Ось, лежащая целиком в межколоннике, уходит в колонку ближайшего по высоте текста (отточия не в счёт) —
  но если соседей на её высоте нет вовсе, она остаётся вне колонок.
* В ячейке таблицы короче трёх глифов (одиночные `a₁`, `R`, столбец однозначных чисел) оси нет:
  строкой считается набор от `segment.MIN_GLYPHS`.
* Строки, потерянные сегментацией (жирный или разрядка), оставляют разрыв: блок может разделиться,
  хотя обрывки короче трёх рядов приклеиваются обратно.
* Разделитель сноски, который на рендере распался на куски, не находится, и сноска остаётся в
  блоке колонки (1973/08 с.85). Целую черту — прямую или волнистую — детектор берёт.
* Таблица с отточиями разбирается правильно (точки входят и в строку, и в блок), но правая кромка
  блока идёт по концам отточий — то есть по графе чисел, а не по тексту.
* Строка, набранная ВРАЗРЯДКУ и с широкими пробелами (сноска «М а р к с К. и Энгельс Ф. Соч.,
  т. 25,» — 1973/08 с.85), распадается на куски: пробел между словами там 12.7 мм при высоте
  строки 3 мм, а поднять общий предел разрыва нельзя — на таблицах это склеивает графы
  (замер: 1971/10 с.93 — 13 блоков против 16 при пределе в 4.5 высоты).
* Шапка статьи из логотипа, заголовка и подзаголовка с разными интервалами может остаться одним
  блоком с пустотами внутри, если кегли близки (1973/11 с.79).
