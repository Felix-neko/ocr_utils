# curved_layout — разбор текста страницы в терминах кривой бумаги

Подпакет отвечает на два вопроса про страницу, снятую с изогнутой бумаги:

1. **где границы текстового блока** — не bounding box, а плавная замкнутая кривая по телу блока;
2. **где идёт каждая строка** — осевая кривая через все символы строки примерно по её центру.

Дополнительно по каждому блоку определяется **выключка**: выровнен ли он по левому краю, по правому,
по обоим (по формату) или рваный — и это работает, даже если блок сильно наклонён или изогнут.

В детектор порчи геометрии (`ocr_utils/geometry_regression`, `research/geometry_regression`) подпакет
пока НЕ подключён: он разрабатывается и отлаживается отдельно.

## Вход и выход

Вход — серый рендер страницы в 300 dpi (бинарный PDF FineReader, вариант с коррекцией геометрии или без).
Все координаты наружу отдаются в пикселях рабочей копии (`WORK_DPI = 150`).

```python
from ocr_utils.curved_layout.engines.ink import InkEngine
from ocr_utils.curved_layout.page import analyse_pdf_page

analysis = analyse_pdf_page(pdf, page=65, engine=InkEngine(), variant="nogeo")
analysis.axes       # оси строк: LineAxis(points, height, column, sagitta_mm, slope_deg, bend_mm, …)
analysis.blocks     # блоки: TextBlock(rows, pitch_px, envelope, envelope_coarse)
analysis.alignments # выключка блоков: Alignment(kind, left: SideStats, right: SideStats)
analysis.gutters    # локальные межколонники Gutter(x0, x1, y0, y1)
analysis.zones      # зоны вёрстки Zone(y0, y1, columns)
```

Командой:

```bash
python -m ocr_utils.curved_layout analyze \
    --geo-dir …/full_pdfs_binary_no_bg_brightening \
    --nogeo-dir …/full_pdfs_binary_no_bg_brightening_no_geometry_correction \
    --pages full_1973_06:65,full_1971_10:87 --variant both --engine ink \
    --smooth-block 2.5 --coarse-factor 3 --smooth-line 0.6 \
    --out-dir …/curved_layout_debug
```

## Валидационное множество

Оно разделено на две папки, каждой соответствует свой run-скрипт:

| Набор | Что в нём | Скрипт | Выход |
|---|---|---|---|
| текстовый контент и оглавления | 12 страниц × 2 варианта: сплошной набор в 1–4 колонки, заголовки, сноски, подписи авторов, одна таблица с отточиями | `run_scripts/curved_layout/run_text_pages.sh` | `…/curved_layout_validation/text_and_toc` |
| табличный и нетекстовый контент | 21 страница × 2 варианта: 12 с line art (схемы, графики, чертежи), 3 таблицы с повёрнутым текстом в ячейках, 3 с набранной боком таблицей, 3 с повёрнутым текстом на line art | `run_scripts/curved_layout/run_tables_pages.sh` | `…/curved_layout_validation/tables_and_nontext` |

Второй набор собран по разметке пака (`pack1_reviewed.sqlite`, виды областей `line_art_schema` и
`table`) и по сводке повёрнутых таблиц (`pack1_rotated_tables/summary.csv`). Детектор под него НЕ

## Как это устроено

| Модуль | Что делает |
|---|---|
| `columns.py` | **локальные межколонники**: вертикальные пустоты ищутся по лентам высоты 40 мм и сливаются в отрезки `(x0, x1, y0, y1)`; кандидат подтверждается текстом по обе стороны на его высоте. Из событий «межколонник начался/кончился» строятся **зоны вёрстки** — полосы, внутри которых набор колонок постоянен (врезка сверху справа: 1967/10 с.63) |
| `capsules.py` | **капсулы и конусы**: отрезок с толщиной (радиус может расти к дальнему концу), расстояние между отрезками, точка встречи и угол подхода. На них стоят зоны поиска; растеризация полигонов не нужна |
| `pieces.py` | **куски строк**: сгусток RLSA, разобранный на буквы, с МНК-осью по их якорям, высотой строчной буквы и касательными на концах. Буква приписывается сгустку по любому своему пикселю (по центру бокса терялись «2», «5», «з»), якорь буквы — её базовая линия, поднятая на полвысоты строчной полосы, с односторонним отсевом выносных элементов вниз. Здесь же межстрочный шаг страницы — по самим кускам, без поля |
| `zones.py` | **сцепка по зонам поиска**: от концов оси куска выпускаются КОНУСЫ (у куска направление известно точно, дальше оценка шумит), соединяются куски, чьи зоны встретились под малым углом; с каждой стороны не больше одного соединения, и только взаимно ближайшее. Два круга: длинные куски и первичные зоны коротких, затем вторичные зоны коротких (разрядка). Предохранители: наклон соединения против МЕСТНОГО наклона строк, остаток якорей от оси после слияния, стоп на конце отточия |
| `metrics.py` | валидационные метрики по выкладке прогона: **скрещивания и сближения осей** (прямая мера перескока), отклонение от хорды, оси вне блоков, половинки рядов, пересечения контуров, покрытие краски |
| `legacy_linking/` | прежний ход: жадная цепочка (`linking.py`) и поле хода строк (`baselines.py`). Включается `--linking greedy`; чем плох — в README подпакета |
| `segment.py` | строки по краске (ось — центр масс краски по столбцам; над знаками препинания и отточиями она выравнивается по соседним буквам, а на КОНЦАХ строки неполные столбцы — где столбец держит только угол наклонной буквы — прижимаются к продолжению строки до сглаживания) (плюс продление строки по её отточию — `extend_with_leaders`) (строкой считается набор от `MIN_GLYPHS` = 3 глифов: пороги по длине и отношению сторон низкие, иначе выпадают числовые графы таблиц «500 м» и однословные концы абзацев): маска глифов, смыкание RLSA, сборка кусков (`zones.link_by_zones`) с ЗАДАННЫМИ межколонниками; строка, сшитая через межколонник по случайной краске, режется по нему; сплошные линейки (разделитель сноски, подчёркивание колонтитула) отбрасываются. Сцепка кусков — по зонам поиска (`zones.py`), прежний жадный ход доступен как `--linking greedy`. |
| `lines.py` | **осевая кривая строки** (плюс `mark_spans` — отрезки, занятые точками и запятыми: они стоят на базовой линии, ось там провисает, и в меры формы строки эти участки не входят; на оверлее — оранжевым): точки центра масс краски пересобираются с шагом 1 мм, сглаживаются медианой и Савицким–Голеем окном в долях высоты строки; сводки формы — сагитта, наклон, размах остатка от прямой и от параболы |
| `blocks.py` | ряды колонки (края по краске текста), **гладкая огибающая**: грубый квантильный тренд → отбор рядов тела (без абзацных отступов и коротких концов) → локальная взвешенная прямая (LOWESS) → Савицкий–Голей; деление блока по разрыву, кеглю и штриху (признак кегля гасится, когда размер глифа с обеих сторон границы один и тот же); замкнутый контур из левой, нижней, правой и верхней кривых, а сверху — проглатывание краски рядов (`_swallow_rows`): рамка «ордината → края» режет строку, чей изгиб больше межстрочного шага, поэтому контур объединяется с лентами краски своих рядов и гарантированно охватывает все их буквы |
| `alignment.py` | выключка блока: доля рядов, лежащих на огибающей, отдельно считанные отступы, девиация основной огибающей от крупной и изгиб самой огибающей |
| `columns.py` (доп.) | **вертикальные линейки таблицы** (`rule_separators`, морфология из `page_layout.tables.ruling`) запрещают сцепку так же, как межколонник: графы линованной таблицы разделены не пустотой, а чертой, и пустого межколонника между ними может не быть. Полоса, сквозь которую идут отточия, межколонником не считается (`DOT_GUTTER_LEADERS` = 3): иначе поле точек резало таблицу на колонки |
| `leaders.py` | **отточия**: цепочки точек «. . . . .» (от четырёх точек одного размера с шагом до 4 мм — замер: фактический шаг 3.03 мм). Их точки добавляются в краску текста (иначе маска глифов выбрасывает 0.5-миллиметровую точку), а строка продлевается по ним в `segment.extend_with_leaders` — ось идёт по отточию, но по своему уровню, а не по базовой линии точек |
| `engines/` | поставщики строк: `ink` (свой ход по краске) и адаптеры чужих сегментаторов — `kraken` (blla), `pero` (ParseNet), `eynollah` (`--curved-line`), `surya` (из кэша). Чужие живут в своих `uv venv` под `/mnt/system/raw/mts/curved_layout_engines/`, вызываются подпроцессом-воркером (`engines/workers/`), обмен через PNG и JSON |
| `stages.py` | **отладочные оверлеи по этапам** построения оси: бинаризация → маска глифов → смыкание RLSA → кандидаты → запреты сцепки → цепочки обоих проходов → поле хода строк и выпрямленные ординаты → центр-линия в два прохода → пересборка и сглаживание → ряды → итог. Ничего не считает сам, только показывает промежуточные значения рабочих функций: `python -m ocr_utils.curved_layout stages --pdf … --page …`. Разбор по этапам — `reports/curved_layout_axis_stages.md` |
| `overlay.py`, `report.py`, `cli.py` | оверлеи, JSON/CSV/сводка, командная строка |

## Граница блока и её дилатация

Кромка по краске идёт вплотную к самым дальним символам, поэтому она заметно «зубчатее» осей
строк: выносные элементы («р», «д») и прописные торчат наружу. Рядом с ней строится вторая
кривая — `envelope.polygon_dilated`: исходный контур растеризуется и раздувается ЭЛЛИПТИЧЕСКИМ
ядром на `--dilate-glyphs` (умолчание 0.5) от среднего размера символа блока, после чего контур
снимается заново. Впадины уже двух радиусов при этом заполняются, и граница становится ровнее, а
не только шире. Исходный `polygon` не меняется, меры выключки по-прежнему считаются от `core_*`.

Средний размер символа блока — медианы ширины и высоты компонент краски от 0.8 до 7 мм по рядам
(`blocks.glyph_metrics`); если глифов не набралось, он оценивается от высоты ряда.

Оверлей `--dilate-compare "0.5,1.0"` рисует поверх исходной границы ещё две — на полсимвола и на
символ — с легендой: так видно, что даёт дилатация.

## Настройки, которые стоит крутить

* `--smooth-block` — окно огибающей в **межстрочных интервалах** (умолчание 2.5; пользователь просил 2–3).
  В окно всегда берётся не меньше `MIN_TREND_ROWS = 5` рядов: по двум-трём кромку не провести.
* `--coarse-factor` — во сколько раз шире окно «крупной» огибающей, с которой сравнивается основная
  (мера `envelope_dev_mm` — насколько блок ведёт себя иначе на мелком масштабе).
* `--smooth-line` — окно сглаживания оси строки в долях высоты строки (умолчание 0.6).
* Пороги выключки — `alignment.ALIGN_TOL_MM` (0.8 мм), `CORE_SHARE` (0.8), `INDENT_MIN_MM` (2.5 мм).

## Что важно про кривую бумагу

Зона вёрстки — служебное понятие: горизонтальная полоса, внутри которой постоянно ЧИСЛО колонок.
Границей блока она не является. Все решения о принадлежности строки колонке принимаются по
межколоннику-ЛОМАНОЙ на высоте самой строки, а разрывы между блоками меряются вдоль наклона
(`blocks.row_gap`: ординаты осей берутся в общей точке по x). По той же причине оси сливаются в
ряд не по медианам ординат (`LineAxis.cy`), а в ТОЧКЕ ВСТРЕЧИ: каждая ось продолжается от своего
ближнего конца с собственным наклоном (`blocks._same_row`). Сравнение медиан на перекосе давало
«половинки»: левая и правая половины одной строки стоят на разной высоте (1973/11 с.79 — 11 px
при шаге 20), в один ряд не сливались, и колонку резало пополам правило «слабое перекрытие по x»
— это и были рваные границы блоков. Поэтому на трапеции блок не цепляет
номер полосы, уехавший под него, и не рвётся там, где строки просто наклонены.

## Как делятся блоки

Блок — колонка целиком, но внутри колонки он рвётся, если:

* вертикальный разрыв вдоль наклона больше `BLOCK_GAP_PITCHES` (2.5) межстрочных интервалов;
* медианный кегль по четырём рядам с одной стороны границы отличается от другой стороны больше
  чем в `HEIGHT_BREAK_RATIO` (1.6) раза — заголовок над корпусом, подпись автора под ним;
* между рядами идёт сплошная черта (`segment.rules_of`) — разделитель сноски;
* соседние ряды почти не перекрываются по x (`MIN_ROW_OVERLAP` 0.35) — логотип рубрики слева и
  заголовок заметки справа под ним не один блок, хотя и стоят подряд.

Обратные ходы: куски одной колонки из соседних зон склеиваются (`_merge_pieces`), а хвост широкой
вводки, уместившийся в одну колонку, возвращается в неё (`_absorb_continuation`, не больше двух
строк, с тем же шагом, кеглем и левым краем).

## Два масштаба сегментации

Строки ищутся дважды: корпусным набором и крупным (заголовки, логотипы, подписи). Корпусному
масштабу остаются только строки не выше `BODY_HEIGHT_RATIO` (1.6) медианы страницы — заголовок он
собирает хуже (узкий допуск на перепад высот соседних слов) и рвал его посреди строки. Крупный
масштаб добавляет то, чего корпус не нашёл, и забирает корпусные обрывки внутри своих строк.

## Чего он пока не умеет

* Таблицы с отточиями разбираются как обычный блок: правая кромка идёт по концам отточий (1971/10 с.93).
* Рисунки и растр не исключаются — это делает `page_layout`, и при подключении к детектору его рамки
  надо передавать снаружи.
* Строки, потерянные сегментацией (жирный или разрядка), оставляют разрыв: блок может разделиться,
  хотя обрывки короче трёх рядов приклеиваются обратно.
* Разделитель сноски, который на рендере распался на куски, не находится, и сноска остаётся в
  блоке колонки (1973/08 с.85). Целую черту — прямую или волнистую — детектор берёт.
* Таблица с отточиями разбирается правильно (точки входят и в строку, и в блок), но правая кромка
  блока идёт по концам отточий — то есть по графе чисел, а не по тексту.
* Строка, набранная ВРАЗРЯДКУ и с широкими пробелами (сноска «М а р к с К. и Энгельс Ф. Соч.,
  т. 25,» — 1973/08 с.85), распадается на куски: пробел между словами там 12.7 мм при высоте
  строки 3 мм, а поднять общий предел разрыва нельзя — на таблицах это склеивает графы
  (замер: 1971/10 с.93 — 13 блоков против 16 при пределе в 4.5 высоты).
* Шапка статьи из логотипа, заголовка и подзаголовка с разными интервалами может остаться одним
  блоком с пустотами внутри, если кегли близки (1973/11 с.79).
