# Обзор алгоритмов: осевые кривые строк и границы текстовых блоков

Поиск сделан 2026-09-23 под задачу подпакета. Разбор блоков классикой (RLSA/ARLSA, XY-cut, Docstrum,
area Voronoi, Breuel whitespace, Tesseract tabfind, alpha-shape, морфозакрытие, snakes) уже разобран в
`research/geometry_regression/literature/blocks_and_edges.md` — здесь только то, что добавилось.

## Осевые кривые строк

| Подход | Суть | Что взяли |
|---|---|---|
| **Ridges based curled textline detection** (Bukhari, Shafait, Breuel, 2009) | банк согласованных фильтров сглаживает строку в «хребет», детекция хребтов даёт ЦЕНТРАЛЬНУЮ линию кривой строки | идея, что ось строки — именно центральная линия, а не базовая; у нас та же величина берётся дешевле — центром масс краски по столбцам |
| **Coupled snakelets** (Bukhari и др., IJDAR 2011) | пара активных контуров (x-line и baseline) трассируется по соседним компонентам | отвергнуто: параметры снейков не привязываются к кеглю, а у нас печатный текст и сегментация уже работает |
| **Seam carving для строк** (Saabni, El-Sana; Arvanitopoulos) | энергия по знаковому расстоянию, «медиальный шов» проходит по середине строки, разделяющие швы дают верх и низ | резерв на случай слипшихся строк: у нас они пока редки |
| **ocropus-gpageseg** | производная гауссиана по y + горизонтальное размытие; масштаб — медиана размеров компонент | подтверждает наш выбор масштаба (высота строки как единица всех окон) |
| **Tesseract `textord`** (Ray Smith, 2007) | базовая линия подгоняется КВАДРАТИЧНЫМ СПЛАЙНОМ по наиболее населённому разбиению блобов | подтверждает: одной параболы на строку мало, нужна кусочная модель; у нас — сглаженная ломаная с шагом 1 мм |
| **kraken `blla`** + `calculate_polygonal_environment` | нейросеть даёт базовые линии, полигон строки строится по серединам до соседних строк | берём как чужой движок для сравнения (адаптер) |
| **PERO** (Kodym, Hradiš, 2021), **eynollah** (SBB), P2PaLA, dhSegment, Laypa | совместно предсказывают базовые линии, полигоны строк и блоки | берём как чужие движки для сравнения |

## Границы блоков

* **Breuel, maximal empty rectangles** — межколонник как «препятствие» для сборки строк. У нас та же
  мысль в дешёвой форме: межколонники ищутся до сегментации и запрещают сшивать куски строки.
* **Area Voronoi (Kise, 1998)** — неманхэттенские границы по расстояниям между компонентами. Дорого для
  наших плотных полос; оставлено в резерве.
* **Alpha-shape / concave hull** (`alphashape`, `shapely.concave_hull`) — замкнутый контур по точкам.
  Отвергнуто: контур получается «зубчатым» по краям строк, а пользователю нужна ГЛАДКАЯ кривая по телу
  блока, срезающая абзацные отступы.
* **Локальная регрессия (LOWESS)** — наш путь: кромка блока как робастный тренд краёв рядов с окном в
  межстрочных интервалах. Квантиль в скользящем окне (первая версия) прыгал, когда в окно попадало два
  ряда, поэтому окно берёт не меньше пяти рядов и веса трикубические.

## Выключка

Прямых работ по «определить выключку блока на кривой странице» в поиске не нашлось: в OCR выключка
обычно постулируется. Наша мера строится от огибающей (а не от вертикали), поэтому наклон и изгиб блока
на неё не влияют; абзацные отступы и короткие концы абзацев считаются отдельно как односторонние выбросы.
