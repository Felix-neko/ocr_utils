# `background_smoothing` — сглаживание фона сканов перед бинаризацией в FineReader

Подготовка НЕбинаризованных сканов к бинаризации во внешнем OCR-движке: контент
остаётся нетронутым побитово, весь остальной кадр заменяется гладкой оценкой бумаги.

## Зачем

Сканы после ScanTailor отдаются в FineReader намеренно в оттенках серого — полутона
на границах букв помогают распознаванию, и бинаризовать заранее невыгодно. Но
FineReader бинаризует локально-адаптивным порогом, и на пустом поле он цепляется за
две вещи:

* **просвет текста с оборота листа** (bleed-through / show-through);
* **неровный тон бумаги** — зерно, разводы, остаточная неравномерность освещения.

Обе вещи глобально светлые, но локально контрастные: в окне чистого поля со средним
250 провал до 240 даёт адаптивному порогу достаточно контраста, и пиксель уходит в
чёрное. Результат — «перец» там, где на странице не было ничего.

Замеры по паку `МТС/Готовое/1966/03` (600 dpi, 98 файлов):

| величина | значение |
|---|---|
| уровень бумаги | 250–253 |
| просвет с оборота | 219–250 (медиана 247), до 4.65% площади кадра |
| ядро настоящих букв | ниже 200 |
| порог Оцу | 146–152 |

Ключевое наблюдение: между призраком (≥219) и настоящими чернилами (≤200) есть
чистый зазор. Именно он делает задачу разрешимой.

## Идея

Грубо найти тёмный контент, защитить его маской с солидным припуском, а всё
остальное заменить сильно размытым фоном. Локальная фактура (и призрак, и зерно)
усредняется в ровное поле; буквы со всеми полутонами доходят до FineReader
нетронутыми — под маской результат **побитово равен исходнику**.

```
I_source ──┬─► M_primary ──► M_dilated ──┬─────────────────► compose ──► I_final
           │                             │                      ▲
           └─────────────────────────────┴─► normalized blur ───┘
```

## Алгоритмы

### 1. Защитная маска контента

Самая содержательная часть, поэтому подробно и с правильными названиями.

Маска строится в два приёма: **консервативная (over-inclusive) маска чернил** и
**морфологический защитный поясок** вокруг неё.

#### 1.1. Первичная маска `M_primary`

**Ветка `otsu` (по умолчанию).** Базовый метод — **метод Оцу** (Otsu, 1979):
глобальный порог по гистограмме, максимизирующий межклассовую дисперсию. Но чистый
Оцу нам не нужен, нужен **смещённый в сторону фона порог**:

```
t_otsu = Otsu(gray)
paper  = median(gray[gray > t_otsu])          # уровень бумаги, из самой картинки
T      = t_otsu + bias · (paper − t_otsu)     # bias = --threshold-bias, дефолт 0.5
M_primary = gray ≤ T
```

Порог целиком вычисляется из поданного кадра, без привязки к конкретному паку.
Смещение — сознательная **асимметрия ошибок**: ложноположительный пиксель маски
стоит нам лишь того, что кусочек фона не будет сглажен, а ложноотрицательный —
размывания настоящего контента. Отсюда правило «порог подальше от чернил, поближе к
белому».

Сравнение **нестрогое** (`≤`) — как в самом OpenCV, где Оцу относит к фону строго
более светлое. На строго бимодальном кадре порог садится ровно на уровень чернил, и
строгое `<` потеряло бы их целиком (этот случай поймал тест).

Почему щедрость безопасна — замер на IMG_0130_1L:

| bias | T | маска, % кадра | из них призрака, % кадра |
|---|---|---|---|
| 0.0 | 146 | 12.6 | 0.00 |
| 0.5 | 199 | 15.2 | 0.00 |
| 0.7 | 220 | 16.7 | 0.00 |

Призрак не затягивается даже при 0.7: 99.9% его пикселей лежат выше 226. Поэтому
двухпороговая схема с распространением по связности (**hysteresis thresholding**,
как в детекторе Кэнни) здесь **не нужна** — она решала бы несуществующую проблему.
Это стоит подчеркнуть, потому что структурно она напрашивается первой.

**Ветка `sauvola`.** **Метод Саволы** (Sauvola & Pietikäinen, 2000), развитие
**метода Ниблэка** (Niblack, 1986) — локальный адаптивный порог:

```
T(x,y) = m(x,y) · (1 + k · (s(x,y)/R − 1)),   R = 128
```

`m` и `s` — локальные среднее и СКО в окне. Считаются через **интегральные
изображения** (у нас — `cv2.boxFilter` по бегущим суммам, стоимость O(1) на пиксель
независимо от размера окна). Это стандартный приём из **Shafait, Keysers & Breuel,
«Efficient implementation of local adaptive thresholding techniques using integral
images» (2008)**; `skimage.filters.threshold_sauvola` делает то же самое, но в
float64, что на кадре в 21 Мп даёт ~170 МБ на каждый промежуточный массив.

Локальная маска **объединяется** с глобальной, а не пересекается:

```
M_primary = (gray ≤ T_global) ∪ (gray ≤ T_sauvola)
```

Это **гибридная глобально-локальная бинаризация**. Объединение, а не пересечение —
принципиально, и это второй дефект, который поймали тесты: внутри толстого штриха
локальное СКО близко к нулю, порог Саволы вырождается в `m·(1 − k)` и уходит **ниже
самих чернил**, так что пересечение выгрызало бы в буквах дыры. А смысл локального
порога ровно в том, чтобы *добирать* контент, который глобальный порог пропустил, —
то есть пиксели светлее `T_global`.

#### 1.2. Защитный поясок: `M_dilated`

```
M_dilated = M_primary ⊕ B_r,    r ≈ 15 px при 600 dpi
```

Это **морфологическая дилатация диском** — она же **сумма Минковского** множества с
диском радиуса `r`. Результат — **r-окрестность** множества (в выпуклой геометрии:
*параллельное тело*, outer parallel body). В прикладных областях у той же операции
свои имена: *buffer* в ГИС, *offset* в CAD, *bloat/sizing* в фотошаблонах, а сама
идея запаса — **guard band**, защитный поясок.

Зачем он: под защиту должны попасть полутона на границах букв, бледные перемычки и
тонкие переходы — то, что FineReader использует при распознавании и что маска по
порогу неизбежно срезает. Радиус ≈ половина средней буквы (ядро ≈30×30 при 600 dpi);
берётся как доля длинной стороны кадра, чтобы масштабироваться с DPI.

**Реализация — через преобразование расстояния**, а не структурным элементом
(`dilate_disk` из `scan_cropping/morphology.py`). Работает тождество: дилатация
диском радиуса `r` = множество точек, у которых евклидово расстояние до маски не
больше `r`, то есть **подуровневое множество EDT** (Euclidean distance transform).
Стоимость O(пикселей) и **не зависит от радиуса**, тогда как `cv2.dilate` с
`MORPH_ELLIPSE` стоит O(пиксели × площадь ядра).

По структуре тройка «`M_primary` / кольцо припуска / остальное» — это в точности
**тримап** из терминологии матирования (definite foreground / unknown / definite
background), только «неизвестную» зону мы целиком трактуем как передний план.

### 2. Оценка фона: нормированная свёртка

Наивное `blur(I_source)` не годится — в окно размытия попадают чернила соседних
строк, и фон проседает. Вместо этого пиксели защитной маски исключаются **из самого
усреднения** (а не зануляются — от зануления фон просел бы ещё сильнее), и сумма
делится на фактически набранный в окне вес:

```
I_blurred = blur(I · W) / blur(W),    W = 1 вне M_dilated, 0 внутри
```

Это **нормированная свёртка** (normalized convolution, **Knutsson & Westin, 1993**),
она же *normalized averaging*, *masked/weighted blur*; в статистике — **оценка
Надарая–Уотсона** (ядерная регрессия) с прямоугольным ядром.

В терминах обработки документов весь шаг называется **оценкой фоновой поверхности с
маскированием переднего плана** (background surface estimation). Ближайший
именованный аналог — второй шаг алгоритма **Gatos, Pratikakis & Perantonis,
«Adaptive degraded document image binarization» (2004/2006)**: грубая бинаризация
даёт маску текста, затем фон считается взвешенным средним по окну с исключением
текстовых пикселей. Оператор тот же. **Отличие в сборке:** Гатос оценивает фон *под*
текстом, чтобы потом бинаризовать по разности `B − I`; мы подменяем фон *вне* текста,
под маской оставляем исходник и не бинаризуем вовсе.

Замер на IMG_0130_1L (радиус размытия 60 px, припуск 15 px, бумага 253):

| способ | фон вне маски | скачок яркости на шве маски |
|---|---|---|
| `blur(I_source)` (`--blur-mode plain`) | 168–190 | 18.3 сред. / 63.2 p95 |
| нормированное (`masked`) | 241–253, медиана 253 | **0.7 сред. / 2.7 p95** |

Наивный вариант даёт тёмные полосы между строками и чёрную обводку по контуру маски
— ровно тот перец, ради которого всё затевалось. Режим `plain` оставлен в CLI только
для того, чтобы эту разницу можно было воспроизвести.

**Про деление на ноль.** Его не бывает там, где результат используется: пиксель вне
`M_dilated` всегда даёт вес сам себе в собственном окне, поэтому знаменатель там
строго положителен. Ноль возможен только внутри `M_dilated`, где значение всё равно
отбрасывается композицией; туда пишется 0 — чисто предохранитель от NaN.

Размытие — **три прохода box-фильтра** (приближение гауссианы по центральной
предельной теореме), а не `cv2.GaussianBlur`: box разделим и стоит O(1) на пиксель
независимо от радиуса. Радиус = `--blur-mult` × радиус припуска, по умолчанию ×4.

Если однажды понадобится радиус сильно больше — в плотном тексте опора в окне падала
до 0.6% его площади. Стандартное лекарство для больших «дыр» — **push-pull**,
пирамидальная нормированная интерполяция (**Gortler et al., The Lumigraph, 1996**).
Сейчас она не нужна.

### 3. Композиция

```
I_final = M_dilated ? I_source : I_blurred
```

Жёсткое **альфа-композитирование с бинарной маской**. Под маской — исходник побитово
(проверяется тестом `np.array_equal`).

### 4. Кадры-исключения

Два случая, когда кадр трогать нельзя. Оба кончаются **копированием на выход без
изменений** — не пропуском файла, иначе в паке осталась бы дыра.

**`has_content()` — вырожденный Оцу.** Оцу делит гистограмму надвое всегда, даже
когда делить нечего: на чистом листе он режет собственное зерно бумаги и помечает
контентом половину кадра, а результат выходит пятнистым. Признак — разрыв между
медианами двух классов меньше 40 уровней (у текста он больше 200). Это дешёвый
**прокси теста бимодальности**; канонической величиной здесь была бы **мера
разделимости Оцу** η = σ²_B/σ²_T, определённая в той же статье 1979 года.

**`has_halftone()` — растровые полосы.** Обложки и полутоновые вкладки сглаживать
нельзя: их зерно — это само изображение, и размытие вне защитной маски выедает его
островами (проверено на обложке IMG_0104_2R). Признак — **крупные сплошные области
средних тонов**: маска `100 < I < 225` подвергается **морфологическому размыканию**
ядром 15×15 на копии, уменьшенной вчетверо. Размыкание удаляет структуры мельче
структурного элемента — это базовый приём **гранулометрии** (Matheron); у текста
серое сидит тонкой каймой по краям букв и вычищается целиком, у растровой печати
пятна остаются.

Разделение на реальных данных (1966/03, 98 файлов):

| | доля растра |
|---|---|
| 96 текстовых страниц | **0.00000** (и max, и среднее) |
| IMG_0104_2R (обложка) | 0.0495 |
| IMG_0104_1L (задняя обложка) | 0.1012 |

Порог 0.01 лежит посреди пустого промежутка.

### Чем это не является

Чтобы не путать при поиске литературы:

* не **rolling ball** (Sternberg, 1983) — там фон оценивается морфологически,
  структурным элементом, без маски переднего плана;
* не **flat-field correction** — там делят на поле освещённости, а не подменяют
  область; фон здесь не приводится к константе;
* не **inpainting**, хотя нормированная свёртка используется и как дешёвый
  инпейнтинг: у нас «дыра» не заполняется, а наоборот сохраняется;
* не **unsharp masking** и не билатеральный фильтр — разделение по маске, а не по
  локальному контрасту;
* не **бинаризация**: на выходе те же оттенки серого, бинаризует потом FineReader.

## Результаты

Симуляция локально-адаптивной бинаризации (`cv2.adaptiveThreshold`, окно 51, C=12),
доля чёрного в зонах чистого поля:

| файл | перец до | после | контент побитово цел |
|---|---|---|---|
| IMG_0111_2R | 0.1353% | 0.0371% | 100.00% |
| IMG_0112_2R | 0.2259% | 0.0277% | 100.00% |
| IMG_0117_2R | 0.2425% | 0.0308% | 100.00% |
| IMG_0130_1L | 0.0758% | 0.0284% | 100.00% |

На IMG_0117_2R в подменённой зоне (52.7% кадра) после бинаризации: исходник 0.2330%
чёрного, `masked` — **0.0000%**, `plain` — 4.2323%. Зона сильного просвета: было
219–255 (std 4.0), стало 247–251 (std 1.0).

Скорость — около 5 с на кадр 3452×6096 (маска 0.2 с, дилатация 0.13 с, размытие
2.0 с, композиция 0.17 с, оверлей 1.1 с). Однопоточно.

## Debug-оверлей

При `--debug-dir` рядом кладётся JPEG: **исходный кадр** с полупрозрачной заливкой
масок — жёлтая `M_dilated` (что не размывается), красная `M_primary` (найденный
контент) поверх неё. Результат размытия в оверлей не подмешивается, иначе не отличить,
где фон сгладился, а где просто не было контента. Оверлей пишется и для кадров,
оставленных без обработки: пустой оверлей — тоже ответ.

Что смотреть: `M_primary` должна лежать ровно по буквам, `M_dilated` — накрывать их с
запасом, но не сливаться в сплошное поле на всю страницу.

## Вызов из shell

Минимальный запуск — только вход и выход:

```bash
uv run python -m ocr_utils.background_smoothing \
    --input-dir "/mnt/dump3/.../МТС/Готовое/1966/03" \
    --output-dir /mnt/SYSTEM/pack1/background_blurred
```

Боевой прогон целого пака с оверлеями и таймингами (`--recursive` включён по
умолчанию, структура подкаталогов зеркалится в выход):

```bash
uv run python -m ocr_utils.background_smoothing \
    --input-dir "/mnt/dump3/.../МТС/Готовое" \
    --output-dir /mnt/SYSTEM/pack1_background_blurring/background_blurred \
    --debug-dir  /mnt/SYSTEM/pack1_background_blurring/debug \
    --output-format tiff \
    --log-level INFO
```

Готовый скрипт с этими параметрами — `run_background_smoothing_mts_gotovoe.sh` в
корне репозитория.

Подобрать параметры на одной странице, ничего не пропуская из-за уже готовых файлов:

```bash
uv run python -m ocr_utils.background_smoothing \
    --input-dir ./one_page --output-dir ./out --debug-dir ./dbg \
    --no-skip-if-exists --threshold-bias 0.7 --dilate-px 20 --blur-mult 6
```

Локальный порог вместо глобального (полезно, если освещение внутри страницы гуляет):

```bash
uv run python -m ocr_utils.background_smoothing \
    --input-dir ./in --output-dir ./out \
    --method sauvola --sauvola-k 0.15 --sauvola-window 121
```

Серый 8-битный выход в PNG — втрое меньше файл, для текста и line art цвет ничего
не несёт:

```bash
uv run python -m ocr_utils.background_smoothing \
    --input-dir ./in --output-dir ./out --gray --output-format png
```

Воспроизвести разницу с наивным размытием (ожидаемо хуже исходника — см. выше):

```bash
uv run python -m ocr_utils.background_smoothing \
    --input-dir ./in --output-dir ./out_plain --blur-mode plain
```

Только верхний уровень каталога, без подпапок:

```bash
uv run python -m ocr_utils.background_smoothing \
    --input-dir ./in --output-dir ./out --no-recursive
```

## Параметры

| опция | дефолт | смысл |
|---|---|---|
| `--input-dir` | required | папка с исходниками |
| `--output-dir` | required | папка результата, относительные пути сохраняются |
| `--debug-dir` | нет | оверлеи; не задана — не рисуются |
| `--output-format` | как у входа | `tif` / `tiff` / `png` / `jpg` / `jpeg` |
| `--recursive/--no-recursive` | `--recursive` | обходить подкаталоги |
| `--skip-if-exists/--no-skip-if-exists` | `--skip-if-exists` | не переделывать готовое |
| `--gray/--color` | `--color` | одноканальный выход |
| `--method` | `otsu` | `otsu` / `sauvola` |
| `--threshold-bias` | 0.5 | сдвиг порога от Оцу к бумаге, 0..1; больше — маска щедрее |
| `--sauvola-k` | 0.10 | меньше — порог ближе к локальному среднему, маска щедрее |
| `--sauvola-window` | из размера кадра | окно Саволы, px (≈101 при 600 dpi) |
| `--dilate-px` | из размера кадра | радиус защитного пояска, px (≈15 при 600 dpi) |
| `--blur-mult` | 4.0 | радиус размытия = множитель × радиус пояска |
| `--blur-mode` | `masked` | `masked` — нормированное; `plain` — наивное, для сравнения |
| `--log-level` | `WARNING` | `INFO` показывает тайминги шагов |

Что крутить в первую очередь, если результат не устроил:

* **буквы теряют полутона по краям** — поднять `--dilate-px`;
* **перец остался** — поднять `--blur-mult` (шире окно усреднения) либо опустить
  `--threshold-bias` (маска уже, размывается больше);
* **под защиту попадает просвет с оборота** — опустить `--threshold-bias`;
* **фон между строками выглядит пятнистым** — убедиться, что `--blur-mode masked`.

DPI переносится из исходного файла: `cv2.imwrite` тег разрешения не пишет вовсе, и
скан 600 dpi без тега читается OCR-движком как страница в 96 dpi. Запись идёт через
`write_image` / `read_dpi` из `scan_cropping/image_io.py`.

## Раскладка

| файл | содержимое |
|---|---|
| `processing.py` | весь расчёт по кадру: пороги, маска, дилатация, размытие, композиция |
| `pipeline.py` | `SmoothParams`, обход пачки, ввод-вывод, debug-оверлей |
| `cli.py` | только click |

Переиспользуется: `dilate_disk` из `scan_cropping/morphology.py`, `collect_images` /
`imwrite_params` / `write_image` / `read_dpi` / `resolve_output_suffix` из
`scan_cropping/image_io.py`, `log_timing` из `ocr_utils/timing.py`.

Тесты — `tests/ocr_utils/background_smoothing/`: `test_processing.py` (маска и
размытие как чистые функции) и `test_pipeline.py` (сквозной проход по файлам через
`tmp_path`).

```bash
uv run pytest tests/ocr_utils/background_smoothing/
```
