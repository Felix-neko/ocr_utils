# scan_cropping/v2/gutter_decompression — растяжение сжатых у корешка букв

На туго сшитых подшивках страница у корешка уходит в изгиб, и последние буквы строки левой страницы (первые — правой)
сняты под углом: они сжаты по горизонтали. Выпрямление (Кунс + поле по тексту) это не снимает: у Кунса параметр вдоль
стороны — доля длины дуги на снимке, а поле только сдвигает стороны блоков. Подпакет меряет сжатие по ширине букв на
итоге выпрямления и растягивает зону текста у корешка, расширяя страницу.

Исследование, варианты и числа — стенд `research/gutter_compression` (README) и `reports/gutter_compression.md`.

## Где работает

`rectify/text_run.text_frame` после проходов поля по тексту, если `TextParams.gutter_decompression` (CLI v2:
`--gutter-decompression/--no-gutter-decompression`, по умолчанию включено, только с `--output-pages`):
- только у разворота: у кадра с одной страницей (`Layout.single`) корешка на холсте нет;
- страницы без поля (цветные, тонированные, игнорируемые флагом, `no-text-rectify-*`) не растягиваются;
- холст итога шире раскладки Кунса на `W_L + W_R` (`TextResult.canvas`); `TextResult.dense` ведёт в координаты холста
  Кунса, поэтому области страниц и линия разреза считаются по прежней раскладке (`pages.page_areas`, `cut_line`);
- последний разбор текста (`analyses[-1]`, меры итога) делается заново на расширенном холсте;
- поля сводки кадра `gutter_<L|R>_{applied, widen_mm, amp_max, length_mm, near_mm}` (JSON колонки текста);
- отладочный лист `10_gutter` (`--debug-steps`, только если растяжение применено): «было | стало» разворотом и тремя
  вырезками ×2 у корешка, в шапке — модели страниц.

## Как

1. **Буквы** (`letters.py`). Краска — темнее фона (серое закрытие 2.5 мм) в 0.62 раза. Строки — пики профиля букв
   по рядам холста (после поля строки горизонтальны). Буква — связная компонента пояса строки высотой 0.7–1.25
   строчной; её ширина делится на медиану букв той же строки дальше 25 мм от края у корешка (не меньше 12 таких букв).
   Узкие пятна (у́же 0.5 строчной) на конце строки со стороны корешка, отделённые от текста промежутком шире
   1.5 строчной, отбрасываются (`trim_stray`): обрывки линии складки уводили край строк к корешку (ХиП 1991/01
   IMG_0987 R: край в 0.15 мм вместо 4.7 мм, ложное растяжение 0.89 мм).
2. **Модель** (`model.py`): `c(d, y) = 1 − B(y)·exp(−max(d − e, 0)/L)`; `d` — расстояние от линии корешка, `e` —
   начало зоны текста (наименьшее по высоте), `B(y)` — P-сплайн по высоте (7 узлов, штраф 30) или линия:
   **переключается константой `HEIGHT_SHAPE`**.
3. **Подгонка** (`fit.py`): предсказание для буквы — гармоническое среднее `c` по её отрезку строки; остатки
   `log r − log r̂`, мягкая L1 (масштаб 0.12 — разброс одной буквы); длина спада 0.5–30 мм. Окна 5 мм стенда
   короткий спад не различали и перерастягивали край в 1.5 раза.
4. **План** (`widen.py`): поле у корешка тождественно; зона текста разжимается по модели; разная по высоте прибавка
   строки гасится общим масштабом строки `k(y)`; страница шире на `W` — медиану прибавки по высотам со строками.
   Обе выровненные стороны блока прямые.
5. **Порог** (`WidenLimits`): местное растяжение не больше 2.0; применяется, если лишняя длина в первых 10 мм зоны
   текста не меньше 0.5 мм, наибольшая амплитуда не меньше 0.04 и спад не у верхнего предела 30 мм.

## Числа (ХиП 1991, 30 кадров стенда)

- Сжатые стороны: применено 42 из 48, буквы в 3 мм у края 0.75 → 0.964 (норма конца строки без сжатия ~0.96),
  перерастянутых (> 1.1) нет, стороны блоков p95 0.13 мм (до 0.09).
- Контроль: на стенде срабатывало на 2 сторонах из 12 (08/IMG_0348 L 0.36 мм, 01/IMG_0987 R 0.85 мм); 01/IMG_0987 R
  снято отбрасыванием обрывков складки.
