# research/ragged_edges — рваный внешний край страницы

**Задача.** На фото-разворотах подшивок (ПХ 1975, пак-4; «Хозяйство и право» 1991; пак-6) маска SAM 3 внешней
(дальней) стороны страницы часто уходит языками на белые торцы нижних листов и на рваную бумагу обложки. Выравнивание
сторон v2 сглаживает такой край, но сторона остаётся не на месте. Стенд мерит рваность по шагам сегментации, собирает
листы по поясам меры на разметку, калибрует порог детектора и сравнивает два прогона v2.

Ядро — в боевом коде `ocr_utils/scan_cropping/v2`:
- `ragged_edge.py` — детектор: извилистость сырой маски SAM 3 стороны (`RAGGED_TORTUOSITY = 1.05`, `--ragged-threshold`);
- `edge_zones.py` — двойная грубая сегментация (`--dual-levels`, по умолчанию с 2026-10-24) и добавка у верха и низа
  (`--levels-edges`);
- `edge_refine.py` — тонкое уточнение рваной стороны (`--refine-ragged`, по умолчанию выключено).

Предшественник — черновики `ai_slop/stack_edges/{ragged,refine}.py` (мера по 3192 сторонам, отбор способов уточнения).

## Как устроено

- **Мера** (`ragged_edge.py`, `features.py`). Извилистость — длина контура маски, сглаженного окном 1 мм, к длине
  сглаживающего сплайна стороны на том же участке; концы стороны (по 5 %) и пропуски покрытия длиннее 2 мм не идут в меру.
  Справочные: p90 отклонения от сплайна, доля длины с отклонением больше 1 мм, выбросы на 100 мм, наибольший язык
  наружу и выемка внутрь. Мерится сырая маска SAM 3: итоговая бумага после выравнивания сторон даёт 1.01 и на рваном
  крае.
- **Двойная сегментация** (`edge_zones.py`). База — SAM 3 по кадру как есть; в зонах у внешних кромок книги (5 мм
  наружу, 30 мм внутрь от прямых края грубой маски книги) — проход по кадру с растянутой светлотой. Зона или кадр
  остаются на базе, если там нет страниц, мало бумаги или экземпляр не сопоставлен со страницей базы; кадры с одной
  страницей и обложки — целиком по базе (растяжение на них даёт ямы у корешка, 12/IMG_0085 — 0 страниц).
- **Уточнение** (`edge_refine.py`). Лента вдоль стороны трапеции 18 мм наружу и 25 мм внутрь в полном разрешении,
  куски по 50 мм с перекрытием 12 мм. Сокращённый набор способов: SAM 3 со сжатием куска по вертикали ×4, SAM 2.1 ×4 с
  растяжением по L, SAM 3 без сжатия, SAM 2.1 ×4; при неудаче — полный (плюс SAM 3 ×4 с растяжением, SAM 2.1 без сжатия,
  CLAHE у обеих сетей). Способ годен при покрытии ≥ 90 % длины, рваности ≤ 0.3 мм, ступени ≤ 1 мм и без знаков своей печати за
  краем (не ближе 3 мм внутрь от стороны); из годных берётся согласный с остальными, при равенстве — ближний к
  странице, то есть край верхнего листа (решение пользователя 2026-10-22). Строки «под пальцем» (ядро пальца в ±3 мм от
  грубого края) края не ищут, пропуск — прямая между опорами. Итог стороны и меры способов — `refine.json` кадра.

## Команды

```bash
uv run python -m research.ragged_edges features --run ИМЯ=КЭШ … --out features.csv   # меры сторон по шагам → CSV
uv run python -m research.ragged_edges sheets --csv features.csv --out DIR [--measure raw_tortuosity --belts …]
uv run python -m research.ragged_edges evaluate --csv features.csv --labels sets/….txt   # точность / полнота по порогам
uv run python -m research.ragged_edges copy-cache --src КЭШ --dst КЭШ_НОВЫЙ [--keep sam3.npz]
uv run python -m research.ragged_edges compare --old ИТОГ_1 --new ИТОГ_2 --name НАБОР --out DIR
run_scripts/scan_cropping/run_v2_ragged_edges.sh      # прогон 1: три набора, порог 1.02
run_scripts/scan_cropping/run_v2_ragged_edges_v2.sh   # перепрогон после правок 2026-10-23, кэш SAM 3 из прогона 1
```

Пояса листов по умолчанию: 1.00 / 1.02 / 1.03 / 1.05 / 1.07 / 1.10 / 1.20. `copy-cache` копирует кэш без шагов,
которые новый прогон считает заново (двойная сегментация, детектор, уточнение, страницы, surya, финал), так что база
для сравнения не трогается.

## Итоги

**Мера** (черновик, 2026-10-22, 3192 стороны):

| | сторон | медиана | p90 | p99 | > 1.04 | > 1.08 |
|---|---|---|---|---|---|---|
| ПХ 1975 | 2048 | 1.009 | 1.033 | 1.094 | 6.7 % | 1.7 % |
| ХиП 1991 | 362 | 1.007 | 1.036 | 1.148 | 8.0 % | 1.9 % |
| пак-6 | 782 | 1.006 | 1.047 | 1.328 | 12 % | 6.1 % |

Глазами по 12 сторон на пояс: до 1.02 ровно, 1.02–1.03 в основном ровно (рябь 1–2 px), 1.03–1.05 — примерно половина
с выступами на торцы, 1.05–1.08 почти все рваные, выше 1.08 — все. p90 отклонения связан с извилистостью слабо
(корреляция 0.63) и ловит плавную волну. Рваные стороны пользователя — 1.07–1.58, ровные — 1.000–1.014.

**Двойная сегментация.** Сырой SAM 3 ≥ 1.05: 164 → 119 сторон из 211 тестового набора; на 120 случайных кадрах вне
набора — 58 → 42 из 240, ни одна страница не пропала. Ямы у корешка не лечит (растянутый проход — только у внешних
кромок; у верха и низа у корешка — `--levels-edges`).

**Пробный прогон** (12 кадров ПХ, `smoke/`): выправлено 8 из 9 рваных сторон (01/IMG_0029, 0035, 0046, 03/IMG_0058,
05/IMG_0037, 0038, 09/IMG_0022 — обе, 0040), извилистость 1.05–1.19 → 1.00–1.009; ровные почти не изменились;
мраморный форзац 08/IMG_0080 L — ни один способ не прошёл. После двойной сегментации рваные 01/IMG_0031 L и 0035 L
опускаются до 1.020 и 1.037 — поэтому в прогонах порог 1.02, а не 1.05.

**Прогоны** (порог 1.02, ключи пака-6 + `--finger-shadow`):

| | кадров | сторон | рваных (≥ 1.02) | уточнено, прогон 1 | уточнено, перепрогон |
|---|---|---|---|---|---|
| тестовый набор | 213 | 426 | 204 | 183 | 182 |
| ХиП 1991 | 966 | 1912 | 610 | 552 | 551 |
| ПХ 1975 | 1027 | 2048 | 663 | 590 | 587 |

«Уточнено» — у стороны принят способ (`refine.json`, поле `chosen`); чаще всего `sam3_sq4`, затем `sam2_sq4_lvL`,
`sam2_sq4`, `sam3_sq1`; полный набор понадобился на 15 / 36 / 44 сторонах. Прогон 1 (2026-10-22 16:18 → 10-23 04:04) —
11 ч 46 мин, ~19 с на кадр: упор в CPU-часть закраса пальцев в главном процессе, GPU простаивал. Перепрогон
(05:01 → 10:30) — 5 ч 28 мин: SAM 3 из кэша прогона 1, закрас пальцев в 3 потоках (`--finger-threads`, 17.1 → 12.9 с на
кадр на проверке 24 кадров, 21 кадр байт в байт). Traceback 0, `no_paper` — у тех же 7 кадров ХиП в обоих прогонах.

Правки перед перепрогоном (2026-10-23):
- строки «под пальцем» — только где ядро пальца у грубого края (±3 мм). Раньше строка выбрасывалась, если ядро есть
  где угодно в ленте, и ладонь снаружи книги закрывала открытую кромку: ХиП 07/IMG_0133 R — 134 мм стороны вместо 38,
  SAM 3 работал на 44 % длины, прямая к короткой опоре у угла (−6.5 мм, торцы) шла через торцы по диагонали. После
  правки палец у края — 16 % стороны, уточнение не принято (у всех способов ступень 4–26 мм), сторона на грубой маске
  и она верна. Длинные прямые в прогоне 1 (по 891 уточнённой стороне на момент замера): ≥ 20 % длины — 48 сторон,
  ≥ 50 % — 4 (ХиП 07/IMG_0116 R, 0133 R, ПХ 03/IMG_0029 R, 0030 R);
- полоса-вклейка у корешка (`gutter_strip.py`): щель до связной части страницы, порог 8.2 мм (см. `research/gutter_strip`).

На ПХ тестового набора перепрогон заметно (> 20 мм²) изменил 7 сторон из 190, у корешка — ничего. Сводка
«прогон 1 → перепрогон» по ХиП и ПХ целиком не собиралась.

## Что пробовали и отвергли

- Пропуск под пальцем заполнять грубым краем с плавным швом вместо прямой — грубая маска огибает палец выемкой внутрь
  (ПХ 04/IMG_0042 L — 460 мм²); первый перепрогон остановлен на ПХ тестового набора, прямая возвращена.
- Мерить рваность по итоговой бумаге — выравнивание сторон сглаживает рваный край до 1.01.
- Защита от текста по выпуклой оболочке печати — её тянет к кромке посторонняя метка у края, отвергались все способы;
  теперь проверяются сами знаки.
- В уточнении: SAM 2.1 со сжатием иногда уходит внутрь на кромку текста (ХиП IMG_0286 L) — от этого защита печатью;
  CLAHE и растяжение трёх каналов хуже основных способов (стенд-черновик `ai_slop/stack_edges/refine.py`).
