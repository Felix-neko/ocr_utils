# research/article_problems — статьи о проблемах советских предприятий

Стенд отбирает статьи журнала «Материально-техническое снабжение» (пак-1, 1966–1976, 2880 статей),
в которых описаны проблемы в работе предприятий. Каждая статья целиком уходит одним запросом
в LLM через OpenRouter. Модель выписывает **все** случаи проблем с дословными цитатами и относит
каждый к классам ниже. Код проверяет цитаты по тексту и собирает листы по классам.

## Классы

| Класс | Что |
|---|---|
| 1 | Предприятие не может найти запчасти для своей техники (взгляд потребителя; только запчасти) |
| 2 | Производитель выпускает не то, что нужно потребителям (ассортимент, «вал», выгодное себе) |
| 2.1 | Производитель не делает запчасти или делает их явно мало |
| 3 | Прежняя модель снята, новая дороже сверх роста производительности |
| 4 | Непоставка заказанного (любой поставщик) |
| 5 | Несвоевременная поставка |
| 6 | Поставка брака и некондиции |
| 7 | Любые конкретные проблемы — объединение; код ставит его на каждый случай |
| 8 | Плохая работа подразделений Госснаба СССР (код ставит 8 и сам, если виновник — `gossnab_body`) |
| 9 | Советское оборудование намного дороже или хуже иностранного (явное сравнение) |
| 10 | Производитель отказывается выпускать продукцию из своего же ассортимента |
| 11 | Производитель не совершенствует продукцию и не переходит на новые модели, когда это уместно; вид случая в `improvement_kind`: `stagnation` (застой), `not_launched` (разработка готова к производству, но её не запускают), `barrier` (названа причина, мешающая совершенствовать). С промпта v4 |
| 12 | Производится продукция, которая никому не нужна (нет сбыта, залёживается, выпуск «для плана»). С промпта v4 |

Определения, границы и формат ответа — в `prompts/system_v{N}.md`. Действующая версия —
`PROMPT_VERSION` в `__init__.py`. Правка промпта означает новую версию, а старые файлы остаются:
по ним читаются старые ответы кэша.

## Модули

- `articles.py` — нарезка собранного выпуска по маркерам `<!-- article An -->` и `<!-- rubric Rn -->`,
  `Article` (год, выпуск, рубрика, заголовок, авторы, тело, строка начала в файле).
- `schema.py` — `ProblemClass`, `CulpritKind`, разбор JSON-ответа (`parse_answer`); здесь же правила
  «класс 7 на каждый случай» и «виновник из Госснаба → класс 8».
- `payload.py` — `Variant` (модель, `sync`/`batch`, рассуждения, версия промпта), тело запроса, ключ
  и папка кэша, прикидка цены.
- `run.py` — синхронный прогон пулом потоков с бюджетом; кэш — `external_ocr_services.cache`.
- `batch.py` — Batch API OpenRouter: пачки ≤ 500 запросов / 25 МБ, состояние каждой пачки в
  `batches/{id}.json`, сбор готовых ответов в тот же кэш. **Отмены у Batch API нет**: отправленная пачка
  доработает и будет оплачена.
- `quotes.py` — поиск цитаты в статье (нормализация, rapidfuzz ≥ 90), строка в файле выпуска.
- `report.py` — `results.jsonl`, `cases.csv` (строка на «случай × класс»), `by_class/class_*.md`,
  `summary.md`.

## Команды

```bash
# прикидка цены (без запросов)
uv run python -m research.article_problems estimate --issues 1968_09,1973_05
# синхронно (пилот, итерации промпта): ответ сразу, провайдер DeepSeek без квантования
uv run python -m research.article_problems run --articles 1968_09:A15 --reasoning low
uv run python -m research.article_problems check --articles 1968_09:A15 --reasoning low
# весь пак через Batch API (дешевле, до 24 ч) — run_scripts/article_problems/run_pack1.sh
uv run python -m research.article_problems batch-submit --all --reasoning low
uv run python -m research.article_problems batch-collect --wait
uv run python -m research.article_problems report --all --transport batch --reasoning low --tag pack1
# сравнение двух прогонов и экспорт статей по папкам классов (объединение моделей)
uv run python -m research.article_problems compare A/results.jsonl B/results.jsonl --names deepseek,space_bunny --out-dir …
uv run python -m research.article_problems export --run "DeepSeek V4.1 Flash=A/results.jsonl" \
    --run "Space Bunny Alpha=B/results.jsonl" --out-dir /mnt/hotstore/scan_processing/mts_markup/article_problems/export_pack1
```

Экспорт (`export.py`): папка на класс (`01_нет_запчастей` … `10_отказ_от_своего_ассортимента`),
файл на статью (`{год}_{выпуск}_{An}_{заголовок}.md`). Статья лежит в папке, если класс ей дала хоть одна
модель. Шапка файла: паспорт статьи, какие модели нашли, все классы статьи у каждой модели, резюме
«почему в классе» и случаи с цитатами от каждой нашедшей модели. Ниже — полный текст статьи.

Выход — `/mnt/hotstore/scan_processing/mts_markup/article_problems/`: `cache/{год}/{выпуск}/{An}/problems.v3.batch.low...`
(`request.json` и `response.json`, повтор бесплатен), `batches/`, `runs/{вариант}_{tag}/`.

Пример входа и выхода. Статья 1968_09:A15 «Причина неритмичности» — два письма под одним заголовком.
По ним получены случаи [4, 5, 8] (Калининская контора металлоизделий недопоставила прокат Ржевскому
заводу) и [1, 2, 2.1, 10] (Тбилисскому метро не дают запчастей, заводы предлагают целые узлы вместо
мелких деталей). У каждого случая есть цитата и ссылка `файл:строка`.
