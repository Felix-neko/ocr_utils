# research/photo_bounds — границы растровых фото на полосе

Стенд (только CPU, боевой код не меняется). Три задачи:

1. **Точная осевая рамка фото** — уточнение рамки растрового детектора `page_layout` (`raster/regions.py`: блок surya
   `Picture` ∪ растровые клетки, подрезка до бумаги не глубже блока) до края снимка.
2. **Чёткий край** — у фото с видимой границей «бумага → снимок» каждая сторона подгоняется кривой (многочлен 2-й
   степени по точкам края, робастно), стороны пересекаются в углах: **кривой четырёхугольник**. Фото без чёткой
   границы (виньетка, растворение в фон, светлый край без рамки) — класс `soft`/`partial`, у них только рамка.
3. **Стороны фото как опоры выпрямления** (`supports.py`): верх и низ — выборки `dy` как оси строк, боковые — `dx` как
   выровненные стороны блоков (формат `text_field.Samples`); область фото многоугольником (`PhotoRegion`) вместо
   рамки — для преград разбора и отсева выборок строк. Демонстрация — подменами `text_run` в процессе стенда
   (`rectify.py`), предложение для ядра — патч `/mnt/hotstore/scan_processing/photo_bounds/patches/photo_bounds_core.patch`.

Отчёт с числами — `reports/photo_bounds.md`.

## Данные

- Эталон — ручная разметка CVAT пака-1 МТС, `pack1_reviewed.sqlite` (открывается **только на чтение**, URI `mode=ro`,
  `data.open_readonly`; никаких `open_db`): `rect_regions` видов `grayscale`/`color` без `full_page`, областей почти во
  весь кадр (≥ 0.80) нет. **404 фото на 378 полосах.** Точность эталона — `divisor` = 8 px оригинала (0.34 мм), но
  отсмотр глазами (`sets/verify_sides.csv`, 120 сторон) показал, что рамка CVAT **шире снимка на ~1 мм в медиане**
  (p10 0.5, p90 1.7 мм): разметчик обводил с запасом. Поэтому промах «новая рамка против эталона» −1.2 мм — это не
  срез снимка; правду о тесноте говорят мера по светлому растру у сторон (`measure.band_cover`) и отсмотр.
- Кэш (`cache`): TIFF с Я.Диска читается один раз → `pages/<полоса>/gray300.png`, `bgr150.jpg`, `detector.json`
  (растр `PageLayout(Find.RASTER)` с блоками surya из `LAYOUT_CACHE_DIR`, как `scan_markup detect`).
- Разметка глазами — `sets/`: `photo_classes.csv` (класс каждого фото: `sharp`, `text_adjacent`, `soft`, `ruled`,
  `collage`, `color`, `not_photo`; пометки о грубом эталоне `ref_note`), `verify_sides.csv` (середины 120 сторон
  30 случайных фото: новая рамка на краю / лишнее / срез, насколько эталон шире снимка), `few_text.csv` (32 полосы с
  фото почти без текста — меньше 8 годных строк вне фото, как присланная ХиП 1991/04 IMG_0154).

## Метод (`bounds.py`, размеры — мм бумаги)

- **Карты окна** (затравка + 12 мм): тон — серый, размытый σ 0.35 мм (гасит растровую сетку 0.4–0.5 мм), разброс в
  окне 0.8 мм. Бумага — медиана светлой половины тонов кольца вокруг затравки; местные пороги светлого растра — по
  разбросу этой бумаги (пятнистая бумага 1968/11 иначе уходила в «снимок»).
- **Ядро снимка** — строгая маска (тон ниже бумаги на 30 или разброс > 12) → замыкание 0.5 мм → заливка дыр →
  размыкание 2.5 мм (строки текста выпадают) → компоненты, задевающие затравку, без тонких отростков
  (`robust_extent`: строки/столбцы с заполнением ≥ 0.25 медианы — тень у края листа, задетая буква), без «бумажных»
  (доля бумажного тона > 0.35 — текст); компоненты ближе 1.5 мм — одно фото. Две фотографии под одной рамкой
  детектора разделяются.
- **Рост** рамки ядра на светлые края снимка: сторона идёт наружу шагом 0.25 мм, пока полоска сплошь (≥ 0.7) светлый
  растр (тон ниже местной бумаги на ≥ 12 или разброс > 3).
- **Точки края** — профиль тона поперёк стороны (5 мм внутрь, 3 мм наружу, через 1 мм, усреднение 1 мм вдоль): самый
  внешний максимум производной «светлеет наружу», за которым бумага (окно 0.7–1.5 мм), ступенька ≥ 12, доводка
  параболой. **Подгонка** — Тейл–Сен для старта, IRLS Хьюбер 0.15 мм, отсев 0.6 мм, многочлен 2-й степени.
- **Чёткая сторона**: покрытие точками ≥ 0.6 длины, остаток p90 ≤ 0.3 мм, ширина перехода (ступенька / наибольшая
  производная) ≤ 1.4 мм. Все четыре чёткие → `sharp` и четырёхугольник; рамка по чёткой стороне — самая внешняя
  точка кривой. Нечёткая сторона глубже 2.5 мм внутри затравки возвращается на затравку (белое небо у края снимка).
- Меры (`measure.py`, `report.py`): IoU и промах сторон в мм против эталона (p50/p95, доля срезанных и лишних
  сторон > 1 мм), теснота без эталона (доля сторон, у которых снаружи растр — срез, внутри бумага — лишнее поле).

## Что пробовали и отвергли

- Слабые пороги «тонированного» сразу в маске (тон −12, разброс 3) — склеивали строки над снимком и подпись под
  ним: лишнее до 12 мм у 25 % сторон (прогон v2). Взяты два уровня: строгое ядро и рост по слабому.
- Ступенька по окну 0.3–1.0 мм от края — граница внутри хвоста размытой ступеньки; у резких краёв находилась треть
  точек (1970/01 IMG_0022_1L). Окно 0.7–1.5 мм и «бумага где-то в окне» (максимум, а не среднее).
- Контраст ступеньки как мера чёткости — светлый снимок с резким краем даёт 15–30 уровней; мера — ширина перехода.
- Охват компоненты целиком — тень у края листа поднимала рамку на заголовок (1975/08 IMG_0055_1L, +12 мм).
- Покрытие 0.7 / остаток 0.25 мм — 73 % чётких глазами признавались чёткими, низ ХиП 04/IMG_0154 прыгал от шума JPEG.
- Многочлен 3–4 степени — остаток у «нечётких по остатку» сторон почти не падает (0.38 → 0.38 мм у 1968/10
  IMG_0036_1L): там шум точек края (тёмный фон у края снимка), а не форма.

## Запуск

```bash
run_scripts/photo_bounds/run_pack1.sh        # набор, кэш, меры, листы, проверка глазами, строки выпрямления
run_scripts/photo_bounds/run_rectify_demo.sh # кадры выпрямления с фото: три варианта, листы
uv run python -m research.photo_bounds select|cache|run|sheets|verify|text-count|text-sheets|rectify-scan|rectify-demo|rectify-sheets
uv run pytest tests/research/photo_bounds -q
```

Выход — `/mnt/hotstore/scan_processing/photo_bounds/`: `run_v8/measures.csv` (строка на эталонное фото: IoU, промахи
сторон прежней и новой рамки, меры каждой стороны), `summary.csv`, `sharpness.csv`, `tightness.csv`, `text_count.csv`,
`sheets/{all,class,disagree,new_cut,new_spare,returned}/`, `verify/`; `rectify/demo/<набор>/<кадр>/` — итоги трёх
вариантов, `summary.json`, листы `sheet_photo*.jpg`, `sheet_supports.jpg`.
