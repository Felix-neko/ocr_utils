# Страницы, где коррекция геометрии FineReader сделала хуже

Ядро детектора (метрики, пороги, кэш) — `ocr_utils/geometry_regression`; здесь стенд. Зачем — в докстринге `ocr_utils/geometry_regression/__init__.py`. Коротко: два прогона FineReader по одним промежуточным PDF
(с коррекцией геометрии и без), детектор сравнивает одну и ту же страницу попарно и отдаёт
score «стало хуже» с причиной, а также картинки «было | стало» для проверки глазами.

## Команды

```bash
# весь пак, в фоне (≈ 40 мин на 16 воркерах); ждать по PID
setsid ./run_scripts/geometry_regression/run_pack1.sh > run.log 2>&1 < /dev/null & PID=$!
while kill -0 "$PID" 2>/dev/null; do sleep 30; done

# сводка + картинки по годам с порогами по умолчанию; любые пороги — без пересчёта
./run_scripts/geometry_regression/run_report.sh
./run_scripts/geometry_regression/run_report.sh --thr line_dev_max_delta_mm=1.2 --min-score 1.3

# регрессия на эталоне: вердикты прошлого прогона против текущего кода
uv run python -m ocr_utils.geometry_regression regress --geo-dir … --nogeo-dir … \
    --labels research/geometry_regression/validation/pack1 --old-dir …/pack1_v7 --md-report …

# проба на одном выпуске и нескольких страницах
uv run python -m ocr_utils.geometry_regression run --geo-dir … --nogeo-dir … --out-dir … \
    --only full_1967_01 --pages 38,80,85 --jobs 4
uv run python -m ocr_utils.geometry_regression report --out-dir … --list-thresholds
```

## Что лежит в выходе

* `run.json` — пути к PDF и параметры (размеры в мм), чтобы `report` не спрашивал их снова.
* `cache/<pdf>/pNNN.json` — метрики страницы, рамки-виновники (`culprits`) и сырьё поля
  смещений; повторный `run` берёт их без пересчёта (`--redo` — пересчитать).
* `metrics.csv` — все страницы, все метрики, score и причина по порогам в коде;
  `metrics_flagged.csv` — то же с порогами из `report --thr`.
* `report.md` — счётчики, пояса score, перцентили флаговых метрик по паку (для калибровки),
  флаги по годам, эталон с вердиктами, топ находок.
* `pairs/bad|mixed/<год>/full_ГГГГ_НН_pNNN_d2.31_g0.40_причина.jpg` — слева «было» (без коррекции),
  справа «стало», сетка через 1/12 по обеим осям, синим — виновник порчи: рамка строки или
  кромки, либо сами штрихи (все заметно ушедшие черты, отрезки группы параллельных); третья панель
  (`--arrows`) — поле смещений: стрелки — остаток после аффинной части ×5, квадраты — тайлы
  без пары (лиловый — содержимое тайла деформировано, серый — периодика).

## Как это устроено

Все размеры в коде заданы в миллиметрах бумаги и переводятся в пиксели по фактическому dpi
рендера (`mm_to_px`); рендер — 300 dpi (`line_fit` берёт центр-линии с копии 300 dpi),
рабочая копия — 150 dpi.

| Модуль | Что меряет | Флаговые метрики (Δ = стало − было, «больше — хуже») |
|---|---|---|
| `field.py` | поле смещений B→A по тайлам 27 мм (`matchTemplate` после `phaseCorrelate`, два прохода, IRLS-аффинная подгонка, отбраковка неотчётливых пиков; тайл текста без пары ищется ещё с шаблоном в масштабах ±4/±8 % — верх страницы после снятия трапеции растянут на 6–10 %; внутри рисунков масштаб не подбирается) | `field_lineart_weak_frac` — доля тайлов внутри line art, содержимое которых не находит себе пары (погнутая схема) |
| `strokes.py` | LSD-отрезки от 4 мм на рендере 300 dpi, склейка коллинеарных, два отрезка по кромкам одной линии сводятся к одному по середине, сопоставление через поле; короткий (< 8 мм) горизонтальный штрих вне рисунка — только с краской над и под собой (дробная черта), тире и дефисы отсеяны; линейка для наклона к оси — только то, что и в B стояло на оси (≤ 3°), штрихи внутри рисунка в шапке (логотип рубрики) не линейки; вертикаль в 30 мм от края без соседки и пары напротив — кромка кадра, если в неё упираются линейки меньше чем в двух местах; отсеяны кляксы (толщина, щербатость, конус), одиночные вертикали без перпендикуляра у края кадра (тень корешка; рамка с двух сторон остаётся) и короткие на поле (пометки), росчерки логотипов в шапке; штрихи внутри рисунка без перпендикуляра в наклон к оси не идут | `hstroke/vstroke_dev_max_delta_mm`, `hstroke_tilt_wmean_delta`, `parallel_spread_delta_max`, | `hstroke_dev_max_delta_mm`, `vstroke_dev_max_delta_mm` — на сколько мм ушёл конец линейки от оси; `hstroke_tilt_wmean_delta` — средний по длине наклон горизонтальных штрихов (короткие черты формул); `parallel_spread_delta_max` — разброс углов в группе параллельных; выигрыш `hstroke_gain_mm`, `vstroke_gain_mm` |
| `bend.py` | изгиб длинных (≥ 50 мм) линий по краске: вдоль штриха B через 2 мм поперечный профиль, в нём тонкий прогон краски — сначала ближайший к прогнозу, затем к медиане найденного (поле ошибается на 1–2 мм); то же в A по линии, перенесённой полем; след, где центры прыгают от пробы к пробе (медиана шага > 0.4 мм), — текст, не линия; одиночные скачки убирает медианный фильтр по 5 пробам; сагитта — размах остатка центров от прямой (p2–p98). Пара LSD не нужна: порванную FineReader'ом линию LSD может не найти | `stroke_bend_dev_mm` — сагитта A − сагитта B, мм (ровная линейка 0.1–0.3, погнутая рамка 1966_01 с.95 — 1.7, волна линейки таблицы 1970_06 с.37 — 0.9) |
| `lines.py` | пары строк только внутри одной колонки (по перекрытию после переноса полем), слипшиеся с соседней строки не спариваются; сводки и выигрыш — по колонкам, берётся лучшая колонка | выигрыш: `text_sag_gain_mm`, `text_spread_gain_deg` |
| `stretch.py` | строки по ОДНИМ И ТЕМ ЖЕ глифам: куски строки B по 8 мм ищутся в A (корреляция, субпиксельно); пара строк подтверждена, если нашлись ≥ 3 кусков | `line_tilt_dev_max_mm` — наклон B по центр-линии + доворот по сдвигам кусков, уход конца в мм; `line_glyph_wobble_max` — волна A − волна B (доли высоты); `line_stretch_mm_max` — клин высоты строки ≥ 4 мм (перебор масштаба 0.90–1.10) сверх выигрыша по наклону; выигрыш `line_tilt_gain_mm` |
| `edges.py` | кромки блоков строк (колонка режется по промежуткам > 3 высот) по строкам, доходящим до края (Тейл–Сен); сопоставление по стороне и перекрытию по вертикали | `edge_dev_max_delta_mm` — на сколько мм ушла кромка от вертикали |
| `regions.py` | рамки line art — `ocr_utils.page_layout.line_art.features.analyse_gray`; строки — `curved_lines.detectors.line_fit.line_samples(banded=True)`: межколонники по лентам высоты (заголовок на всю ширину их не ломает), каждой строке — номер колонки | — |

**Вердикт** (`scoring.Thresholds.apply`): порча `score = max(Δ / порог)` и выигрыш
`gain = max(Δ⁻ / порог)` — что коррекция выправила (прогиб строк, разброс наклонов, наклон
строк, линеек, кромок; `GAIN_THRESHOLDS`). Классы с гистерезисом (решение пользователя
«мелкое ухудшение — хрен с ним, берём версию FineReader»):

* `bad` — непрощаемая порча ≥ 1 (средний наклон черт формул при ≥ 3 чертах; погнутый line art
  из ≥ 6 тайлов) ИЛИ порча ≥ 1 при выигрыше < `--min-gain` (1) ИЛИ порча ≥ `--ratio` (0.75)
  выигрыша ИЛИ порча ≥ `--hard` (5);
* `mixed` — порча есть, но выигрыш её перевешивает: испортил чуть, выправил больше — в финальный
  PDF идёт версия с коррекцией, страница в отдельной папке для глаз;
* `ok`.

Пороги в `scoring.py` — по перцентилям пака и просмотру поясов; менять — `report --thr`.

## Пробник VLM (DeepSeek V4.1 Flash)

`vlm-probe` спрашивает модель «стало ли хуже?» по картинке в четырёх вариантах (`overlay` —
A совмещена с B аффинно, краска двумя цветами и зелёная сетка; `side` — «было | стало» с сеткой;
`two` — две картинки в одном запросе; `crop` — кроп области-виновника в полном разрешении),
`vlm-report` сводит ответы. Выборка: эталон + по 30 страниц из поясов score; 2 повтора;
ответы — `vlm/v<редакция промпта>/<вариант>/*.json`, цена из `usage.cost`.

Итог (1104 запроса, $0.26, 0.02–0.03 ¢ и 3 с на запрос): модель отвечает стабильно
(повторы совпадают на 98–100 %) и без ложных срабатываний, но ПОРЧИ НЕ ВИДИТ: на эталонных
плохих страницах 12 % (только погнутая блок-схема с.80), в поясе score ≥ 2 — 8–13 %, в
остальных поясах 0 %. Редакция 2 промпта (по структурам списком, сверка с сеткой, без призыва
к осторожности) — то же: на кропе с.38 с наклонёнными на 1.5° вертикалями каждая структура
«ok/ok». Наклоны и изгибы в 0.5–1.5° ниже разрешающей способности модели (картинка ужимается
до ~1300 px). Как детектор не годится; как второе мнение — только для грубых случаев.

Ранее — 38 страниц с вердиктами пользователя (в том числе «чуть испортил, но выправил больше» — это `mixed`, версия с коррекцией берётся); верно 33: мимо с.95 (гистерезис), с.57 (кромка 0.4 мм), 1966_05 с.70 (черты короче 4 мм), 1967_05 с.26 (клин прощён за доворот), 1968_02 с.92 (клин 0.25 мм на границе различимости).

сидит в нетекстовом (линейки, кромки, крупные заголовки, чертежи); FineReader систематически
наклоняет крупные заголовки (1967_01 с.35, 1967_03 с.36).
