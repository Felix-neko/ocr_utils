# Страницы, где коррекция геометрии FineReader сделала хуже

Зачем — в докстринге `__init__.py`. Коротко: два прогона FineReader по одним промежуточным PDF
(с коррекцией геометрии и без), детектор сравнивает одну и ту же страницу попарно и отдаёт
score «стало хуже» с причиной, а также картинки «было | стало» для проверки глазами.

## Команды

```bash
# весь пак, в фоне (≈ 40 мин на 16 воркерах); ждать по PID
setsid ./run_scripts/geometry_regression/run_pack1.sh > run.log 2>&1 < /dev/null & PID=$!
while kill -0 "$PID" 2>/dev/null; do sleep 30; done

# сводка + картинки по годам с порогами по умолчанию; любые пороги — без пересчёта
./run_scripts/geometry_regression/run_report.sh
./run_scripts/geometry_regression/run_report.sh --thr line_dev_max_delta_mm=1.2 --min-score 1.3

# проба на одном выпуске и нескольких страницах
uv run python -m research.geometry_regression run --geo-dir … --nogeo-dir … --out-dir … \
    --only full_1967_01 --pages 38,80,85 --jobs 4
uv run python -m research.geometry_regression report --out-dir … --list-thresholds
```

## Что лежит в выходе

* `run.json` — пути к PDF и параметры (размеры в мм), чтобы `report` не спрашивал их снова.
* `cache/<pdf>/pNNN.json` — метрики страницы, рамки-виновники (`culprits`) и сырьё поля
  смещений; повторный `run` берёт их без пересчёта (`--redo` — пересчитать).
* `metrics.csv` — все страницы, все метрики, score и причина по порогам в коде;
  `metrics_flagged.csv` — то же с порогами из `report --thr`.
* `report.md` — счётчики, пояса score, перцентили флаговых метрик по паку (для калибровки),
  флаги по годам, эталон с вердиктами, топ находок.
* `pairs/<год>/full_ГГГГ_НН_pNNN_s2.31_причина.jpg` — слева «было» (без коррекции), справа
  «стало», сетка через 1/12 по обеим осям, синяя рамка — область, давшая score; третья панель
  (`--arrows`) — поле смещений: стрелки — остаток после аффинной части ×5, квадраты — тайлы
  без пары (лиловый — содержимое тайла деформировано, серый — периодика).

## Как это устроено

Все размеры в коде заданы в миллиметрах бумаги и переводятся в пиксели по фактическому dpi
рендера (`mm_to_px`); рендер — 300 dpi (`line_fit` берёт центр-линии с копии 300 dpi),
рабочая копия — 150 dpi.

| Модуль | Что меряет | Флаговые метрики (Δ = стало − было, «больше — хуже») |
|---|---|---|
| `field.py` | поле смещений B→A по тайлам 27 мм (`matchTemplate` после `phaseCorrelate`, два прохода, IRLS-аффинная подгонка, отбраковка неотчётливых пиков) | `field_lineart_weak_frac` — доля тайлов внутри line art, содержимое которых не находит себе пары (погнутая схема) |
| `strokes.py` | LSD-отрезки от 8 мм на рендере 300 dpi, склейка коллинеарных, сопоставление через поле | `hstroke_dev_max_delta_mm`, `vstroke_dev_max_delta_mm` — на сколько мм ушёл конец линейки от оси; `parallel_spread_delta_max` — разброс углов в группе параллельных штрихов |
| `lines.py` | строки `line_fit` попарно (центр строки через поле, перекрытие ≥ 0.75 длинной) | `line_dev_max_delta_mm` — на сколько мм ушёл конец строки от горизонтали (заголовок наклонился); `line_wobble_delta_max` — остаток от параболы в долях высоты (разрядка запрыгала) |
| `edges.py` | кромки блоков строк (колонка режется по промежуткам > 3 высот) по строкам, доходящим до края (Тейл–Сен); сопоставление по стороне и перекрытию по вертикали | `edge_dev_max_delta_mm` — на сколько мм ушла кромка от вертикали |
| `regions.py` | рамки line art — `ocr_utils.line_art_detection.features.analyse_gray`; строки — `curved_lines.detectors.line_fit.line_samples` | — |

`score = max(Δ / порог)`, `reason` — метрика-победитель. Пороги в `scoring.py` — стартовые, по
эталону; рабочие подбираются по перцентилям в `report.md` и просмотру поясов глазами.

## Эталон и что показал замер

`run_scripts/geometry_regression/labels.csv`: 8 плохих страниц (наклонённые вертикали рамок
и таблиц, погнутый шкаф в перспективе, блок-схема, дробные черты формул, кромка колонки,
заголовок в разрядку, крупный заголовок) и 4 хороших. Ловится 7 из 8; пропуск —
1967_03 с.36: верх букв заголовка сдвинут на 0.25 мм при ровном низе, это ниже шума любой
метрики по строке. На хороших и случайных страницах score 0.27–0.98.

Замечено по ходу: текстовые строки FineReader выправляет и на «плохих» страницах — порча
сидит в нетекстовом (линейки, кромки, крупные заголовки, чертежи); FineReader систематически
наклоняет крупные заголовки (1967_01 с.35, 1967_03 с.36).

Что не сработало и почему — в `docs/status.md` («что пробовали и отвергли», geometry_regression).
