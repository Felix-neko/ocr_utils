# Отдельное окружение под PaddleOCR

## Зачем отдельное

`paddlepaddle` тянет свой рантайм и свою сборку protobuf и конфликтует с тем, что уже стоит
в основном окружении проекта (в `pyproject.toml` проекта индекс для `paddlepaddle-gpu`
объявлен, а сама зависимость намеренно закомментирована). Ставить его туда ради одного
сравнительного замера нельзя: сломается всё остальное.

Поэтому PaddleOCR живёт здесь, а основной пакет разговаривает с ним подпроцессом через
папку с вырезками и JSON — так же, как проект разговаривает с tesseract.

## Как поставить

```bash
uv sync --project research/legacy/table_processing/paddle_env
```

## Как проверить руками

```bash
uv run --project research/legacy/table_processing/paddle_env python \
    research/legacy/table_processing/paddle_env/worker.py --in-dir /путь/к/вырезкам --out /tmp/paddle.json
```

## Что внутри

`worker.py` читает все PNG из папки, гонит их через `PaddleOCR(lang="ru")` и пишет JSON
`{имя файла: {"lines": [...], "confidence": ...}}`. Ничего больше он не делает: вся
подготовка вырезки (поворот, поля, увеличение) сделана в основном пакете и одинакова
для всех движков — иначе сравнение мерило бы удачность предобработки, а не распознавание.
