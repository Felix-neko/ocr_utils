# research/cut_lines — дорисовка срезанных краем листа строк по второму фотосету

Подшивка РИСК 1991/05 снята дважды. Подшивка-основа (1) хорошая, но у многих страниц край строки срезан краем
листа: лист загибается, и строка уходит за кромку. В доноре (2) края страниц целые, зато убит текст у корешков.
Стенд берёт кадры (1), находит строки, срезанные у нижнего, верхнего и наружного края (корешок не трогается), и
дорисовывает их по (2).

Фотосеты:
- **(1)** `пак-6 от Лены (1989-1992)/РИСК/1991/05 есть фотографии по страницам/` — 110 кадров, 5687×4268. Разворот
  обычно снят дважды, с фокусом на каждую страницу.
- **(2)** `пак-7 от Бори/РИСК/1991/05/` — 59 кадров, 4622×3584.

Выход (только SSD): `/mnt/hotstore/scan_processing/cut_lines/risk_1991_05/`.
- `frames/` — все кадры (1). Дорисованные перекодированы в JPEG q95, остальные скопированы как есть.
- `sheets/<кадр>_p<стр>.jpg` — «было | донор после совмещения и цвета | стало» по каждой дорисованной странице.
- `pairs.csv` — пары кадров; `patches.csv` — сводка по страницам.

## Шаги

1. **Пары кадров** (`pairing.py`). SIFT по кадрам, уменьшенным до ширины 1400. Сходство — доля RANSAC-инлайеров
   гомографии. Пары выбираются монотонным выравниванием `merge_best_shoots.align`, а вторые снимки разворота в (1)
   добираются лучшим кадром (2).
2. **Страницы (1).** Берутся из кэша scan_cropping v2: маска бумаги, раздача по экземплярам SAM 3 (`v2.glue.split_pages`).
3. **Совмещение страницы** (`register.py`), на масштабе ½ кадра (1):
   - гомография по SIFT внутри страницы (RANSAC 25 px);
   - два прохода DIS-потока по размытому серому;
   - надёжная зона: видимая бумага с отступом 7 px, корреляция в окне 21 px > 0.6, есть краска;
   - за краем надёжной зоны поправка к гомографии продлевается TPS со сглаживанием. Срезанная строка за кромкой (1)
     изгибается и тянется так же, как соседние видимые.
   - Страница с медианой корреляции < 0.35 не дорисовывается.
4. **Срезанные строки** (`lines.py`). Строки печати донора после совмещения: адаптивная краска, смыкание 5×25.
   Строка считается срезанной, если:
   - похожа на строку текста: высота 6–45 px, длина ≥ 3 высот, ≥ 6 глифов — торец стопки и кромка обложки отсекаются;
   - ≥ 3% её площади и ≥ 40 px лежат на бумаге донора за видимой бумагой (1);
   - она в зоне своей страницы и не в полосе корешка (±8% ширины страницы).
5. **Вклейка** (`compose.py`), в полном разрешении. Отображение поднимается с масштаба совмещения, затем
   `cv2.remap` полного кадра (2).
   - **Цвет:** глубина чернил донора `D = 1 − I/фон донора` переносится на фон бумаги основы, продлённый за кромку
     (ближайший надёжный пиксель + размытие): `I = фон основы · (1 − k·D)`. Множитель `k` — отношение глубин в видимой
     части срезанных строк.
   - **Область:** строка целиком из (2) плюс полстроки вокруг; в бумаге (1) — до середины межстрочного промежутка.
     За кромку — поле донора на 25 px под строкой. Альфа размыта на 4 px.

## Команды

```bash
uv run python -m research.cut_lines pairs --jobs 12
uv run python -m research.cut_lines run --jobs 12 [--keys IMG_0542,IMG_0560]
```

## Ограничения

- Нужен кэш scan_cropping v2 по (1): маски бумаги и страниц.
- Пальцы в (1) остаются: основа — сырые кадры. Дорисованная строка перекрывает палец, только если он лежит на ней.
- Начала строк у корешка, ушедшие под соседнюю страницу, не дорисовываются.

## Режим `extend`: продление кромки и допечатка строк буквами своей подшивки

Постановка (2026-10-11, после отсмотра 47 кадров списка глазами): нижний край подшивки (1) обрезан переплётчиком,
у многих страниц нижняя строка стоит у самой кромки, у 15 страниц (8 разворотов) срезана часть знаков. Донор (2)
нужен только чтобы **прочитать** срезанную строку; буквы берутся из самой подшивки (1), с той же и соседних страниц.

- `sets/risk_1991_05_bottom.csv` — набор вердиктов: `frame,page(L|R),status(cut|tight),texts` (тексты колонок
  слева направо через `|`, пустой — колонка не срезана). 94 страницы 47 кадров; тексты срезанных строк прочитаны
  глазами по кадрам (2).
- `extend.py` — кромка страницы (низ маски бумаги v2 на ½ кадра → уточнение на полном по спаду яркости → медиана
  61, гаусс 15); полоса кромки (светлый ободок, тень, торец стопки, 80 px) **едет вниз как есть** на `d` px, щель
  заливается бумагой: тон по столбцам из двух окон над кромкой (150 px) с продлением вертикального хода яркости,
  зерно по σ бумаги; пиксели бумаги выше кромки не меняются, холст при нужде доращивается снизу. Пальцы: кромка
  продлевается по LaMa-кадру v2 (`clean.png`), ядро пальца возвращается поверх.
- `fragments.py` — допечатка: колонки нижнего ряда по краске у кромки; строки колонки в окне 26 высот буквы
  (наклон по дисперсии проекции, базовые линии по спадам краски, ось каждой строки по низам букв); ось срезанной
  строки — на шаг ниже последней видимой (если под ней есть верхушки) или сама последняя (срезаны выносные);
  библиотека букв — строки колонки (8 окон вверх, вся страница) + общая библиотека подшивки (`--library`), образец
  по классу высоты (строчные / высокие / подстрочные / дефис) и согласию с медианным отпечатком; раскладка:
  номинально с выключкой по формату (если видимая краска доходит до правого края колонки), затем динамика
  (Витерби) по профилям корреляции верхушек букв с видимой краской, штраф за отклонение просветов; **слова, у
  которых хоть одна буква заходит в зону кромки, стираются и набираются целиком**, остальные остаются (старая
  краска режется на слова-пробеги и относится к ближайшему слову раскладки); проверка — tesseract по набранной
  строке (`check` при сходстве < 70).
- `process_extend.py` — кадр: страницы из кэша v2 → продление → допечатка по набору → сверка tesseract нижних
  строк (1) и (2) → `frames/`, `sheets/` («было | стало» по нижним полосам), строки `lines.csv`; `harvest_frame` —
  буквы кадра для общей библиотеки.

```bash
run_scripts/cut_lines/run_risk_1991_05_extend.sh        # harvest (библиотека) + extend по 47 кадрам набора
uv run python -m research.cut_lines harvest --keys IMG_0569,… --out …/library.npz
uv run python -m research.cut_lines extend --set research/cut_lines/sets/risk_1991_05_bottom.csv \
    --out-root …/risk_1991_05_extend --library …/library.npz --extend-mm 9 --px-per-mm 16 --keys IMG_0569
```

Выход: `/mnt/hotstore/scan_processing/cut_lines/risk_1991_05_extend/` — `frames/` (47 кадров, JPEG q95, холст
выше исходного там, где кромка была у низа кадра), `sheets/`, `lines.csv`, `library.npz`.

Ограничения: латиница формул («(F)», «(Ver-») набирается, только если буква есть в библиотеке; сигнатура «Риск № 5»
(IMG_0578 R, мелкий кегль по центру) не допечатывается — образцов этого кегля нет; знак «;» без образца —
слово остаётся как было.

### Правки по отсмотру (2026-10-12)

Четыре дефекта первого прогона и что сделано:

- **Чёрные треугольники у корешка** (IMG_0596, IMG_0618). Горизонтальное смыкание щели корешка включало чёрный
  V-клин между нижними углами страниц в маску, и он оставался над новой бумагой. Теперь клин едет вниз вместе с
  полосой кромки (`extend_bottom`: `gap`, `band_d`), его старое место — бумага; тон бумаги у корешка берётся без
  пикселей клина; у кромки отрезаются хвостовые столбцы с прыжками низа и правятся концы по робастной прямой
  (`page_bottom_edge`: `EDGE_JUMP`, `EDGE_LINE_SPAN`).
- **Артефакты букв** (IMG_0634, IMG_0572). Тёмная рамка окна — ремап с чёрным бордером учитывал его дважды;
  теперь ремап премультиплицированный (`paste_strip`). Набор в два прохода: сначала ячейки заменяемых слов
  заливаются поверхностью бумаги по окружению (размытие вне краски, без порога «светлое», с зерном, верх окна —
  под выносными строки выше; `paper_surface`, `window_top`), потом на неё наносятся буквы. Столбцы, где лист
  уходит за нижнюю рамку кадра, — кромка равна рамке, под листом только бумага (`EDGE_FRAME`, `at_frame`).
- **Вставленная строка не следует изгибу** (IMG_0541, IMG_0572). Парабола строки с жёстким отсевом теряла подъём
  у корешка (12–16 px). Теперь ось — гладкая кривая (`synth.smooth_curve`: локальная прямая с ядром 1.5 очка и
  робастными весами), строки колонки — базовые линии по вертикальным срезам (`slice_baselines`, `track_rows`),
  одна общая форма на все строки окна плюс свой сдвиг каждой (`shared_shape`); срезанная строка — строка выше,
  сдвинутая на шаг, если низы последней найденной лежат на кромке (`CUT_SHARE`). Буквы сжимаются по ширине, если
  строка шире отрезка (ракурс у корешка, `MIN_SQUEEZE`).
- **Полоса бумаги короче страницы** (IMG_0648). Зона пальца возвращалась поверх новой бумаги; теперь часть над
  кромкой — на место, часть под кромкой — со сдвигом вместе с кромкой, новая бумага не перекрывается. Торец
  стопки за наружным краем страницы (`stack_columns`: столбцы между страницей и краем книги со светлым прогоном
  над кромкой, кромка — по столбцам от страницы наружу) продлевается вместе со страницей; низ полосы кромки за
  углами — по прямой через последние столбцы (`CORNER_FIT`).

Проверка: `tests/research/cut_lines/test_extend.py` (кромка с V-щелью, столбцы у рамки кадра, кривая с подъёмом
у края, общая форма строк, окно без тёмной рамки, бумага с зерном под буквами); автопроверка по прогону — доля
пикселей темнее 60 в полосе между старой и новой кромкой по страницам.

### Правки по второму отсмотру (2026-10-12)

- **Чёрный клин над полосой и белый прямоугольник** (IMG_0582 и др.). Признак «лист уходит за рамку кадра»
  брался по расстоянию низа маски до рамки (30 px) и срабатывал там, где кромка настоящая, в 2–26 px над рамкой.
  Теперь признак — по маске фона scan_cropping v2 (`book.npz: bg`): лист у рамки, только если под низом маски
  фона нет (`page_bottom_edge(..., bg_half)`, `BottomEdge.frame`); одиночные переключения убираются. Столбцы вне
  тела кромки (отрезанные хвосты) из маски страницы исключаются. В столбцах у рамки кромка достраивается по
  соседям с настоящей кромкой (прямая между якорями по обе стороны пробега, якорь — кромка заметно выше рамки),
  до неё бумага, под ней полоса кромки — медианный профиль полосы соседей (`frame_extension`). Холст доращивается
  повтором последней строки с лёгким размытием вдоль x внутри окна продления (торец стопки продолжается) и цветом фона
  v2 вне окна (рука, рукав обрезаются рамкой честно), источник полосы кромки — только настоящие строки кадра. Якорь
  достройки — пробег не короче 60 столбцов с настоящей кромкой; без якорей под листом только бумага. В столбцах
  корешка без маски (обрезанные хвосты масок) низ интерполируется по соседям, иначе клин щели копировал бы вниз
  полосу текста (IMG_0636, «цены»).
- **Клинья на новой кромке** (IMG_0635). `robust_line` стартовала с МНК по всем точкам, и крутой хвост у
  корешка/угла наклонял прямую, а `straighten_ends` опускала начало окна на неё. Теперь старт — горизонталь на
  медиане, правится только пробег нарушений, упирающийся в край.
- **Рваный палец** (IMG_0636). Низ маски страницы под большим пальцем у обреза обрывается выше пальца (маска
  кончается, где он её закрыл), и часть пальца уезжала вниз. Низ по столбцам сглаживается максимумом в окне
  61 столбец (`FINGER_EDGE_WIN`); «под кромкой» — только где лист не уходит за рамку.
- **Низ слева** (IMG_0639). Размноженные строки холста и плоский блок бумаги под столбцами у рамки — см. первый
  пункт. Клин щели корешка (`gap`) теперь берётся только в зоне между страницами (`spine`), а не из любой дырки
  закрытия: выемка у наружного угла больше не копируется вниз чёрным блоком.
- **«F» → «Г»** (IMG_0570). В корзине «F» общей библиотеки нет ни одной настоящей F (15 образцов — «Г», «р», «п»
  с чужой меткой tesseract rus+eng), а при отсутствии подтверждённого образца брался лучший по форме. Теперь для
  латиницы берётся только образец, который tesseract перечитывает как эту букву, иначе кириллический двойник,
  иначе буква из шрифта DejaVu Serif по высоте прописных и глубине краски библиотеки (`font_glyph`,
  `source="font"`).
- **Серый шлейф под логотипом «ЭО»** (IMG_0624, IMG_0626). Полутоновая заливка логотипа у самой кромки не
  ловится порогом краски и шла в замер тона бумаги как «бумага». Теперь в замер идут только пиксели не темнее
  медианы бумаги страницы на `TONE_DARK`; столбцы без чистой бумаги в нижнем окне берут тон из верхнего без
  тренда, а длинный пробег таких столбцов (`TONE_GAP_MAX`) получает тон ближайшего чистого столбца с каждой
  стороны, а не смесь через столбцы с краской.
