# Внешний OCR, промпт v16: восстановление обрезанных слов без «[неразборчиво]», без второго прохода

## 1. Задача

Боевой внешний OCR (`ocr_utils/external_ocr_services`, DeepSeek V4.1 Flash) читает сканы подшивок,
где буквы у корешка обрезаны, сплющены, в тени или не в фокусе. Нужно, чтобы модель достраивала
обрезанные слова до целых (или до фрагмента с переносом) и восстанавливала повреждённые буквы по
очертанию и контексту, помечая это тегами `<supplied>`/`<unclear>`/`<gap>`. Опасения по промпту v15:
правило 1 («Never invent… write [неразборчиво]») спорит с правилом 5 и модель понимает его буквально;
правило о повреждениях повторено трижды; второй проход по повреждённым полосам портит текст
(`reports/external_ocr_hyphenation_second_pass.md`). Что менялось — в `README.md` пакета
(«Промпт v16»); здесь — регрессия v15 → v16 на трёх наборах.

Что выяснилось до правок (логи сессий 14–18.09, выходы `scripts/debug_bad_issue_out/`): модель
достраивает обрезанные слова всегда и молча — «Never invent» её не останавливает; проблема в
непометке и в конфликте правил у края: `[неразборчиво]` она ставила вместо одной буквы
(«сущест[неразборчиво]ует», с. 89 1991/02) и на продолжениях переносов (23 на с. 93); ложные
`<gap>` в целых словах на 3 полосах вставлял наш же код из `edge_words`; четверть записей
`edge_words` пустые (`seen == full`).

## 2. Стенд и данные

Три набора, каждый распознан промптом v15 и v16 в одну ночь (19.09.2026, 00:50–01:10 МСК,
льготные часы DeepSeek), одним и тем же кодом `scripts/replay_page.py` (боевой
`ocr.recognize_page`, без второго прохода и без списка статей выпуска, тайлы 4500/2200, `jobs 4`).
Шаблоны v15 подставлены через `--prompts-dir` (v14 из git + правки v15, фраза по умолчанию v15).
Код — `6b9189e` + незакоммиченные правки этого дня. Выходы — `/mnt/SYSTEM/raw/mts/replay/`
(`damaged_v15`, `damaged_v16`, `issue1991_v15`, `issue1991_v16`, `clean1966_v15`, `clean1966_v16`;
в каждом `run1/`, `run2/`, `debug/`, `summary.md`).

## 3. Метод

Метрики по `.json`/`.meta.json` (`replay_page.py summarize`): `is_damaged`; теги
`supplied/unclear/gap` в теле; записей `edge_words`, из них пустых (`seen == full`, счётчик
`edge_words_empty`) и с дефисом на конце `seen` (перенос, объявленный повреждением); тегов дослано
кодом из `edge_words`; снято `<supplied>` с продолжений переносов; «[неразборчиво]»; дефисов между
буквами (составные слова + разорванные переносы); знаков; сходство текстов без тегов между
повторами и между версиями (`difflib`). Ложность тегов на с. 93 проверена по тайлу глазами.

(системный 2253 слов против 2226, пользовательский 154 против 251).

## 5. Что пробовали и отвергли

- Второй проход по умолчанию (`--second-pass` остался опцией): на 44 парах 1991/02 снимал теги с
  достроек, не меняя букв (с. 93: 8 → 0), обвешивал чистые слова `<supplied>` (с. 4: 2 → 23), а
  страховка по счётчикам брала его вместе с ошибкой «перетерпеть»; ×2.1 к цене повреждённых полос.
- `[неразборчиво]` в правиле 1 при тегах TEI в правиле 5 — модель ставила его вместо одной буквы и
  на продолжениях переносов.
- Перенос `<gap>` из `edge_words` в тело кодом — почти всегда строка, оборванная переносом; 24
  ложных пропуска на 3 полосах 1991/02; теперь пропускам верим только из тела.
- Догадки `full` из `edge_words` в подсказке второго прохода — модель перечитывала названные строки
  и портила соседние чистые слова («Солкомфлот» 8/12, без списка 0/12).
- Третий повтор правила («Apply rule 5 strictly» в пользовательском сообщении) — без него теги на
  срезанных полосах не хуже (см. 4.1), абзац убран.

## 6. Что дальше

- Смазанная печать: подстановка без тега на смазанном слове осталась (с. 46 в обеих версиях).
  Проверить на 6 повторах с. 46 фразу «на смазанном слове — тег, не подстановка»; если не
  помогает — искать сигнал в `notes` (модель на 9 полосах 1991/02 и 18 ответах мини-набора сама пишет
  «восстановлен по смыслу») или в согласии двух прогонов.
- `<unclear>` модель не ставит (0 на 64 ответах): сплющенные и размытые буквы читает уверенно; на
  IMG_0068_L в одном повторе 47 `<supplied>` вместо `<unclear>`. Решить, нужен ли этот тег вообще,
  или оставить только `<supplied>` и `<gap>`.
- Нестабильность пометок между повторами (IMG_0008_L 0 ↔ 46) — сравнивать версии только по ≥ 2
  повторам (`replay_page.py`); при слиянии с FineReader верить пересечению двух прогонов.
- Ложный `is_damaged` на пальце, тени, просвете (1991/02: 12 полос v16 при 6–8 реально
  обрезанных) — при выключенном втором проходе это только неточное поле; уточнение определения в
  схеме — отдельный опыт.
- Исследования из плана: склейка разорванных переносов по словарю (`pymorphy3` против
  `mawo-pymorphy3`), укороченный промпт для повреждённых полос, подсказка от детектора корешка
  (`gutter_loss_detection` сначала проверить сам по себе), три тайла по ~1450 px вместо двух по 2200.
