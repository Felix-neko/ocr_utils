# Плавная экстраполяция цвета бумаги на границах кропа

Отчёт по улучшению заливки зоны «внутри crop-bbox, но вне зоны копирования E2»
в `ocr_utils/detect_and_crop.py` (`fill_outside_mask`).

---

## 1. Что мы делаем сейчас и почему это проблема

`fill_outside_mask` закрашивает всё, что попадает в повёрнутый crop-прямоугольник,
но лежит **вне** силуэта страницы E2 (углы поворота, кривой/рваный край книги,
кольцо расширения под layout). Цель — чтобы в углах кропа была «бумага», а не
чёрный фон стола.

Текущий алгоритм:

```python
avg_color = small_bgr[eroded_E2].mean(axis=0)   # ОДИН средний цвет по всей странице
out[~E2] = avg_color                            # заливаем им всю внешнюю зону
```

Два принципиальных недостатка (оба отмечены в задаче):

1. **В средний цвет попадают чернила.** `mean` по всем пикселям E2 включает текст,
   печати, иллюстрации → результат темнее и «грязнее» чистой бумаги. Нужен цвет
   **бумаги**, а не смеси «бумага+чернила».
2. **Свет по краям книги разный.** Разворот освещён неравномерно (вигнетирование,
   боковой источник, тень у корешка, загиб страницы). Один глобальный цвет
   заметно не совпадает с локальной бумагой у конкретного угла → видна ступенька
   на шве E2 ↔ заливка.

### Геометрическая специфика (важно для выбора метода)

Это **не классический инпейнтинг дырки**, окружённой контентом со всех сторон.
Заполняемая зона — это **внешняя кайма**: с одной стороны граница — край страницы
(известная бумага), с другой — либо настоящий фон/стол, либо просто край
crop-прямоугольника. То есть нам нужна **односторонняя экстраполяция наружу** от
края страницы, а не интерполяция между двумя известными берегами.

Отсюда следствия:

- Ширина заливки мала (только углы и тонкие полоски у краёв повёрнутого bbox).
  Экстраполировать далеко не нужно → дорогие глобальные методы избыточны.
- Метод должен **затухать к локальному цвету края**, а не к глобальному среднему.
- Данные для оценки берём из **приграничной полосы бумаги**, а не со всей страницы.

### Ограничения пайплайна

- Кадры 30–48 Мп. Тяжёлая морфология/percentile уже считаются на копии,
  уменьшенной до `WORK_SIDE` (см. `fill_outside_mask`, `compensate_levels`),
  а к полному разрешению применяется только финальная операция. Новый метод
  должен жить по тем же правилам: оценка на downscale, заливка на полном.
- Есть родственная стадия `compensate_levels` (контраст-стретч по перцентилям
  бумаги) — стоит переиспользовать идею «оценка по бумаге, а не по всему кадру».
- Нужно сохранять цветовой баланс (не разъезжать каналы независимо без нужды).

## 2. Задача распадается на две независимые подзадачи

Их полезно решать **раздельно** — почти все хорошие варианты = комбинация «A + B»:

- **(A) Оценка цвета БУМАГИ без чернил** — как из пикселей страницы получить
  «фоновый слой» (paper/shading layer), очищенный от текста.
- **(B) Пространственная модель + экстраполяция** — как разложить этот цвет по
  полю (x, y) и продлить его в зону заливки, отслеживая неравномерный свет.

---

## 3. Подзадача A: цвет бумаги без чернил

> **Уточнение по итогам обсуждения (важно).** Принято допущение: **на краях
> страницы текста/чернил нет** — заливаемая кайма граничит только с чистой
> бумагой или цветной обложкой. Тогда **вся подзадача A для этой заливки не
> нужна**: приграничная полоса уже является чистым источником цвета, её можно
> сэмплировать напрямую, без масок чернил и перцентилей. Раздел A оставлен для
> полноты (пригодится, если тем же background-слоем нормализовать свет НА
> странице, где текст есть), но в рекомендацию (§7) он больше не входит.

Ключевое свойство сканов: **бумага светлее чернил**. Значит «локальный фон» ≈
локально-светлая компонента. Варианты, от простого к сильному:

### A1. Перцентиль вместо среднего
Вместо `mean` брать высокий перцентиль яркости (например, 75–90-й) по бумаге —
он отсекает тёмные чернила. Дёшево (уже считаем percentile в `compensate_levels`).
Минус: перцентиль по интенсивности надо аккуратно переносить в цвет (брать цвет
пикселей, чья яркость ≥ порога, и усреднять их — «paper-only mean»).

### A2. Маска чернил + статистика только по бумаге
Порогом (Otsu/Sauvola по локальному окну) или по расстоянию от локально-светлого
отделяем «чернила» от «бумаги», дальше любую статистику (mean/median) считаем
**только по бумажным** пикселям. Точнее A1, но нужен адекватный бинаризатор.

### A3. Морфологическое «фоновое» закрытие (rolling ball / grayscale closing)
Серошкальное **closing** (или closing-by-reconstruction) структурным элементом
шире штриха «съедает» тёмные буквы и оставляет плавный фон освещения — это
классический *background shading layer* из литературы по бинаризации документов
(morphological background detection, top-hat). Даёт **сразу пространственно
переменную** карту фона (перекрывается с подзадачей B!).
Минус: радиус элемента должен превышать толщину самого толстого тёмного объекта
(жирный заголовок, картинка), иначе фон «протекает». На больших иллюстрациях
ломается.

### A4. Инпейнтинг чернил на самой странице
Сначала «стереть» текст внутри E2 (заменить бумагой) любым из методов B, затем
брать цвет уже с очищенной страницы. Дороже; обычно не нужно, если сразу считать
статистику по бумаге (A2).

> **Вывод по A:** для одноцветной заливки достаточно A1/A2 («paper-only»
> статистика). Если сразу хотим переменный фон — A3 закрывает и A, и часть B.

## 4. Подзадача B: пространственная модель и экстраполяция

### B0. Один цвет (текущий baseline)
Простейший. Не решает проблему №2 (разный свет по краям). Годится только если
свет ровный. С заменой `mean`→`paper-only` (A1/A2) уже станет чище, но всё ещё
плоский.

### B1. Низкопорядковая полиномиальная/плоскостная аппроксимация цвета  ⭐
Модель: для каждого канала (лучше в LAB — см. §6) подгоняем поверхность
`c(x, y) = polynomial(x, y)` невысокого порядка (степень 1 — плоскость, степень 2
— парабола/вигнетка) методом наименьших квадратов **по бумажным пикселям**
(ink-suppressed, A2). Затем просто **вычисляем полином во всей зоне заливки** —
это и есть гладкая экстраполяция с учётом градиента освещения.

- **Плюсы:** дёшево (LSQ на нескольких тысячах точек downscale), гладко по
  построению, **напрямую моделирует наклон освещения** (проблема №2), нет швов,
  тривиально устойчиво к «дыркам» произвольной формы. Экстраполяция за пределы
  данных ведёт себя предсказуемо для степени 1–2.
- **Минусы:** глобальная модель — если свет не полиномиальный (резкая тень у
  корешка, локальный блик), степени 2 не хватит, а высокие степени «идут вразнос»
  в углах при экстраполяции. Остаточные чернила тянут фит → нужен робастный
  LSQ (Huber/IRLS или RANSAC).
- **Литература:** flat-field correction в астрономии/индустрии — освещение
  моделируют полиномом 2–4-й степени именно потому, что оно «пространственно
  гладкое».

### B2. Приграничная полоса + экстраполяция наружу (edge-band + diffusion)  ⭐
Идея, максимально совпадающая с геометрией задачи (§1): берём цвет бумаги в
**тонкой полосе сразу внутри края** страницы (ink-suppressed), и **продляем его
наружу**. Способы продления:

- **Нормализованная свёртка / normalized convolution:** известные (бумажные)
  пиксели с весами гауссом «размазываются» в неизвестную зону с нормировкой на
  сумму весов. Один-два прохода большим гауссом на downscale.
- **Push-pull (pull-push) пирамида:** классический быстрый алгоритм
  интерполяции разреженных данных (из компьютерной графики). Многоуровневый:
  «pull» усредняет вниз по пирамиде, «push» достраивает вверх. O(N), очень
  быстро, гладко, идеально для «заполнить неизвестное по редким известным».
- **Диффузия от края (см. B3).**

  - **Плюсы:** цвет **локальный** для каждого края (проблема №2 решена честно, без
  глобальной модели), устойчиво к сложному свету, дёшево на downscale.
- **Минусы:** чуть больше кода (полоса + пирамида/свёртка), надо аккуратно
  сэмплировать полосу так, чтобы не поймать краевую тень/загиб (отступить от
  самого края внутрь).

### B3. Гармоническая / Laplace-диффузия (Dirichlet + Neumann)
Решаем `Δc = 0` в зоне заливки с граничным условием: на стороне страницы —
Дирихле (заданный бумажный цвет из полосы), на стороне прямоугольника — Нейман
(нулевой поток). Решение — «мембранная» гладкая поверхность, затухающая к цвету
края. По сути непрерывный аналог B2.

- **Плюсы:** гладко, локально, математически чисто; естественно учитывает
  одностороннюю экстраполяцию через условие Неймана.
- **Минусы:** нужен решатель Пуассона/Лапласа (несколько итераций Якоби/
  многосеточно) — тяжелее push-pull при той же сути; гармоническое продолжение
  «плоское» (без текстуры), но для однотонной бумаги это ок.

### B4. Telea / Navier–Stokes (`cv2.inpaint`)
Готовые методы OpenCV (`INPAINT_TELEA` — fast marching; `INPAINT_NS` —
Навье-Стокс). Продлевают изофоты и цвет от границы внутрь маски.

- **Плюсы:** одна строка, в проекте уже есть OpenCV.
- **Минусы:** заточены под **тонкие** дырки; `inpaintRadius` мал, на широких
  зонах мылят и тянут в углы полосы/артефакты; будут тащить внутрь **чернила** с
  края страницы (метод не знает, что край — это текст). Требует предварительной
  очистки края от чернил. Для «однородная бумага в углу» — из пушки по воробьям и
  скорее хуже B1/B2.

### B5. Guided / joint-bilateral upsampling грубого фона
Оценить фон на сильном downscale (A3 closing), затем поднять до полного
разрешения **guided-фильтром** по исходнику. Даёт переменный фон дёшево.
Минус: guidance по исходнику потянет текстуру/чернила обратно — для чистой
заливки не нужно, полезнее когда фон накладывается на весь кадр (нормализация
освещения), а не только в кайму.

### B6. Глубокий инпейнтинг (LaMa) — уже есть в проекте
В пайплайне уже используется LaMa (удаление пальцев). Формально можно отдать ему
и кайму.

- **Плюсы:** переиспользование готовой модели; хорошо галлюцинирует текстуру.
- **Минусы:** LaMa обучен **достраивать контент внутри** изображения, а не
  экстраполировать за край страницы в пустоту — тут он ненадёжен, может
  «дорисовать» несуществующий текст/край. Дорого (GPU) ради однотонной бумаги.
  Не рекомендуется для этой конкретной зоны.

## 6. Детали, общие для всех вариантов

- **Цветовое пространство.** Считать и экстраполировать лучше в **LAB** (или
  YCrCb): отделяет яркость (L) — где и живёт неравномерный свет — от цвета (a, b),
  который у бумаги почти постоянен. Тогда переменным можно делать в основном L, а
  a/b держать почти плоскими → меньше цветовых разъездов. Это согласуется с
  идеологией `compensate_levels` (общий диапазон, а не независимые каналы).
- **Ink-suppression для фита.** Любую подгонку (B1) и сэмплирование полосы (B2/B3)
  вести по бумажным пикселям: маска чернил (A2) ∪ робастные веса (Huber) в LSQ.
- **Сэмплировать не у самого края.** Край страницы часто в тени/загибе — брать
  полосу с отступом внутрь (как уже делает `erosion_px` при усреднении).
- **Всё оценивать на `WORK_SIDE`-копии**, заливку/полином применять к полному
  разрешению — ровно как сейчас в `fill_outside_mask`/`compensate_levels`.
- **Синергия с `compensate_levels`.** Если фоновый слой (A3/B1) уже оценён, его
  можно переиспользовать и для нормализации освещения самой страницы (деление на
  фон / вычитание) — то есть один и тот же background-estimate закрывает и заливку
  каймы, и выравнивание света на странице. Стоит держать в уме как следующий шаг.

## 7. Рекомендация

Уточнённые вводные:

- **Цвет края сложный** — бумага И/ИЛИ **цветная обложка**, которую иногда нужно
  продлить наружу. Локальный цвет каймы может быть каким угодно.
- **На краях текста нет** — источник цвета (приграничная полоса) заведомо чистый,
  подавление чернил (подзадача A) не требуется.
- Кайма тонкая (углы поворота + кольцо под layout), экстраполяция короткая; важны
  скорость на 30–48 Мп и отсутствие галлюцинаций.

При таких условиях **глобальные модели отпадают**:

- **B0 (один средний цвет)** и **B1 (полином)** предполагают ± однородный или
  гладко-градиентный фон. Цветную обложку с локальным цветом одной поверхностью
  не продлить — они замажут угол «средним по больнице». Исключаются.
- Подзадача **A** не нужна (нет чернил на краю).

**Остаётся один правильный класс — локально продлить цвет края наружу.** Основной
выбор:

**B2 «edge-band + push-pull / нормализованная свёртка»** — цвет берётся из
приграничной полосы и локально экстраполируется в кайму. Каждый угол получает
цвет СВОЕГО края → и сложный свет, и цветная обложка воспроизводятся честно, без
глобальных допущений. Быстро (пирамида O(N) на downscale), без галлюцинаций.

Близкие альтернативы:

- **B3 (Laplace-диффузия, Dirichlet по краю + Neumann по прямоугольнику)** — тот
  же результат «мембраной», но дороже (итеративный решатель). Брать, если push-
  pull даст видимые пирамидные артефакты.
- **B4 (`cv2.inpaint`, Navier–Stokes)** — теперь **применима** (главный её минус,
  «тянет чернила с края», снят допущением про отсутствие текста): одна строка,
  годится как быстрый бейзлайн для сравнения. Минус — на широких углах мылит и не
  так управляема, как push-pull.

> Оговорка про «расширение цветной обложки»: если у обложки near-edge есть
> выраженная **текстура/узор**, честно «дорисовать» её умеет только контент-аварный
> инпейнтинг (LaMa/exemplar). Но цель заливки — убрать чёрный угол правдоподобным
> фоном, а не восстановить узор; для этого достаточно гладкого локального
> продолжения цвета (B2). Текстурное расширение — отдельная задача, если
> понадобится.

### Псевдокод предлагаемого `fill_outside_mask` (вариант B2)

```python
def fill_outside_mask(bgr, mask, ...):
    small_bgr, small_mask = downscale(bgr, mask, WORK_SIDE)   # оценка — на уменьшенной копии

    # Известные значения — приграничная полоса СТРАНИЦЫ (E2), слегка эродированная,
    # чтобы не поймать шумный/тенёвый край и подтёкший фон. Чернил на краю нет —
    # маска чернил НЕ нужна, берём цвет напрямую.
    known = erode(small_mask, erosion_px)                     # bool-маска валидных пикселей-источников

    # Локальная экстраполяция цвета из known во все прочие пиксели (в т.ч. внешнюю кайму).
    # push-pull: пирамида «вниз усредняем валидное — вверх достраиваем дырки».
    filled = push_pull(small_bgr, known)                      # гладкая карта цвета, без деталей

    full = upscale(filled, bgr.shape)                         # карта гладкая → INTER_LINEAR достаточно
    out = bgr.copy()
    out[~E2] = full[~E2]                                      # подставляем ТОЛЬКО во внешнюю кайму
    return out
```

`push_pull` — компактная пирамида на `cv2.pyrDown`/`pyrUp` с весами валидности
(нормированная свёртка на каждом уровне). Альтернативно — итеративный
`dilate + gaussian blur` от known наружу (проще кода, чуть менее гладко).
Работаем в BGR (обложка цветная — незачем гонять через LAB); при желании L-канал
можно сглаживать сильнее a/b, но для тонкой каймы это избыточно.

### Что проверить (валидация)

- Цветная обложка у края: угол продлевается ЦВЕТОМ обложки, а не бумагой/серым.
- Кадры с сильным боковым светом и тенью у корешка: цвет каймы совпадает с
  локальным краем, шов E2↔заливка без ступеньки.
- Крупный план шва: нет цветовой/яркостной границы.
- push-pull: нет «блочных» пирамидных артефактов в широких углах (иначе поднять
  число уровней сглаживания или перейти на B3).
- Скорость на 36–48 Мп: оценка и экстраполяция — на downscale, к полному
  разрешению применяется только апскейл карты + подстановка каймы.
