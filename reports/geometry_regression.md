# Страницы, где коррекция геометрии FineReader сделала хуже

Код — `research/geometry_regression` (README там), прогон — `run_scripts/geometry_regression/`.
Выход прогона по паку-1: `/mnt/SYSTEM/raw/mts/pack1_geometry_regression/pack1_v7/` (v6 — `pack1/`) (`metrics.csv` —
12 135 строк, `report.md`, `cache/` JSON на страницу, `pairs/<вердикт>/<год>/` — картинки
«было | стало», `vlm/` — ответы DeepSeek).

## 1. Задача

Полные PDF пака-1 сделаны в FineReader дважды по одним и тем же промежуточным PDF: с коррекцией
геометрии («исправлять перекос», «искажение строк», «трапецию») и без. Коррекция обычно
помогает, но на части страниц (по оценке пользователя < 10 %) портит то, чего не видит её модель
«страница — это строки текста»: наклоняет вертикальные линейки и рамки, гнёт прямые на чертежах
и блок-схемах, косит и растягивает крупные заголовки, наклоняет дробные черты формул и кромки
колонок. Нужен список таких страниц, чтобы при сборке финального PDF брать их из прогона без
коррекции (постраничная сборка из двух PDF уже есть в `pdf_utils.final_pdfs.assemble_issue`,
третий источник — следующий шаг). Дополнительно проверить, увидит ли такую порчу VLM
(DeepSeek V4.1 Flash) по картинке.

## 2. Стенд и данные

* A = `/mnt/SYSTEM/raw/mts/pack1_pdf/full_pdfs_binary_no_bg_brightening` (с коррекцией),
  B = `…_no_geometry_correction` (без); 123 выпуска 1966–1976, 12 135 страниц, страницы
  сопоставляются по индексу (число страниц в парах совпало у всех 123).
* Рендер `fitz` 300 dpi, рабочая копия 150 dpi; все размеры в коде — в мм бумаги, переводятся по
  фактическому dpi (замечание пользователя: dpi плавает).
* 16 воркеров (`forkserver`), ~1 ч на пак (2.3–5 стр/с, упирается в CPU: LSD + корреляция),
  0 ошибок. Код `61f7242` + правки этой сессии (подпакет новый).
* Эталон — `run_scripts/geometry_regression/labels.csv`: 8 плохих страниц, названных
  пользователем и проверенных глазами (1966_01 с.78, с.95; 1967_01 с.38, с.80, с.85; 1967_02
  с.57; 1967_03 с.11, с.36) и 4 хороших (1967_02 с.2, с.29, с.55; 1967_01 с.17 — не тронута).
  Два наблюдения пользователя не подтвердились и заменены: 1967_01 с.17 (край одинаков, поле
  смещений ≈ тождество) исключена, «с.84 формулы» оказалась с.85.

## 3. Метод

Всё попарно, без эталона: метрика(A) − метрика(B) в шкале «больше — хуже», `score = max(Δ/порог)`.
Ключевой замер: текстовые строки FineReader выправляет и на плохих страницах (сагитта и
разброс наклонов по `line_fit` падают везде) — порча сидит в нетекстовом.

| Модуль | Что | Флаговая метрика | Порог |
|---|---|---|---|
| `field.py` | поле смещений B→A: тайлы 27 мм, `phaseCorrelate` + `matchTemplate` в два прохода, IRLS-аффинная подгонка, отбраковка неотчётливых пиков (линейки, отточия) | `field_lineart_weak_frac` — доля тайлов внутри рамок line art (`line_art_detection.analyse_gray`), содержимое которых не находит пары | 0.3 |
| `strokes.py` | LSD-отрезки от 8 мм на 300 dpi, склейка коллинеарных, сопоставление через поле | `vstroke_dev_max_delta_mm`, `hstroke_dev_max_delta_mm` — уход конца линейки от оси, мм (длина × sin) | 0.7 / 0.8 |
| | | `parallel_spread_delta_max` — разброс углов группы параллельных штрихов, ° | 1.5 |
| `lines.py` | строки `line_fit` попарно (перекрытие ≥ 0.75 длинной) | `line_dev_max_delta_mm` — уход конца строки, мм; `line_wobble_delta_max` — остаток от параболы, доли высоты | 0.9 / 0.1 |
| `stretch.py` | куски строки B по 12 мм ищутся в A с перебором масштаба по y (0.90–1.10, парабола), строки ≥ 40 мм и ≥ 4 мм высотой | `line_stretch_mm_max` — клин высоты строки, мм | 0.23 |
| `edges.py` | кромки блоков строк (колонка режется по промежуткам > 3 высот), Тейл–Сен, сопоставление по перекрытию | `edge_dev_max_delta_mm` — уход кромки от вертикали, мм | 2.4 |

Пороги — по перцентилям Δ на паке (p97–p99, таблица в `report.md`) с проверкой поясов глазами и
значениями эталона; `line_stretch` — так, чтобы проходила с.36 (0.24 мм; 0.22 мм глазом уже
почти не видно).

## 4. Результат

**Вердикт** — три класса с относительным гистерезисом (`scoring.py`, v7): `bad` — порча
непрощаемая (средний наклон горизонтальных штрихов ≥ 0.5° при ≥ 3 чертах — формулы; line art
из ≥ 6 тайлов с долей тайлов без пары ≥ 0.45) ≥ 1, либо порча ≥ 1 при выигрыше < 1, либо
порча ≥ ¾ выигрыша, либо порча ≥ 5; `mixed` — порча ≥ 1, но выигрыш её перевешивает (берём
версию с коррекцией, страница в списке для глаз); `ok`. Выигрыш — прогиб строк (мм), разброс
наклонов (°), выравнивание строк (мм; коротких рубрик 15–25 мм — в °), линеек (только тех,
что и были почти на оси), кромок. Кромка колонки — «мягкая» метрика: в одиночку `bad` не даёт.

По паку (прогон v7, `pack1_v7/`): порча ≥ 1 у 595 страниц (4.9 %): **bad 490 (4.0 %)**,
**mixed 105**. Причины bad: parallel 135, htilt 80, vtilt 67, line 40, wobble 29, hmean 29,
stretch 28, edge 57, lineart 25. Прогон v6 (`pack1/`, bad 668) сохранён для сравнения.

По паку, прогон v12 (`pack1_v12/`): порча ≥ 1 у 510 страниц (4.2 %): **bad 424 (3.5 %)**,
**mixed 86**. Причины bad: parallel 95, edge 55, htilt 48, vtilt 47, hmean 42, line 37,
lineart 28, stretch 26, wobble 24, bend 22. Промежуточные прогоны: v8 — 718 bad (296 по
кусочному изгибу), v9 — 612 (53 лишних по «чертам формул» из тире), v10 — 492 (ложные
изгибы и логотипы), v11 — 434 (масштаб тайлов, см. v12). Картинки — `pairs/bad|mixed/<год>/`.

**Этап 6 (v8): колонки, одиночные штрихи, честные пары строк.** По разбору `bad` прогона v7
пользователем (ложных «практически нет», разобраны 6): межколонники по лентам высоты и
номера колонок у строк, спаривание только внутри колонки, выигрыш по лучшей колонке;
слипшиеся строки (по разнице наклона с перекрытым соседом) не спариваются, куски строки
должны лежать в боксе A; одиночные вертикали без перпендикуляра у края кадра (тень корешка —
но рамка с двух сторон остаётся) и короткие на поле (пометки) — не штрихи; росчерки логотипов
в шапке — не штрихи; штрихи внутри рисунка без перпендикуляра — не линейки; новая метрика
`stroke_bend_dev_mm` (длинная рамка распалась в A на куски под разными углами, 1966_01 с.95).
Эталон переехал в `validation/pack1/fr_correction_{bad,good}.csv` (63 страницы), регрессия —
командой `regress`: **v7 → v8: 54 → 59 верно, 0 регрессий** (`regression_v7_v8.md`).

**v9: изгиб линии по краске.** Прогон v8 дал 718 bad (v7 — 490), и 296 из них — по
`stroke_bend_dev_mm`: кусочный вариант по LSD (штрих B в A распался на отрезки под разными
углами) считал изгибом дрожание LSD на ровных толстых линейках (1969_01 с.85, 1973_03 с.86) и

профиль краски, в нём — ближайший к оси прогон не толще 1.5 мм; то же в A по линии,
перенесённой полем; сагитта — размах остатка центров от прямой, метрика — сагитта A − B.
На эталоне: bad-страницы с погнутыми линиями 1.7–3.5 мм (1966_01 с.95 — 1.65, с.78 — 3.5,
1967_07 с.73 — 2.1, 1971_08 с.79 — 2.1, 1974_10 с.30 — 3.5, 1974_12 с.34 — 3.0), хорошие ≤ 0.2;
из 20 случайных «bend»-bad прогона v8 по новой метрике остаются 4 (0.9–1.1 мм, волна линейки
таблицы 1970_06 с.37 проверена глазами), остальные ≤ 0.4. Порог 0.8 мм. Пара LSD не нужна —
линия, которую FineReader порвал так, что LSD её не нашёл, всё равно мерится. Регрессия
**v8 → v9: 59 из 63, 0 регрессий** (`regression_v8_v9.md`). Заодно run-скрипт приведён к

**v10: тире — не черты формул, двойники кромок.** Прогон v9 (612 bad) при штрихах от 4 мм
дал 53 новых bad по `hmean` на страницах без единой формулы (1968_10 с.20: три «черты» — две
кромки линейки под сноской и одно тире). Две правки в `strokes.py`: (1) короткий (< 8 мм)
горизонтальный штрих вне рисунка принимается, только если у него есть краска и над, и под
собой в 0.2–1.2 мм от краёв (числитель и знаменатель); тире и дефисы (соседние строки дальше
1.5 мм) отсеиваются, дробные черты 1967_01 с.85 и 1966_06 с.58 остаются; (2) два отрезка LSD
по кромкам одной линии сводятся к одному по её середине (`_drop_twins`), и порог «≥ 3 черт»
для непрощаемого среднего наклона стал «≥ 2» — старый порог считал те же две черты за четыре.
Регрессия v9 → v10: 57 из 63; два «ушедших» — 1966_01 с.95 и 1968_04 с.86 — держались на
артефактах (см. ниже), остальные без изменений.

подтверждается по глифам (кусок строки B должен найтись в A), иначе на почти пустой странице

минус); клин заголовка считается сверх доворота и выпрямления строки; штрихи от 4 мм и средний
наклон горизонтальных штрихов для коротких черт формул (1966/06 с.58, 1967/06 с.39); на

недосвета у корешка (1966/01 с.91) отсеиваются по толщине краски поперёк отрезка в 15
точках: конус (толщина растёт вдоль отрезка, > 0.7 медианы), щербатость (межквартильный
разброс > 0.6 медианы) или толщина > 2.5 мм — не штрих. Наклон строки в A — прямая по
положениям кусков, а не «наклон B + доворот»: у изогнутой строки сдвиги кусков — её
распрямление (1966/05 с.86). Выигрыш по линейкам — только для линеек, что и в B были в 3°
от оси (полки шкафа под 5°, повёрнутые к оси, — порча, не выигрыш).

**Пробник DeepSeek V4.1 Flash** (`vlm-probe`, 132 страницы: эталон + по 30 из четырёх поясов,
4 варианта картинки, 2 повтора, 1104 запроса, $0.26, 0.02–0.03 ¢ и 3 с на запрос):

| вариант | эталон bad → damaged | эталон good → damaged | пояс ≥ 2 → damaged | согласие повторов |
|---|---|---|---|---|
| overlay (A совмещена с B аффинно, два цвета, сетка) | 12 % | 0 % | 10 % | 98 % |
| side («было \| стало» с сеткой) | 12 % | 0 % | 10 % | 100 % |
| two (две картинки в запросе) | 12 % | 0 % | 13 % | 100 % |
| crop (область-виновник в полном разрешении) | 0 % | 0 % | 8 % | 99 % |

Пояса < 2 — 0 % во всех вариантах. Видит только грубую порчу (блок-схема с.80); на кропе
с.38 с вертикалями под 1.5° отвечает «ok/ok» по каждой структуре и во второй редакции промпта
(чек-лист структур, сверка с сеткой, без «be conservative»). Наклоны 0.5–1.5° ниже разрешения
модели (картинка ужимается до ~1300 px, 1024 токена). Как детектор не годится; как второе
мнение — только для грубых случаев, и там классика уже не ошибается.

## 5. Что пробовали и отвергли

* Профильный deskew (сдвиг столбцов, `warpAffine` + профиль) на бинарном рендере — все углы
  ровно 0.00°: при нуле нет интерполяции и округления, профиль всегда резче.
* Линейки морфологическим открытием — наклонённая на 6° дробная черта (с.85) рвётся; LSD.
* Наклон линейки/строки/кромки в градусах — короткие штрихи и куски строк дают 1.5–2° шума
  (с.2 хорошая, 1973_01 с.43); мерить уход конца в мм.
* Остаток поля внутри line art — велик и в таблицах на хороших страницах (там правка законна);
  решает доля тайлов со слабым пиком корреляции.
* Клин высоты строки по краске самой строки (верх/низ по третям) — шум формы букв 0.05–0.25
  против 0.056 у с.36; заменён замером по тем же глифам (`stretch.py`).
* Центроид куска строки как положение строки — полоса вокруг строки цепляет соседей, форма B
  выходила ложной (с.62); положение B — центр-линия `line_fit`, положение A — плюс сдвиг куска.
* `wobble` по остатку центр-линии от параболы при p99 — куски строк без видимой разницы;
  ненаправленная волна по сдвигам ловила и выпрямление (с.62).
* Порог порчи один на всё — страницы, где FineReader чуть испортил, но выправил больше
  (с.62, 1967_09 с.81, 1967_10 с.30), уходили в bad; введён выигрыш и гистерезис.
* Кромки по номеру колонки — сегментация колонок в A и B расходится (1967_04 с.9); по
  перекрытию и по блокам строк.
* DeepSeek как детектор — см. выше.
