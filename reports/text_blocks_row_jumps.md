# Текстовые блоки: перескок оси на соседнюю строку

## Задача

На оверлее v4 1966/01 IMG_0011_2R ось строки «ярмарка по продаже…» от первого слова по диагонали
уходит на строку ниже («было реализовано…»). Нужно было понять причину, завести меру и посчитать
такие перескоки по паку-1, затем проверить лечение (резку двухрядных сгустков) на проблемных и на
стольких же нормальных полосах до вноса в основной код.

## Стенд и данные

- Мера — по осям всего пака из прогона стенда межколонников (`pack1_gutter_crossing/legacy/pages`,
  12 135 JSON с осями, прежний ход межколонников). Пересчёт полос — вход разбора v4
  (`pack1_page_analysis_v4/pages`: объекты, запреты), вторая ось строки, межколонники `short`.
- Стенд `research/row_jumps` (`measure` / `select` / `run --variant plain|split` / `compare`), run-скрипт
  `run_scripts/text_blocks/run_row_jumps.sh`; выход `/mnt/system/raw/mts/pack1_row_jumps/`:
  `measures.csv`, `problem.txt`, `normal.txt`, `plain/`, `split/`, `compare/` (`compare.csv`, склейки
  изменившихся полос `pages/`, вырезки у находок `zoom/`).
- Код: HEAD 0af789a + правки этой работы; `--jobs 16` (машина загружена чужими прогонами, пересчёт
  704 полос — около 5 мин на вариант).

## Причина

Смыкание RLSA (горизонтальное, ядро 8 px) сливает буквы двух соседних рядов в один сгусток через
мостик: карандашную «/» (1966/01 IMG_0011_2R — «ярмарка» + «/» + «реализовано»), соринку или
выносной элемент, подошедший к букве следующей строки (1967/06 IMG_0150_1L — «ходу;» + «Авторы»;
1972/07 IMG_0006_1L). Кусок строки — это сгусток, поэтому он уходит на соседний ряд ещё ДО сцепки,
и ни один запрет сцепки (межколонник, `LinkVerdict.SPECK` для пометок на полях) до него не доходит.
Межколонники и свежие правки здесь ни при чём: перескок одинаков в v3, v4 и на текущем коде.

## Метод

**Мера** — `metrics.row_jumps_of`: для каждой оси берутся соседние оси, накрывающие её по x не меньше
чем на 90 % её длины и лежащие в среднем ближе 2.5 шага; вдоль общего участка считается разброс
расстояния до соседа (p95 − p5); мерой оси берётся наименьший разброс по соседям. Изгиб и наклон
полосы соседи повторяют, у перескока расстояние меняется на шаг. Перескок — разброс больше 0.6 шага.
Ступенька (`steps_of`) косой переход не ловит: на 1966/01 IMG_0011_2R ступенька 14.6 px при пороге 17.6,
разброс — 21.9 px при шаге 23.4.

**Резка** — `segment._split_two_rows` (флаг `split_rows`, `InkEngine(split_rows=…)`,
`final.text_blocks(split_rows=…)`): сгусток выше медианы букв страницы в 1.6 раза с буквами двух
уровней (середины разошлись больше 1.1 высоты буквы, в каждом уровне не меньше 3 букв; точки и
запятые не голосуют) разрезается. Глиф-мост, накрывающий середины обоих рядов, выпадает. Каждая
группа смыкается тем же ядром отдельно, её связные части получают свои метки.

## Результат

Мера по паку: перескоки на **352 полосах из 12 135** (412 осей). Глазами по 24 вырезкам поясов
разброса 0.6–0.8 / 0.8–0.95 / ≥ 0.95 шага настоящих перескоков 7/8, 6/8, 7/8. Ложные: заголовок
крупного набора с неровной осью, выходные данные вразрядку, ось по краю тени, сноска петитом с шагом
меньше страничного.

пользователя.

## Вторая причина: знаки над буквой («й», «ё»)

После резки остались 170 полос P. Выборка из 24 вырезок показала второй механизм: кратка «й» и точки
«ё» — мелкий глиф, у которого «базовая линия» (низ бокса) стоит на высоте строчной над строкой. Якорь
такой буквы поднимался, парабола оси куска задиралась на конце («путей.», «этой», «дней;», «связей.»),
ступенька на стыке со строкой выше пряталась, и сцепка уводила последнюю строку абзаца на строку выше
(1974/08 IMG_0089_2R, 1972/07 IMG_0009_1L, 1968/06 IMG_0142_2R).

Лечение — `pieces.baselines_of`: мелкий глиф (не выше 0.6 икса), низ которого выше прямой по низам
больше чем на 0.5 икса и который перекрывает по x букву тела, получает базовую линию с прямой. Условие
«над буквой» обязательно: без него дефис («услу-», 1971/04 IMG_0005_2R) и сноска («²», 1973/02
IMG_0095_1L) тоже опускались, и сцепка уводила строку на соседний ряд.

## Третья причина: высота строчной по соринкам (вторая ось заголовка)

Пример пользователя 1966/03 IMG_0120_2R: вторая ось строки заголовка из прописных «ТИПОВЫЕ ПРОЕКТЫ»
ходила от пола до потолка строки (размах 61 px при высоте строки 34; первая ось — 3 px). Высота
строчной (`baseline_axis.line_x_height`) считалась по нижним 30 % высот глифов, а в строке из прописных
нижний «этаж» — соринки 2–6 px; высота строчной выходила ~5 px, и в голосование за базовую линию
пускались только глифы до 2.3 такой высоты — одна пыль. Лечение: глифы ниже 0.4 медианы высот строки
в оценку не входят. Размах второй оси в заголовке — 0–5 px. Контрольный стенд второй оси (18 полос
кривизны и трапеции, `run_axis_body.sh`): отклонение середины строчных p90 0.060 → 0.061 мм, разность
наклонов соседних строк на концах 1.40° → 1.42°, скрещиваний 0 — без изменений. На 61 случайной полосе
сдвиг осей больше 0.5 px — у единиц осей; просмотренные сдвиги больше 2 px — к лучшему (ось по середине
строчных вместо просадки к базовой линии в строках с цифрами и сокращениями), хуже — одна короткая
строка «тыс. руб.» (1966/06 IMG_0136_1L), ось легла по диагонали.

## Стороны блока: край, меняющий наклон по высоте

Требование пользователя: край набора по формату на искажённой полосе может быть не только наклонным,
но и менять наклон от верха к середине и от середины к низу — линия стороны должна за ним следовать.
Проверка выравнивания `robust` (`sides._resid_robust`) подгоняла ОДНУ прямую (Тейл–Сен) или параболу
(RANSAC) на весь блок. Синтетика (колонка по формату, край сдвинут по x в зависимости от y):

| Край | Доля выровненных, лев./прав.: было | стало |
|---|---|---|
| прямой наклон 1.5° | 1.00 / 1.00 | 1.00 / 1.00 |
| излом 0° → 2° → −1° | 0.84 / 0.90 | 1.00 / 1.00 |
| S-образный ±40 px | 0.60 / 0.91 | 1.00 / 0.94 |

Лечение — местная кривая `sides._fit_local`: у каждого конца строки своя прямая Тейла–Сена по ±5
соседним концам; отсев ОДНОСТОРОННИЙ и в три раунда (концы, ушедшие внутрь блока дальше допуска, —
абзацные отступы, серия отступов списка, края рисунка внутри блока — в прямые не берутся; изгиб
бумаги сдвигает край в обе стороны и остаётся); наклон местной прямой — не дальше 6° от общей.
Местная кривая берётся, только если вписывает хотя бы на 2 конца больше общей. На 306 сторонах
настоящих полос (18 контрольных кривизны и трапеции + 60 случайных) не изменилось ни одного вердикта.
Рваный край остаётся рваным (доля ≤ 0.43).

## Четвёртая и пятая причины: кружок «%» и сгусток на три строки (2026-09-29)

- 1969/12 IMG_0118_2R: верхний кружок «%» — отдельный глиф со строчную, его низ на 6 px выше строки;
  конец оси куска «8%.» задирался, и строка сцеплялась со строкой выше. Лечение
  (`pieces.baselines_of`): знаком над буквой считается и глиф не выше строчной, стоящий вплотную (зазор
  до 0.25 икса) над другим глифом, который уже в 2.5 раза, не выше 1.8 икса и выше самого знака.
  Без этих ограничений правило портило 4 полосы (буквы над подчёркиванием, буквы верхней строки в
  куске из двух строк, «%», сросшийся с буквой строки ниже, стержень «?» и «!» над точкой).
- 1967/05 IMG_0084_1L: карандашная кривая сливала три строки; резка делила на два уровня, и в
  нижнем оставались две строки. Лечение: резка повторяется до 4 проходов (`segment.SPLIT_MAX_PASSES`).

На P ∪ N (обе правки против их отсутствия, текущий код): новых перескоков 0, изменились 5 полос.
Пересчёт v4: 70 полос с перескоками (88 осей) против 59 в прошлом v4 — снято 6 (в том числе оба
примера), новых от этих правок 0; 17 появились из-за кода соседних сессий в коммите `1f72c33`,
который прошлый пересчёт не видел (он загрузил код до них). Оверлеи с обводкой —
`/mnt/system/raw/mts/pack1_row_jumps/v4_перескоки/{остались,от_правок_соседних_сессий}`.

## Разбор 70 оставшихся полос и ещё три правки (2026-09-29)

Причины 70 полос (88 осей) после `c37863b`:
- **17 полос и два случая оси «не по середине букв» — замена осей `axes_fix.fixed_axes`** (модуль соседней
  сессии, режим `BlocksMode.SMOOTH`). Выключение замены снимает все 17. Замена принимала за «выброс
  крупного набора» строку корпуса на изгибе бумаги (высота оси раздута изгибом, наклон 2–5°) и ставила
  прямую с наклоном, зажатым в корпус, — прямая уходила в межстрочный просвет; то же — заголовок рубрики
  с настоящим наклоном (1966/02 IMG_0077_1L, сессия 307c8e5e: +9.7 px от середины букв при букве 20 px)
  и последняя строка «снабжения.» на загибе (1966/04 IMG_0011_2R: до 6.3 px). Сама вторая ось во всех
  этих случаях шла по серединам букв (0.01–0.03 высоты глифа).
  **Правка:** крупный набор — по медианной высоте БУКВ строки, а не по высоте оси; ось, которая ложится
  на свои буквы (медиана |середина буквы − ось| < 0.1 высоты буквы) и согласна по наклону с осью по
  центру краски (< 1°), не заменяется. Замен на P ∪ N 124 → 34.
- **Сцепка кусков через ступеньку (короткий конец абзаца + слово следующей строки).** Пара, отбитая в
  первом круге, принималась во втором, когда куски уже подросли: остаток якорей от параболы
  «строка + слово строки ниже» ступеньку сглаживал (1971/08 IMG_0090_2R: ступенька 16.8 px при шаге
  21.9). **Правка** — отложенная в 2026-09-27 «сверка по обращённым концам кусков»:
  `zones.joint_step` — ордината начала правого куска против конца левого (по крайним буквам) за вычетом
  подъёма по средней касательной, в `zones._guard` отбивается ступенька больше 0.5 шага. Замер по
  принятым слияниям: на 120 полосах N p99.9 = 0.33 шага, больше 0.5 — 2 из 32 270; на 53 полосах P — 36
  из 10 824.
- **Петит (сноски).** Резка двухрядных сгустков мерила кегль по странице, и два ряда сноски не
  проходили порог. **Правка:** кегль — свой у каждого сгустка; если в сгустке есть глиф выше 1.6 его
  букв (сросшиеся буквы рядов), уровни признаются и по двум буквам (1974/09 IMG_0113_2R).

Сводное сравнение HEAD (`c37863b`) против трёх правок на P (379 полос: 70 + прежние P) ∪ N (352):

| | Перескоков | Полос с перескоком | Новые | Ступенек | Скрещиваний | Изменилось полос |
|---|---|---|---|---|---|---|
| P | 87 → 26 | 69 → 21 | 0 | 1 → 0 | 5 → 2 | 98 |
| N | 1 → 0 | 1 → 0 | 0 | 0 → 0 | 1 → 1 | 27 |

Глазами: все 27 полос N — без порчи (оси по середине строк вместо просадки на наклоне и загибе,
заголовки «ПИСЬМА», «ИНФОРМАЦИЯ», «Индустрия» — по своему наклону); на P — оба случая оси «не по
середине», «района (Кпр).», «72,3%.», сноски петитом, 1973/12 IMG_0297_2R (одна из четырёх осей).

## Короткие куски у конца строки, глиф из двух рядов, «%» из обрывков (2026-09-29)

Три правки поверх v4, проверка «было | стало» на P (379 полос) ∪ N (352) стендом `research/row_jumps`
(`/mnt/system/raw/mts/pack1_row_jumps3/`, `…/pack1_row_jumps4/`).

- **Звёздочки «* * *» под концом строки** (1969/02 IMG_0101_1L). Ступенька на стыке не мерилась у
  кусков короче 3 букв. **Правка:** `zones.joint_step` меряет короткий кусок по медиане якорей его
  НЕнизких букв (кусок из одних меток — не меряется), наклон — по длинному; порог для пары
  «короткий + длинный» — 0.6 шага (`JOINT_STEP_SHORT_PITCHES`; на 120 полосах N из 8 690 таких
  слияний больше 0.6 — 2).
- **Хвост «у» коснулся «Ш» строки ниже** («ку»» / «ШС-60, 275», та же полоса): один глиф в два ряда
  держал «к», «у» и «ШС-60.» одним сгустком. **Правка:** `segment._cut_tall_glyphs` режет глиф выше
  1.9 букв своего сгустка и не шире 4 букв по самой узкой строке перемычки в средней трети (перемычка
  ≤ 0.3 ширины глифа, половинки ≥ 0.6 буквы). Кегль — по буквам своего сгустка: по странице резались
  буквы крупных заголовков.
- **«%» из обрывков** (1973/10 IMG_0194_1L «10%.», 1969/05 IMG_0080_1L «9%», 1975/11 IMG_0083_2R «88%.»,
  1975/01 IMG_0026_2R «100%»). «%» распадается на 2–4 компоненты (кружки, черта); кружок не узнавался
  знаком над буквой (у куска из цифр икс равен высоте цифры, середины масс кружка и черты расходятся
  меньше чем на полыкса), базовая линия знака задиралась на 7–10 px, и короткая последняя строка
  абзаца цеплялась к строке выше. **Правка** в `pieces.baselines_of`: обрывки одного знака друг над
  другом (перекрытие по x ≥ 0.2 ширины узкого, середины расходятся ≥ 0.25 икса, просвет ≤ 0.25 икса,
  каждый обрывок не выше 1.8 икса) склеиваются в один глиф до поиска базовой линии (`_glued_groups`);
  на куске до 6 букв тела выносной ищется по уровню ОСТАЛЬНЫХ букв (`_hangs_leave_one_out`: прямая
  от 4 букв, иначе медиана) — склеенный «%» с центром масс у нижнего кружка тянул МНК-прямую по трём
  точкам.

## Участки перескока в API и на оверлеях (2026-09-29)

- **API.** `LineAxis.jump_spans` — участки по x, где ось уходит на соседнюю строку. Проставляет
  `page.marked_jumps` после сборки блоков: перескоки — `metrics.row_jumps_of` (шаг строк по рядам),
  участок — `metrics.jump_span` по соседу с наименьшим разбросом. Если уровни расстояния до соседа у
  концов оси расходятся (ось перешла на строку и осталась), участок — сам переход; если ось ушла и
  вернулась — весь уход. Ось заменяется и в `analysis.axes`, и в рядах блоков.
- **Меры формы** (`slope_deg`, `sagitta_mm`, `bend_mm`, `resid_parabola_mm`) у такой оси — по самому
  длинному участку без перескока (`lines.clean_run`), а не по концам через две строки.
- **JSON.** В разборе текстовых блоков (`report.page_json`) у оси — `jump_spans`; в итоговом JSON пака —
  `text_blocks.row_jump_spans` (`axis`, `x0`, `x1`, `y0`, `y1`, пиксели рабочей копии), `row_jumps` —
  число осей с участками.
- **Оверлей** (`text_blocks.overlay`, им же рисует пак): участок — полупрозрачная красная полоса
  `(60, 60, 220)`, альфа 0.45, в 0.8 высоты строки вдоль оси; строка в легенде.

Проверка на 12 полосах с перескоками (`/mnt/system/raw/mts/pack1_row_jumps/v4_перескоки_3/`): 16
участков; на местах перехода — «ГДР», «МЕТОД», промежуток между подписью и текстом (1974/03), между
колонками списков (1972/12, 1973/12). У подписи, сращённой с целой строкой текста (1970/11
IMG_0086_1L), участок — вся ось.

## Что пробовали и отвергли

- Синтетическая полоса с косой чертой как тест на весь разбор — черта, касающаяся букв, сливается
  с ними в один глиф (такой мост резка по уровням букв не разделит), а отдельная тонкая черта гаснет
  при уменьшении до рабочей копии; тесты сделаны на уровне меры и смыкания.
- Сосед меры с перекрытием 60 % длины оси — остаток строки, с которой ось ушла, накрывает только её
  часть и выдаёт перескок за норму; взято 90 %.
- Глиф-мост в группу ближнего уровня — вытягивает её сгусток обратно на два ряда.
- Опускать на базовую линию ВСЕ мелкие верхние глифы — дефис и сноска «²» уводят сцепку на соседний
  ряд (1971/04 IMG_0005_2R, 1973/02 IMG_0095_1L); взяты только знаки над буквой.
- Страховка второй оси (откат на первую ось, если вторая отходит больше полувысоты строки) — откат
  приносит скачки первой оси: на P ступенек 0 → 25, на N появились перескоки на 3 полосах.
- Абсолютный предел ступеньки без учёта касательной концов — наклонная строка давала ложную ступеньку;
  ступенька считается за вычетом подъёма по средней касательной (зажатой в ±5°).
- Кегль для резки по всей странице — сноски петитом не резались (порог 1.6 страничной буквы).
- Местная кривая стороны без ограничений — заходит в серию отступов списка (1966/05 0260_2R); с
  ограничением наклона, но двусторонним отсевом — в края рисунка внутри блока (1971/01 IMG_0032_1L).
- «%» правкой признаков знака над буквой по отдельным обрывкам («ниже» по низам боксов, узость по иксу,
  меньший подъём у знака над глифом) — на «6%.» из четырёх обрывков прямая через три из них подняла
  саму «6» на 22 px (1969/03 IMG_0124_2R, на N: «%» отвалился от строки); взята склейка обрывков.
- Выносной по прямой через две оставшиеся буквы — на «5—7%» выносной объявлялась «5» (1975/02
  IMG_0058_2R, новый перескок на N); до трёх оставшихся — медиана.
- Склейка обрывков без предела высоты — глиф 2.4 икса (буквы двух строк) склеивался с буквой строки
  выше, и кусок садился между строк (1967/06 IMG_0144_2R, новый перескок).
