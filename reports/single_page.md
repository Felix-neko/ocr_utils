# «В кадре одна страница» в scan_cropping v2

## Задача

На фото-съёмке подшивок и выпусков бывают кадры не с раскрытым разворотом, а с одной страницей: крышка подшивки
(лицо и оборот), обложка выпуска без подшивки, страница «фото по страницам», где соседняя видна полоской у корешка.
v2 такие кадры всё равно режет на две страницы. Пример — ПХ 1975/10 IMG_0085 (задняя крышка, мраморная бумага и
штрихкод): выход страниц записал `IMG_0085_L` на весь лист и `IMG_0085_R` — полоску 15 мм по ложному корешку
(лист `/mnt/hotstore/scan_processing/scan_cropping_v2/ph/pages_try/1975_sel/debug/08_rectify/10/IMG_0085_08_rectify.jpg`).
Нужно распознавать такие кадры и не строить две страницы.

## Где v2 решает число страниц

1. `paper.sam3_pages` — экземпляры-страницы SAM 3 (`inst` в `sam3.npz`), слияние вложенных (`merge_inserts`).
2. `glue.split_pages` — страницы бумаги: при ≥ 2 экземплярах пиксели раздаются ближайшему экземпляру; **при одном —
   запасной разрез по «корешку» = самому глубокому провалу профиля оболочек печати в средних 20–80 % книги**, если по обе
   стороны есть ≥ 1000 px печати; иначе компоненты маски. Проверки, что провал — настоящий корешок, нет.
3. `page_pose.frame_pages` / `page_quads` — страницы ≥ 5 % бумаги, трапеции, позы (`pages.json`); одна страница —
   поза `FLAT`.
4. Дальше по числу трапеций: `pipeline.spine_on_frame` (шов закраса), `keystone.plan_warp` (одна трапеция
   поддержана), `coons_layout.coons_warp` (`NOT_TWO_PAGES` → откат на трапеции), `pipeline.frame_spread_lines` и
   `spread_fit` (`None` при числе трапеций ≠ 2) → `write_rectified_pages`: без областей двух страниц —
   `pages_status=no_frames`, **кадр в выход страниц не попадает**. `rectify/coons.py` (`plan_layout`, `rectify_maps`),
   `rectify/pages.py` (`page_areas`, `cut_pages`) и `rectify/text_run.text_frame` жёстко рассчитаны на две области.

Ветки «одна страница» до выхода страниц нет: одна трапеция проходит основной итог (вырезка, закрас без шва), но
страниц не даёт; ложная вторая трапеция даёт две страницы.

## Правило

`research/single_page/rule.py`, пороги — середины зазоров распределений:

1. бумаги нет или рамка бумаги ниже **130 мм** → `no_page` (зазор 72 … 195 мм);
2. одна трапеция → `single`;
3. две трапеции, узкая уже **0.5** широкой **и** рамка бумаги уже **0.78** своей высоты (зазоры 0.39 … 0.714 и
   0.72 … 0.807; условия независимы, оба нужны) → одна страница: экземпляр SAM 3 один (две «страницы» — от разреза по
   печати) — `single`, экземпляров два (настоящий корешок) — `sliver`;
4. иначе `spread`.

Сверка (`evaluate.txt`):

| разметка \ вердикт | spread | single | sliver | no_page |
|---|---|---|---|---|
| single (21) | 0 | 19 | 0 | **2** |
| sliver (31) | 0 | 0 | 31 | 0 |
| no_page (29) | 0 | 0 | 0 | 29 |
| spread (4 658) | **4 658** | 0 | 0 | 0 |

**Ложных срабатываний на разворотах — 0 из 4 658**, в том числе карточка-вклейка ПХ 1974/01 IMG_0005/0006 (отношение
ширин 0.94 / 0.86), полоса-вклейка у корешка (набор `gutter_strip`, ПХ 1975), все кадры с поднятой или опущенной страницей (поза `raised`/`lowered`; узкие среди них — только одностраничные).
Два промаха — передние обложки РИСК 1'93 и 2'93 (`РИСК__1993__01__IMG_0176`, `РИСК__1993__02__IMG_0054`): SAM 3 не
нашёл бумаги вовсе (голубая обложка), кадр уходит в `no_page`. Это не задача правила, а сегментации цветных страниц
(`colour_pages`): по кэшу их не отличить от закрытой крышки (печать и краска внутри книги — в том же диапазоне, что у
коленкора с ярлыком; нужен текст surya по книге).

## План встраивания в v2

1. **Новый модуль `ocr_utils/scan_cropping/v2/single_page.py`** (перенос `rule.py`): `FrameKind(StrEnum)` =
   `SPREAD/SINGLE/SLIVER/NO_PAGE`, константы `MIN_PAPER_H_MM = 130`, `MAX_WIDTH_RATIO = 0.5`, `MAX_ASPECT = 0.78`,
   `classify_frame(pages: list[PageQuad], paper, n_inst) -> FrameKind` и `resolve_pages(pages, kind, book, hulls) ->
   list[PageQuad]`: `SINGLE` — одна `PageQuad` по объединению масок (`fit_enclosing_quad`), поза `FLAT`; `SLIVER` —
   только широкая страница (бумага полоски остаётся в маске бумаги основного итога); `NO_PAGE` — пусто.
2. **`page_pose.page_quads`**: после трапеций — `classify_frame` + `resolve_pages` до `classify_poses` (тогда кусок не
   станет `raised`); `pipeline.write_pages` пишет `frame_kind` в `pages.json` и колонку в сводку `FrameStats`.
   Корень ложного разреза можно закрыть и в `glue.split_pages`: разрез по провалу печати принимать, только если обе
   «страницы» не уже 0.5 друг друга (на наборах эта ветка ни разу не дала настоящий разворот), — но правило после трапеций
   нужно всё равно ради `sliver`.
3. **Подгоночная область одной страницы** — `page_frames.single_frame(page, paint, core_zone, text) -> PageFrame`:
   `fit_boundary_adaptive` с обеих сторон как с внешних (без `fold_points` и `spine_zone_mm`), `far` — левая сторона,
   `spine` — правая кривая; `pipeline.spread_fit` при одной трапеции зовёт её (`SpreadFit.frames` из одной области,
   `spine=None`, без `find_strip`).
4. **Кунс по одной области** — `rectify/coons.py`: `plan_layout`/`rectify_maps`/`rectify_maps_scaled`/`coons_at` от
   `tuple[Patch, ...]` длины 1–2 (`Layout.rects` из одного прямоугольника, `spine_x = None`); `coons_layout.coons_warp`
   — то же для surya (`NOT_TWO_PAGES` только при нуле областей). `page_patch(frame, left_page=True, …)` подходит без
   правки: `far` → левая сторона, `spine` → правая.
5. **`rectify/text_run.text_frame`, `rectify/pages.py`**: одна страница — `controls` из одного `PageControl`, поле по
   строкам одной области; `page_areas` → одна маска; новый `PagePart.SINGLE = "_P"` (суффикс, чтобы в папке страниц у
   каждого файла была часть; `scan_markup/content_box/layers.part_of` дополнить `("_P", "P")` → без стороны разреза,
   `content.cut_side_of` уже вернёт `None`); `wanted_parts(flags, kind)`: `SINGLE` → `[SINGLE]`, `SLIVER` → часть
   широкой стороны (`_L`/`_R`: у неё настоящий корешок, обрезка `content_box` учтёт сторону разреза), `NO_PAGE` → `[]`
   с исходом `PagesStatus.NO_PAGE`.
6. **`pipeline.write_rectified_pages`**: `sides_of[PagePart.SINGLE] = (0,)`, паспорт `part="P"`; `pages_done`
   учитывает `frame_kind` из `pages.json`.
7. Тесты: `tests/ocr_utils/scan_cropping/v2/test_single_page.py` на синтетических масках (лист, разрезанный по
   ложному корешку; страница + полоска; ярлык; разворот с узкой поднятой страницей ≥ 0.714).

## Флаги кадров

Предложение для `ocr_utils/frame_flags` (`FrameFlag`):

* `single-page` — «в кадре одна страница, не резать»: перекрывает автомат (вердикт `SINGLE`, при двух трапециях —
  объединение); вместе с `cover-both` — обложка выпуска. Противоречит `no-splitting`, `ignore-left/right`,
  `cover-left/right` (проверка в `flags.py`).
* `spread` — «это разворот»: выключает автомат на кадре (страховка от будущих ложных срабатываний, сейчас их 0).

Крышки подшивок (ПХ 1975, ХиП, пак-6) автомат честно признаёт одной страницей, но в выход они не нужны — как и сейчас,
их снимает `ignore-both` (навык `frame-flags`, «обложки подшивки»; так помечены ПХ 1974/01 IMG_0001–0002). Отличить
крышку подшивки от обложки выпуска по кэшу нельзя (у ПХ 1975 крышка — бумажная обтяжка с узором и ярлыком).

## Surya и keystone

После `resolve_pages` у одностраничного кадра одна трапеция: `keystone.plan_warp` уже строит одну гомографию
(`spine_x = None`), `warp_for_layout` и `page_of` её поддерживают; холст Кунса для surya станет одной областью (п. 4),
до этого — штатный откат на трапецию (`FramesReason.NOT_TWO_PAGES`). Сейчас у ложно разрезанных кадров surya видит
холст со второй, вырожденной гомографией куска (сход до 90° у ПХ 1975/02 IMG_0086) — после правки это уйдёт.
`spine_on_frame` вернёт `None`, и закрас `border_fill` пойдёт без шва по ложному корешку.

## Что пробовали и отвергли

* `print_spine` (провал печати на линии разреза) — не разделяет: оболочки печати (`hulls`) выпуклые, на развороте
  у корешка медиана 0.90.
* Ширина страницы относительно типичной для набора (`narrow_rel`, `wide_rel`) — разделяет так же, но требует числа на
  пак (или набор без ровных разворотов); отношение двух трапеций кадра — нет.
* Отличить обложку без бумаги (`no_page`, РИСК 1'93, 2'93) от закрытой крышки по краске/печати кэша — не выходит.
