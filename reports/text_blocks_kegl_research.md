# Кегль строки по глифам: как это делают другие

## 1. Tesseract (textord), github.com/tesseract-ocr/tesseract/src

**Главное: мерит не высоту бокса, а ВЕРХ глифа над базовой линией** (`fill_heights`, makerow.cpp:1413):
`top = box.top − baseline(xc)`. Поэтому выносные вниз (р, у, д, ц, щ, ф) дают ту же высоту, что строчные, —
их хвосты не портят распределение вообще.

- Базовая линия (`BaselineRow::FitBaseline`, baselinedetect.cpp:146): точки `(xc, baseline_position)` →
  `DetLineFit` — детерминированный LMedS (минимизирует ошибку верхнего квартиля, не среднее), точка несёт
  полуширину, и точка, перекрытая соседом больше чем наполовину и лежащая дальше, игнорируется (точки «i»,
  диакритика). Если ошибка > 3/64 шага строк — повторить без 3 крайних точек, принять при ошибке вдвое меньше.
  Резерв — обычный МНК. Потом сплайн (`make_baseline_spline`) и выравнивание по сетке шага строк блока.
- Гистограмма `STATS heights[min..max]` с шагом 1 px по `top`; диапазон `min = max(10, 0.25·line_size)`,
  `max = 3·line_size`. Отдельно — «плавающие» глифы: `height/top < 0.75` (тире, кавычки, `^`, степени — висят
  над базой).
- `compute_xheight_from_modes` (makerow.cpp:1475): до 12 крупнейших пиков гистограммы. Пик x — кандидат в
  x-height, если `count(x) − floating(x) ≥ 0.4·count(моды)`; и найдётся пик a с
  `1.25 < a/x < 1.8` и `count(a) ≥ 0.08·count(моды)` → `xheight = x`, `ascrise = a − x`. Нет пары — берётся
  единственная мода без плавающих, `ascrise = 0`. Возвращается «evidence» = число глифов в пике x.
- `compute_row_descdrop`: мода глубин `baseline − bottom` в `[0.25, 0.6]·x`; принимается, если
  (выносных + возможных верхних) ≥ 0.16·evidence.
- Блок (`compute_block_xheight`): медиана x-height по строкам с найденными верхними выносными (вес = evidence);
  иначе — по строкам с нижними; иначе — поиск двух мод по всем строкам; всё прописное → `cap·0.5/0.75`.
- `correct_row_xheight`: строка без выносных, чей «x» в ±10% от `x_блока + ascrise_блока`, — **ВСЕ ПРОПИСНЫЕ**,
  ей ставят x блока; иначе — капитель: `ascrise = h·asc/(x+asc)`, `x = h − ascrise`.
- Уточнение после распознавания (`ComputeCompatibleXheight`, ccmain/fixxht.cpp:105): каждая буква/цифра по
  своему классу знает допустимый диапазон top в нормированных координатах → голосует за ИНТЕРВАЛ
  `[h·X/max_top, h·X/min_top]` с весом = промах; классы с «дикой» разбежкой top (> 48 из 256) не голосуют;
  отдельно голосование за сдвиг базовой линии. Итог — мода голосов.
- Константы ccstruct.h: доли 0.25/0.5/0.25 (desc/x/asc), `kXHeightCapRatio = 2/3`.

## 2. OCRopus / Calamari / kraken / Leptonica / PERO

- **ocropy** `psegutils.estimate_scale` (есть в .venv/ocrolib): компоненты от крупных к мелким, каждая
  закрашивает свой бокс значением `sqrt(area)`, если он ещё пуст (мелочь внутри крупного не голосует);
  `scale = median(scalemap[3 < v < 100])` — ПО ПИКСЕЛЯМ, т.е. взвешено площадью. Масштаб страницы, не строки.
- **CenterNormalizer** (ocrolib/lineest.py, его же использует Calamari): центр строки = argmax гауссова сглаживания
  по столбцам (σ = 0.5h × 1.0h), `mad = mean|y − center|` по пикселям краски, полувысота нормализации
  `r = 1 + 4·mad`. Это оценка масштаба по разбросу краски вокруг осевой — без боксов и классов глифов.
- Breuel 2002 (DRR IX, «Robust least square baseline finding… branch and bound») — модель строки (база + линия
  нижних выносных, робастный МНК, глобальный branch-and-bound); x-height как отдельный параметр в OCRopus 0.x.
- **kraken** (lib/segmentation.py): базовые линии от сети, высота строки — из полигонизатора по соседям;
  x-height не оценивает.
- **Leptonica** `pixFindBaselinesGen` (baseline.c): горизонтальная проекция строки после closing, разность
  соседних рядов; сильные пики = базовые линии (порог — 1/80 максимума).
- **Zramdini & Ingold** (ApOFIS 1995, TPAMI 1998): по профилю Hp строки — базовая линия и «upperline» (верх
  строчных) по перепадам профиля, x-height = их разность; кегль/жирность/наклон — байесовский классификатор.
- **Spitz 1997 (TPAMI)**: база — мода низов компонент, x-линия — мода верхов, строка за строкой.
- **PERO, Kodym & Hradiš 2021** (arXiv 2102.11838): сеть предсказывает на пикселях базовой линии высоту над
  (ascender) и под ней; на строку — **75-й перцентиль** по пикселям базовой линии; вход масштабируется так, чтобы
  медиана ascender была 12 px.
- **Fischer, Hartelt & Puppe 2023** (Algorithms 16:136, /mnt/dump3/DOWN/algorithms-16-00136.pdf, с. 14–15): базовую
  линию от сети сдвигают вверх по пикселю и считают, сколько чёрных пикселей она пересекает; запоминают максимум;
  когда покрытие «значительно» падает относительно максимума — число шагов = x-height (с «тёплым стартом», чтобы
  не оборваться в первых шагах). Числа порога в статье нет; оценка названа грубой. Заголовки отличает сеть
  (Mask-RCNN/классы), а не кегль.
- Bloomberg & Chen 1996: x-height преобладающего шрифта = медиана высот компонент блока.

## 3. Что есть в репо

- `baseline_axis.line_x_height`: 30-й перцентиль высот БОКСОВ, медиана тех, что ≤ 1.2× его.
- `pieces.pieces_of`: `Piece.x_h` = медиана высот букв куска (≥ 3 букв, иначе медиана страницы) — для куска из
  прописных/с выносными это не x-height (в коде это признано).
- `pieces.end_kegl`: вторая по малости высота из 4 крайних букв, метки и знаки ниже `END_KEGL_MIN_XH·x_h` не в счёт.
- `blocks.glyph_metrics` / `axis_glyph_height`: медианы ширины/высоты компонент в [GLYPH_MIN_MM, GLYPH_MAX_MM].
- `defocus_detection/scale.py`: шаг строк по спектру профиля краски (для страницы, не для куска).

Во всех — высота бокса, не верх над базой; поэтому выносные и тире/точки мешают, а решает квантиль.

## 4. Рекомендации для кусков из 3–15 глифов

**A. Верх над базовой линией + две моды (порт Tesseract).** Базовая линия куска у нас уже есть (baseline_axis).
Для каждого глифа `t = baseline(xc) − top`, `d = bottom − baseline(xc)`. Отбросить: плавающие (`h/t < 0.75`:
тире, «», кавычки, степени м², ³), низкие метки (`t < 0.4·x_стр`). Кириллица помогает: строчные почти без верхних
выносных (только б, ф, й/ё с надстрочными), д/ц/щ/р/у/ф внизу на `t` не влияют. Мода/KDE по `t` (σ ≈ 0.05·x_стр,
а не бины по 1 px — при x = 9–20 px бин в 1 px = 5–10%). Нижняя мода x, если есть пик в `1.25–1.8·x` (прописные,
цифры, б) — это cap; нет пары → неоднозначно: либо все строчные, либо всё прописное.
Плюсы: убирает главную шумиху (выносные), даёт x и cap раздельно.
Подводные камни: нужна верная база (у курсива и перекоса — локальная); у заголовков ВСЕ ПРОПИСНЫЕ одна мода =
cap — решать, как `correct_row_xheight`: одна мода, совпадающая в ±10% с `cap` соседа, — тот же кегль; слипшиеся
буквы дают тот же `t`, так что для `t` слипание не страшно (для ширины — страшно).

**B. Сравнение кусков голосованием интервалов, а не точечными оценками (идея fixxht).** Каждый глиф с `t`
голосует за x ∈ {t} (как строчная) и за x ∈ [t/1.8, t/1.25] (как прописная/цифра) с весами по форме (строчные
шире и ниже, у цифр/прописных меньшая доля пустоты; без OCR — слабые веса). Для пары кусков считать
правдоподобие общей x (сумма голосов обоих при одном x) против лучших раздельных x: log-отношение даёт
«тот же кегль?» с учётом числа глифов — кусок из 3 глифов сам собой получает широкий интервал, и порог
промежутка можно брать от НИЖНЕЙ границы общего x, а не от шумной точки. Подводные камни: веса форм
калибровать по паку (правило CLAUDE.md про пороги), курсив сдвигает ширины.

**C. Профиль краски вдоль оси (Zramdini/Leptonica/CenterNormalizer) как второй независимый замер.** Выпрямить
полосу куска по базовой линии, взять горизонтальный профиль; x-линия и база — по наибольшим перепадам профиля
(субпиксельно, парабола по трём точкам), x = разность; разброс `mad` краски — дополнительная мера. Не зависит от
разбиения на компоненты (слипание при расфокусе, разрывы тонких штрихов), даёт долю пикселя. Подводные камни:
на 3–4 глифах перепад x-линии слабый, у прописных профиль без ступени; жирность раздувает профиль на толщину
штриха — вычитать `stroke_weight` или сравнивать только куски близкой жирности.

Практически: основная оценка — A; B — решающее правило «одинаковый кегль / промежуток в x» с неопределённостью;
C — проверка на кусках ≥ 6 глифов и там, где A даёт одну моду. Метрику ratio брать как `max(x1/x2, cap1/cap2)` только
по однородным парам (x↔x, cap↔cap, либо cap↔x·(1.25–1.8) с явной неоднозначностью), а не медианы смешанных высот.
