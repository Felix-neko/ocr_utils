# Внешний OCR: паразитные заголовки в md выпуска — id статей и рубрик (промпт v20), номера страниц по соседям, сверка с оглавлением на сборке

## 1. Задача

В целиковых md выпусков (`out/{год}/{год}_{выпуск}.md`, до 21.09.2026 — `out/{год}/{выпуск}.md`) пакета `ocr_utils/external_ocr_services` `#` бывало больше,
чем статей в оглавлении: лишний `#` режет статью пополам при будущей нарезке по статьям для LCIR
(на вход LLM — целая статья, не половинки). Задача из `задачи на перспективу/дублирование_заголовков.md`:
разобраться, откуда берутся лишние `#` (и есть ли то же у `<rubric>`), и сделать так, чтобы в md
выпуска на статью приходился ровно один `#`, на рубрику — один `<rubric>`, с id из оглавления, по
которому нарезка их найдёт. Проверить, что новый промпт не ухудшил распознавание текста и пометку
повреждённых букв, — отдельный отчёт `reports/external_ocr_prompt_v20.md`.

## 3. Разбор: откуда лишние `#`

Скрипт по 15 выпускам (теперь `scripts/check_issue_headings.py`): `#` в теле против статей `toc.json`.
Лишние `#` — в 6 выпусках (1974/02, 03, 08, 10, 11, 1976/12), 12 штук, плюс скрытый дубль в 1974/05
(одна статья без `#` компенсировала один дубль). Все 12 — из сырого ответа модели, все с
`title_in_list: true`; код ни одного не добавил и не снял. По сканам:

| источник | сколько | пример |
|---|---|---|
| продолжение статьи, в колонтитуле — рубрика; модель подставила название единственной статьи этой рубрики из списка промпта | 8 | 1974/05 с. 33: колонтитул «В коллегии Госснаба СССР» → `# Повышать эффективность снабжения`; 1974/03 с. 7: колонтитул «Сотрудничество развивается» → полное название из списка с уточнением в скобках, которого на полосе нет |
| колонтитул с названием статьи переписан как `#` | 1 | 1974/03 с. 43 |
| вторая полоса двухстраничного «Содержания» с выдуманным `# СОДЕРЖАНИЕ` (`continues_previous: false`) | 2 | 1974/08 IMG_0055_1L, 1976/12 0030_1L |
| шапка журнала как `#` на полосе содержания | 1 | 1974/11 IMG_0053_2R |
| лозунг под фото, совпавший с названием статьи | (1 из 8 выше) | 1974/02 IMG_0054_1L, статья начинается на с. 13 |

Почему код не ловил: `demote_unlisted_headings` *защищает* `#`, совпавший со списком;
`drop_leaked_titles` смотрит только `##`; на сборке заголовки между собой и с `toc.json` не
сверялись. Запрет в промпте («продолжение не получает название из списка», с v7) модель не
останавливал. `<rubric>`: модель писала рубрику из колонтитула тегом на 77 полосах, но страховки
(`drop_header_rubrics`, `drop_repeated_rubrics`) снимали всё, кроме трёх тегов, где модель записала
колонтитул вместе с номером страницы («Резервы — на службу пятилетке! 65») и точное сравнение не
сошлось.

Ключевое наблюдение: фантомы модель ставила с **верным** названием из списка, значит id сами по
себе их не отсеют (с id она поставила бы верный id на фантом) — отсеивает номер страницы из
оглавления на сборке. Id нужны для другого: сопоставление при перефразированном названии («Сотрудничество
развивается» против полного с уточнением — 0.46 по `difflib`), пометка колонтитулов, стабильная
идентичность статьи для нарезки.

## 4. Что сделано

### 4.1. Id статей и рубрик (`toc.py`, `schema.py`)

`TocArticle.id`, `TocSection.id`; `toc.assign_ids` при слиянии «Содержания»: статьи `A1…` по порядку
чтения, рубрики `R1…` по первому появлению, секции с одной рубрикой делят id; `toc.json` прежних
прогонов получает id при чтении тем же правилом. Буква, а не число или hex, чтобы модель не путала
id с номером страницы или пункта. `prompt_lists` отдаёт статьи `{"id","title","authors","rubric","rubric_id"}`
и рубрики `{"id","title"}`; `toc_hash` меняется сам — все полосы устаревают для `--skip-done`.
`toc.best_title_match` — выбор одного лучшего совпадения (равенство → вхождение → похожесть ≥ 0.75).

### 4.2. Промпт v20 (`prompts/`, `PROMPT_VERSION = 20`)

* Список в пользовательском сообщении: `* A3: «Название» — авторы [рубрика R2: …]`, `Rubrics: R1 «…»`.
* Id — **в полях JSON, не в тегах** (`<articleheader id=…>` из исходной задачи отвергнут: атрибут
  внутри тега — самое слабое место DeepSeek, омоглифы/пробелы/кавычки, и формат md менялся бы для
  всех потребителей): `headings: [{"text","article_id"}]` на каждый `#`, `rubrics: [{"text","rubric_id"}]`
  на каждый `<rubric>`, `running_header_article_id` / `running_header_rubric_id` / `running_footer_…`.
  Поля `title` / `title_in_list` / `rubric` из схемы убраны (при разборе выводятся из новых, файлы до
  v20 читаются).
* Правило о рубрике ужато (по решению пользователя): шапка раздела → `<rubric>` с id; строка в
  верхнем **или нижнем** поле → только поля колонтитула с id; «не разобрать — в колонтитул, код
  восстановит». Запрет выдумывать заголовок продолжения дополнен «даже если колонтитул называет
  статью или её рубрику». Переводы `system.ru.md`/`user.ru.md` обновлены.
* Повторов запроса при плохом id нет (при `temperature 0` тот же запрос — тот же ответ, кэш вернёт
  его с диска): `#` без id или с чужим id получает id по названию, доля таких — метрика промпта
  (`meta.structure.heading_ids`, колонка `heading_ids` в `summary.csv`, строка в итоге прогона;
  порог 30 % — критерий смены модели по задаче).

### 4.3. Доводка полосы (`structure.py`, `ocr.py`)

`heading_refs` / `rubric_refs`: id модели принимается, только если согласован с текстом
(`title_matches` с названием по этому id), иначе по названию; `headings`/`rubrics` переписываются
ровно по строкам тела — источник истины для сборки. `drop_header_rubrics` сравнивает колонтитул без
цифр (закрыло три утечки). Страховку «снять `#` с текстом колонтитула» на уровне полосы **не
делал**: в журнале, где название статьи печатается в колонтитуле и на первой полосе, она снесла бы
настоящий заголовок; фантомы снимает только сверка по выпуску (кандидатов ≥ 2).

### 4.4. Номера страниц по соседям (`numbering.py`)

У каждой пятой полосы МТС номер не напечатан. Смещение «номер − индекс полосы» постоянно на участке
сплошной нумерации: каждая сторона (до 3 ближайших нумерованных полос) надёжна, если ≥ 2 её полосы
дают одно смещение; стороны согласны — их смещение, надёжна одна — её, обе надёжны, но разные
(вклейка без номеров, разворот одной картинкой) — ближняя, при равном расстоянии — номер не
выводится. Напечатанный номер против двух согласных сторон — `suspect` (опечатка модели: «44» вместо
41, «2» из подписи тетради «2 МТС № 5»). Замер на 15 выпусках, 1291 нумерованная полоса с поочерёдно
спрятанным номером: **98,8 %** угадано, 0 не выведено, 15 «ошибок» — ровно те опечатки, что
помечаются `suspect`. В sidecar `suggested_page_number`, `page_number_source`.

### 4.5. Сверка с оглавлением на сборке (`reconcile.py`, вызов из `assemble.py`)

После склейки стыков, до `drop_repeated_rubrics`; работает по блокам выпуска, правки применяет
`assemble._apply_edits` (удаление, замена, вставка; начала полос пересчитываются).

* **Статьи.** Каждый `#` → статья по id из `headings` полосы (если согласован с текстом), иначе по
  названию. Настоящий — на странице статьи по оглавлению (номер напечатанный или выведенный), иначе
  ближайший по номеру, иначе первый. Фантомы: **удалить**, если текст ≈ колонтитул (без цифр) или
  `#` сверху полосы, полоса не страница статьи и ниже идёт текст; иначе (лозунг под фото) → `##`.
* **Статья без `#`** восстанавливается: из тела своей страницы — короткий абзац, похожий на
  название, набранный `##`–`######`, жирным, курсивом или подчёркнутым, становится `#` как напечатан
  (с пометкой «Тема:»; лекции «Экономического образования кадров»: «**Тема: Ленинские принципы…**»
  под названием курса); иначе из колонтитула с её id — но только если текст колонтитула похож на
  название: модель ставит id статьи и колонтитулу с одной лишь рубрикой, и без проверки
  `# Экономическое образование кадров` вставал посреди лекции (1974/02, 1974/05 — поймано и исправлено).
* **Рубрики.** `<rubric>` → рубрика по id/тексту; настоящий — непосредственно перед `#` первой статьи
  раздела (или ближайший выше без текста между), раздел дважды в выпуске — два; остальные: ≈
  колонтитул → удалить, иначе → `<marker>`. Без тега: `<marker>` с текстом рубрики над `#` первой статьи
  → `<rubric>`; иначе из колонтитула с её id, похожего на название («Плановое хозяйство»; эмблема
  «АСУ МТС» 1974/08). Не напечатанная нигде — не вставляется (решение 19.09).
* **Полосы оглавления.** `#` не заголовок списка → `##`; вторая подряд полоса того же вида (или
  слитая по `<toc>`) теряет `# СОДЕРЖАНИЕ`; заголовок годового указателя — статья «Содержания», остаётся.
* Перед настоящим `#` — `<!-- article A3 -->`, перед `<rubric>` — `<!-- rubric R2 -->`; в sidecar
  `articles` / `rubrics` (id, название, страница по оглавлению, `status` found / restored / missing,
  полоса, номер, `offset`, `line`), `phantom_headings`, `phantom_rubrics`, `toc_page_headings`.
  `drop_repeated_rubrics` остаётся последней страховкой.

### 4.6. Стенд и проверка

`scripts/replay_page.py --toc-root` (список статей с id в промпт из `toc.json` боевого прогона) и
метрики id в `summarize`; `scripts/check_issue_headings.py --pages-dir …/pages --issues-dir …/out [--verbose]` — `#` в теле
против оглавления и итог сверки по всем выпускам.

### 4.7. Сбои разбора ответа (21.09)

Прогон пака дал 15 сбоев «невалидный JSON»: 12 — модель зациклилась до потолка токенов в обоих
режимах JSON, 3 — битые `\`-escape в строке (`\(разборных\)`, `\н`). Сделано: терпимый разбор
escape (`schema._repair_escapes`, счётчик `repaired_escapes`) — закрыл все 3; потолок токенов
16 000 → 10 000 (99,9 % ответов ≤ 6006 токенов, максимум 6774); второй раунд запроса с пометкой о
причине в конце пользовательского сообщения (`PageJob.retry_note`) после исчерпания режимов JSON или
ошибки разбора — без подъёма температуры (при `temperature 0` иной текст и так даёт иной ответ) —
снял 5 из 12 циклов. 7 полос зацикливаются и с пометкой (0,06 % пака), остаются без результата.
Заодно: `#`, названный моделью в `headings`/`title`, но не написанный в теле, вставляется кодом
(`structure.restore_heading_from_refs`; 1966/03 «Важная служба»).

### 4.8. Статьи без `#` после сверки: ярусы A и B (21.09)

После сверки по всему паку без заголовка остались 12 статей из 2884. По страницам из оглавления:
1 — заголовок напечатан и транскрибирован, но похожесть ниже 0.75 («НА ОДНОМ ИЗ ГЛАВНЫХ НАПРАВЛЕНИЙ»
↔ «На главном направлении», 0.72); 6 — запись оглавления есть раздел («Информация», «Наш стол справок»,
«Зарубежный опыт», «Критика и библиография»), на полосе — `<marker>` с тем же текстом; 3 — строки с
названием в транскрипции нет (лекция 1973/04, сборник «Типовые положения…» 1976/10–11); 2 — мусор
оглавления (выходные данные как статья; название, разрезанное переносом на две записи).

**Ярус A — код** (`reconcile._restore_from_body`, только когда у статьи нет ни одного `#`):
кандидаты — `##`–`######`, жирный, курсив, подчёркнутый **и `<marker>`**; окно — полосы с номером
страницы статьи, затем ±1; строгое совпадение (`title_matches`) берётся сразу, иначе лучший по
`difflib` ≥ 0.6 (`BODY_TITLE_MIN_RATIO`) и только если второй кандидат на полосе отстаёт на ≥ 0.1
(`BODY_TITLE_MIN_GAP`) — иначе неоднозначно, оставить модели. `<rubric>` кандидатом не бывает: тег
уже принадлежит разделу. В sidecar `source`: `body` / `body_loose` / `marker` / `running_header`.

**Ярус B — вспомогательный запрос модели** (`heading_check.py`, `--check-headings`, по умолчанию
включён), **текстом, без картинок**: один запрос на выпуск (до 10 статей) — всё оглавление выпуска
(контекст, что уже привязано), непривязанные статьи и для каждой до 20 пронумерованных
строк-кандидатов из транскрипции полос окна ±1 (`##`, жирные и курсивные абзацы, маркеры, первые
два абзаца полосы; без окна — только заголовочные строки со всех полос). Ответ — номер строки и
`confidence`; принимается только `high`, строка из окна и не маркер с названием рубрики оглавления.
Принятая строка → `#` (`source: model`, вердикт в sidecar `model`), отклонённая — `missing` с
`model.status: rejected`. Промпты `prompts/heading_system.md.j2`, `heading_user.md.j2` (перевод
`heading.ru.md`), `HEADING_PROMPT_VERSION = 1`; кэш `cache/{год}/{выпуск}/_headings/`, ≈ 0.05 ¢ на
выпуск. Сборка идёт в два прохода сверки: пробный на копии блоков — узнать `missing`, запрос,
основной с подсказками (`reconcile_headings(hints=…)`). Мусор оглавления в запрос не идёт —
`status: skipped` с причиной (`reconcile.skip_reason`).

Попутно вскрытое аудитом: повтор сбойных полос списком `--pages` шёл без списка статей (полос
оглавления в списке нет) — теперь `toc.json` берётся с диска; понижение `#` смотрело только первую
строку абзаца — шапка журнала «Материально-/техническое/снабжение» одной строкой «Материально-»
входила в название статьи (1972/04) — теперь по абзацу целиком; `# СОДЕРЖАНИЕ` на полосе оглавления
уходил лекции «… Содержание …» по вхождению слова (1973/06) — кандидат только по началу названия;
восстановление из тела брало чужой готовый `#` (1976/08) — готовые `#` пропускаются.

## 5. Результат

### 5.1. Сверка на полосах v19 (без перегона, id по названию)

Все 15 выпусков: 12 фантомов сняты (11 удалено, лозунг под фото понижен), 3 лишних `<rubric>`
удалены, `#` в теле каждого выпуска = заголовки списков + найденные статьи, настоящие заголовки не
тронуты; без `#` осталось 8 статей (нет заголовка в транскрипции).

### 5.2. Пробник v20 (replay, 44 полосы × 2: 12 полос с фантомами, 16 первых полос статей, 10 с
печатными шапками рубрик, 6 продолжений с рубрикой в колонтитуле)

* `#` с id от модели **26 из 26**, чужих id 0 (в обоих повторах).
* На всех 7 полосах-продолжениях, где v19 выдумывал `#`, у v20 `#` нет: статья/рубрика уходит в
  `running_header_article_id` / `rubric_id` («Сотрудничество развивается» → A1; «Официальный отдел» → R6).
  Лозунг под фото (1974/02 IMG_0054_1L) — по-прежнему `#` с A2, его понижает сверка.
* `<rubric>` с id от модели 7 из 8; восьмая (1974/09 IMG_0144_2R, шапка «В ГОССНАБЕ СССР» с
  буквицей) — модель написала `<marker>` без записи в `rubrics`; код перетегировал по оглавлению и
  присвоил R6 по названию.

## 6. Что пробовали и отвергли

* Id в тегах `<articleheader id=…>` / `<rubric id=…>` — атрибут внутри тега у DeepSeek ненадёжен
  (история `<toc>`: 1–11 верных из 20), формат md менялся бы; id — полями JSON.
* Повтор запроса при плохом id «до 3 раз» — бессмыслен при `temperature 0` и кэше запросов; id
  присваивает код, доля — метрика.
* Снимать `#` с текстом колонтитула на уровне полосы — снесло бы настоящий заголовок там, где название
  печатается в колонтитуле и на первой полосе; только сверка по выпуску.
* Восстанавливать заголовок по одному лишь `running_header_article_id` — модель ставит id статьи по
  колонтитулу с одной рубрикой; нужна похожесть текста колонтитула на название.
* Восстанавливать заголовок из тела с любой страницы — повтор «Тема: …» в тексте другой страницы стал бы
  заголовком; только страница статьи по оглавлению.
* Обходиться промптом (запрет с v7 и его усиление) — сам по себе фантомы не убирал; убрала связка
  «поля id колонтитула как выход для модели» + сверка по номеру страницы.
* Слать в ярус B картинки полос — не понадобилось: текстовый запрос закрывает перефразировки, а то,
  чего нет в транскрипции, — одна статья на пак; решение пользователя — только текст.
* Принимать в ярусе B маркер с названием рубрики оглавления за название статьи (модель отдала
  «ОФИЦИАЛЬНЫЙ ОТДЕЛ» за «Типовые положения…» с `high`) — отклоняется кодом.
* Ослабленный порог без проверки отрыва от второго кандидата — два подзаголовка одной темы на
  полосе дали бы случайный выбор; при отрыве < 0.1 статья уходит модели.
* Повтор запроса при сбое разбора с подъёмом температуры — заменён пометкой в тексте запроса: при
  `temperature 0` иной текст даёт иной ответ, а пометка объясняет модели, что чинить.

## 7. Что дальше

* Нарезка выпуска по статьям для LCIR — по `articles[].offset` из sidecar (или комментариям
  `<!-- article A3 -->`); рубрика статьи — из `toc.json` по `rubric_id`; статьи со `status: skipped`
  (мусор оглавления) нарезке не нужны.
* 7 полос пака зацикливаются до потолка токенов и с пометкой повтора — следующий ход для них другая
  нарезка тайлов на повторе (три полосы по вертикали вместо двух).
* Название, разрезанное переносом на две записи оглавления (1976/08 «О разработке и внедрении систе-» /
  «мы обеспечения…»), — чинить на этапе слияния оглавления (`toc.merge_pages`): запись со строчной
  буквы без автора приклеивать к предыдущей.

  раздела» проверено тестом и одним случаем МТС («АСУ МТС»); на самом журнале не гонялось — нет `toc.json`.
* Недопометка срезанных букв на с. 1 1991/02 у v20 (см. отчёт по регрессии).
* 11 замечаний аудита по месту/порядку — просмотрены, дефектов нет; при следующих паках смотреть
  вывод `check_issue_headings.py --verbose` тем же способом.
