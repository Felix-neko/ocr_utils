# Отбор статей пака-1 о проблемах предприятий: LLM по статье на запрос

Дата: 2026-09-30. Стенд: `research/article_problems`. Прогон пака: `run_scripts/article_problems/run_pack1.sh`.

## 1. Задача

Среди 2880 статей журнала «Материально-техническое снабжение» (пак-1, 1966–1976) нужно найти случаи
по десяти классам: предприятие не может найти запчасти (1); производитель выпускает не то, что нужно
потребителям (2); производитель не делает запчасти или делает их мало (2.1); прежнюю модель заменили
более дорогой, а производительность выросла меньше цены (3); непоставка (4); несвоевременная поставка (5);
брак и некондиция (6); любые конкретные проблемы (7, объединение); плохая работа подразделений Госснаба (8);
советское намного дороже или хуже иностранного (9); производитель отказывается делать продукцию из своего
же ассортимента (10). По каждому классу статьи модель пишет короткое резюме «почему сюда», по каждому
случаю — цитату и объяснение. Ключевые слова для этого не годятся: предыдущий разбор показал, что
они ловят 38 % статей и выносят наверх нормативку (`reports/article_filter_enterprise_problems.md`).

## 2. Стенд и данные

- Вход: `…/md-файлы/пак-1/{год}/{год}_{выпуск}.md`, 123 выпуска. Нарезка на 2880 статей идёт по маркерам
  `<!-- article An -->` сборки внешнего OCR. Статьи — от 2,5 тыс. до 151 тыс. символов, медиана 10,5 тыс.
- Модель: `deepseek/deepseek-v4.1-flash`, контекст 1 млн токенов, статья целиком в одном запросе.
  - Пилот — синхронный chat/completions через провайдера DeepSeek без квантования: $0,15 / $0,60 за млн
    токенов, ответ сразу.
  - Пак — Batch API `deepseek/deepseek-v4.1-flash:batch` (провайдер DeepInfra): $0,112 / $0,336 за млн
    токенов, окно 24 ч. Chat/completions с этим слагом отвечает 404, работает только
    `POST /api/v1/batches`. Отменить пачку нельзя: у API есть только list, create, get и delete,
    а delete работает лишь для завершённых пачек.
- Кэш: `/mnt/hotstore/scan_processing/mts_markup/article_problems/cache/`, ключ — хэш payload (`external_ocr_services.cache`).
  Все ответы сохранены, повторный разбор бесплатен.
- Код: ветка `zonal_defocus_with_surya`, база `4f39abe`.

## 3. Метод

Long Context Information Retrieval по одной статье на запрос. Модель получает паспорт статьи (год, выпуск,
рубрика, заголовок, авторы) и её текст целиком. Её просят пройти статью до конца, выписать **все** случаи
(вложенные письма `##`, таблицы, сноски), дать каждому классы, пострадавшего, виновника и его вид,
продукцию, дословную цитату, объяснение и признак конкретики, а затем резюме по каждому классу статьи.
Ответ — JSON (`response_format: json_object`, схема описана в промпте).

Код после ответа:
1. Нормализует классы. Класс 7 ставится на каждый случай. Если виновник — подразделение Госснаба
   (`culprit_kind = gossnab_body`), ставится класс 8: без рассуждений модель теряла его в 13 статьях из 18.
2. Ищет каждую цитату в тексте статьи. Сначала точное совпадение после нормализации (регистр, ё/е, кавычки,
   тире, теги, пробелы), затем rapidfuzz `partial_ratio` ≥ 90. Записывает строку файла выпуска.

Пилот: выпуски 1968_09 и 1973_05, 55 статей. Эталон размечен по тексту всех 55 статей: для каждой статьи
классы с обоснованием и цитатой, для каждого случая модели — валиден ли он и верны ли классы. Точность
и полнота считаются по статьям (класс у статьи есть или нет), классы кроме 7.

## 4. Результат пилота

Контрольная статья 1968_09:A15 «Причина неритмичности» состоит из двух писем. Во всех вариантах
найдены оба: Ржевскому заводу не допоставили прокат (4, 5, 8 — Калининская контора металлоизделий)
и Тбилисскому метро не дают запчастей (1, 2, 2.1, в v3 ещё 10). Все цитаты нашлись в тексте.

| Вариант | Точность | Полнота | Главные ошибки | Цена 55 статей (sync) |
|---|---|---|---|---|
| v1, без рассуждений | 65 % | 66 % | теряет 8 (полнота 28 %), ставит 1/2.1 на любой дефицит (микроскопы, поддоны, баллоны) | $0,073 |
| v1, low | 84 % | 93 % | дробит методические перечни, 4 при нехватке фондов | $0,199 |
| v1 + правило «Госснаб → 8», без рассуждений | 65 % | 88 % | | $0 (пересчёт кэша) |
| v2, без рассуждений | 83 % | 80 % | пропуски 5 и 6 | $0,070 |
| v2, low | 81 % | 86 % | 2 на спорных случаях (3 из 6 ложных — пограничные) | $0,207 |
| **v3, low** (выбран) | **83 %** | **86 %** | 2: 4 ложных; 10 у отказа теруправления, а не производителя | $0,183 |

Цитаты: 251 из 251 (v1 off) и 259 из 259 (v1 low) нашлись в тексте, ни одной выдуманной.
По оценке эталона валидны 88 % случаев v1 без рассуждений и 93 % случаев v1 low. Около 40 % случаев —
пограничные обобщения класса 7 без адресов и цифр (`concrete: false`).

v2 (правки по ошибкам v1): классы 1 и 2.1 ставятся только на запчасти; класс 4 не ставится при
нехватке фондов, неподаче вагонов и отказе потребителя принять груз; класс 5 — только сроки поставки;
для класса 8 перечислены названия органов Госснаба и введено правило про виновника; исключены
расчётные примеры, рекомендации, типовые перечни и повторы.
v3 = v2 + класс 10.

На выборке из нескольких статей на класс разница между v1 low, v2 low и v3 low в пределах шума
(±1 статья меняет точность класса на 10–25 п. п.). v2/v3 выбраны потому, что убирают систематические
ошибки v1: точность класса 1 выросла с 75 % до 100 %.

Классы 3 и 9 в пилоте не встретились. Их проверяли на 19 кандидатах, отобранных регуляркой
(«зарубежн/иностранн» рядом с «дороже/хуже/металлоёмк»):
- класс 9 найден в 10–11 статьях. Все случаи — прямые сравнения с цифрами: ТЭ40 на 16 % тяжелее
  «Алстома», Т-100 против Д-6, МАЗ-525 против «Летура», расход бурильных труб в 3 раза выше, чем в США.
  Спорные — ЗИЛ-130 против «РИО» (всего 6 %) и размерные ряды ГОСТа против DIN;
- класс 3 не найден ни разу, даже в единственном кандидате-регулярке. Возможно, в паке его почти нет.

## 4a. Сравнение с Space Bunny Alpha

`stealth/space-bunny-alpha` — анонимная модель OpenRouter. Контекст 1 млн, бесплатна на время теста.
Рассуждения у неё обязательны, минимальный уровень `low`. Stealth-модели бесплатны в обмен на то,
что провайдер сохраняет запросы. Промпт, пилот и эталон те же (v3, 55 статей), рассуждения `low`
у обеих моделей, синхронный путь, у Space Bunny 4 потока.

| Класс | DeepSeek V4.1 Flash, точность / полнота | Space Bunny Alpha, точность / полнота |
|---|---|---|
| 1 | 100 % / 100 % | 100 % / 67 % |
| 2 | 60 % / 86 % | **100 % / 86 %** |
| 2.1 | 100 % / 100 % | 100 % / 100 % |
| 4 | 77 % / 91 % | 77 % / 91 % |
| 5 | 89 % / 73 % | 82 % / 82 % |
| 6 | 100 % / 75 % | 100 % / 75 % |
| 8 | **89 % / 89 %** | 62 % / 83 % |
| 7 (есть ли проблемы) | 100 % / 95 % | 93 % / 98 % |
| **Итого без 7** | **83 % / 86 %** | 77 % / 84 % |
| Итого без правила «Госснаб → 8» | 79 % / 86 % | 78 % / 84 % |

| | DeepSeek | Space Bunny |
|---|---|---|
| Случаев на 55 статей | 228 | 300 |
| Цитаты найдены в тексте | 228 / 228 | 298 / 300 (2 пересказа, сходство 88 и 75) |
| Невалидный JSON | 0 / 55 | 3 / 55: `"class": "7": "текст"` без ключа `summary`; починено в `schema._extract_json`, после починки 0 |
| Время на статью | ≈ 7–20 с | ≈ 20–80 с |
| Цена пилота | $0,183 (sync) | $0 |

Где Space Bunny хуже:
- **Класс 8.** Она ставит `culprit_kind: gossnab_body` на критику системы снабжения вообще (издержки,
  наценки, классификаторы, «средние и низовые снабсбытовые организации») и даже на Госбанк. Правило кода
  «Госснаб → 8» по этой метке даёт 9 ложных статей из 55; без правила у неё 78 / 84 %, то есть правило
  ей не помогает (DeepSeek с правилом выигрывает 4 п. п. точности).
- Изредка ломает JSON резюме.
- Цитаты иногда пересказывает.
- Выписывает больше мелких случаев.

Где лучше: класс 2 — ни одного ложного срабатывания против четырёх у DeepSeek; класс 5 — полнота 82 %
против 73 %.
На 19 кандидатах классов 3 и 9 модели почти совпали: у 13 статей из 19 одинаковое число случаев
класса 9. Класс 3 не нашла ни одна.

Вывод: на эталоне Space Bunny хуже DeepSeek на ≈ 6 п. п. по точности и ≈ 2 п. п. по полноте. Почти
вся разница — в классе 8. Без правила «Госснаб → 8» модели равны (78–79 % / 84–86 %), но DeepSeek
этим правилом пользоваться может, а Space Bunny — нет. При выборке по 2–18 статей на класс различие
по отдельным классам — в пределах шума. Space Bunny бесплатна, но медленнее в 2–4 раза, анонимна и
доступна только на время теста.
