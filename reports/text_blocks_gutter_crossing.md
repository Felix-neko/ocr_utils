# Текстовые блоки: строки, сращённые через межколонник

## Задача

На оверлеях разбора пака-1 v3 (`pack1_page_analysis_v3`) оси строк левой колонки местами уходят в
правую через межколонник, и блоки занимают обе колонки (пример пользователя — 1966/02 IMG_0076_1L:
три блока во всю ширину полосы, выключка и стороны блоков неверны). Нужно было найти все такие
случаи по паку, понять причины, исправить и проверить исправление на проблемных и на стольких же
нормальных полосах до вноса в основной код.

- Пак-1, 12 135 полос, вход — заострённые копии (`SHARPENED_DIR`), объекты и запреты (растр из базы,
  таблицы, line art, формулы, повёрнутый текст) — из итоговых JSON v3, вторая ось строки
  (`--axis body`), как в v3.

## Причины

| Класс | Механизм | Где в коде |
|---|---|---|
| A. Наклонный межколонник выпадает | `gutters_of` находит межколонник на всю высоту, но `separators_for_segmentation` брала ОБЩУЮ часть ломаной по x; на полосе с наклоном ~1° она пуста (1966/02 IMG_0076_1L: 426..451 вверху → 452..479 внизу, max x0 = 452 > min x1 = 451), и межколонник молча исчезал из запретов сцепки и резки строк | `columns.separators_for_segmentation` |
| B. Короткий межколонник не находится | двухколонный фрагмент в 3–8 строк под заголовком во всю ширину (или над ним) короче двух лент по 40 мм, затравки нет (1969/03 IMG_0147_1L — семь строк под «Реорганизация помогла») | `columns.gutters_of` (`MIN_GUTTER_BANDS` = 2) |
| C. Межколонник найден, строка всё равно сшита | карандашная подчёркивающая линия через межколонник (1966/05 0410_1L), таблицы, подписи | разное, не лечилось |

Хинт пользователя «детектировать межколонники до сращивания и запрещать сращивание через них»
в коде уже был (`InkEngine`: межколонники → `separators_for_segmentation` → `segment._crosses` и
`segment._split_at_gutters`) — ломался перевод межколонника в запрет (A) и затравка (B).

## Метод

Режим межколонников — `columns.GutterMode` (CLI `--gutter-mode` у `analyze-pack` и `reblock-pack`):

- `legacy` — прежний ход;
- `segmented` — запрет на каждый отрезок ломаной между соседними узлами (общая часть двух узлов по
  x; если её нет — отрезок делится пополам, `_segment_separators`);
- `short` (умолчание с 2026-09-28) — плюс короткие межколонники (`short_gutters`): мелкие ленты
  12 мм с шагом 3 мм; кандидат — только продолжение уже найденного межколонника (середина не дальше
  3 мм от его середины на ближнем конце), отделённое от него преградой — строкой, где полоса
  длинного межколонника перегорожена (`_behind_obstacle`); не меньше 3 строк с каждой стороны и
  выровненная кромка хотя бы одной колонки — 75 % строк не дальше 0.8 мм от прямой с наклоном до 2°
  (`_edge_aligned` / `_aligned`, идея табуляторов Tesseract); продлевается только по совсем пустой
  полосе. В новых режимах межколонник не продлевается сквозь строку, где с обеих сторон к нему
  подходит крупный набор — сгусток маски текста выше медианы страницы в 1.6 раза (`heading_mask`).
- Во всех режимах (`segment._split_at_gutters`): строка не режется по межколоннику, если просвет на
  нём уже 0.8 медианной высоты её букв или не шире медианы остальных её пробелов в 1.5 раза —
  это пробел заголовка над межколонником (1968/04: 22 px против 19 и 19).

Мера «ось через межколонник» — `metrics.gutter_crossings_of`: под осью пустота шире 2.5 мм и 1.2
высоты строки, шире остальных пробелов строки в 1.8 раза, продолжается пустым столбцом (наклон
столбца — по наклону строки), общая пустота по всей его высоте не уже 2 мм, к столбцу с каждой
стороны подходят не меньше 5 осей. Пороги подобраны глазами по поясам «осей на полосу» (24 полосы
поясов 1–9): при 3 соседях пояса 1–3 — сплошь «реки» пробелов в наборе по формату.

Как отделяют колонки другие движки (сводка по исходникам окружений `curved_layout_engines`,
`line_axis_engines`): eynollah — поворот страницы до поиска колонок и профиль в полосах между
заголовками; kraken (`pageseg.compute_colseps_conv`) — пустота только рядом с ровной кромкой текста,
высота в кеглях; Tesseract — табуляторы по выровненным краям строк (допуск ≈ 0.8 мм, от 4 строк);
pero, surya, laypa и прочие — только нейросеть. Взяты кромка (kraken, Tesseract) и высота в строках.

осями через межколонник. N — 71 полоса без находок с межколонником, по слоям: наклонный межколонник
выпадает (17 из 107 таких полос), межколонник кончается выше низа (17), «не только текст» (17),
обычные (20).

## Что пробовали и отвергли

- Короткие межколонники без привязки к длинному — проверка кромки не отличает их от «рек» пробелов:
  на 1976/04 IMG_0036_1L и 1967/05 IMG_0095_2R десятки ложных межколонников, 1966/02: блоков 6 → 54.
- Цепочка мелких лент с допуском длинных (4 мм) — ползёт по рекам через всю полосу; кромка,
  мерянная от самой ломаной кандидата, у реки выходит «ровной». Взяты 1.5 мм и абсолютная кромка.
- Короткий кандидат, заходящий на высоты длинного межколонника или примыкающий к нему без преграды,
  и продление с допуском 30 % краски — резали заголовок над межколонником (1967/07 IMG_0051_1L).
- Запрет СЦЕПКИ не действует при просвете уже высоты строчной (для заголовков) — на полосе по формату
  с растянутыми пробелами строки колонок сцеплялись через межколонник (1972/04 IMG_0047_1L).
- Порог крупного набора ниже 1.6 — слова корпуса с выносными дают до 1.3, межколонник оборвался бы
  на обычных строках.
- Мера с 3 соседями по столбцу — пояса 1–3 оси на полосу почти целиком реки.
