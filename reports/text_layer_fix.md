# Текстовый слой финальных PDF: чистка россыпи от повёрнутого текста и вставка своего чтения

Исследование `ocr_utils/text_layer_fix` (стенд: команды `survey`, `run`, `eval-lineart`, `llm-compare`…; пак-1, PDF FineReader из
`full_pdfs_binary_no_bg_brightening`). Оверлеи — в `reports/text_layer_fix/` (вне git), полный выход
прогона — `/mnt/SYSTEM/raw/mts/pack1_text_layer_fix/pack1_v1/` (кэш JSON на страницу, CSV,
исправленные копии PDF в `pdf/`).

## 1. Задача

FineReader кладёт в финальные бинаризованные PDF невидимый текстовый слой, но повёрнутый на
90/180/270° текст (шапки узких граф таблиц, подписи на чертежах и блок-схемах, отдельные
боковые подписи) распознаёт как горизонтальный: на его месте в слое лежит россыпь «слов» из
одного-трёх случайных знаков, и поиск по этим местам не работает. Нужна стадия после сборки
финальных PDF: найти зоны повёрнутого текста на странице-картинке, аккуратно убрать
относящиеся к ним фрагменты слоя, не задев здоровый текст, прочитать повёрнутый текст своими
средствами и вписать его в слой. Вопросы пользователя: как далеко от ячеек FineReader кладёт
эти фрагменты; смешивает ли он здоровый и больной текст в одном прямоугольнике; можно ли
надёжно отличать прямоугольники «удалить целиком» от «санировать»; насколько хорош детектор
line art; годятся ли методики ориентации и чтения ячеек из `rotated_text`; как вставлять слой.

## 3. Что оказалось внутри PDF FineReader (обзор по всему паку)

Всё ниже замерено `survey` по 12 135 страницам и пробами на отдельных страницах.

* **Один поток содержимого на страницу, слово = маркированный спан.** Каждое слово —
  `/Span <</MCID n>> BDC BT … ET EMC`, внутри `Tf`, `3 Tr` (невидимый), `a 0 0 d x y Tm` и по
  `(код)Tj` + `dx 0 Td` на глиф. Матрица растянута под ширину слова (медиана `a` 1,01; слов с
  растяжением вне [0,7; 1,5] на странице — медиана 0, p90 2). Гранулярность слоя — слово, и это
  снимает вопрос о «смешанных прямоугольниках»: править можно по словам и даже по глифам.
* **`cm` внутри первого спана.** Страничный сдвиг `1 0 0 1 0 dy cm` лежит внутри спана MCID 0
  перед `BT`. Удалять спан целиком нельзя (уедет картинка) — вырезается только `BT … ET`, спан
  остаётся пустым. Тогда и дерево структуры (`StructTreeRoot`, `ParentTree` по MCID) остаётся
  валидным, чистить его не надо.
* **FineReader иногда пишет повёрнутый текст правильно** — с повёрнутой матрицей (`0 b c 0 x y Tm`):
  220 слов на 39 страницах пака, из них 18 страниц — последняя страница выпуска (вертикальные
  выходные данные). Такие слова помечаются `KEEP_ROTATED` и не трогаются; своё чтение в их зоны
  не вставляется (иначе дубль в поиске).
* **Куски, которые FineReader счёл картинкой, лежат отдельными JBIG2-образами** (чертежи, схемы,
  а иногда полоска вертикального текста): 1 337 таких образов на 1 006 страницах пака. Слоя на них
  нет вовсе — ни прямых подписей, ни повёрнутых. Значит, для line art задача — в основном
  *добавить* текст, а не удалить; при этом рамки этих образов — готовый признак «FineReader
  считает это картинкой» (см. § 6).
* **Текст обрезанной части образа FineReader кладёт за CropBox**: 1 673 глифа вне страницы на
  18 страницах (1966/04 с. 28 — 1 225 глифов над верхним краем). `rawdict` их не видит; в правке
  они не участвуют. Внутри страницы непривязанных глифов на весь пак 29 (по одному на страницу).
* **Таблица целиком без слоя** — редкость: 1 из 337 таблиц с боковыми ячейками (1967/07
  IMG_0044_2R). Чаще FineReader теряет отдельные прямые ячейки (см. `TABLE_CELL_UPRIGHT`).
* **Что не работает как признак россыпи по странице.** Словарная эвристика (доля неизвестных
  слов) — медиана 8 % на любой странице, лидеры — указатели, почти всё «неизвестное» — половинки
  переносов. Число коротких слов (1–2 знака) — медиана 101 на страницу, p90 140: россыпь в этом
  шуме не видна. Пословный аспект компонент чернил (рамка слова FineReader режет повёрнутые буквы)
  — не разделяет (медианы 0,94 против 0,83). Ориентацию надо мерить по зонам растра, не по словам.
* Разбор слоя: привязка глифов к символам `rawdict` по началу глифа — 100 % внутри страницы
  (0 непривязанных на паке после учёта глифов за CropBox), 0,27 с на страницу.

## 4. Метод

1. **Слой** (`text_layer.py`): свой токенизатор и интерпретатор текстовых операторов (`cm`,
   `Tm`, `Td`, `Tj`, `TJ`, `Tf`, `Tz`, `Tc`, `Tw`), координаты через `page.transformation_matrix`
   (MediaBox не от нуля переворот по высоте ломает), ширины глифов из шрифтов через pikepdf (для
   многоглифных строк не-FineReader), привязка к `rawdict` по ближайшему началу (допуск 0,35 pt).
2. **Растр** (`raster.py`): страница рендерится целиком в родном разрешении основного образа
   (PyMuPDF, 0,27 с), рамки дополнительных образов сохраняются как `figures`.
3. **Зоны** (`zones.py`, `docstrum.py`):
   * таблицы — детектор `scan_markup.table_detection` на копии 150 dpi → вырезка 600 dpi →
     выравнивание по линейкам → сетка 300 dpi → склейка разрезанных ячеек → ориентация ячеек
     (ось по форме глифов, сторона по буквам tesseract, приор по таблице) — всё из
     `rotated_text.tables`; боковые ячейки → `TABLE_CELL`; смешанные ячейки → боковая часть по
     соседям глифов внутри ячейки; прямые ячейки с краской без единого слова слоя →
     `TABLE_CELL_UPRIGHT` (FineReader потерял текст — читаем и вставляем прямо);
   * вне таблиц — Docstrum: компоненты размера глифа (0,8–7 мм), пара «глиф — ближайший сосед»
     считается вертикальной, если сосед стоит над/под глифом ближе 1,15 его высоты И ни у одного
     из двух нет более близкого горизонтального соседа (иначе первые буквы строк абзаца
     собирались бы в «боковое слово»); цепочки от трёх глифов, склейка кусков строки через пробел
     (в том числе через одиночную букву «с») и соседних строк подписи; сторона — tesseract под 90
     и 270 по числу букв или уверенных цифр (`evidence_at`). Зона внутри картинки FineReader или
     схемы детектора — `LINE_ART_LABEL`, иначе `STANDALONE`;
   * **прямой текст без слоя** вне таблиц — те же цепочки по транспонированному растру (шаг букв в
     строке до 1,6 высоты глифа; межстрочный шаг отсекается правилом «нет более близкого соседа
     поперёк»); цепочка берётся, только если слова слоя накрывают её рамку меньше чем на 20 %.
     Внутри картинки FineReader или схемы детектора — `LINE_ART_UPRIGHT`, иначе
     `STANDALONE_UPRIGHT`. Эти зоны ничего не удаляют: только читаются (поворот 0) и вставляются.
4. **Чтение зон** (`ocr.py`): tesseract `rus`, psm 6 по выпрямленной вырезке; ячейки режутся ровно
   по внутренности (с полем в вырезку попадают линейки, и tesseract молчит) и чистятся от
   обрубков линеек. **Сравнение с прямым чтением**: ячейка читается и без поворота; если прямое
   чтение заметно увереннее (от двух букв и +0,1 к уверенности) или не уступает по буквам при
   большей уверенности — зона снимается (широкие «ШТ.» по форме «лежат»; на выборке снято 287
   зон, большинство — смешанные ячейки с прямым текстом «Всего», «Единица измерения»). Приём
   чтения — пороги `rotated_text`: уверенность ≥ 0,6, слово от трёх букв; число без букв — только
   при ≥ 0,9 (в поясе 0,8–0,9 треть чисел с чертежей читается с лишними нулями: «00098», «0099»).
   Второе мнение surya (`second_opinion.py`) — по зонам, где чтение не принято или уверенность
   < 0,7, с фильтром выдумок из `rotated_text`.
5. **Вердикт по слову** (`classify.py`): доля площади рамки слова в зоне ≥ 0,6 → `DELETE`; 0,15–0,6
   → `SANITIZE` (усечение до глифов вне зоны по рамке каждого глифа); спан с повёрнутой матрицей →
   `KEEP_ROTATED`; короткое или бессмысленное слово в 4 мм от зоны, но вне её — `SUSPECT` (не
   трогается, показывается). Страховка словарём: в зоне, чьё чтение НЕ принято, удаляется только
   похожее на мусор; настоящее слово (словарное от трёх букв по `pymorphy3`) или число остаётся
   как `SUSPECT` — FineReader мог прочитать его верно, и терять его ради пустоты незачем
   (на выборке так спаслись «Наименование материалов», «Нормы текущего … запасов»).
6. **Правка PDF** (`rewrite.py`, `fixer.py`): все правки — одним проходом по исходному потоку
   (после первой вырезки смещения плывут — на этом ловился первый вариант); удаление —
   `BT … ET` → пробел; усечение — пересборка `BT … ET` из оставленных глифов с прежними `Tf`,
   `a b c d` и шестнадцатеричными кодами глифов; вставка — `BT /TLFnoto k Tf 3 Tr a b c d e f Tm
   <GID…> Tj ET` в тот же поток, шрифт Noto Sans, встроенный один раз через `page.insert_font`
   (Type0 Identity-H с ToUnicode — читают и `search_for`, и `pdftotext`), матрица по стороне
   зоны (90 — читается снизу вверх, `dir (0, −1)`), растяжение — чтобы строка легла в длинную
   сторону зоны, кегль — по короткой (2,5–10 pt). Никаких `insert_text`/`TextWriter`: они плодят по
   потоку на вызов. Сверка каждой страницы после сохранения: все оставленные глифы на прежних
   местах, ни один удалённый не извлекается, каждая вставка находится `search_for` в своей рамке,
   md5 сырых байт JBIG2 не изменился.

### 5.2 Ответы на вопросы

**Как далеко от ячеек FineReader кладёт фрагменты повёрнутого текста.** Не кладёт вовсе: россыпь
лежит внутри внутренности ячейки. Из 9043 удалённых слов 95,8 % целиком внутри зоны (перекрытие
1,0), медианная длина «слова» — 1 знак. Подозрительные слова вне зон (россыпь в 4 мм от зоны):
1112, медиана расстояния 2 мм, p90 3,5 мм — это соседние ячейки без стороны и знаки препинания
обычного текста, они не трогаются.

**Смешивает ли FineReader здоровый и больной текст в одном прямоугольнике.** На уровне слова —
нет: слов, задетых зоной частично, всего 9 из 9052 (0,1 %), и все они усекаются по глифам без
потерь (сверка 100 %). На уровне строки дерева структуры (абзац/строка FineReader) смешение
редкое: из 4097 строк дерева с удалёнными словами только 29 (0,7 %) содержат и оставленные слова —
FineReader группирует россыпь боковой ячейки в свои строки, отдельно от прямого текста. Дерево
для правки и не нужно: единица слоя слово, спаны остаются на местах, ссылки дерева не рвутся.
Токенов без букв и цифр вне зон на страницах с зонами — 12 497, из них в 4 мм от зоны 357,
остальные — тире, отточия и знаки препинания обычного текста (медиана расстояния 60 мм).
Настоящее смешение — смешанные ячейки сетки (боковая шапка склеена с прямой): 217 на выборке;
боковая часть 22 из них найдена по соседям глифов и прочитана, остальные (77 слов) помечены
SUSPECT и не трогаются.

**Надёжность «удалить целиком» / «санировать».** Решение чисто геометрическое, по перекрытию
рамки слова с зоной; санация как редактирование текста не понадобилась. Надёжность держится на
трёх страховках: сравнение с прямым чтением снимает ложные боковые ячейки (287 зон — «ШТ.»,
«Всего», «Единица измерения» в смешанных ячейках); в зоне без принятого чтения удаляется только
похожее на мусор, словарные слова и числа остаются (137 слов, среди них «Наименование материалов»,
«Нормы текущего … запасов» — FineReader прочёл их верно, а tesseract ячейку не взял); FineReader-овские
повёрнутые спаны неприкосновенны. Остаток риска — 185 удалённых слов с четырьмя и более буквами
подряд: просмотр показал, что это мусор из перевёрнутых (180°) ячеек («КВНХЭВЗЕСЬОЯОНВЦЦ»,
«шипвеибэн») и латинские обрывки («feggsi», «gags»); их зоны прочитаны и заменены.

**Line art и отдельный текст.** На 203 полосах со схемами найдено 314 подписей, прочитано 223;
FineReader на схемах не оставляет ничего, так что там нечего удалять — только добавлять. Отдельный
боковой текст вне таблиц и схем: 93 зоны, прочитано 22 (остальное — короткие вертикальные
обозначения, сноски, номера). Полнота подписей на схемах по глазам (30 схем из оверлеев): длинные
подписи (от трёх букв в цепочке) находятся; размеры на чертежах («24 000», «12 000») находятся,
но чтение цифр без букв принимается только при уверенности ≥ 0,9 — половина остаётся без вставки.

**Годятся ли методики `rotated_text`.** Да, целиком: сетка, ориентация ячеек и чтение перенесены
на растр PDF без изменений (только вырезка ячейки без поля и с чисткой обрубков линеек — с полем
tesseract молчит). Согласие с прогоном по заострённым копиям — те же таблицы и те же боковые
ячейки; сторона чтения ячеек: 90° — 1679, 270° — 73, 180° — 71, прямые (снятые) — 287. Второе
мнение surya по 958 ненадёжным зонам: 499 ответов прошли фильтр, 210 зон стали пригодными для
вставки (в основном курсивные бланки и мелкий петит).

**Вставка слоя.** 2750 вставок на 1050 страницах, 18 пропущены как дубли повёрнутых спанов
FineReader. Сверка после сохранения — 0 расхождений: все оставленные глифы на местах, ни одно
удалённое слово не извлекается, каждая вставка находится `search_for` и `pdftotext` в своей
рамке, JBIG2 побайтно тот же, поток содержимого один, шрифт один на страницу.

### 5.4 Сравнение с языковой моделью

Идея «отдать строку слоя LLM и попросить вычеркнуть мусор» проверена как альтернатива на 150
случайных строках дерева структуры FineReader, где есть хотя бы одно слово не KEEP (DeepSeek V4.1
Flash через OpenRouter, только текст, JSON-ответ; `llm-compare`). По 405 токенам:

| | LLM: мусор | LLM: оставить |
|---|---|---|
| геометрия: удалить | 171 | 133 |
| геометрия: оставить | 17 | 84 |

Согласие 0,63; цена $0,0044 на 150 строк, 0,96 с на строку. Расхождения в пользу геометрии:
модель «когда не уверена — оставляет» и держит одиночные буквы и знаки («о», «я», «—», «S»)
внутри боковых ячеек, то есть половину россыпи; из 133 таких токенов 117 — DELETE в прочитанных
зонах. Расхождения в пользу модели (17): половинки переносов («разме», «\xad», «тупле») и
формульные обрывки («i=l») — это не россыпь, а обычный текст, который удалять нельзя. Вывод:
языковая модель как санитайзер медленнее на два порядка (секунда на строку против миллисекунд),
платная и хуже отличает россыпь от коротких слов; как геометрия она не знает, где на странице
повёрнутый текст. Годится разве что как второе мнение по SUSPECT-словам, но на выборке они и так
не трогаются.

### 5.5 Стоимость

Разбор слоя 0,27 с на страницу; полный разбор страницы (сетка + tesseract по ячейкам + чтение зон)
медиана 1,8 с, p90 5,6 с; на 12 воркерах пак-1 целиком — около часа; surya — 0,3 с на зону на GPU.
Исправленная копия выпуска — 1–3 с.

## 6. Line art: точность и полнота источников

Сверка на PDF без коррекции геометрии, 221 ручная область на 207 полосах плюс 200 контрольных
страниц без эталона; совпадение — IoU ≥ 0,5, «накрытие» — эталон накрыт объединением
предсказаний хотя бы наполовину.

## 7. Что пробовали и отвергли

* `get_texttrace()` PyMuPDF для привязки спанов — падает (`none_dealloc`) на этих PDF; свой
  разбор потока + `rawdict` даёт 100 %.
* Удаление спана `BDC … EMC` целиком — внутри первого спана лежит `cm` страницы, картинка уезжает.
* Декодирование одного JBIG2-объекта вместо рендера страницы — чертежи и схемы лежат отдельными
  образами и пропадают с растра.
* Переворот координат по высоте страницы — врёт при MediaBox не от нуля; только
  `page.transformation_matrix`.
* `insert_text`/`TextWriter` для вставок — по отдельному потоку на вызов; свой `BT … ET` в тот же
  поток даёт одну матрицу и один шрифт.
* RLSA-цепочки `ink_axis.line_boxes` для подписей на схемах — ловят только длинные строки,
  подписи в 1–3 слова пропускают; вертикальные пары «по ближайшему соседу» без проверки
  горизонтального соседа — собирают первые буквы строк абзаца в «боковое слово».
* Словарь и число коротких слов как страничный признак россыпи — не разделяют (§ 3).
* Пословный аспект компонент чернил под рамкой слова — не разделяет (§ 3).
* Ориентация ячейки без сравнения с прямым чтением — «ШТ.» и смешанные ячейки шли под нож.
* Правки потока в два прохода (удаления, потом усечения) — смещения второго прохода плывут,
  соседние слова терялись.
* Порог 0,8 для чисел без букв — в поясе 0,8–0,9 треть чисел с чертежей с лишними нулями.
