# Восстановление повреждённых начал строк на двух фотографиях книжного разворота

Технический отчёт: что делалось, какими алгоритмами и с какими параметрами.

---

## 0. Главное сразу: никаких нейросетей здесь нет

Ни одна генеративная модель изображений не использовалась. Ни inpainting-диффузия, ни GAN, ни
super-resolution, ни OCR-нейросеть. Причина простая: любая генеративная модель дорисовала бы
*правдоподобные* буквы, а не *те самые*. На печатном тексте это видно мгновенно — плывёт
начертание, толщина штриха, зерно фотографии.

Вместо этого — классическое компьютерное зрение (пороги, морфология, связные компоненты,
проекции, диффузия) плюс приём, который в реставрации называется **донорским**: недостающие
буквы физически вырезаны из других мест **той же фотографии** и вставлены на место утраченных.
Поэтому у вставок совпадает всё: гарнитура, кегль, нажим печати, размытие объектива, зерно
плёнки/матрицы, оттенок бумаги.

Роль модели (Claude Opus 5) здесь — не рисование, а:

* прочитать текст и восстановить утраченные фрагменты по смыслу и по разбивке на строки;
* написать и отладить конвейер обработки на Python;
* визуально проверять промежуточные результаты и исправлять то, что пошло не так.

**Стек:** Python 3.11.15, NumPy 2.4.4, OpenCV 4.13.0, Pillow 12.2.0. Всё — CPU, без GPU.

## 2. Схема конвейера

```
исходный JPEG
   │
   ├─ (A) геометрия: шаг строк, локальные базовые линии, наклон, левое поле
   │
   ├─ (B) текстология: что именно утрачено (по смыслу + по концам предыдущих строк)
   │
   ├─ (C) маска повреждения
   │
   ├─ (D) синтез бумаги в маске  ──►  «чистый» кадр
   │
   ├─ (E) вырезание донорских глифов из этого же кадра
   │
   ├─ (F) расчёт позиций (правый якорь + выравнивание левого поля)
   │
   ├─ (G) аддитивное наложение доноров
   │
   └─ (H) сохранение с исходными таблицами квантования + контроль диффа
```

## 3. (A) Геометрия страницы

### 3.1 Шаг строк

Горизонтальная проекция «тёмных» пикселей (`gray < 130`) по колонке текста, сглаживание
скользящим средним (окно 9), поиск локальных максимумов с минимальным расстоянием 30 px.
Пики — это полосы x-height.

* снимок 1: шаг **60.55 px**, 18 строк в рабочей зоне;
* снимок 2: шаг **61.0 px**, 20 строк.

### 3.2 Ключевая находка: строки не горизонтальны

На первом снимке базовая линия одной и той же строки уходит вниз примерно на **45 px** при
движении вправо на 1650 px. Пока это не было учтено, все автоматические замеры (левый край,
высота букв, границы глифов) врали на 15–20 px, потому что полоса анализа не совпадала с
реальным положением строки.

Измерение наклона: полоса x-height ищется в окнах шириной 150–200 px на разных `x`; по сдвигу
её нижней границы считается наклон.

```
snapshot 1:  SLOPE = +0.027   (базовая линия ниже справа)
snapshot 2:  SLOPE = −0.0067  (базовая линия выше справа)
```

### 3.3 Локальная базовая линия

Для полосы строки берётся окно `[bguess−half, bguess+half]`, считается построчная сумма тёмных
пикселей `p(y)`, порог `0.4·max(p)`; из непрерывных участков выше порога выбирается тот, чей
центр ближе всего к `bguess`. Нижняя граница участка = **базовая линия**.

Параметр `half` оказался критичным: при `half = 40` (шаг строк 61) поиск иногда «перепрыгивал»
на соседнюю строку — так один донор был вырезан со сдвигом 23 px и в первом прогоне на
последней строке вылезли обрывки чужой строки. После `half = 26` промахи исчезли.

Итоговая формула для каждой строки *n*:

```
BL(n, x) = fit(n) + SLOPE · (x − x_ref)
```

где `fit(n)` — квадратичная (снимок 1) или прямая аппроксимация измеренных базовых линий по
номеру строки; она гасит шум измерения ±2 px.

### 3.4 Левое поле и абзацный отступ

Левое поле измерялось по неповреждённым строкам сверху: крайняя левая колонка с достаточно
высоким столбиком чернил в полосе `[bl−33, bl+16]`.

* Снимок 1: 3240 px при y=1696 → 3216 при y=3028; линейная экстраполяция вниз давала ≈3205,
  но арифметика вставок (ширина донора + естественный просвет) указывала на 3198–3204.
* Снимок 2: 3175–3177 практически по всей высоте; абзацный отступ **99 px** (проверен по трём
  абзацным строкам «Результаты», «В настоящее», «Ввод»).

Высота строчных (x-height) ≈ 30 px, прописных ≈ 42–45 px, ширина знака 25–30 px,
межбуквенный просвет **2–7 px** (медиана 4), межсловный **20–38 px** (зависит от выключки
конкретной строки). Все эти числа измерены, а не взяты «на глаз», — они нужны для позиционирования.

## 4. (B) Текстология: что именно утрачено

Это не автоматизируется — здесь работает не алгоритм, а чтение.

Главный приём: **смотреть не только на начало повреждённой строки, но и на конец предыдущей.**
Для этого отдельно вырезался правый край текстовой колонки. Это дало две поправки, которых не
было в присланной расшифровке:

1. Снимок 1: строка кончается на «под боевым» **без дефиса** → следующая начинается с
   «**ло**зунгом», то есть пропало две буквы, а не ноль. Совпало и по геометрии: «зунгом» стояло
   с отступом 67 px от поля, ширина «ло» — 63 px.
2. Снимок 1: «производст-» → следующая строка «**ва** —».

Второй приём — **проверка шириной**. Для каждой строки известно расстояние от левого поля до
первой уцелевшей буквы; оно должно совпасть с суммарной шириной предполагаемых утраченных
знаков плюс просвет. Все восстановления сошлись в пределах ±10 px, кроме одного:

* Снимок 2, строка «…включит в себя…»: предыдущая строка кончается точкой, значит начинается
  новое предложение и его подлежащее скрыто. Ширина пропуска 95 px. «Он » = О(41) + н(28) +
  просвет(4) + пробел(24) = 97. Это единственное место, восстановленное по смыслу, а не по
  разорванному переносом слову.

Отдельно: там, где сгиб/разрыв срезал первую уцелевшую букву лишь частично (к, п, н, с, м, а,
У, щ, е), эта буква тоже перерисовывалась целиком — иначе она читалась бы обломком. Поэтому
вставки местами длиннее пропуска: не «об», а «общ»; не «Гос», а «Госст».

## 5. (C) Маска повреждения

### 5.1 Снимок 1: сегментация по цвету

Картон отличается от бумаги надёжнее по **цвету**, чем по яркости:

```
бумага:  R − B ≈ −7 … −19   (холодная, синеватая)
картон:  R − B ≈ +38 … +47  (тёплая, бежевая)
```

Порог `R − B > 4`, затем:

1. `MORPH_CLOSE` ядром 45×45 — сомкнуть разрывы;
2. `MORPH_OPEN` 7×7 — убрать одиночные пиксели;
3. `dilate` 17×17 — захватить мягкий край и клеевой ореол;
4. **заливка внутренних дыр** через `cv2.floodFill` от угла кадра — без неё рукописные
   «Листов печат.» и «18» не попадали в маску: тёмные чернила по цвету нейтральны, а по размеру
   больше ядра замыкания, и на промежуточном результате они остались висеть чёрной кляксой;
5. плюс явные прямоугольники на оба куска картона и мелкий обрывок у корешка;
6. плюс узкие полоски по строкам, где после отрыва остались клочки бумаги.

### 5.2 Снимок 2: маска по геометрии

Здесь помеха — не инородное тело, а страница того же цвета; сегментация по цвету не работает.
Зато точно известно, где кончается помеха: у каждой строки есть **x первой уцелевшей буквы**.
Маска задана как

```
mask[y, 3105 : prot(y)] = 1
```

где `prot(y)` — «первая уцелевшая буква − 3 px», разложенная по полосам строк
`[bl − 47, bl + 17]`.

### 5.3 Защита настоящего текста

На первом снимке маска строилась «широко» и из неё вычитались чернила
(`gray < 155`, `dilate 3`) правее границы защиты. На втором снимке этот же приём **дал брак**:
у буквы «Г» в «Госснаба» стёрлась верхняя перекладина, а вертикаль стала серой — антиалиасные
края с яркостью выше 155 в защиту не попали. Поэтому на втором снимке маску просто обрезали по
`prot(y)`: **ничего правее не трогается вообще**, защищать нечего.

Дополнительно на первом снимке работала чистка мусора по связным компонентам: компонента
чернил, целиком лежащая левее границы защиты, добавлялась в маску (`dilate 7×7`). Это убрало
одиночные тёмные крапины от разрыва бумаги.

## 6. (D) Синтез бумаги — три итерации

Здесь было две провальные попытки, о них стоит рассказать, потому что причина неочевидна.

**Попытка 1 — нормализованная свёртка.** Поле бумаги как
`blur(img · valid) / blur(valid)`, σ = 30. В центре дыры 325 × 485 px знаменатель обращается в
ноль, поле улетает в мусор — получилось **чёрное пятно** размером с бывший скотч.

**Попытка 2 — переключение масштабов.** σ ∈ {12, 25, 50, 100, 200, 400}, для каждого пикселя
берётся самый мелкий масштаб с достаточной плотностью данных. Пятно исчезло, но на границах
между масштабами появились **«горбыли»** — контурные полосы, повторяющие форму скотча.

**Рабочий вариант — итеративная диффузия на пирамиде:**

1. уменьшить область в 8 раз (`INTER_AREA`), сохранив маску известных пикселей
   (`плотность > 0.35`);
2. 600–700 итераций: `f = GaussianBlur(f, σ=1.6)`, после каждой известные пиксели
   восстанавливаются на место — это и есть решение уравнения Лапласа релаксацией;
3. увеличить обратно бикубикой и сгладить σ = 6.

Получается гладкое поле освещённости без швов и без зависимости от размера дыры.

**Текстура.** Гладкого поля мало: заплатка читается как «слишком чистая». Поверх добавляется
высокочастотная составляющая реальной бумаги — чистый участок вне текста минус его же размытие:

```
hi = patch − GaussianBlur(patch, σ = 28)
```

Первая версия использовала σ = 5 — сохранялось только мелкое зерно, и залатанные места
выделялись плоскостью. σ = 28 сохраняет все частоты до ~28 px и убирает эффект.

**Края маски** растушёваны гауссианом σ = 3.0–3.5.

**Снятие тёплого оттенка (только снимок 1).** Там, куда маска не дошла из-за защиты букв,
оставался клеевой ореол. Пиксели с `R − B > 2` в области правки подтягиваются к нейтральному
бумажному цвету с весом `clip((R−B−2)/8, 0, 1)`: яркость сохраняется, уходит только цветность.

## 7. (E) Донорские глифы

### 7.1 Почему не шрифт

Гарнитура — «обыкновенная новая» (советский книжный антиквенный шрифт с вертикальным контрастом
и тонкими плоскими засечками). Свободного кириллического аналога с тем же рисунком нет, а
промах в форме или весе штриха на такой фактуре виден сразу — тем более рядом с настоящими
буквами той же строки.

### 7.2 Правила выбора донора

1. **По возможности — из той же строки.** Тогда совпадает не только начертание, но и
   освещённость, размытие, наклон.
2. **По возможности — целыми парами/группами букв.** «ше», «тр», «фун», «лен», «водс», «Госс»
   взяты цельными кусками из настоящих слов — так сохраняется естественный, а не расчётный
   межбуквенный просвет.
3. Одиночные буквы — только там, где нужного сочетания на странице нет.

Итоговые донорские наборы:

*Снимок 1 (12 доноров):* р ← «го**р**ячий»; ше ← «боль**ше**»; л ← «**л**учшего»;
о ← «зунг**о**м»; тр ← «элек**тр**о…»; у ← «л**у**чшего»; то ← «сосредо**то**чивается»;
ва ← «качест**ва**»; по, ле ← «**по**станов**ле**-»; на ← «**на**правлениями»;
со ← «**со**ревнования».

*Снимок 2 (21 донор):* п, у, с, к, в, ы, н, м, о, О, т — одиночные; фун ← «**фун**кциональной»;
лен ← «направ**лен**иями»; водс ← «из**водс**твенных»; раз ← «**раз**мещение»;
рав ← «нап**рав**лениями»; отр ← «**отр**аслей»; АСУ, АС ← «(**АСУ**П)»;
Госс ← «**Госс**наба»; общ ← «**общ**егосударственные».

### 7.3 Как вырезаются

* локальная базовая линия в окне `[x0−60, x1+60]` (см. 3.3);
* вертикальный вырез `[bs − 47, bs + 17]` — 64 строки;
* горизонтально: колоночная проекция при пороге 138, обрезка по фактическим чернилам ± 2 px
  «воздуха».

Про 47 стоит сказать отдельно. В первой версии вырез был `bs − 34`, чего хватает строчным
(x-height 30) с запасом, но **не хватает прописным**: их высота 42–45 px. Из-за этого у
«Г», «А», «С», «У» срезалась верхушка — «Г» превратилась в вертикальную палку. Ошибка вылезла
не сразу, потому что на первом снимке доноров-прописных не было вообще.

Все 33 донора проверялись глазами на увеличенном монтаже; окна подрезались итеративно, пока
из вырезов не исчезли хвосты соседних букв («р» тянула за собой кусок «я», «то» — кусок «ч»,
«общ» — кусок «е»).

## 8. (F) Позиционирование

### 8.1 Вертикаль

Верх заплатки = `BL(строка, x_центра_вставки) − 47`. Поскольку донор вырезан с тем же
отступом от **своей** базовой линии, выравнивание получается автоматически. Наклон строки
учитывается через `SLOPE` — без этого донор, взятый в 1000 px правее, сел бы на 7 px выше.

### 8.2 Горизонталь

Приоритет — **правый стык**: просвет между вставкой и первой уцелевшей буквой должен выглядеть
как обычный межбуквенный. Это самое заметное место; ошибка в 3 px там бросается в глаза,
а такая же ошибка в левом поле — нет.

Но при фиксированном просвете 5 px левые края разъезжались на 21 px (снимок 1) — левое поле
выглядело бы рваным. Причина: накопление погрешностей в измеренных ширинах доноров плюс
реальный разброс приладки в оригинале.

**Решение.** По полученным левым краям строится прямая (МНК), затем для каждой строки
подбирается просвет так, чтобы левый край сел на эту прямую, с зажимом в допустимый диапазон
**2–8 px** (измеренный диапазон настоящих просветов). Для многосоставных вставок «люфт»
распределяется поровну между внутренними просветами и стыковым:

```
slack = (якорь − поле) − Σ ширин
g     = clip(round(slack / n_просветов), 2, 8)
left  = якорь − g − (Σ ширин + (n−1)·g)
```

Результат: снимок 1 — левое поле идёт ровной кривой 3220 → 3198; снимок 2 — 3182–3186 при
просветах 2–8 px.

**Строки с пробелом** («ва », «ле », «Он », «вом », «АСУ ») правого стыка не имеют — там
пробел, а не буква. Для них ширина пробела бралась равной измеренной медиане межсловных
пробелов **этой конкретной строки** (у выключенных строк они разные: 20–38 px), а левый край
получался как следствие.

## 9. (G) Смешивание — тоже не с первого раза

**Попытка 1 — умножение** `dst · (patch / paper)`. Вокруг каждой вставки появился заметный
прямоугольник. Причина: локальный «уровень бумаги» считался максимальным фильтром 25 × 25, а
тот хватает **светлый ореол вокруг букв** — 245 при настоящей бумаге 205. Фон заплатки темнел
на 4–8 %. Нормализация по медиане не спасла: «бумажных» пикселей выше порога почти не
оставалось.

**Рабочий вариант — аддитивное наложение:**

```
delta = patch − paper_level
out   = clip(dst + delta, 0, 255)
```

`paper_level` считается по контексту вокруг донора и **только по пикселям дальше 7 px от любой
краски** — маска чернил, `cv2.distanceTransform(1 − ink, DIST_L2, 3) > 7`, медиана по каналам.

Почему это работает:

* на бумаге `delta` — шум со средним 0 → рамки нет вообще;
* на краске корректно темнит, сохраняя относительный контраст;
* светлый ореол вокруг букв переносится вместе с буквой, а не теряется;
* цвет обрабатывается поканально, поэтому не «синит» и не «желтит».

Контроль: 2-й перцентиль яркости у вставленных букв 1–6, у соседних настоящих — 1–2. То есть
насыщенность краски совпадает.

## 12. Что осталось неидеальным

1. **Левое поле снимка 2** легло на 3182–3186 px, тогда как у строк выше сгиба оно 3175–3177.

   было только растянув буквы на 5–10 %, что заметнее.

   слову. Ширина совпадает до пикселя, но это всё-таки реконструкция, а не чтение.

   чуть спокойнее оригинала.
4. **Снимок 2:** край завёрнутой страницы «отодвинут» влево. Физически это правдоподобно (лист
