## Что пробовали и отвергли

**defocus_detection**
- `edge_width` как рабочая метрика — AP 0.330 против 0.732 у `dom`, уровень плывёт между сессиями на 12.9 % (`reports/defocus_validation_si_report.md`).
- DeQA-Doc (7B, GPU) — AUC 0.68–0.77 против 1.00 у `dom` на тех же пикселях (`reports/defocus_validation_si_report.md`).
- `pyiqa`, DeFusionNET/BTBNet/MSDU-Net, SMBlurDetect, коммерческий куллинг — обучены на натурных сценах и глубине резкости, нет понятия «читается ли петит» (`reports/defocus_detection_state_of_the_art.md`).
- Выравнивание уровней `dom_eq` — нулевой эффект: `dom` есть отношение сумм, линейное растяжение сокращается (`reports/defocus_validation_si_report.md`).
- Первая версия `edge_dir` (поворот кадра на 4 угла) — сам поворот размывает, резкий кадр получал анизотропию 1.40 (`reports/defocus_validation_si_report.md`).
- Детектор смаза на реальных данных — на синтетике безупречен, на съёмке не подтвердился (`reports/defocus_validation_si_report.md`).
- Счёт балла только по тайлам с ритмом строк — средняя точность падает, верное срабатывание теряется (`reports/defocus_validation_si_report.md`).
- Нормировка порога на шаг строк — не понадобилась: уровень балла перенёсся на другую газету и гарнитуру (`reports/defocus_validation_si_report.md`).
- Сырой `moire` = std(NEAREST−AREA) — на 50 % объясняется количеством краски, а не фокусом (`reports/defocus_moire_improvement_plan.md`).

**dewarp**
- DocScanner, UVDoc, DocTr, DocTr-Plus, DewarpNet — обучены на Doc3D (фото мятых листов), на флэтбед-скане сдвигают, режут и «курсивят» страницу (`reports/dewarp_report.md`).
- `page-dewarp` (cubic sheet) — модель камеры и цельного листа, поворачивает всю полосу (`reports/dewarp_report.md`).
- ScanTailor заменил собой весь старый подпакет dewarp (`ocr_utils/legacy/README.md`).

**page_layout.text_blocks**
- граница блока ступенями по строкам с ОДНОЙ прямой или параболой на всю сторону — на длинной колонке с изгибом у корешка сторона признаётся рваной, граница зазубривается у каждой короткой строки; выровненность решается по окну ±5 соседей (`reports/block_envelopes.md`).
- группировка блоков с нуля по графу рядов (`graph`) — дробит подписи по кеглю и чистые полосы, ложных разрезов 63 против 47 у доработанного боевого хода (`reports/block_envelopes.md`).
- surya layout как источник границ блоков — боксы по абзацам, последняя строка абзаца отдельным боксом, только прямоугольники (`reports/block_envelopes.md`).
- кегль у стыка кусков сцепки медианой крайних букв (прописные инициалы рвут подписи) или наименьшей высотой («;» — 8 px вместо 11); берётся вторая по малости из 4 (`reports/text_blocks_axis_body.md`).
- первый отсев низов для второй оси по сдвинутой первой оси или по местной медиане одних низов — выносные на конце строки («…ру,») стягивали конец оси до 4 px; нужны голоса по верхам глифов (`reports/text_blocks_axis_body.md`).
- порог второго круга сцепки 0 для крупного масштаба текстовой полосы — мусорные оси через чертежи (1968/01 с.54); порог решается по маске до скрытия абзацев (`reports/text_blocks_axis_body.md`).
- окно центр-линии от медианного глифа строки вместо зажима по медианной высоте сгустков полосы — мера верная (у крупного набора зажим даёт полосу ±0.25 высоты буквы вместо ±0.55), но выигрыша нет: отклонения от хорды те же, половинок 5 против 4, заголовки — один лучше, один хуже; защита от слипшихся строк при этом не страдает (A/B по 47 сегментам, наклон +0.000°), так что замена безопасна, если когда-нибудь понадобится (`reports/text_blocks.md`).
- проверять у кромки-полосы всю её ленту, а не точки осей — растровый контур получают 94 % блоков вместо 2 %, гладкая огибающая становится лесенкой на ровном месте (`reports/text_blocks.md`).
- углы границы блока по кривизне контура — в литературе для текстовых блоков не применяют, на скруглённых контурах точка кривизны не совпадает с переходом «строки — концы строк»; мера выравнивания стороны «доля рядов на кривой» обманчива на рваном крае (0.62 против 0.22 по сериям) — берётся доля рядов в выровненных сериях (`reports/text_blocks_sides.md`).
- запрещать текст внутри таблиц и line art всегда, а не по флагу — на табличных полосах гасит сам разбираемый материал (1967/07 с.73 осей 58 → 1) (`reports/text_blocks.md`).
- судьба обрывка в межколоннике по расстоянию до концов соседних осей — у строки с отточиями конец оси это конец точек, а не текста (`reports/text_blocks.md`).
- внутренность ячейки (`inner`, без линеек) как область разбора вместо полного бокса — буквы выходят за внутренность и даже за бокс, строка у края ячейки терялась: покрытие краски 1973/08 с.19 90.0 % против 93.2 % у полного бокса (`reports/text_blocks.md`).
- `pack1_rotated_tables/info/*.json` как источник ячеек — координаты привязаны к заострённым сканам, а не к PDF FineReader (`reports/text_blocks.md`).
- alpha-shape / concave hull по точкам строк — контур «зубчатый», нужна гладкая кривая по телу блока (`reports/text_blocks.md`).
- соринки у края строки: порог по площади без шаблонов знаков (1 469 сдвигов концов на 50 чистых полосах), признаки крайнего глифа по базовой линии всей строки (на nogeo дефис «ниже строки»), DeepSeek-OCR-2 разностным судьёй на всех крайних компонентах (157 против 240 из 250 соринок у шаблонов; вето DeepSeek теряет 38 соринок ради 6 знаков) (`reports/text_block_specks.md`).
- сор и пометки у края, судьи «символ или нет»: разностные судьи по строке 60 мм (tesseract, docTR PARSeq, pero OCR, DeepSeek `free`/`ocr`, surya — AUC 0.51–0.75, при вреде ≤5 % ноль), DeepSeek-OCR-2 во всех масштабах (AUC ≤0.68, 13 ГБ), рамки символов surya 0.17 (вырождены в рамку строки), рамка кандидата «вся краска за стороной» (склеивает висячий дефис с соринкой) (`reports/edge_marks_judges.md`).
- защита сторон от сора: зона фильтра CRAFT на 3 мм внутрь стороны (выбросила обломок разорванной «щ»), зона наружу до края страницы (выбросила тире вне блоков), фильтр горизонтальных штрихов (дефис «Глав-», тире), раздутие компоненты перед чтением карты (теряет сор, знаков не спасает), порог выступа 0.5 мм без минимума строк (15 % полос аномальны, половина — короткие блоки) (`reports/edge_guard.md`).
- Квантиль в скользящем окне как кромка — прыгает на двух рядах в окне; заменён LOWESS с окном не меньше 5 рядов.
- Готовый `line_fit.column_separators_banded` — не набирал голосов на 1973/06 с.65; свой поиск межколонников с долей 0.5 и подтверждением текстом.
- Межколонник прямой полосой и без диапазона высот — режет не там на трапеции и рвёт заголовок над колонками; заменён ломаной с высотой жизни.
- «Строка длиннее 6 своих высот и 10 мм» — выбрасывало числовые графы таблиц и однословные концы абзацев; строка считается от 3 глифов и 4 мм.
- Одна высота строки как признак заголовка — жирный заголовок того же кегля оставался в блоке корпуса; добавлена толщина штриха.
- Точки отточий выбрасывались маской глифов (порог 5 px) — теперь добавляются в краску текста цепочками от четырёх точек; мостик в маске RLSA отвергнут: он привязывал отточие к соседней строке.
- Ось по наклону хвоста строки на отточии уезжает вниз на десяти сантиметрах — ось ведётся по самим точкам, поднятым до уровня строки.
- Поле отточий принималось за межколонник и резало таблицу на 19 блоков (1971/10 с.93): полоса с тремя и более отточиями межколонником не считается, проверка — после продления межколонника.
- Полная пересборка кусков по уровням поля вместо жадного хода — кусок без своего уровня становится отдельной строкой: пересечения контуров 41 → 109 тыс. px², блоков 119 → 136. Оставлен жадный ход с ограничителем по полю и сшиванием.
- Ограничитель по МЕДИАНЕ цепочки — медиана ползёт вместе с цепочкой и не срабатывает; уровень берётся по началу цепочки.
- Сшивание цепочек без исключения отточий — строка оглавления набиралась из двух десятков цепочек-точек (1971/10 с.93 geo: блоков 9 → 23, краска 99 → 86 %).
- Поле с наклоном до 12–20° и слабым сглаживанием — местный изгиб в углу страницы всё равно не догоняет, пересечения контуров хуже (53.5 против 47.8 тыс. px²).
- Слияние осей в ряд по медианам ординат (`LineAxis.cy`) — на перекосе половинки одной строки стоят на разной высоте (11 px при шаге 20), ряд не собирался и колонку резало правилом «слабое перекрытие по x»; оси сводятся в точке встречи с продолжением по наклону конца.
- Линейка толщиной 0.42–0.45 мм не проходила порог `RULE_MAX_THICKNESS_MM` = 0.4 мм и не находилась: колонтитул и заголовок рубрики попадали в один блок (1975/05 с.97). Порог поднят до 0.6 мм.
- Правило смены набора у группы ровно из двух рядов отключалось (окно сравнения = 1 < `MIN_BREAK_WINDOW`); для пары рядов окно в один ряд разрешено, решает совместная мера кегля и штриха.
- Ось считалась пристроенной по факту попадания в колонку, а не по факту попадания в РЯД: `rows_of` выбрасывает ряд за вылет за колонку, и такие оси пропадали совсем.
- Запасной кусок «строк без колонки» мерился границами колонки по межколоннику — на 1971/10 с.93 одиннадцать строк не проходили проверку вылета; у него границы колонки больше не применяются.
- Ряды-«проливы» держались отдельным куском от запасного: куски одной широкой строки попадали в разные куски и не сравнивались (заголовок «Минимальные нормы заказа…» делился на два блока).
- Слияние оси с ЛЮБОЙ осью ряда — на перекосе начало второй строки склеивалось с серединой первой; сверка идёт с ближайшей осью.
- Проброс поля хода строк в сборку рядов (`_same_row`) — на валидационном наборе не изменил ни одного числа: поле строится по охвату якорей и вне его клампится; откачено.
- Зона-колбаска постоянной толщины: направление конца куска шумит на 8–10°, и зоны двух соседних слов одной строки расходились веером (23 пары на 1973/08 с.85); зона сделана конусом, раскрытие ограничено 0.35 шага строк.
- Абсолютный предел наклона соединения (6°): в изогнутом углу полосы соседние слова законно стоят с перепадом 10° (16 верных пар отбито); наклон сверяется с местным наклоном строк по соседям.

**geometry_regression**
- Профильный deskew (сдвиг столбцов, `warpAffine` + профиль) на БИНАРНОМ рендере — все углы ровно 0.00°: при нулевом угле нет интерполяции и округления сдвигов, профиль всегда резче; годятся только центр-линии строк, `fitLine`/LSD и блочное сопоставление (`research/geometry_regression/README.md`).
- Линейки морфологическим открытием длинным ядром — наклонённая на 6° дробная черта (1967/01 с.85) рвётся в пыль; заменено LSD на 300 dpi со склейкой коллинеарных кусков.
- Наклон линейки в градусах как флаг — хорошая с.2 1967/02 давала 2° на 9-мм вертикалях (0.2 мм, глазу незаметно); мерится отклонение конца в мм.
- Остаток поля смещений внутри line art как флаг — велик и внутри таблиц на хороших страницах (там FineReader правит законно); решает доля тайлов со слабым пиком корреляции (61 % на погнутой блок-схеме с.80 против ≤ 6 % везде).
- Клин высоты строки (верх/низ букв по третям) для наклонённых заголовков — 0.056 на 1967/03 с.36 при шуме 0.05–0.25 на обычных строках.
- Сопоставление строк по перекрытию от короткой — строке, распавшейся в A на куски, доставался короткий кусок с шумным наклоном (1967/01 с.4); перекрытие ≥ 0.75 от длинной.
- Наклон строки и кромки в градусах как флаг — короткие куски строк дают 1.5° шума (1973/01 с.43); мерится уход конца в мм (длина × sin).
- Штрихи от 4 мм без разбора (v9) — 53 ложных bad по среднему наклону «черт формул» на страницах без формул: тире и дефисы 4–5 мм плюс две кромки одной линейки как две черты; лечится признаком дробной черты (краска над и под) и сведением двойников кромок.
- Отбраковка выбросов пробы изгиба по остатку от прямой (MAD) — принимала за выбросы настоящий изгиб конца линейки (1971/08 с.79, 1.2 мм на последних 4 пробах); вместо неё медианный фильтр по 5 пробам, который убирает только одиночные скачки (точки отточий на 1975/07 с.44).
- Изгиб линии по кускам LSD (штрих B, в A распавшийся на отрезки под разными углами; v8) — 296 ложных bad на паке: LSD режет ровную толстую линейку на параллельные куски со своими углами, а с B ничего не сравнивалось. Заменён сагиттой по краске вдоль линии в обеих версиях (`ocr_utils/geometry_regression/bend.py`).
- Рваность кромки (p80 остатка краёв строк от прямой, A − B) и дрожание соседних строк как признак «равнение перекосило» (v15) — на 28 страницах пользователя A − B ≈ 0: явление — наклон кромки относительно строк (блок стал параллелограммом), не рваность; оставлены как контекст (`reports/geometry_regression_v15.md`).
- Сдвиг по полю смещений как симметричная часть якобиана (du_x/dy + du_y/dx) и как самостоятельный флаг (v15) — выпрямление кривых строк (du_y/dx) давало «сдвиг» 2° на 1966/06 с.62, снятая трапеция (x растянут по-разному по высоте) — 1.9–2.3° на эталонных good; поле меряет преобразование, а не результат: сдвиг = du_x/dy + поворот страницы и только гейт, знак — по кромкам тех же строк.
- Балл перекоса в градусах сдвига против выигрыша (v15) — 1975/05 с.61: 2.3° → балл 3.1 при уходе кромки 1.5 мм и выигрыше 7.9 мм; балл — от ухода кромки в мм (1 до 1.2 мм, дальше уход/1.2).
- Разрыв следа краски на пропущенных пробах (v15) — полки шкафа с подписями поперёк (1966/01 с.78) рвались на куски и изгиб терялся; скачок мерится на пропуск с допуском пропорционально его длине.
- Наклон фото средним по кромкам (v15) — одна задранная кромка 1971/07 с.43 разбавлялась до 0.7 мм; сумма приростов по кромкам.
- Параллельность в рисунках от 20 мм и без рисунков (v15) — терялись эталонные bad по полкам и лучам; в рисунках от 12 мм и 4 членов, вне — от 15 мм.
- Растяжение заголовка относительно высоты (v15) — 0.043–0.066 у порчи против 0.057–0.058 у не-порчи, не разделяет; слабое правило — кривизна в долях длины ≥ 0.0008 (4 страницы).
- Порог выигрыша spread 0.8° (v15) — эталонный good 1968/05 с.55 становился bad; 0.65°.
- Перекос блока как прирост МОДУЛЯ шира, `|шир A| − |шир B|` (v15–v16) — кромка, которая в B клонилась на 0.7° в одну сторону, а в A клонится на 0.7° в другую, деформирована на 1.4°, а мера давала 0.05 мм; в v15 ошибку прятал шум кромок по боксам строк, с чистой кромкой по краске она увела 124 страницы в ok (просмотр пользователя 2026-09-23). Мерится изменение шира с ограничением остаточным перекосом A.
- Кромка блока по боксам строк и парам `match_lines` (v16) — кружки падали в отступы и внутрь блока: `line_fit` рвёт выключенную строку по широкому пробелу и теряет одиночную первую букву, обрезки встают в огибающую как строки (1966/03 с.13, 1967/11 с.75); кромка считается по первой краске ряда.
- Форма заголовка по абсолютным базовым линиям (центроид краски куска, разность размахов A − B) (v16) — шум формы букв ±5 px входит в размах по-разному в A и B, а выправленный наклон сам по себе даёт «ступеньку» (1972/01 с.92, 1967/05 с.41); форма — по остатку сдвигов кусков от прямой, а выпрямленная строка гасится (остаток знака не имеет: убранная дуга даёт тот же размах, что и наведённая, — 1968/01 с.96).
- Ступенька как наибольший скачок между соседними кусками и дуга полным размахом остатка (v16) — одиночный промах куска даёт и то и другое (1968/02 с.92); ступенька = сдвиг уровня с ≥ 2 кусками по сторонам, дуга = усечённый размах p10–p90.
- Разброс поворотов линий в семействе рисунка и поворот линии сверх поворота рисунка с порогом 2° (v16) — выпрямленная блок-схема (1975/06 с.39, 1972/11 с.27) шла в порчу; разброс считается по углам A − B, порог поворота 3°.
- Line art без исключения логотипов рубрик (v16) — росчерк с линейкой вокруг заголовка (1974/04 с.59) давал угол между «осями» 1.45° при законной правке заголовка; рамка, занятая строками текста по высоте наполовину, — не чертёж.
- Форма line art относительно гомографии страницы по DIS-потоку (v18) — гомография не описывает законное выпрямление изогнутой полосы (бланк 1974/02 с.95), на заливках DIS «плывёт» (портреты 1970/04 с.26/28: перекос осей 10–14°); эталон good 1975/04 с.95 — 5.2 мм при 2.5 мм у порченой 1972/10 с.79.
- Форма line art по сопоставлению участков с опорой на тайлы текста вокруг рамки и проверкой направления по прямоте черт (v18, `lineart_shape_mm` ≥ 1.5 мм) — верна 1 смена вердикта из 13: полутоновые фото, которые разбор v6 относит к «неясно»/«рисунок», и штриховка сопоставляются неоднозначно; оставлена информационной.
- Перенос строк без пары в A полем без ограничений (v18) — 33 ложных смены из 36: «строки» разбора в полутоне фото (обложки 1973/10 с.1, 1973/02 с.1) и концы осей у вертикальной линейки («ИЮНЬ» 1971/06 с.3), где вертикальный сдвиг потоком не определён; растр v16 как запрет переноса накрывал рисунок с подписью (1972/10 с.79).

- Подбор дилатации маски пальца против склейки с ложной детекцией — арифметически не лечится (`reports/finger_border_check_predilate_report.md`).

**final_pdfs**
- Фильтр выдумок surya из `rotated_text` как есть — на слое пропускал латиницу без кириллицы (66 из 514 принятых) и ряды одинаковых чисел; свой фильтр `text_layer_fix.second_opinion.hallucination_reason` (`reports/final_pdfs_pack1.md`).
- Затирание бинарного растра под иллюстрацией через перекодирование JBIG2 → CCITT G4 — G4 на 40 % больше JBIG2, а выигрыш от затирания ~1 КБ; вместо этого снимаются образы-фигуры FineReader (60–120 КБ каждый), под которыми основной образ и так пуст (краска 0.05 %).
- Иллюстрации из заострённых копий (Capture One) — заострение подчёркивает растровую сетку фото; источник — очищенные полосы `blurred/` (печати закрашены, растр под защитной маской не размыт); оригиналы «Готово» не годятся: на 48 обложках рукописные надписи ещё не закрашены.
- Уменьшение 600 → 300 dpi одним INTER_AREA — сетка растра остаётся видимой; Gaussian σ 0.1 мм уже мылит окна зданий; взято σ 0.05 мм.

**text_layer_fix**
- `get_texttrace()` PyMuPDF для привязки спанов — падает на PDF FineReader; свой разбор потока + `rawdict` даёт 100 % (`reports/text_layer_fix.md`).
- Удаление спана `BDC…EMC` целиком — внутри первого спана лежит `cm` страницы, картинка уезжает; удалять только `BT…ET`.
- `insert_text`/`TextWriter` для вставок — по отдельному потоку на вызов; свой `BT…ET` в тот же поток.
- Словарная доля и число коротких слов как страничный признак россыпи — не разделяют (медиана 8 % и 101 слово на любой странице); пословный аспект компонент чернил — не разделяет.
- RLSA-цепочки для подписей на схемах — ловят только длинные строки; вертикальные пары по ближайшему соседу без проверки горизонтального соседа — собирают первые буквы строк абзаца.
- Ориентация ячейки без сравнения с прямым чтением — «ШТ.» и смешанные ячейки шли под нож (287 зон на выборке).
- Порог 0.8 для чисел без букв — в поясе 0.8–0.9 треть чисел с чертежей с лишними нулями.
