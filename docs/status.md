## Что пробовали и отвергли

**defocus_detection**
- `edge_width` как рабочая метрика — AP 0.330 против 0.732 у `dom`, уровень плывёт между сессиями на 12.9 % (`reports/defocus_validation_si_report.md`).
- DeQA-Doc (7B, GPU) — AUC 0.68–0.77 против 1.00 у `dom` на тех же пикселях (`reports/defocus_validation_si_report.md`).
- `pyiqa`, DeFusionNET/BTBNet/MSDU-Net, SMBlurDetect, коммерческий куллинг — обучены на натурных сценах и глубине резкости, нет понятия «читается ли петит» (`reports/defocus_detection_state_of_the_art.md`).
- Выравнивание уровней `dom_eq` — нулевой эффект: `dom` есть отношение сумм, линейное растяжение сокращается (`reports/defocus_validation_si_report.md`).
- Первая версия `edge_dir` (поворот кадра на 4 угла) — сам поворот размывает, резкий кадр получал анизотропию 1.40 (`reports/defocus_validation_si_report.md`).
- Детектор смаза на реальных данных — на синтетике безупречен, на съёмке не подтвердился (`reports/defocus_validation_si_report.md`).
- Счёт балла только по тайлам с ритмом строк — средняя точность падает, верное срабатывание теряется (`reports/defocus_validation_si_report.md`).
- Нормировка порога на шаг строк — не понадобилась: уровень балла перенёсся на другую газету и гарнитуру (`reports/defocus_validation_si_report.md`).
- Сырой `moire` = std(NEAREST−AREA) — на 50 % объясняется количеством краски, а не фокусом (`reports/defocus_moire_improvement_plan.md`).

**dewarp**
- DocScanner, UVDoc, DocTr, DocTr-Plus, DewarpNet — обучены на Doc3D (фото мятых листов), на флэтбед-скане сдвигают, режут и «курсивят» страницу (`reports/dewarp_report.md`).
- `page-dewarp` (cubic sheet) — модель камеры и цельного листа, поворачивает всю полосу (`reports/dewarp_report.md`).
- ScanTailor заменил собой весь старый подпакет dewarp (`ocr_utils/legacy/README.md`).

**curved_lines**
- Край колонки (Leptonica edge curvature, ScanTailor) — абзацные отступы и висячие строки шумят сильнее прогиба (`reports/curved_lines_detection_report.md`).
- `strip_shift` — на ровных полосах гребёнка цепляется за соседнюю строку, лишён права одиночного голоса (`reports/curved_lines_detection_report.md`).
- Базовая линия по нижней огибающей — AUC 0.50 (`reports/curved_lines_detection_report.md`).
- Ridge-центр-линии (Bukhari) — хребет прыгает между строками, AUC 0.56 (`reports/curved_lines_detection_report.md`).
- Базовые точки слов (Ulges) — слишком мало точек на строку (`reports/curved_lines_detection_report.md`).
- Kraken blla — векторизация упрощает линию до двух точек, формы кончика нет; 10–25 с на полосу (`reports/curved_lines_detection_report.md`).

**geometry_regression**

- Фраза «перенос у повреждённого края — не повреждение» в промпте — не влияет ни на разорванные переносы (1/5 против 0/5), ни на ложные `edge_words` (1/5 против 2/5); склейка переносов по корпусу выпуска — 17/39, по словарю `pymorphy3` — 36/39 (`reports/external_ocr_hyphenation_second_pass.md`).
- Второй проход без абзаца «Apply rule 5 strictly» — не меняет ничего; без списка `edge_words` — убирает порчу чистых слов, но смазанное слово всё равно подставляется без тега (6/6 «немецкое») (`reports/external_ocr_hyphenation_second_pass.md`).
- Второй проход по умолчанию — на 44 парах 1991/02 снимал теги с достроек, не меняя букв (с. 93: 8 → 0), обвешивал чистые слова `<supplied>` (с. 4: 2 → 23, и страховка по счётчикам брала его с ошибкой «перетерпеть»), ×2.1 к цене повреждённых полос; с v16 выключен, оставлен опцией (`ocr_utils/external_ocr_services/README.md`).
- `[неразборчиво]` в правиле 1 при тегах TEI в правиле 5 — модель ставила его вместо одной буквы («сущест[неразборчиво]ует», с. 89 1991/02) и на продолжениях переносов (23 на с. 93); убран в v16.
- Перенос `<gap>` из `edge_words` в тело кодом — почти всегда строка, оборванная переносом, слово в теле целое: 24 ложных пропуска вида «в первую<gap>▒▒▒</gap> очередь» на 3 полосах 1991/02; с v16 пропускам верим только из тела (`schema.tags_from_edge_words`).
- `mawo-pymorphy3` как словарь для склейки переносов — `is_known` истинен почти для любой склейки («фирмыизготовителя», «купляпродажа», «както»), 227/234 ложных слияний (`reports/external_ocr_damaged_research.md`).
- Детектор `gutter_loss_detection` как источник подсказок для OCR — мерит «текст вплотную к сгибу», не утрату букв: на фото-сканах балл 0.97 у всех кадров мини-набора и 58 из 59 кадров 1991/02, «таблица» на 51 текстовой полосе, сторона всегда «обе» (`reports/external_ocr_damaged_research.md`).
- Короткий промпт (без таблиц, иллюстраций, формул, структуры) для повреждённых полос — пометка достроенного не выше v16, ложные `<supplied>` на сплющенных буквах те же, структура теряется (`reports/external_ocr_damaged_research.md`).
- Горизонтальные полосы 1×3…1×6 вместо сетки тайлов 1×2 — CER к FineReader на 20 чистых полосах не изменился (медиана 0.0023), цена +15…+58 %, при 6 полосах пустая обложка; потолок «≈ 800 токенов на картинку при 1.8 Мпкс» не подтвердился — токены растут с площадью и дальше (1070 → 1340 при 1.3 → 4 Мпкс) (`reports/external_ocr_damaged_research.md`).
- Догадки `full` из `edge_words` в подсказке второго прохода — модель перечитывала названные строки и портила соседние чистые слова («Солкомфлот» 8/12, без списка 0/12); во второй проход уходят только `seen` и вид.

- `get_texttrace()` PyMuPDF для привязки спанов — падает на PDF FineReader; свой разбор потока + `rawdict` даёт 100 % (`reports/text_layer_fix.md`).

- `insert_text`/`TextWriter` для вставок — по отдельному потоку на вызов; свой `BT…ET` в тот же поток.
- Словарная доля и число коротких слов как страничный признак россыпи — не разделяют (медиана 8 % и 101 слово на любой странице); пословный аспект компонент чернил — не разделяет.
- RLSA-цепочки для подписей на схемах — ловят только длинные строки; вертикальные пары по ближайшему соседу без проверки горизонтального соседа — собирают первые буквы строк абзаца.
- Ориентация ячейки без сравнения с прямым чтением — «ШТ.» и смешанные ячейки шли под нож (287 зон на выборке).
- Порог 0.8 для чисел без букв — в поясе 0.8–0.9 треть чисел с чертежей с лишними нулями.
