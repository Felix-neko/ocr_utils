# Ориентация RAF-снимков газет: решение, раскладка, поворот

Сделано по двум сессиям: `5997a0af` (2026-10-05: ЭГ 1968, СИ 1987/1989, ~2400 кадров СИ/РТ) и `dc21bfe6`
(2026-10-08: ЭГ `2026-10-07`, 182 кадра). Ошибки, на которых учились, — в конце.

**Несколько путей.** Аргументом можно дать несколько папок съёмки (каждая — в своих кавычках или
обратных апострофах: в именах пробелы). Тогда:

- корни нумеруются `A`, `B`, … в порядке аргументов; превью — в `$S/<буква>/<подпапка>/` (или
  `$S/<буква>/`, если кадры лежат прямо в корне), чтобы одноимённые подпапки разных корней (`290_FUJI`) не
  перезаписали друг друга;
- проверка тегов (шаг 1) — по каждому корню отдельно;
- счёт `score4.sh` — один общий прогон по всему `$S`;
- `final.txt` — со столбцом корня: `<буква>\t<подпапка или .>\t<DSCFxxxx>\tCW|CCW|NONE|SKIP`;
- `apply.sh` — один на все корни: массив `ROOTS=( "<путь A>" "<путь B>" )`, в строках `mv` — полный путь
  корня; циклы exiftool и сверка — по каждому корню (`for R in "${ROOTS[@]}"`). Кадры прямо в корне
  раскладываются в `"$R/$CW"` (без промежуточной подпапки), поэтому exiftool-цикл ходит и по
  `"$R/$CW"`, и по `"$R"/*/"$CW"`;
- ответ — таблица по каждому корню и подпапке.

Полосы сняты боком: кадр почти всегда надо повернуть на 90° в одну из сторон. Правильная ориентация —
та, при которой **номер страницы** стоит прямо: на части полос (вклейки «Лекций», таблицы) основной текст
напечатан поперёк, и по нему решать нельзя.

## 0. Запись в Я.Диск — только при остановленном демоне (останавливает и включает Claude, шаги 4.1, 4.6)

Кадры лежат под `/mnt/dump3/yandex_disk_linux_baby_zergling` (живая синхронизация, `docs/data_layout.md`).
`mkdir`, `mv` и `exiftool` по кадрам — это запись туда. 2026-10-05 запись при работающем демоне совпала с
пропаданием и докачкой сотен кадров в соседних папках.

- Шаги 1–3 (превью, счёт, листы) — только чтение; превью, листы и списки — в scratchpad.
- Всё, что пишет в папку кадров (подпапки, перенос, теги, вынос обратно), — **скриптами в scratchpad**
  (`apply.sh`, `retag.sh`, `flatten.sh`), их запускает Claude, но только после остановки демона и её проверки (шаги 4.1–4.2).
  Каждый скрипт первой строкой сам проверяет `yandex-disk status`
  и выходит, если демон работает.
- Прямые `mv`/`mkdir`/`exiftool` по путям Я.Диска в командах Bash не писать (хук их блокирует) и **не
  обходить хук путём в переменной** (`R=…; mv … "$R/…"`) в обычной команде — так 2026-10-08 запись прошла
  мимо хука без проверки демона. Скрипт с проверкой демона — единственный путь.
- Ни одного файла на Я.Диск не копировать: только `mv -n` внутри папки съёмки и `exiftool
  -overwrite_original` на месте. Манифесты, логи, превью — в scratchpad.

## 1. Превью

Пиксели RAF не нужны — хватает встроенного JPEG:

```bash
S=<scratch>/orient; cd "<папка съёмки>"
exiftool -q -T -Directory -FileName -Orientation -ImageSize -r -ext RAF . | awk -F'\t' '{print $3,$4}' | sort | uniq -c
for d in */; do mkdir -p "$S/${d%/}"; exiftool -q -b -PreviewImage -w "$S/${d%/}/%f.jpg" "$d"; done
```

Первая команда — какие теги уже стоят (обычно `Horizontal (normal)`; если стоит поворот, сказать
пользователю до любых действий). Если кадры лежат прямо в папке, без подпапок, — `-w "$S/%f.jpg" .`.
Скрытые подпапки (`.covers`, `.defocus_for_debugging`) не трогать, если пользователь не сказал.

## 2. Счёт: четыре поворота, `--psm 6`

```bash
find "$S" -name '*.jpg' -print0 | xargs -0 -P16 -n1 sh /home/felix/Projects/ocr_utils/.claude/skills/raf-orientation/score4.sh | sort > "$S/score4.txt"
```

В именах подпапок съёмки бывают пробелы и скобки («297_FUJI ЭГ 1969 7-9 по порядку»): списки файлов — только
через `-print0`/`xargs -0` или массив bash, не `ls | xargs`. Число полей в строке `score4.txt` поэтому
не постоянно — счёт брать из **последних четырёх** полей (`$(NF-3)…$NF` в awk).

`score4.sh` (рядом с этим файлом) для каждого превью даёт `файл s0 s90 s180 s270` — число уверенных слов
после поворота на 0/90/180/270° **по часовой**. ~5 с на кадр на ядро; 182 кадра — ~15 мин при 16 потоках.

Решение по строке:

| Лучший угол | Значит | Подпапка | Тег `-n -Orientation=` |
|---|---|---|---|
| 90 | текст в кадре идёт снизу вверх | «повернуть по часовой» | `6` (Rotate 90 CW) |
| 270 | текст идёт сверху вниз | «повернуть против часовой» | `8` (Rotate 270 CW) |
| 0 или 180 | **основной текст в кадре горизонтален** — вклейка поперёк полосы или кадр уже прямой | → шаг 3, по номеру страницы | — |

Уверенный ответ — лучший угол в ≥3 раза больше второго (на газетных полосах обычно 7–20 раз) и ≥ ~20 слов.
Всё остальное (обложки, форзацы, полосы почти без текста) — на просмотр глазами.

**Не использовать** tesseract OSD (`--psm 0`) и сравнение только 90 против 270 с `--psm 3`: оба доворачивают
текст сами. OSD ещё и ненадёжен на обложках (уверенность ~0, на части — нет ответа или неверный).

## 3. Глазами: листы, номера страниц, обложки

- **Контактные листы всех кадров**, уже повёрнутых по решению шага 2, — проверка, что всё встало прямо
  (заголовки, шапка газеты). Смотреть все листы, не выборку:
  ```bash
  montage <список повёрнутых превью> -tile 6x4 -geometry 300x300+4+4 -label '%t' -pointsize 14 "$S/sheet_NN.jpg"
  ```
- **Кадры с горизонтальным текстом** (лучший угол 0/180) — по **номеру полосы**. Вырезать окрестность
  номера из превью крупно (`convert -crop … -resize 200%`): на склейке цифры не читаются. Наблюдение по
  ЭГ «Лекции» 2026-10-07, выполнилось на 38/38: чётный номер стоит справа и читается снизу вверх → по
  часовой; нечётный слева, читается сверху вниз → против часовой. Это подсказка, не замена просмотра.
- **Кадр уже прямой** (журнальный разворот, номера внизу прямые) — не поворачивать, оставить в корне папки,
  тег `1` (если стоял другой). Сказать пользователю отдельной строкой.
- **Обложки подшивок** — по рукописной наклейке и надписям на обложке, вырезанным крупно («Социалистическая
  индустрия 1989 IV–VI» сверху вниз → против часовой).
- **Форзац, чистый лист, штрихкод без номера** — если направление не читается однозначно, кадр **не
  раскладывать**, оставить в исходной папке и назвать в ответе. Не переносить решение с соседнего кадра
  (титул рядом ≠ форзац; 2026-10-05, `289_FUJI/DSCF0063` — ошибка).
- Если пользователь сказал, что внутри папки направление одно (папки «чётная» / «нечётная» подшивки), —
  направление папки по большинству, а каждый кадр против большинства просмотреть глазами.

## 4. Применение: восемь шагов с пользователем

Итог решений — `"$S/final.txt"`: строки `<подпапка>\t<DSCFxxxx>\tCW|CCW|NONE|SKIP` (табуляция: в именах
подпапок пробелы; при нескольких корнях — со столбцом корня впереди). Перед шагом 4.1 — сводка решений
пользователю (таблица по подпапкам и сомнительные поимённо, как в разделе 5).

**4.1. Остановка демона — сам Claude** (sudo не нужен: демон пользовательский; команды `yandex-disk`
пишут не в папку кадров, хук их не трогает). Пользователя не спрашивать, только сообщить одной строкой.
- Если демон уже остановлен (`yandex-disk status` → `Error: daemon not started`) — запомнить, что он был
  выключен **до нас**, и на 4.6 не включать без вопроса.
- Если работает: дождаться `Synchronization core status: idle` (опрос раз в ~30 с через `Monitor`, прогресс
  пользователю раз в 3–5 мин) — не обрывать идущую отправку или докачку; затем `yandex-disk stop`.
  Статус `error` — не останавливать молча: показать текст ошибки пользователю и спросить.

**4.2. Проверка остановки.** До 30 с ждать, пока одновременно: `yandex-disk status` печатает
`daemon not started` (без строки `core status`) и `pgrep -x yandex-disk` пуст. Не остановился — второй
`yandex-disk stop`, потом сказать пользователю и не писать в папку кадров (`kill` не делать).

**4.3. Перенос и теги.** Перед запуском — md5 «до» в scratchpad: пиксели превью по jpg шага 1
(`pixmd5.sh`) и блок сырых данных каждого RAF (`rawmd5.sh`, читает ~85 МБ на кадр, `xargs -P4`). Из них и
`final.txt` — план `путь после раскладки\tтег 6|8\tmd5 пикселей\tmd5 сырых`. Затем `apply.sh` (образец ниже) в фоне:
`setsid bash "$S/apply.sh" > "$S/apply.log" 2>&1 < /dev/null & PID=$!`. Скрипт пишет строку прогресса
каждые 25 файлов (`перенесено N/всего`, `тег: подпапка N/всего`). Ждать по PID (`Monitor` с until-циклом
`kill -0 $PID`) и **раз в 3–5 минут показывать пользователю последнюю строку лога**. ~1 с на файл на dump3:
300 кадров — ~5 мин, 2400 — ~40 мин.

**4.4. Проверка целостности после поворота** — `verify.sh <план> <манифест после> 4` (рядом с этим файлом,
только чтение; рядом же `rawmd5.sh`, `pixmd5.sh`), по каждому файлу на новом месте:
- файл есть, `-n -Orientation` = 6 у CW и 8 у CCW;
- `exiftool -validate -warning -error` — без ошибок и предупреждений, **кроме** `VignettingParams overlaps
  ChromaticAberrationParams`: оно есть у нетронутых RAF этой камеры (проверено 2026-10-31);
- md5 **пикселей** превью = «до» и md5 блока сырых данных (`FujiIFD:StripOffsets/StripByteCounts`) = «до».
  Сравнивать байты файла или байты `PreviewImage` нельзя: у RAF EXIF с `Orientation` лежит внутри встроенного
  JPEG, а exiftool перепаковывает файл (минус ~52 КБ, сырые сдвигаются) — сами сырые и пиксели при этом
  побайтно те же (проверено на копии 2026-10-31);
- отдельно: число RAF в папках съёмки то же, в исходных местах кадров нет, нет `*_original`, `*_exiftool_tmp`.
Выход `verify.sh` — манифест «после»: md5 **всего файла**, он нужен на шаге 4.7.

**4.5. Отсмотр пользователем.** Сказать, что готово, где лежат подпапки, что просмотрщик должен понимать тег
`Orientation`. `AskUserQuestion`: «Всё отсмотрел, всё повёрнуто правильно?» — варианты «Да, всё верно»
/ «Перенёс неверные в другую подпапку поворота» (/ «Ещё не досмотрел» — ждать).
- «Перенёс…» — найти перенесённые: файл в `повернуть по часовой`, а тег 8 (или наоборот) —
  `exiftool -q -T -Directory -FileName -n -Orientation -r -ext RAF <корень>`; сверить с `final.txt`, обновить
  `final.txt`. Перетегировать только их (`retag.sh`: проверка демона, `exiftool -overwrite_original -n
  -Orientation=6|8` по списку файлов), повторить 4.4 для них, назвать пользователю поимённо, спросить снова.
- «Да, всё верно» — вынести кадры из подпапок поворота в их родительскую подпапку (`flatten.sh`: проверка
  демона, `mv -n` по строке на файл, `rmdir` пустых подпапок поворота, сверка числа RAF с исходным и тегов),
  обновить манифест «после» на новые пути (md5 при `mv` не меняется).

**4.6. Включение демона — сам Claude**, сразу после выноса из подпапок (или после 4.4, если выносить не
просили), если на 4.1 демон работал. `yandex-disk start` (без `--read-only`, `--exclude-dirs` — с тем же
конфигом, что был), затем до 60 с ждать: `pgrep -x yandex-disk` не пуст и `yandex-disk status` печатает
`Synchronization core status: …` (обычно сначала `index`). Не поднялся — показать вывод `start` пользователю
и остановиться. Если демон был выключен до нас — спросить `AskUserQuestion`, включать ли.

**4.7. Синхронизация и проверка.** Ждать, пока `yandex-disk status` не покажет
`Synchronization core status: idle` дважды подряд с интервалом ~1 мин (`Monitor`, раз в несколько минут —
строка прогресса пользователю из `status`). Затем, только чтение:
- md5 всех файлов совпадает с манифестом «после», число RAF то же;
- в папках съёмки нет паразитных файлов: всё, что не `DSCF????.RAF` и не `*.flags.json`, — особенно
  `* (1).RAF`, `*conflict*`, `*.tmp`, `*_original`, `*_exiftool_tmp`, вернувшиеся пустые или полные подпапки
  `повернуть …`, кадры, снова появившиеся в старом месте (докачка удалённой копии);
- `yandex-disk status` без ошибок (`error`, `Error`).

**4.8. Доклад.** Что в порядке и что нет, поимённо; где манифесты и логи.

Образец `"$S/apply.sh"`:

```bash
#!/bin/bash
# Раскладка кадров по подпапкам и тег Orientation; запускать при остановленном yandex-disk.
set -euo pipefail
# Запущенный демон печатает «Synchronization core status: idle|busy|index|error…» (и при error тоже жив)
if yandex-disk status 2>&1 | grep -q 'core status'; then
    echo "yandex-disk запущен — сначала yandex-disk stop"; exit 1
fi
ROOT="<папка съёмки>"
CW="повернуть по часовой"; CCW="повернуть против часовой"
# По каждой подпапке: создать подподпапки, перенести без перезаписи (mv -n)
mkdir -p "$ROOT/290_FUJI/$CW" "$ROOT/290_FUJI/$CCW"
mv -n "$ROOT/290_FUJI/DSCF0001.RAF" "$ROOT/290_FUJI/$CW/"
# … по строке на кадр, сгенерировать из final.txt …
# Тег — один вызов exiftool на подподпапку; значение абсолютное, повторный запуск не довернёт ещё раз
for d in "$ROOT"/*/"$CW";  do [ -n "$(ls -A "$d")" ] && exiftool -q -overwrite_original -n -Orientation=6 -ext RAF "$d"; done
for d in "$ROOT"/*/"$CCW"; do [ -n "$(ls -A "$d")" ] && exiftool -q -overwrite_original -n -Orientation=8 -ext RAF "$d"; done
# Сверка: число RAF и теги по папкам, посторонние файлы
exiftool -q -T -Directory -Orientation -r -ext RAF "$ROOT" | sed "s|^$ROOT/||" | sort | uniq -c
find "$ROOT" -name '*_exiftool_tmp' -o -name '*_original'
```

- Имена подподпапок — как сказал пользователь («надо повернуть …», «нужно повернуть …»); по умолчанию
  «повернуть по часовой» / «повернуть против часовой». Если просят только разложить — без блока exiftool;
  если только повернуть (направление одно на папку) — без `mkdir`/`mv`.
- `-overwrite_original` — чтобы не оставались копии `*_original`; пиксели RAF не перекодируются.
- `mv` в цикле по списку — в bash-массиве или по строке на файл: в zsh `for f in $list` не бьёт строку на
  слова (2026-10-05 все 64 файла уехали в одну подпапку).
- Прогресс: в цикле `mv` — `i=$((i+1)); (( i % 25 == 0 )) && echo "перенесено $i/$N"`; exiftool на
  подпапку печатает «N image files updated» — достаточно для тегов.
- Под `set -e` условие в цикле писать через `if …; then …; fi`, не `[ … ] && …`.
- exiftool — только по подпапкам поворота из `final.txt` этого прогона, не глобом `"$ROOT"/*/"$CW"`: 2026-10-31
  глоб по дню задел уже повёрнутую соседнюю 297 (значения те же, но файлы переписаны лишний раз).

## 5. Сводка перед 4.1 и доклад

Таблица по подпапкам (по часовой / против / без поворота / оставлены), как решались сомнительные (поимённо:
кадр → по чему решил), что оставлено в исходной папке и почему, путь к `final.txt` и листам в scratchpad.

**Исключать папку из синхронизации вместо `yandex-disk stop` не надо**: `exclude-dirs` в
`~/.config/yandex-disk/config.cfg` применяется только после перезапуска демона, а при возврате папки демон
сверяет её заново без своего индекса переносов — перенесённые кадры могут уйти как новые файлы, а старые
пути докачаться обратно с сервера (дубли). Остановка демона проще и проверена.
