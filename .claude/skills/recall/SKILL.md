# Поиск по прошлым сессиям

Транскрипты всех сессий лежат в `~/.claude/projects/-home-felix-Projects-ocr-utils/*.jsonl` (JSONL, по файлу
на сессию, ~1 ГБ). Читать их напрямую не надо — есть скрипт, который вынимает только текст диалога и кэширует
его в `~/.cache/claude_recall/`:

```bash
uv run python scripts/search_sessions.py titles [--since YYYY-MM-DD]      # список сессий с названиями
uv run python scripts/search_sessions.py search 'регулярка' [опции]       # поиск по репликам
uv run python scripts/search_sessions.py dump <префикс id> [--start N --end M]   # диалог одной сессии
```

Опции `search`: `--since` — сессии не старше даты; `--session <префикс>` — одна сессия; `--role U|A|S|N`
(пользователь / ассистент / сводка после сжатия контекста / уведомление фоновой задачи, можно несколько);
`-C N` — соседних реплик вокруг совпадения (по умолчанию 1); `--max-chars` — обрезка реплики (1500; 0 — целиком);
`--limit` — потолок совпадений (50). Регулярка без учёта регистра; для русских словоформ писать корень:
`'расфокус'`, `'LaMa.*кра'`.

## Порядок

1. Из запроса `$ARGUMENTS` выделить 1–3 ключевых слова (термин, имя модуля, число, название пака) и сузить период,
   если пользователь его назвал. Начать с `--role U` — вопросы и решения пользователя короче и точнее ответов.
2. Пусто — **снять `--role`** и расширить регулярку синонимами (`'huge|THP'`), а не сужать: технические
   детали часто лежат не в диалоге, а в сводке `S` или в отчёте субагента, пришедшем уведомлением `N`.
   Слишком много — добавить `--since`, второе слово в регулярку (`'dewarp.*textline'`), `--role A`
   для выводов ассистента, `--role S` для сводок (в них уже сжатые итоги длинных сессий).
3. Найдя нужную сессию, взять контекст через `-C 3` или `dump <префикс> --start N --end M` — не выгружать сессию целиком,
   в них по 200+ реплик.
4. В ответе: дата, короткий id и название сессии, суть — цитатой или пересказом. Если нашлось несколько
   противоречащих обсуждений, показать оба с датами: позднее обычно актуальнее, но это решает пользователь.

## Оговорки

- В логах лежат и отвергнутые ветки, и промежуточные ошибочные выводы. Прежде чем выдавать найденное за
  решение, сверить с `docs/status.md` и кодом: если в репо иначе — репо прав.
- Если найденный факт стоит того, чтобы его не искать заново, — предложить перенести в `docs/status.md`,
  `CLAUDE.md` или README подпакета, а не полагаться на поиск по логам.
- Результаты инструментов, размышления модели и субагенты (`<id сессии>/subagents/`) в поиск не входят; если
  нужны числа из вывода команды, они чаще есть в ответе ассистента или в уведомлении `--role N`.
- Текущая сессия тоже в списке (файл дописывается по ходу), кэш сам обновляется по mtime.
