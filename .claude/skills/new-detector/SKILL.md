# Новый детектор / подпакет

Образцы: `ocr_utils/show_through_detection` (компактный), `ocr_utils/line_art_detection`
(с экспортом и отчётом), `ocr_utils/scan_markup/curved_lines` (с кэшем измерений).
Перед созданием — проверить в `docs/modules.md` и `docs/status.md`, что похожего нет и что
направление не отвергнуто.

## Скелет

```
ocr_utils/<имя>/
├── __init__.py      # докстринг: одна строка, что ищет и на чём
├── __main__.py      # """Точка входа: ``python -m ocr_utils.<имя>``.""" → cli.main()
├── cli.py           # только click: опции, вызов pipeline
├── pipeline.py      # обход пачки + пул воркеров, инициализатор воркера
├── features.py      # расчёт по одному кадру: чистая функция (ndarray → dataclass)
├── report.py        # CSV → md-сводка, контактные листы (если нужны)
└── README.md        # зачем, что на входе/выходе, как калибровать пороги
tests/ocr_utils/<имя>/test_features.py   # на синтетике
run_scripts/<имя>/run_<пак>.sh          # source common.sh, числа в шапке
```

## Обязательные свойства

- `--jobs` с умолчанием 16 (или меньше с обоснованием), `mp_context=forkserver`, инициализатор
  воркера отключает hugepage и потоки BLAS (образец `ocr_utils/dewarp/cli.py`).
- GPU-модель (surya и т.п.) — один экземпляр в родителе, воркерам только CPU-часть; layout брать
  из кэша `LAYOUT_CACHE_DIR`.
- Размеры, привязанные к бумаге, — опциями CLI в пикселях; умолчания с пометкой «пак-1, 600 dpi».
- Выход — CSV со всеми метриками всех полос (на SSD) + md-сводка + контактный лист худших /
  флагнутых. Пороги ставятся по распределению этого CSV, а не по эталону из десятка полос:
  сначала прогон без порога, потом выборка по поясам score глазами, потом порог в run-скрипт.
- Идемпотентность: `--skip-if-exists` или кэш измерений, чтобы прерванный прогон дозабирался.
- Сообщения, логи, докстринги — на русском; `black -l 120 -C`.

## Завершение

1. `uv run pytest tests/ocr_utils/<имя> -q`.
2. `uv run python scripts/gen_module_map.py` (хук делает это сам после правки .py, но проверить).
3. Строка в карту подпакетов `CLAUDE.md` и строка в `docs/status.md` (статус, отчёт, пороги).
4. Отчёт по прогону — навык `write-report`.
