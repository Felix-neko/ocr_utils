# Пулы процессов и GPU

- **GPU-задачи (surya, torch, YOLO, SAM, LaMa) в пул процессов не заворачивать** — видеопамять
  одна. Модели грузить один раз на прогон (образец — `scan_cropping/gpu_models.py`), а в пул
  отдавать только CPU-часть. Если layout нужен воркерам — читать из кэша, без импорта surya.
- **Инициализатор воркера** любого пула с большими массивами обязан отключать hugepage и
  потоки BLAS, иначе выделения в 40 раз медленнее (замер в `ocr_utils/dewarp`):

  ```python
  np._core.multiarray._set_madvise_hugepage(False)
  cv2.setNumThreads(1)
  threadpoolctl.threadpool_limits(1)
  ```

  Готовый образец — `ocr_utils/dewarp/cli.py`, `ocr_utils/scan_markup/curved_lines/analysis.py`.
- `mp_context=forkserver`; число воркеров — параметр `--jobs` с умолчанием 16, но если задача
  упирается в память или диск, умолчание ниже и с обоснованием в комментарии.
- **Размеры, привязанные к бумаге** (окна фильтров, радиусы, окно бинаризации), не выводить
  из размера кадра и не хранить долями: в «Готовое» попадают неполные страницы. Мерить пак
  заранее (`ocr_utils.defocus_detection.scale`: штрих, шаг строк) и передавать числами из
  run-скрипта. Умолчание в коде допустимо с пометкой «для пака-1 при 600 dpi».
- Файлы, которые прямо сейчас пишет внешний экспорт (Capture One, FineReader, ScanTailor),
  открывать только при `mtime` старше 10 минут; опция `--min-age-minutes`, скрипт идемпотентный.
- Логи и сообщения — на русском, как и комментарии.
