# Run-скрипты

- Каждый скрипт начинается с `source` ближайшего `common.sh` — пути к данным только оттуда,
  абсолютные пути в скриптах не дублировать. Новый путь → новая переменная в `common.sh` с
  комментарием, на каком диске и почему.
- Шапка скрипта: что делает, что читает, что пишет, сколько идёт по паку, откуда взяты числа
  (окна, радиусы, пороги) — со ссылкой на замер или отчёт.
- Число воркеров — переменная `JOBS` в шапке. 16 по умолчанию; меньше — с обоснованием
  («упирается в диск/память», «лимиты API»).
- Скрипт с пулом процессов: `set -m` и `trap 'kill -- -$$' EXIT INT TERM`, иначе после
  остановки остаются сироты forkserver и воркеры (случай 2026-09-08: 67 процессов, машина
  думала, что загружена извне).
- Запуск в фон из сессии агента — только `setsid ./run_x.sh > лог 2>&1 < /dev/null & PID=$!`:
  без `setsid` pgid ≠ pid, и `kill -- -$PID` промахивается. Ждать — `while kill -0 "$PID"`,
  живость — `ps -p "$PID"`. Перед повторным запуском — `ps -eo pid,pgid,cmd | grep '[r]un_'`.
- Выход прогона — на SSD (`/mnt/SYSTEM/...`, регистр значим) или в `~/Projects/mts_markup`,
  никогда в корень `/mnt/dump3` (Я.Диск переименует поверх исходников). См. `docs/data_layout.md`.
- Скрипты, забирающие внешний экспорт, — идемпотентные и с `--min-age-minutes 10`.
