# Run-скрипты

- Каждый скрипт начинается с `source` ближайшего `common.sh` — пути к данным только оттуда,
  абсолютные пути в скриптах не дублировать. Новый путь → новая переменная в `common.sh` с
  комментарием, на каком диске и почему.
- Шапка скрипта: что делает, что читает, что пишет, сколько идёт по паку, откуда взяты числа
  (окна, радиусы, пороги) — со ссылкой на замер или отчёт.
- Число воркеров — переменная `JOBS` в шапке. 16 по умолчанию; меньше — с обоснованием
  («упирается в диск/память», «лимиты API»).
- Скрипт с пулом процессов: `set -m` и гашение группы на выходе, иначе после остановки остаются
  сироты forkserver и воркеры (случай 2026-09-08: 67 процессов, машина думала, что загружена извне).
  Ловушки — ровно такие:
  ```bash
  trap 'rc=$?; trap - EXIT; trap "" INT TERM; kill -- -$$ 2>/dev/null || true; exit $rc' EXIT
  trap 'exit 130' INT
  trap 'exit 143' TERM
  ```
  Не `trap 'kill -- -$$' EXIT INT TERM`: свой же TERM снова зовёт ловушку, рекурсия до переполнения
  стека — bash падает SIGSEGV и отдаёт 139 после успешного прогона (2026-10-18, все прогоны пака-2);
  ловушка только на EXIT убивает сам bash и отдаёт 143. `|| true` после `kill` обязателен: при запуске
  без `setsid` группы с номером `$$` нет, `kill` отдаёт 1, и `set -e` роняет успешный прогон с кодом 1
  до `exit $rc` (2026-10-19, `to-cvat` досканов пака-1).
- Запуск в фон из сессии агента — только `setsid ./run_x.sh > лог 2>&1 < /dev/null & PID=$!`:
  без `setsid` pgid ≠ pid, и `kill -- -$PID` промахивается. Ждать — `while kill -0 "$PID"`,
  живость — `ps -p "$PID"`. Перед повторным запуском — `ps -eo pid,pgid,cmd | grep '[r]un_'`.
- Выход прогона — на SSD `/mnt/hotstore/scan_processing/...` (переменные `HOT_ROOT`, `HOT_MTS_ROOT`, `HOT_MARKUP_ROOT`
  из `common.sh` пака-1; на `/mnt/system` проектных данных больше нет), базы — в `~/Projects/mts_markup`,
  никогда в корень `/mnt/dump3` (Я.Диск переименует поверх исходников). См. `docs/data_layout.md`.
- Скрипты, забирающие внешний экспорт, — идемпотентные и с `--min-age-minutes 10`.
