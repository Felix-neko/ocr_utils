# Разметка пака (scan_markup, scan_cleanup)

- **База разметки невоспроизводима.** `pack1.sqlite` и `pack1_reviewed.sqlite` содержат ручную
  разметку из CVAT, которую делают неделями. Любой шаг, который пишет в базу, запускать только
  через run-скрипт с `source common.sh` (он делает бэкап `$DB.bak`). Схему менять миграцией
  (`run_8_migrate_db.sh`), не пересозданием.
- **Координаты CVAT — в уменьшенных копиях.** Умножать на `divisor` из базы (у каждой полосы свой,
  `round(dpi/75)`), никогда на константу.
- **Кэш surya layout** (`LAYOUT_CACHE_DIR` — корень `page_layout.surya.SuryaCache`,
  `<корень>/<вариант>/<полоса>.json`; вариант `scan` полон на весь пак-1). Детекцию запускать с
  `--layout-cache`, иначе модель считает 3,5 часа на GPU. Детекторы (растр, таблицы, line art,
  повёрнутый текст, ориентация) живут в `ocr_utils/page_layout` — те же, что у сборки PDF;
  правка детектора = подъём версии семейства в `page_layout/__init__.py`.
- **Дозаливка в CVAT** — `to-cvat --append-kinds` / `--append-tags` (PATCH, ручная разметка цела).
  Полный `to-cvat` по уже размеченному проекту — только по явному решению пользователя.
- Пороги детекторов калибровать по распределению метрик всего пака (CSV с метриками → выборка
  по поясам score глазами → порог), а не по эталону из десятка полос. См. `docs/status.md`.
- Один прогон на пак идёт 12 136 полос; читать оригиналы с `/mnt/dump3` по разу, всё остальное
  (превью, оверлеи, кэши) держать на SSD. См. `docs/data_layout.md`.
